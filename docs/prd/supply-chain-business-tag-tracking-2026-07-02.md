# 大葱产业链解构优化方案 V2：业务阶段、三高证据、预期差与多维拆解

日期：2026-07-02

## 这次优化要解决什么

大葱产业链解构不能停在“某公司属于某板块”。真正要解决的是：一家公司有多块业务，哪一块业务命中了产业链标签，这块业务处于什么阶段，收入和利润占比有多少，护城河有没有证据，公告和研报说过的预期后来有没有兑现。

本次优化围绕 8 个问题：

| 编号 | 问题 | 方案抓手 |
|---|---|---|
| 1 | 区分标签相关业务的研发阶段、商用阶段 | 建立“公司-业务-标签”阶段卡片 |
| 2 | 区分标签相关业务的增长、盈利、围墙，不再看公司整体 | 以业务标签为评分单元 |
| 3 | 寻找证据证明所处板块和三高情况 | 建立证据事件和证据强度 |
| 4 | 跟踪公司公告、研报声明业务后的预期差 | 建立“声明-进展-市场认知”预期差模型 |
| 5 | 优化拆解逻辑，支持 BOM、上下游、价值链、竞争格局 | 一条产业链同时给出四种拆法 |
| 6 | 拆解层级更细，层层拆解 | 政策主题到产品型号、材料、客户场景逐级下钻 |
| 7 | 多业务公司如何拆三高 | 分业务归因收入、毛利、护城河 |
| 8 | 评分和排序如何优化 | 公司排序拆成产业链价值排序和预期差排序 |

## 核心口径

新的最小分析单元不是“公司”，而是：

```text
公司 + 业务分部 + 产业链标签 + BOM 节点
```

示例：

```text
中际旭创
→ 高速数通光模块
→ AI算力 / 光模块 / 800G
→ 光模块中游制造节点
```

同一家公司可以有多个业务标签。同一个业务标签也可以同时命中多个政策主题。系统要做收入、毛利和证据归因，不能把公司整体指标直接套到所有标签上。

## 总体流程

完整流程分 10 步：

```text
1. 定政策主题
2. 定产业方向
3. 按四种方法拆产业链
4. 拆到细粒度节点
5. 映射公司业务分部
6. 归因收入、毛利和围墙证据
7. 判断研发阶段和商用阶段
8. 跟踪公告、研报、互动问答证据
9. 计算三高和预期差
10. 输出排序、分池和解释
```

这套流程要求每个结论都能回答三个问题：

```text
这家公司哪块业务命中了标签？
这块业务有多少收入和利润相关性？
证据来自哪里，进展有没有变化？
```

## 政策主题和标签关系

三类政策主题继续保留：

| 主题 | 用途 |
|---|---|
| 未来产业主攻方向 | 找早期新赛道，例如量子、脑机、核聚变、6G |
| 新质生产力 | 找能提升效率和形成新动能的产业，例如 AI 算力、机器人、工业软件 |
| 科技自立自强 | 找卡脖子、国产替代、自主可控环节，例如半导体设备、基础软件 |

这三类不互斥。系统给每个节点设置一个主标签，再允许多个副标签。

示例：

| 产业链节点 | 主标签 | 副标签 |
|---|---|---|
| 光模块 | 新质生产力 | 科技自立自强、AI算力 |
| 半导体设备 | 科技自立自强 | 新质生产力、高端装备 |
| 量子通信 | 未来产业主攻方向 | 科技自立自强、新质生产力 |
| 具身智能关节模组 | 未来产业主攻方向 | 新质生产力、机器人 |

主标签用于归档，副标签用于解释政策共振。评分时不能因为一个节点命中多个主题就重复加分。

## 四种产业链拆解方法

大葱产业链解构页面要支持四种拆法。四种拆法看的是同一条产业链，但视角不同。

### 1. BOM 拆解

BOM 拆解回答“这个产业需要哪些关键零部件、材料、设备和工艺”。

通用层级：

```text
整机/系统
→ 核心模块
→ 关键零部件
→ 核心材料
→ 专用设备
→ 关键工艺
→ 测试验证
```

以光模块为例：

```text
AI 数据中心互联
→ 高速光模块
→ 光芯片 / 光器件 / DSP / 驱动芯片
→ 陶瓷基板 / PCB / 连接器
→ 封装设备 / 测试设备
→ 800G / 1.6T / 硅光 / CPO / LPO
```

BOM 拆解适合找卡脖子和高壁垒环节。

### 2. 上下游拆解

上下游拆解回答“谁给谁供货，需求从哪里来”。

通用层级：

```text
上游资源/材料
→ 上游设备/零部件
→ 中游制造/集成
→ 下游客户
→ 最终应用场景
```

以光模块为例：

```text
光芯片、陶瓷基板、PCB
→ 光器件
→ 光模块厂
→ 交换机、服务器、云厂商
→ AI 数据中心
```

上下游拆解适合判断需求传导和订单兑现。

### 3. 价值链拆解

价值链拆解回答“产业链里谁最赚钱，谁有定价权”。

要看四个点：

```text
收入空间
毛利率
价格传导能力
客户议价能力
```

示例：

```text
普通组装环节：收入可能大，但毛利和议价弱
核心芯片环节：收入占比可能不高，但技术壁垒强
高端模块环节：收入弹性和客户验证价值高
测试设备环节：容易被忽视，但放量期可能受益
```

价值链拆解适合判断盈利能力和利润弹性。

### 4. 竞争格局拆解

竞争格局拆解回答“这个环节是不是好生意，这家公司有没有位置”。

要看：

```text
市场份额
竞争对手数量
客户认证门槛
产品迭代速度
国产替代空间
价格战压力
进入壁垒
```

同一个环节可以出现不同结论：

```text
市场空间大，但竞争拥挤：增长高，围墙弱
市场空间小，但客户认证难：增长一般，围墙强
技术迭代快，老产品降价：现有收入高，但预期差可能转负
```

竞争格局拆解适合判断护城河和风险。

## 层级拆解标准

拆解层级要足够细。建议统一成 8 层：

| 层级 | 名称 | 示例 |
|---:|---|---|
| L1 | 政策主题 | 新质生产力 |
| L2 | 产业方向 | AI算力 |
| L3 | 产业链 | 光模块产业链 |
| L4 | 环节 | 光芯片、光器件、光模块、测试设备 |
| L5 | BOM 节点 | EML、硅光芯片、TOSA、ROSA、DSP |
| L6 | 产品/技术路线 | 400G、800G、1.6T、CPO、LPO |
| L7 | 公司业务分部 | 高速数通光模块业务 |
| L8 | 证据事件 | 客户验证、订单、量产、毛利改善 |

页面展示时可以折叠，但数据库要保留完整层级。

## 公司多业务拆分

系统要先拆公司业务，再映射产业链标签。

```text
公司
→ 主营业务分部
→ 产品/服务
→ 产业链标签
→ 政策主题
→ 证据
```

数据优先级：

| 优先级 | 来源 | 用途 |
|---:|---|---|
| 1 | 年报、半年报主营构成 | 收入和业务分部 |
| 2 | 公司公告 | 订单、产能、量产、客户验证 |
| 3 | 互动问答 | 产品进展、客户导入、技术路线 |
| 4 | 研报 | 产业链位置、竞争格局、盈利预期 |
| 5 | 新闻和市场资料 | 观察线索，不能直接入核心评分 |

如果业务分部命中多个标签，按置信度分摊收入。

示例：

```text
业务分部：高速通信模块
收入：10 亿元
标签归因：
AI算力 70%
通信设备 20%
6G 10%

AI算力标签收入 = 7 亿元
通信设备标签收入 = 2 亿元
6G 标签收入 = 1 亿元
```

如果没有分业务收入，只能进入观察池，不能进入核心池。

## 标签相关业务的阶段判断

研发阶段和商用阶段要分开。研发阶段看技术推进，商用阶段看收入兑现。

### 研发阶段

| 阶段 | 名称 | 判断依据 |
|---:|---|---|
| R0 | 无明确研发 | 只有概念提及 |
| R1 | 研发立项 | 公告、年报提到研发项目或技术方向 |
| R2 | 样品原型 | 有样品、原型机、实验室验证 |
| R3 | 内部测试 | 公司内部测试、性能验证 |
| R4 | 客户送样 | 向客户送样、进入认证 |
| R5 | 客户验证通过 | 通过客户验证、进入供应链 |
| R6 | 研发完成 | 产品定型，可量产 |

### 商用阶段

| 阶段 | 名称 | 判断依据 |
|---:|---|---|
| C0 | 无商业化 | 没有订单或收入证据 |
| C1 | 小批试产 | 小批量试产、试订单 |
| C2 | 小批交付 | 小批量交付，收入贡献较小 |
| C3 | 量产爬坡 | 明确量产、产线建设、产能释放 |
| C4 | 批量订单 | 批量订单、框架协议、客户采购 |
| C5 | 规模收入 | 该业务收入占比可见 |
| C6 | 利润兑现 | 毛利率、净利率或利润贡献改善 |
| C7 | 成熟业务 | 稳定收入和利润 |

阶段变化必须有证据。没有证据时，系统只能维持原阶段或标记为待复核。

## 三高定义

这里的“三高”指标签相关业务的高增长、高盈利、高围墙。它不是公司整体三高。

### 高增长

高增长看这块业务的增长，不看公司总收入。

证据包括：

```text
标签业务收入同比增长
订单或框架协议增加
产能扩张
客户数量增加
产品从低速率升级到高速率
收入占比提升
业绩预告明确受益于该业务
```

评分口径：

| 分值区间 | 判断 |
|---:|---|
| 80 到 100 | 标签业务收入或订单高增长，且来源明确 |
| 60 到 79 | 有订单、扩产或客户导入，但收入占比未完全披露 |
| 40 到 59 | 有业务进展，但增长证据弱 |
| 0 到 39 | 没有增长证据，或增长来自公司其他业务 |

### 高盈利

高盈利看标签业务的毛利和利润质量。

证据包括：

```text
分业务毛利率
高端产品占比提升
成本下降
产品单价提升
客户结构改善
该业务带动公司整体毛利率改善
```

数据状态必须标清：

| 状态 | 含义 |
|---|---|
| 披露值 | 公司披露了分业务毛利或毛利率 |
| 估算值 | 用收入占比和整体毛利率估算 |
| 代理值 | 用同行或同节点毛利率代理 |
| 不可用 | 数据不足，不参与高盈利评分 |

评分时，披露值权重最高，估算值降权，代理值只做参考。

### 高围墙

围墙指护城河，也就是业务壁垒。高围墙必须有证据。

证据包括：

```text
客户认证周期长
进入头部客户供应链
专利或技术秘密
国产替代
卡脖子环节
少数供应商
独家或核心供应商
行业标准参与
良率、工艺、产能壁垒
```

评分时区分三类证据：

| 类型 | 权重 |
|---|---:|
| 公司公告、年报、正式认证 | 高 |
| 研报明确列证据 | 中 |
| 概念归纳、新闻描述 | 低 |

没有证据的“龙头”“稀缺”“壁垒高”不能入分。

## 板块归属证据

系统要证明公司为什么属于某板块。证据分四层：

| 层级 | 证据 | 示例 |
|---|---|---|
| 业务证据 | 主营业务、产品、收入 | 年报主营构成显示高速光模块收入 |
| 产业链证据 | BOM 节点、上下游位置 | 公司产品属于光模块中游制造 |
| 政策证据 | 命中政策主题 | AI算力属于新质生产力方向 |
| 市场证据 | 指数、概念、研报覆盖 | 同花顺概念、券商研报、板块成员 |

只有市场概念证据，不足以证明板块归属。至少要有业务证据或产业链证据。

## 证据事件模型

公告、研报、互动问答进入系统后，要拆成事件。

事件字段：

| 字段 | 说明 |
|---|---|
| 公司 | 股票代码和名称 |
| 业务 | 对应业务分部或产品 |
| 标签 | 产业链标签 |
| 节点 | BOM 节点 |
| 来源 | 公告、研报、互动问答、财报 |
| 日期 | 来源日期 |
| 原文 | 可追溯片段 |
| 事件类型 | 研发、送样、认证、订单、量产、收入、毛利、风险 |
| 影响维度 | 研发阶段、商用阶段、增长、盈利、围墙、预期差 |
| 可信度 | 高、中、低 |
| 审核状态 | 待复核、通过、驳回 |

事件类型示例：

| 事件类型 | 关键词 |
|---|---|
| 研发 | 研发、样品、原型、测试 |
| 客户验证 | 送样、认证、通过验证、导入客户 |
| 订单 | 订单、合同、框架协议、批量采购 |
| 量产 | 量产、投产、产线、爬坡、扩产 |
| 收入 | 收入、占比、贡献、销售额 |
| 毛利 | 毛利率、盈利能力、高端产品占比 |
| 围墙 | 专利、独家、首家、国产替代、核心供应商 |
| 风险 | 延期、取消、降价、毛利下滑、客户流失 |

## 预期差模型

预期差不是“题材热不热”，而是声明、进展和市场认知之间的差。

系统要跟踪三条线：

```text
公司声明线：公司公告、年报、互动问答说了什么
研报预期线：券商研报预计什么业务、收入、毛利、时间点
实际进展线：后续有没有订单、量产、收入、毛利兑现
```

再加入市场认知：

```text
研报覆盖数量
新闻热度
板块热度
股价和成交反应
概念标签数量
```

### 预期差分类

| 类型 | 判断 |
|---|---|
| 正预期差 | 市场关注低，但业务阶段、订单或收入进展强 |
| 负预期差 | 市场关注高，但后续进展低于公司或研报预期 |
| 兑现差 | 公司或研报说了业务，后续没有证据跟进 |
| 隐性预期差 | 财务开始兑现，但市场还没有明显关注 |
| 风险预期差 | 价格或研报已充分反映，但业务证据不足 |

### 预期差评分

```text
预期差分 = 实际进展分 - 市场预期分 + 证据增量分 - 风险扣分
```

解释：

| 项 | 含义 |
|---|---|
| 实际进展分 | 研发阶段、商用阶段、订单、收入、毛利 |
| 市场预期分 | 研报覆盖、新闻热度、板块拥挤度、价格反应 |
| 证据增量分 | 最近 30/60/90 天新增证据 |
| 风险扣分 | 延期、毛利下滑、客户验证不及预期 |

输出时给两个排序：

```text
产业链价值排序：谁的业务质量最高
预期差排序：谁的进展更可能还没被充分定价
```

## 多业务公司的三高拆分

多业务公司不能用公司总增长、总毛利、总护城河代表所有业务。

### 拆分规则

| 场景 | 处理 |
|---|---|
| 年报披露分业务收入 | 直接按分业务收入归因 |
| 年报披露分业务毛利 | 直接按分业务毛利归因 |
| 只披露收入不披露毛利 | 用整体毛利率估算，并标记为估算 |
| 业务名称太粗 | 用公告和研报二次拆分，进入待复核 |
| 一项业务命中多个标签 | 按映射置信度分摊 |
| 业务没有收入证据 | 只能进入主题池或观察池 |

### 三高卡片

每个业务标签生成一张三高卡片：

```text
公司：A
业务：高速光模块
标签：AI算力 / 光模块

收入归因：65%
毛利归因：估算 58%
研发阶段：R6
商用阶段：C5
高增长：82
高盈利：76
高围墙：88
证据强度：高
预期差：正预期差
```

公司详情页展示的是多张卡片，而不是一个总标签。

## 评分体系

评分分两层：业务标签分和公司排序分。

### 业务标签分

每个“公司 + 业务 + 标签 + 节点”单独评分，满分 100。

| 维度 | 权重 | 说明 |
|---|---:|---|
| 映射质量 | 10 | 业务和标签是否真实匹配 |
| 阶段进展 | 15 | 研发阶段和商用阶段 |
| 高增长 | 15 | 标签业务收入、订单、客户、产能 |
| 高盈利 | 15 | 标签业务毛利、产品结构、利润兑现 |
| 高围墙 | 20 | 卡脖子、客户认证、专利、国产替代 |
| 证据强度 | 10 | 来源可信度、证据数量、更新时间 |
| 节点价值 | 10 | BOM 关键性、价值链位置、竞争格局 |
| 预期差 | 5 | 实际进展和市场预期的差 |

阶段进展可以拆成：

```text
阶段进展分 = 研发阶段分 × 40% + 商用阶段分 × 60%
```

商用阶段权重大于研发阶段。已经商业化的业务比停在实验室阶段的业务更适合进入核心池。

### 公司排序分

公司排序不再使用公司整体分。它由业务标签分加权得到。

```text
公司产业链价值分 =
Σ(业务标签分 × 标签收入占比 × 映射置信度 × 证据权重)
```

如果分业务毛利可用，使用毛利口径：

```text
公司产业链价值分 =
Σ(业务标签分 × 标签毛利占比 × 映射置信度 × 证据权重)
```

如果收入和毛利都不可用，只能输出主题相关分，不能进入核心排序。

### 预期差排序分

```text
预期差排序分 =
业务进展增量 × 35%
+ 证据增量 × 25%
+ 市场低关注度 × 20%
+ 估值/价格未充分反映 × 10%
- 风险扣分 × 10%
```

预期差排序用于找“业务在进展，但市场还没充分反应”的公司。它不能替代产业链价值排序。

## 分池规则

输出分五个池：

| 分池 | 条件 |
|---|---|
| 核心池 | 业务标签分高，收入或毛利占比可证，商用阶段至少 C3 |
| 进展池 | 阶段上升明显，订单、客户验证或产能有新增证据 |
| 预期差池 | 进展强于市场认知，且证据可信 |
| 观察池 | 方向正确，但收入、毛利或订单证据不足 |
| 剔除池 | 主营不匹配、证据弱、业务无法验证或阶段倒退 |

具体规则：

```text
核心池：
业务标签分 >= 75
标签收入占比 >= 30% 或标签毛利占比 >= 30%
商用阶段 >= C3
证据状态不低于 pending_review

进展池：
最近 90 天研发阶段或商用阶段上升
且新增证据可信度为中以上

预期差池：
预期差排序分 >= 70
且市场关注度不高
且没有重大负面证据

观察池：
业务标签分 50 到 75
或阶段低于 C3
或收入、毛利不可证

剔除池：
映射状态 rejected
或只有弱证据
或业务与标签不匹配
```

## 自动抽取和人工复核

系统先用规则抽取，后续接 LLM。规则负责高精度关键词，LLM 负责长文本理解和业务归因。

抽取内容：

```text
业务名称
产品型号
技术路线
客户类型
订单
产能
收入
毛利
专利
认证
风险
时间点
```

人工复核负责四件事：

```text
确认业务是否真实存在
确认标签映射是否正确
确认阶段变化是否合理
确认证据能不能入评分
```

复核动作：

| 动作 | 影响 |
|---|---|
| 通过 | 证据进入评分 |
| 修改标签 | 重新归因收入和证据 |
| 降级 | 只进入观察池 |
| 驳回 | 不参与评分 |

## 实施路线

### 第一阶段：业务标签和收入归因

交付：

```text
公司业务分部表
业务标签映射表
标签收入占比
公司多业务标签卡片
```

验收：

```text
一家公司可以显示多张业务标签卡
每张卡能说明收入归因和证据来源
没有收入证据的标签不能进入核心池
```

### 第二阶段：阶段跟踪和三高评分

交付：

```text
研发阶段 R0 到 R6
商用阶段 C0 到 C7
高增长、高盈利、高围墙评分
证据事件表
```

验收：

```text
阶段变化必须有证据事件
三高评分必须落到业务标签
公司整体增长不能替代标签业务增长
```

### 第三阶段：预期差模型

交付：

```text
公司声明线
研报预期线
实际进展线
市场关注度
预期差排序
```

验收：

```text
系统能区分正预期差、负预期差、兑现差
预期差排序和产业链价值排序分开
```

### 第四阶段：四种拆解视图

交付：

```text
BOM 拆解
上下游拆解
价值链拆解
竞争格局拆解
```

验收：

```text
同一产业链能从四种视角查看
用户能从政策主题一路下钻到公司业务和证据
```

### 第五阶段：回测和样本外验证

交付：

```text
业务标签评分历史
预期差评分历史
cutoff-aware 回测
核心池、预期差池、观察池表现对比
```

验收：

```text
历史评分不能使用未来公告、未来研报、未来财报
回测能分别验证产业链价值分和预期差分
```

## 验收标准

| 编号 | 验收项 |
|---|---|
| AC-1 | 一家公司可以映射多个业务标签 |
| AC-2 | 每个业务标签能显示研发阶段和商用阶段 |
| AC-3 | 每个业务标签能显示增长、盈利、围墙三项评分 |
| AC-4 | 三高评分不得直接使用公司整体指标替代 |
| AC-5 | 标签收入占比必须有来源，无法证明时标记为不可用 |
| AC-6 | 毛利数据必须区分披露值、估算值、代理值、不可用 |
| AC-7 | 每个核心池标签至少有一条中高可信证据 |
| AC-8 | 公告和研报声明的业务要形成预期跟踪记录 |
| AC-9 | 系统能输出正预期差、负预期差、兑现差、隐性预期差 |
| AC-10 | 支持 BOM、上下游、价值链、竞争格局四种拆解 |
| AC-11 | 拆解层级能从政策主题下钻到产品、材料、客户场景 |
| AC-12 | 排序区分产业链价值排序和预期差排序 |
| AC-13 | 多标签政策共振不能重复加分 |
| AC-14 | 样本外验证不能读取 cutoff 之后的数据 |

## 风险和边界

1. 分业务毛利不一定完整。第一版要标清“披露、估算、代理、不可用”。
2. 研报预期不是公司承诺。系统要把公司公告和研报推断分开。
3. 多标签业务不能每个标签都按 100% 收入计算，必须做归因。
4. 未来产业商业化周期长，不能用成熟产业的收入标准直接剔除。
5. 预期差分不能单独作为买入依据，它只是研究线索。
6. 历史评分必须保存快照，否则回测会产生未来数据泄露。

第一版先做四件事：

```text
业务分部识别

```

第二版再做：


这样可以先解决“公司哪块业务真的属于这个标签”，再解决“这块业务值不值得排到前面”。
