# PRD — 产业链证据链补全与业务阶段持续跟踪

- **Date**: 2026-07-03
- **Owner**: product-lead
- **Status**: Draft
- **Estimated effort tier**: Large

## 1. Background

现有产业链拆解已经能把公司映射到 18 条产业链、L5 BOM 标签和 L8 证据状态，但证据来源偏窄。当前 18 条产业链批量落库后，证据主要来自互动问答和公告目录，缺少公告正文、财报正文、调研纪要、财经新闻、研报、招投标、专利、官网、招聘和社区弱信号。

这会带来三个问题。第一，证据不够及时，很多产业事件先出现在新闻、调研、研报或公司官网。第二，证据不够强，互动问答不能替代公告、财报、订单、中标、专利和客户认证。第三，阶段判断不够稳定，研发阶段、商用阶段、三高评分和预期差需要用业务标签级证据持续更新，而不能只看公司整体。

本需求要把产业链模块升级为业务证据跟踪系统。系统需要围绕公司业务标签持续采集证据、结构化事实、更新研发和商用阶段、更新三高评分、跟踪研报和市场预期是否兑现。

## 2. Goal & Non-Goals

目标：

- 建立“公司 + 业务分部 + L5/BOM 标签 + L6 技术路线 + L8 证据事件”的证据跟踪体系。
- 把证据源分成强证据、半强证据、弱信号，并明确每类证据能影响哪些结论。
- 支持每日或定期增量采集，能发现新证据、阶段变化、证据过期和预期差。
- 让每个公司业务标签都能回答：真实业务是什么，研发到哪一步，是否商用，收入和毛利是否可见，是否具备卡脖子和围墙证据。

KPI：

- 核心池公司 L5 标签强证据覆盖率达到 60% 以上。
- 核心池公司半强证据覆盖率达到 80% 以上。
- 业务标签阶段变化 100% 可追溯到原文摘录和来源。
- 弱信号 0 条直接改变研发阶段或商用阶段。
- 证据重复率低于 10%。

Non-Goals：

- 本期不承诺接入所有付费数据源。Wind、Choice、iFinD、财联社等需要凭证或授权的数据源先做接口预留和来源目录管理。
- 本期不把自媒体、股吧、雪球、招聘信息作为强证据。
- 本期不把模型推断当成事实。模型只能抽取、归类和建议，不能生成无来源结论。
- 本期不重做产业链八层拆解逻辑，只在现有 L1-L8 结构上补证据体系。

## 3. User Stories

| ID | As a | I want to | So that |
|---|---|---|---|
| US-1 | 产品经理 | 查看某家公司某个 L5 标签的完整证据链 | 判断这家公司是不是产业链核心标的 |
| US-2 | 产品经理 | 区分研发阶段和商用阶段 | 避免把“概念提及”误判成“收入兑现” |
| US-3 | 投研使用者 | 看到高增长、高盈利、高围墙分别由哪些证据支撑 | 不再用公司整体指标替代业务标签指标 |
| US-4 | 投研使用者 | 看到研报或新闻提出的预期后续是否兑现 | 识别预期差和证伪风险 |
| US-5 | 运营使用者 | 看到证据过期、弱信号、待复核证据 | 每天知道该优先核查哪些公司和标签 |
| US-6 | 开发者 | 通过统一表结构接入公告、研报、新闻、专利、招投标和弱信号 | 后续新增数据源时不用改核心评分逻辑 |

## 4. Acceptance Criteria

| ID | Priority | AC | Verification method |
|---|---|---|---|
| AC-1 | P0 | 系统新增数据源目录，能记录来源类型、强弱等级、置信度上限、是否官方、是否需要交叉验证 | 查询 `evidence_source_catalog` 字段和种子数据 |
| AC-2 | P0 | 系统新增原始文档库，能保存标题、正文、发布时间、采集时间、URL、正文 hash 和来源 | 插入一条公告或新闻样例后查询 `raw_evidence_documents` |
| AC-3 | P0 | 系统新增结构化事实表，能把原文抽成公司、L5 标签、L6 技术路线、事实类型、原文摘录、阶段信号、三高信号 | 使用样例文本跑抽取脚本，查询 `evidence_extracted_facts` |
| AC-4 | P0 | 强证据可以触发阶段升级候选，半强证据进入待复核，弱信号只能进入预警 | 用公告、研报、社区三类样例分别验证输出状态 |
| AC-5 | P0 | 每条阶段变化必须写入阶段变更日志，并关联结构化事实或证据事件 | 查询 `business_tag_stage_transition_log` |
| AC-6 | P0 | 系统能计算每个业务标签的证据新鲜度，90 天无强证据标记为过期 | 构造历史证据样例并查询 `business_tag_evidence_freshness` |
| AC-7 | P0 | 新闻、研报、招聘、社区弱信号不能直接把 R/C 阶段升高 | 单元测试覆盖弱信号路径 |
| AC-8 | P1 | 系统能记录研报和新闻声明的预期，并跟踪后续兑现、部分兑现、未兑现或反向 | 查询 `business_tag_expectation_monitor` |
| AC-9 | P1 | 系统能从现有 `business_tag_mapping` 批量生成公司和 L5/L6 检索词 | 跑采集任务 dry-run，输出检索词清单 |
| AC-10 | P1 | 系统能把新增证据同步写入现有 `business_tag_evidence_events`，前端原证据时间线不失效 | 查询新事件并打开现有证据接口 |
| AC-11 | P1 | 系统能输出待复核队列，包括阶段升级候选、弱信号、证据过期、预期未兑现 | 调用待复核查询或 SQL 验证队列数量 |
| AC-12 | P2 | 支持第二批和第三批数据源的接入预留，包括财经新闻、研报、行业价格、社区、招聘、公众号和展会 | 查询来源目录和采集器配置 |

## 5. Design

UI：

- 本 PRD 不要求立即改前端，但后续前端需要新增“证据链总览、公司业务标签卡、阶段时间线、待复核中心、预期差看板”。

API 契约：

- 第一阶段可先通过离线脚本和 SQL 验证，不强制新增 API。
- 后续需要新增证据源状态、业务标签证据卡、待复核队列、阶段时间线、预期差详情接口。

数据模型：

- 新增 `evidence_source_catalog`：数据源目录。
- 新增 `raw_evidence_documents`：原始文档。
- 新增 `evidence_extracted_facts`：结构化事实。
- 新增 `business_tag_stage_transition_log`：阶段变化日志。
- 新增 `business_tag_evidence_freshness`：证据新鲜度。
- 新增 `business_tag_expectation_monitor`：预期差声明跟踪。

证据等级：

| 等级 | 来源示例 | 结论影响 |
|---|---|---|
| strong | 公告、财报、招投标、专利、政府项目 | 可触发阶段升级，部分自动通过 |
| mid | 互动问答、调研纪要、官网、财经新闻、研报、行业数据 | 进入待复核，可辅助三高和预期差 |
| weak | 社区、招聘、公众号转载、自媒体、展会零散信息 | 只预警，不直接改阶段 |

## 6. Technical Constraints

- 必须复用现有 PostgreSQL 和 Alembic 迁移体系。
- 必须复用现有 `business_tag_mapping`、`business_tag_evidence_events`、`business_tag_stage_tracking`、`business_tag_three_high_scores`、`business_tag_l8_evidence_status`。
- 所有新增表必须支持幂等写入，不能重复采集同一篇文档。
- 原始证据必须保留原文摘录、来源、发布时间和采集时间。
- 未授权的付费数据源不能模拟数据，必须标记为未配置或待授权。
- 模型抽取结果必须带置信度和证据等级上限。

## 7. Cost Estimate

- 预估 LLM token / 月：取决于文档量。第一版按每日 300 篇短文档、每篇 2,000 tokens 估算，约 1,800 万 tokens / 月。
- 预估 Agent Team 开发 token：Large。
- 成本档位：Large。原因是涉及数据库、采集、抽取、评分、前端和验收闭环。

## 8. Out of Scope / Future Work

- 全量 Wind、Choice、iFinD、财联社商用接口接入需要授权后单独实施。
- OCR 解析 PDF 研报全文可以作为第二阶段增强，不阻塞第一版。
- 多语言来源、海外新闻、海外专利先不纳入。
- 自动交易信号不在本需求范围内，本需求只提供证据和阶段跟踪。
