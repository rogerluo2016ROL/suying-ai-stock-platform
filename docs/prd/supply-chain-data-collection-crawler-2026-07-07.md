# PRD — 产业链三层数据采集与爬虫中心

- **Date**: 2026-07-07
- **Owner**: product-lead
- **Status**: Draft
- **Estimated effort tier**: Large

## 1. Background

现有产业链证据链已经能把公司映射到 L1-L8、记录 L8 证据、研发/商用阶段、三高评分和预期差评分。但目前数据支撑仍偏离散：部分数据来自 Tushare、部分来自已有批处理、部分来自互动问答和研报标题，缺少一个统一的数据采集、爬虫、调度、去重、解析和质量审计中心。

预期差判断需要持续回答三类问题：第一，公司业务是否有强证据支撑；第二，市场是否已经充分预期；第三，产业景气和弱信号是否出现变化。为避免模型用静态标签或弱信号误导判断，本需求建设专门的“产业链三层数据采集与爬虫中心”，为现有 `business_tag_*`、`supply_chain_*` 和 ChatBI/选股模型提供稳定、可追溯、可复核的数据输入。

## 2. Goal & Non-Goals

**目标**:

- 建立统一的数据源目录，覆盖第一层强证据、第二层预期和景气数据、第三层弱信号。
- 支持定时采集、增量采集、失败重试、去重、原文留存、结构化解析、证据质量评分。
- 把采集结果持续同步到现有产业链证据表，支撑研发阶段、商用阶段、三高、预期差更新。
- 明确每类数据的证据权重上限，防止弱信号直接改变阶段或选股结论。
- 支持 18 个产业链候选公司池的全量增量采集和验收试跑。

**KPI**:

- 第一批强证据源接入后，核心候选公司强证据覆盖率达到 60% 以上。
- 每条新增 L8 证据 100% 可追溯到原始文档、URL、发布时间和摘录。
- 采集任务失败可见，失败重试后仍失败的任务进入待处理队列。
- 重复文档入库率低于 5%。
- 弱信号直接触发阶段升级次数为 0。

**Non-Goals**:

- 本模块不直接输出买入、卖出或交易建议。
- 本期不绕过授权采集 Wind、Choice、iFinD、财联社等付费源；未授权源只做接口预留或人工导入。
- 本期不把社区、自媒体、招聘作为强证据。
- 本期不重写产业链 L1-L8 拆解逻辑，只给现有拆解体系补数据。
- 本期不保证所有 PDF 研报全文 OCR 完美解析，先保证公告、网页、接口类数据。

## 3. User Stories

| ID | As a | I want to | So that |
|---|---|---|---|
| US-1 | 产品经理 | 查看每个产业链候选公司的最新强证据覆盖情况 | 判断哪些标的证据不足、需要复核 |
| US-2 | 投研使用者 | 看到公司业务标签新增了哪些研发、订单、量产、收入证据 | 判断业务推进阶段是否变化 |
| US-3 | 投研使用者 | 区分强证据、半强证据和弱信号 | 避免把市场传闻当作事实 |
| US-4 | 数据运营 | 每天查看采集任务成功、失败、重复、待授权情况 | 维护数据质量 |
| US-5 | 模型开发者 | 通过统一表读取结构化证据和预期数据 | 更新预期差模型而不改每个爬虫 |
| US-6 | ChatBI 用户 | 询问某家公司预期差时看到最新证据来源 | 知道结论来自哪里 |

## 5. Design

UI:

- 本 PRD 第一阶段不要求新增完整前端。
- 需要提供 CLI/SQL 可验收的采集质量报告。
- 后续可在 ChatBI 或产业链后台增加“采集状态、证据新增、待复核队列”页面。

API 契约:

- 第一阶段以离线任务和 CLI 为主。
- 后续补充：
  - `GET /api/v1/evidence/sources`
  - `GET /api/v1/evidence/jobs`
  - `POST /api/v1/evidence/jobs/run`
  - `GET /api/v1/evidence/documents`
  - `GET /api/v1/evidence/review-queue`

数据模型:

- 复用已有表：`business_tag_mapping`、`business_tag_evidence_events`、`business_tag_l8_evidence_status`、`business_tag_stage_tracking`、`business_tag_three_high_scores`、`business_tag_expectation_gap_scores`、`business_tag_expectation_monitor`。
- 新增或标准化表：数据源目录、采集任务、原始文档、解析事实、采集质量审计、专利事件、招投标事件、官网/IR事件、产业价格序列。

## 6. Technical Constraints

- 所有采集器必须幂等写入。
- 所有证据必须保留原文来源，不允许模型生成无来源事实。
- 对需要授权的数据源，系统只能标记为 `not_configured` 或 `license_required`，不能伪造数据。
- 抓取公开网页必须控制频率，遵守 robots、登录授权和版权边界。
- 大模型只负责抽取、归类、摘要和置信度建议，不负责创造结论。
- 每次阶段升级必须能追溯到强证据或人工复核。

## 7. Cost Estimate

- 预估 LLM token / 月：第一阶段按每日 300-500 篇文档、每篇 1500-2500 tokens 估算，约 1350 万到 3750 万 tokens / 月。
- 预估 Agent Team 开发 token：Large。
- 成本档位：Large。原因是涉及采集、调度、数据库、抽取、证据同步、质量审计和 UAT。

## 8. Out of Scope / Future Work

- 商业数据源授权采购和合同不在工程范围内。
- 全量 PDF OCR 和复杂表格抽取放到第二阶段。
- 海外数据源、海外专利和英文新闻不在第一阶段。
- 自动交易、仓位管理不在本模块范围内。
