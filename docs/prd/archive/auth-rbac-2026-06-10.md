## 1. Background

投资管理平台覆盖选股→方案→预测→回测→交易→诊断全链路，涉及敏感金融数据和实盘资金操作。当前系统无任何用户认证和权限隔离——所有访问等同管理员。

**业务驱动**：
- 平台需要面向外部普通用户开放（Phase 1），必须有登录注册和权限隔离
- 实盘交易操作必须有身份校验和审计追溯（合规要求）
- Phase 4 将引入分析师角色，权限矩阵必须从 Day 1 设计好

## 2. Goal & Non-Goals

**目标**:
- 实现 4 角色 RBAC 认证授权体系，覆盖所有后端 API 和前端路由
- 注册/登录/Token 刷新/登出 API 完整可用

**KPI**:
- 登录成功率 > 99%（排除用户输错密码）
- API 鉴权延迟 < 50ms（P95）
- 所有受保护 API 不可绕过鉴权（E2E 全覆盖）

**Non-Goals**:
- 不做 OAuth/社交登录（V1 不含，留 Open Question）
- 不做多因素认证 MFA（V1 不含）
- 不做组织/租户隔离（单租户平台）
- 不做 IP 白名单/黑名单
- 不做邮箱验证流程（留 Open Question）

### 5.2 JWT Payload 设计

```json
{
  "sub": "user_uuid",
  "email": "user@example.com",
  "role": "user",
  "name": "张三",
  "iat": 1718000000,
  "exp": 1718000900,
  "type": "access"
}
```

| Claim | 类型 | 说明 |
|-------|------|------|
| `sub` | UUID string | 用户唯一标识 |
| `email` | string | 用户邮箱 |
| `role` | enum | `admin` / `internal_analyst` / `external_analyst` / `user` |
| `name` | string | 显示名称 |
| `iat` | unix timestamp | 签发时间 |
| `exp` | unix timestamp | 过期时间 |
| `type` | enum | `access` / `refresh` |

**Refresh Token** 仅在 `type` 字段取 `refresh`，`exp` 更长（建议 7 天），其余字段相同。

**Access Token 有效期**: 15 分钟（900s）。**Refresh Token 有效期**: 7 天（604800s），通过 httpOnly cookie 存储。

### 5.2.1 Token 存储策略

| Token | 存储位置 | 说明 |
|-------|---------|------|
| `access_token` | 前端内存（React state） | 不持久化到 localStorage/cookie，页面刷新后通过 refresh 恢复 |
| `refresh_token` | httpOnly Secure SameSite=Strict Cookie | 浏览器自动携带，JS 不可读取（防 XSS）；path=/api/v1/auth；后端 Set-Cookie 下发 + 每次 refresh 轮转 |

**选择理由**（参考 ADR-001）:
- httpOnly cookie 防 XSS 窃取 refresh_token
- SameSite=Strict 防 CSRF
- access_token 仅存内存，即使 XSS 也只能获取短命 token（15min 过期）
- 页面刷新 → 前端调 POST /api/v1/auth/refresh（cookie 自动携带）→ 静默恢复 access_token

**开发环境**: Vite dev server 需配置 proxy 将 `/api/v1` 转发到后端，确保同域 cookie 生效。

### 5.3 API 契约

#### `POST /api/v1/auth/register`

```
Request:
{
  "email": "string (valid email)",
  "password": "string (min 8 chars)",
  "name": "string (1-50 chars)"
}

Response 201:
{
  "access_token": "jwt_string",
  "refresh_token": "jwt_string",
  "token_type": "bearer",
  "expires_in": 900,
  "user": {
    "id": "uuid",
    "email": "string",
    "name": "string",
    "role": "user",
    "created_at": "2026-06-10T08:00:00Z"
  }
}

实现要点:
- 注册成功自动登录（直接返回 token，无需二次登录），对应 AC-26
- 新用户 role 固定为 "user"，不可通过请求体指定
- 后端通过 Set-Cookie 下发 refresh_token（httpOnly, Secure, SameSite=Strict, path=/api/v1/auth, max-age=604800）

Errors:
  409 - 邮箱已注册
  422 - 参数校验失败
```

#### `POST /api/v1/auth/login`

```
Request:
{
  "email": "string",
  "password": "string"
}

Response 200:
{
  "access_token": "jwt_string",
  "token_type": "bearer",
  "expires_in": 900,
  "user": {
    "id": "uuid",
    "email": "string",
    "name": "string",
    "role": "admin|internal_analyst|external_analyst|user"
  }
}

实现要点:
- 后端通过 Set-Cookie 下发 refresh_token（httpOnly, Secure, SameSite=Strict, path=/api/v1/auth, max-age=604800）
- access_token 仅在响应 body 返回，不存入 cookie
- refresh_token 不在响应 body 中返回（仅 httpOnly cookie）

Errors:
  401 - 邮箱或密码错误
  403 - 账号已被禁用
```

#### `POST /api/v1/auth/refresh`

```
Request:
Cookie 自动携带 refresh_token（httpOnly cookie）

Response 200:
{
  "access_token": "new_jwt_string",
  "token_type": "bearer",
  "expires_in": 900
}

实现要点:
- refresh_token 从 httpOnly cookie 自动提取，无需在请求 body 中传递
- 每次 refresh 轮转 refresh_token（新 Set-Cookie 覆盖旧 cookie）
- 旧 refresh_token 立即失效（rotation + replay detection）

Errors:
  401 - refresh_token 无效或已过期
```

#### `POST /api/v1/auth/logout`

```
Headers: Authorization: Bearer <access_token>

Response 200:
{
  "message": "已登出"
}

Errors:
  401 - 未认证
```

#### `GET /api/v1/admin/users`（管理员专属）

```
Headers: Authorization: Bearer <admin_access_token>

Response 200:
{
  "users": [
    {
      "id": "uuid",
      "email": "string",
      "name": "string",
      "role": "string",
      "is_active": true,
      "created_at": "string"
    }
  ]
}

Errors:
  401 - 未认证
  403 - 非管理员
```

#### `PATCH /api/v1/admin/users/{user_id}`（管理员专属）

```
Request:
{
  "role": "internal_analyst",  // optional
  "is_active": false            // optional
}

Response 200:
{
  "id": "uuid",
  "email": "string",
  "name": "string",
  "role": "internal_analyst",
  "is_active": false
}

Errors:
  401 - 未认证
  403 - 非管理员
  404 - 用户不存在
```

### 5.4 数据模型（新增表）

## 6. Technical Constraints

- 密码哈希：bcrypt（cost factor ≥ 12）或 argon2id
- JWT 签名算法：HS256（单服务）或 RS256（微服务间验证）；Phase 1 用 HS256
- JWT secret 来自环境变量 `JWT_SECRET`（≥ 32 字符随机字符串）
- Refresh token rotation：每次 refresh 发新 token pair + 旧 refresh token 立即失效
- 后端 RBAC 中间件：FastAPI dependency `Depends(require_role("admin"))` 模式
- 遵循 `.claude/standards/security.md`（不可记录 JWT/session 到日志）
- 遵循 `.claude/standards/coding.md`（FastAPI + SQLAlchemy + Pydantic v2 规范）
- 数据库 migration：Alembic（新增 `users` 和 `refresh_tokens` 表）
- 不引入新依赖：FastAPI 内置 `python-jose` + `passlib[bcrypt]` 或 `bcrypt` 即可

## 8. Out of Scope / Future Work

- 邮箱验证（发送验证邮件 + 验证码确认）
- OAuth 第三方登录（微信/Google/GitHub）
- 多因素认证（MFA / TOTP）
- 登录失败限流（5 次错误锁定 15 分钟）
- 密码重置流程（忘记密码）
- 会话管理（查看/踢出在线设备）
- API Key 管理与发放（V1 仅预留数据模型，不做管理界面）
- SSO / LDAP 集成
- 登录历史 / 设备指纹记录
- 敏感操作二次密码确认（实盘交易等场景用独立交易密码，非本模块范围）
