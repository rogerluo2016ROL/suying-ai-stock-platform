# 速赢AI UI 设计规范

适用文件：`suying-ai-workbench-redesign.html`  
适用范围：速赢AI桌面端高密度交易工作台，以及后续的选股、预测、信号、交易、回测、模型和数据页面改造。

## 1. 产品定位

速赢AI不是营销展示页，也不是普通管理后台。它是面向A股量化交易员、投研、风控和产品评审者的开盘前决策工作台。

界面要帮助用户在短时间内完成四件事：

- 判断市场状态。
- 比较AI候选股。
- 核对K线预测和交易信号。
- 在风控闸门下生成可执行交易计划。

核心体验标准是“可判断、可比较、可执行”。每个模块必须回答一个业务问题，不能只承担装饰或占位。

## 2. 设计原则

### 2.1 信息密度优先

首屏应该像交易终端，而不是SaaS首页。行情、候选、预测、风控和服务状态可以同时出现，但每个区域必须有清楚的阅读顺序。

推荐阅读路径：

1. 左侧确认当前业务模块。
2. 顶部确认当前工作流阶段和交易上下文。
3. 中央查看候选股和K线预测。
4. 右侧完成交易票和风控确认。
5. 底部检查服务健康。

### 2.2 双导航分工

左侧竖向菜单负责跨页面一级模块。顶部横向菜单负责当前页面内的业务流程。

左侧菜单不得变成当前页面锚点集合。顶部菜单不得重复所有产品模块。两者必须分工明确。

### 2.3 状态留在界面中

交易类产品不能只靠短暂提示传达风险。加载、空结果、降级和错误状态必须留在对应模块内，直到用户看到并处理。

### 2.4 克制使用强调色

电光蓝只用于当前态和关键操作。红色和绿色只表达A股涨跌，不用于普通装饰。警告色只表达延迟、复核和降级。

## 3. 信息架构

### 3.1 左侧一级模块

左侧菜单分三组：

- 行情决策：AI智能看板、开盘决策舱、智能选股、产业链拆解、K线预测、方案管理、交易信号。
- 交易执行：交易中心、量化交易、回测分析、个股诊断。
- 模型 / 系统：模型训练、模型注册、数据更新。

当前页面使用 `aria-current="page"`。当前项背景使用 `--accent-dim`，文字使用 `--fg`，左侧指示条使用 `--accent`。

### 3.2 顶部工作流

顶部横向菜单用于开盘决策舱内的流程：

- 总览
- 候选池
- K线预测
- 风控交易
- 服务监控
- 回测验证

页面内锚点使用真实业务区域，不做演示用标签切换。当前项使用底部蓝色短线，并同步 `aria-current="true"`。

### 3.3 交易上下文条

顶部菜单下方必须显示当前交易上下文：

- 交易日
- 执行模式
- 风控闸门
- 数据状态

上下文条是工作台状态，不是筛选器。它应随二次确认、服务降级、候选选择等操作同步变化。

## 4. 视觉系统

### 4.1 色彩 tokens

当前规范以深色交易终端为基础：

```css
:root {
  --bg: #0b0e14;
  --surface: #101620;
  --surface-2: #151d2a;
  --surface-3: #1a2433;
  --fg: #e8edf4;
  --fg-2: #a8b3c3;
  --muted: #667286;
  --border: rgba(255,255,255,.08);
  --border-strong: rgba(255,255,255,.14);
  --accent: #3d8bff;
  --accent-dim: rgba(61,139,255,.14);
  --up: #ff4d4f;
  --up-dim: rgba(255,77,79,.14);
  --down: #2ec27e;
  --down-dim: rgba(46,194,126,.14);
  --warn: #f5a623;
  --warn-dim: rgba(245,166,35,.14);
  --grid: rgba(255,255,255,.045);
}
```

使用规则：

- 背景使用 `--bg`，面板使用 `--surface` 到 `--surface-3`。
- 普通边框使用 `--border`，当前态或重要边界使用 `--border-strong`。
- 上涨使用 `--up`，下跌使用 `--down`。这是A股习惯，不能反过来。
- 风险、延迟、复核使用 `--warn`。
- CTA、当前导航和关键聚焦态使用 `--accent`。

### 4.2 字体

```css
--font-display: "SF Pro Display", "PingFang SC", -apple-system, BlinkMacSystemFont, system-ui, sans-serif;
--font-body: "SF Pro Text", "PingFang SC", -apple-system, BlinkMacSystemFont, system-ui, sans-serif;
--font-mono: "SF Mono", "JetBrains Mono", "IBM Plex Mono", ui-monospace, Menlo, Consolas, monospace;
```

使用规则：

- 页面标题、面板标题使用 `--font-display`。
- 正文、按钮、导航使用 `--font-body`。
- 股票代码、价格、涨跌幅、评分、延迟、时间使用 `--font-mono` 和 `font-variant-numeric: tabular-nums`。
- 大标题不超过一屏一个。交易工作台更需要快速扫描，不需要营销式巨型标题。

### 4.3 栅格和背景

背景允许使用非常轻的终端网格：

- 网格透明度维持在 `rgba(255,255,255,.045)` 附近。
- 只允许一处低透明度蓝色光晕，不能扩展成紫蓝渐变英雄区。
- 面板圆角使用 `8px`。不要使用大圆角卡片堆叠。

## 5. 组件规范

### 5.1 面板

面板用于承载一个完整业务判断：

- 标题区高度约 `45px`。
- 标题左侧是业务名，右侧是状态或元信息。
- 内容区必须出现真实数据、真实状态或可操作控件。
- 禁止空面板、装饰面板和“功能一 / 功能二”式占位。

### 5.2 按钮

按钮分三类：

- 默认按钮：刷新、加入观察池、辅助操作。
- 主按钮：复制交易计划、查看信号等关键推进动作。
- 危险按钮：只保存不下单、降级、撤销等风险动作。

按钮必须包含 hover、active、focus-visible、disabled 或 loading 中的相应状态。带状态的按钮需同步 `aria-pressed` 或 `aria-busy`。

### 5.3 候选股卡片

候选股卡片是按钮，不是静态卡片。每张卡必须包含：

- 股票名称和代码。
- 所属行业或主题。
- 涨跌幅。
- 综合评分。
- 至少三个因子分值。
- 当前选中态。

选中候选股后，K线预测、交易票和下单闸门必须同步更新。

### 5.4 K线预测区

K线区域需要表达三层信息：

- 历史走势。
- 模型预测路径。
- 阻力、支撑、止损等操作价位。

图内可保留技术服务名，如 Kronos。所有可见说明必须使用中文。研究信号必须标注“不构成投资建议”。

### 5.5 半自动交易票

交易票必须保留人工确认语义。字段至少包含：

- 标的
- 模式
- 计划价格
- 仓位上限
- 止损线
- 有效期

下单前必须显示风险盒和下单闸门。二次确认开关应使用 `role="switch"` 和 `aria-checked`。

### 5.6 服务健康

服务状态不是运维装饰，它直接影响交易链路。服务卡必须包含：

- 服务名。
- 端口或延迟。
- 在线、警告或降级状态。
- 对业务的影响说明。

当 `screener-service` 降级时，候选池、顶部数据状态和服务卡必须同时变化。

## 6. 状态规范

### 6.1 加载态

刷新按钮进入加载时：

- 按钮加 `aria-busy="true"`。
- 文案变为“刷新中”。
- 操作完成后恢复原文案。

加载态不能只依赖图标旋转。读屏和键盘用户也要知道当前状态。

### 6.2 空态

候选池搜索无结果时显示空态：

- 标题说明“没有匹配的候选股”。
- 正文给出恢复方法，例如清空搜索或切回“全部”。
- 使用 `role="status"` 和 `aria-live="polite"`。

### 6.3 错误和降级态

错误态必须显示在受影响模块内。降级操作至少同步三处：

- 顶部数据状态。
- 服务健康卡。
- 业务影响文案。

短暂 toast 只用于确认操作，例如“已复制交易计划”。它不能替代错误态。

### 6.4 当前态

当前态需要同时满足视觉和语义：

- 左侧当前页面：`aria-current="page"`。
- 顶部当前锚点：`aria-current="true"`。
- 当前筛选：`aria-pressed="true"`。
- 当前候选股：`aria-pressed="true"`。

## 7. 响应式规则

### 7.1 桌面优先

主目标是桌面端交易工作台。推荐宽度为 `1366px` 以上，最佳为 `1440px` 到 `1920px`。

桌面布局：

- 左侧固定宽度约 `236px`。
- 右侧主区域使用顶部导航加内容网格。
- 候选、预测和交易票并排构成核心工作区。

### 7.2 中等宽度

在 `1320px` 以下：

- 总览区改为单列。
- 工作区改为单列。
- 图表高度降至约 `320px`。
- 服务卡使用三列。

### 7.3 窄屏

在 `900px` 以下：

- 左侧导航变为顶部内容前的静态区域。
- 左侧菜单改为两列。
- 顶部操作按钮允许换行。
- 交易上下文条改为两列。

在 `560px` 以下：

- 菜单改为单列。
- 操作按钮占满宽度。
- 交易上下文、行情指标、表单、服务卡都改为单列。
- 图表高度降至约 `280px`。
- 图表说明不得绝对定位覆盖内容。

## 8. 可访问性规则

必须保留以下能力：

- 全局 `:focus-visible` 聚焦环。
- 所有输入项有明确 `label for`。
- 搜索框有 `aria-label`。
- 导航有 `aria-label`。
- toast、空态等反馈使用 `aria-live="polite"`。
- 开关使用 `role="switch"`。
- 可切换按钮使用 `aria-pressed`。
- 用户选择减少动态时，禁用或压缩动画。

颜色不能成为唯一状态来源。上涨、下跌、警告还需要数字、标签或文案辅助。

## 9. 动效和交互

动效只服务状态变化：

- 按钮按下可有 `translateY(1px)`。
- hover 只改变边框、背景或文字亮度。
- toast 可以淡入淡出。
- 刷新可以短暂进入 loading。

禁止使用大面积入场动画、粒子背景、连续闪烁或影响行情阅读的动效。

## 10. 文案规则

文案必须像交易产品，不像宣传页。

推荐写法：

- “候选池延迟 1 个周期”
- “触发前二次确认”
- “只保存，不下单”
- “单票 ≤ 8% 仓位”

避免写法：

- “开启智能投资新时代”
- “一键释放AI潜能”
- “让交易更简单”
- “功能一 / 功能二”
- “承诺收益翻倍”

没有真实来源的数据，不写成收益承诺。需要保留示例时，用业务标签说明它是研究信号或模拟状态。

## 11. 禁用清单

以下模式不得出现在速赢AI交付稿中：

- 紫蓝渐变英雄区。
- 营销页式大标题和大留白。
- 装饰性卡片堆叠。
- 表情符号图标。
- 设计器控制面板。
- 只靠 toast 承载错误。
- 虚构收益率、虚构胜率或无来源的夸张指标。
- 左侧彩色边框加圆角卡片的模板式信息块。
- 把A股涨跌色做反。
- 把产品导航做成演示用平台切换器。

## 12. 后续页面套用顺序

后续页面建议按核心链路迁移：

1. `screener.html`：智能选股，先套用候选股卡、筛选、空态和加载态。
2. `predictions.html`：K线预测，先套用图表、价位标签和研究信号声明。
3. `signals.html`：交易信号，先套用信号来源、置信度和风险状态。
4. `trade.html`：交易中心，先套用交易票、风控闸门和二次确认。
5. `backtest.html`：回测分析，先套用结果表、失败态和参数复核。

每个页面都保留同一套左侧一级菜单和顶部页面内工作流。页面之间只改变业务内容，不改变视觉系统。
