# ChatBI 原型说明

- **日期**: 2026-07-03
- **状态**: Draft
- **对应 PRD**: `docs/prd/chatbi-standalone-reuse-2026-07-03.md`
- **对应实施计划**: `docs/prd/chatbi-standalone-reuse-implementation-plan-2026-07-03.md`
- **阶段**: Design Gate A

## 1. 设计目标

ChatBI 是速赢 AI 的独立移动端投研问答应用，不是现有 PC 工作台里的一个页面。原型必须优先满足手机和企业 WebView 使用，帮助用户围绕产业链、选股、选债、证据链、三高、模型结果和报告生成完成判断。移动端应用必须独立建设，不修改现有 PC 端页面、路由、左侧导航、业务组件和既有接口契约。

第一版原型要先解决四个问题：

1. 用户能快速问问题，并看到清楚的流式过程。
2. 回答不是纯文本，而是带表格、证据链、模型门槛、数据日期和来源。
3. 管理员能配置模型供应商、节点级模型、提示词和报告模板。
4. 后续能挂到飞书、钉钉、企业微信 WebView，移动端不遮挡关键操作。

视觉上以原 ChatBI 移动聊天交互为主，参考 `docs/design/new front/design-spec.md` 的卡片密度、状态标签和表格表达：

- 不使用 PC 左侧一级模块导航作为主体验。
- 不改动现有 PC 端页面内容、菜单结构、路由和布局。
- PC 如需入口，只能作为独立外链或独立管理入口，不能影响原 PC 页面。
- 顶部是移动端应用栏、身份、数据状态和模型状态。
- 页面主体是单列移动信息流。
- 卡片圆角控制在 8px 左右。
- 表格、证据和状态优先，不做营销式大标题。
- 空状态必须说明原因和下一步，不出现大片空白。

设计复用约束：

| 来源 | 必须复用的内容 |
|---|---|
| `chatBI/ai 前端.zip` | 代码优先复用 `index.vue`、`module1.vue`、`Markdown.vue`、`componentsHistory.vue`、`feedback.vue`、`feedView.vue` |
| `chatBI/AI 后端.zip` | 代码优先复用 `GacDifyAIController`、`AiHistoryController`、`AiAgentTypeDifyController`、`AiHistoryEntity`、`AiHistoryMapper.xml`、`GacDifyData`、RuoYi 权限和审计基础 |
| K线大模型现有产业链设计 | 产业链标签、证据链、L8 明细、三高、研发/商用阶段、模型解释 |
| `docs/design/new front/` | 只参考卡片密度、状态标签、表格和颜色，不作为 PC 工作台壳 |

PC 端边界：

```text
不修改现有 PC 页面。
不修改现有 PC 路由。
不修改现有 PC 左侧导航。
不修改现有 PC 业务组件。
不修改现有 PC 既有接口契约。
```

## 2. 信息架构

### 2.1 应用入口

建议作为独立 H5 应用入口：

```text
速赢 ChatBI
```

入口形态：

```text
独立 H5 URL
飞书应用入口
钉钉应用入口
企业微信应用入口
PC 后台中的管理入口
```

### 2.2 模块页签

进入 ChatBI 后，顶部模块页签建议为：

| 页签 | 用途 |
|---|---|
| 问答工作台 | 普通提问、流式回答、结构化结果 |
| 证据链分析 | 公司、产业链标签、L8 证据和三高拆解 |
| 模型解释 | 选股、选债、无票原因、共振解释 |
| 报告生成 | 选择报告模板，把问答结果整理成报告 |
| 配置中心 | 智能体、模型、提示词、报告模板配置 |

移动端 WebView 不展示 PC 左侧导航，采用顶部应用栏 + 横向页签 + 底部导航 + 底部输入区。

## 3. 页面清单

### 3.1 首页

**页面目的**

让用户进入后马上知道可以问什么、最近问过什么、当前数据是否可用。

**入口**

- 从独立 H5 URL 或企业应用入口打开“速赢 ChatBI”。
- 企业应用 WebView 打开默认进入首页。

**主要区域**

| 区域 | 内容 |
|---|---|
| 顶部上下文条 | 交易日、数据更新状态、当前用户、模型状态、是否模拟盘 |
| 欢迎区 | 简短标题、输入框、当前默认智能体 |
| 热门问题 | 今日模型汇总、AI 算力候选、中际旭创证据链、无票原因、生成报告 |
| 历史会话 | 最近 10 条，显示问题、智能体、时间、状态 |
| 能力入口 | 产业链、选股、选债、证据链、报告生成 |

**主要控件**

| 控件 | 行为 |
|---|---|
| 输入框 | 回车或点击发送后进入问答页 |
| 智能体选择 | 切换总入口、产业链、选股、选债、报告助手 |
| 热门问题 | 点击后自动填入并发起问题 |
| 历史会话 | 点击后打开会话详情 |
| 新建会话 | 创建空会话 |

**状态**

| 状态 | 展示 |
|---|---|
| 加载中 | 热门问题和历史会话区域骨架屏 |
| 无历史 | 显示“暂无历史会话”，保留热门问题 |
| 数据延迟 | 顶部上下文条显示黄色状态，并提示最近更新时间 |
| 模型不可用 | 输入框仍可输入，但发送按钮旁显示降级说明 |

**移动端**

- 历史会话默认折叠。
- 热门问题横向滚动。
- 输入框固定底部，但不能遮挡内容。

### 3.2 问答页

**页面目的**

承载用户提问、节点过程、结构化答案、证据和反馈。

**入口**

- 首页输入问题后进入。
- 历史会话点击进入。
- 企业应用深链进入。

**布局**

| 区域 | 内容 |
|---|---|
| 左侧会话栏 | 会话列表、搜索、新建会话 |
| 中央问答区 | 用户问题、模型过程、回答正文、artifact |
| 右侧上下文栏 | 当前智能体、数据日期、工具调用、模型节点、引用来源 |

移动端中，会话列表和上下文详情收进抽屉或二级页，不出现 PC 左右分栏。

**节点过程**

每次回答至少展示：

```text
问题识别
工具选择
数据查询
答案生成
生成完成
```

如果启用节点级模型配置，节点详情中展示：

```text
node_type
model_id
prompt_version_id
耗时
fallback 状态
```

普通用户默认看到中文节点名和状态；管理员可以展开查看技术字段。

**主要控件**

| 控件 | 行为 |
|---|---|
| 发送 | 发起 `messages/stream` |
| 停止生成 | 中断 SSE，保留已生成内容 |
| 重新生成 | 使用同一问题重新跑一次 |
| 复制 | 复制当前回答 Markdown |
| 导出报告 | 进入报告生成页，并带入当前会话 |
| 赞/踩 | 提交反馈 |
| 查看来源 | 打开证据或工具调用详情 |

**状态**

| 状态 | 展示 |
|---|---|
| 流式生成中 | 节点逐个点亮，正文分段出现 |
| 工具无数据 | 显示缺失原因、数据日期和补数建议 |
| 模型 fallback | 节点显示“已切换备用模型”，保留原因 |
| 被风控拒答 | 明确说明不能提供下单、绕过风控或实盘交易建议 |
| 回答失败 | 保留问题，显示重试按钮和错误摘要 |

### 3.3 结构化结果展示

**页面目的**

让 ChatBI 的回答能承载真实投研数据，而不是只有长段文字。

**组件清单**

| 组件 | 用途 |
|---|---|
| 表格结果 | 候选公司、模型结果、无票门槛、共振清单 |
| 公司卡片 | 股票代码、名称、产业链标签、评分、股价、近期涨幅 |
| 证据链卡片 | L8 证据、来源、日期、可信度、业务阶段 |
| 三高标签 | 高技术壁垒、高成长、高盈利，显示分数和证据数 |
| 研发/商用阶段 | 研发、试产、商用、放量、成熟 |
| 模型过滤门槛 | 每道门槛通过数量、失败原因、代表样本 |
| 数据日期条 | as_of、trade_date、latest_update_at |
| 限制说明 | 数据缺口、模型局限、不构成投资建议 |

**表格规则**

- 每个表格必须有列名、数据日期、来源。
- 股票代码、分数、涨跌幅使用等宽数字。
- 超出宽度时横向滚动，不压缩到不可读。
- 空表格必须说明“为什么没有数据”。

**证据链规则**

证据卡片必须至少展示：

```text
证据标题
证据类型
来源名称
发布日期
关联产业链标签
关联业务
业务阶段
三高维度
原文摘要
可信度
```

### 3.4 证据链分析页

**页面目的**

围绕公司或产业链标签，集中查看证据、三高、研发/商用阶段和预期差。

**入口**

- 问答结果中点击公司卡片。
- 顶部页签点击“证据链分析”。
- 搜索公司或产业链标签。

**布局**

| 区域 | 内容 |
|---|---|
| 搜索区 | 公司、股票代码、产业链标签 |
| 摘要区 | 公司基本信息、命中标签数、证据数、最新证据时间 |
| 标签分布 | L1-L8 层级、三高得分、阶段 |
| 证据列表 | 按来源、时间、业务阶段、三高维度筛选 |
| 右侧明细 | 选中证据的结构化字段和原文摘要 |

**关键筛选**

```text
产业链
L1-L8 层级
业务阶段
三高维度
证据来源
发布日期
可信度
```

**状态**

- 证据不足时显示“待补证据”，并列出缺口。
- 证据过期时显示“需更新”，并标出最后更新时间。
- 公司多业务映射时，按业务标签拆分，不用公司整体数据替代标签数据。

### 3.5 模型解释页

**页面目的**

解释选股、选债、产业链候选、共振和无票原因。

**主要模块**

| 模块 | 内容 |
|---|---|
| 今日模型结果 | 模型名称、运行时间、候选数、通过率 |
| 无票原因 | 分层过滤漏斗、失败门槛、典型失败样本 |
| 共振统计 | 命中模型数、产业链标签数、三高情况 |
| 个股解释 | 入选原因、未入选原因、相关证据 |

**交互**

- 点击模型行，右侧显示门槛详情。
- 点击失败门槛，展示被过滤样本。
- 点击候选公司，跳到证据链分析页。

### 3.6 报告生成页

**页面目的**

把问答结果、证据和结构化数据整理为 Markdown、Word 或 Excel 报告。

**布局**

| 区域 | 内容 |
|---|---|
| 左侧模板列表 | 公司深度报告、产业链报告、模型复盘、债券模型报告 |
| 中央报告预览 | 章节目录、正文预览、表格和证据块 |
| 右侧参数 | 标的、产业链、日期范围、数据来源、导出格式 |

**主要控件**

| 控件 | 行为 |
|---|---|
| 选择模板 | 切换报告结构 |
| 选择会话 | 把会话结果带入报告 |
| 重新生成正文 | 调用报告生成节点模型 |
| 导出 Markdown | 下载或保存 Markdown |
| 导出 Word | 生成 docx |
| 导出 Excel | 生成明细表 |

**状态**

- 模板未发布：不能用于正式导出，只能预览。
- 数据不足：报告中保留缺口说明。
- 生成中：显示章节级进度。

### 3.7 配置中心

配置中心面向管理员，不面向普通用户。

## 4. 核心交互流程

### 4.1 普通问答

```text
打开首页
输入问题
选择智能体
发送
进入问答页
显示节点过程
展示结构化答案
用户查看来源或导出报告
提交反馈
```

### 4.2 查看公司证据链

```text
输入“中际旭创证据链”
系统识别公司和产业链标签
返回公司卡片、标签分布、证据列表
用户点击证据
右侧显示 L8 明细
用户筛选三高或研发/商用阶段
```

### 4.3 解释无票原因

```text
输入“今天匪爷竞价选债为什么没票”
系统识别模型
调用无票诊断工具
展示门槛漏斗
展示每层过滤数量和失败原因
给出数据日期和限制说明
```

### 4.4 生成报告

```text
在回答中点击导出报告
进入报告生成页
选择模板
确认数据范围
预览章节
生成正文
导出 Markdown / Word / Excel
保存 render_log
```

### 4.5 管理节点级模型

```text
管理员进入配置中心
选择智能体
进入节点级模型配置
分别配置语义识别、证据抽取、报告生成模型
保存
点击测试当前节点
查看 token、耗时和 fallback
发布配置
```

## 7. 移动端 WebView 规则

| 项目 | 规则 |
|---|---|
| 导航 | 使用底部导航和顶部横向页签，不依赖 PC 左侧导航 |
