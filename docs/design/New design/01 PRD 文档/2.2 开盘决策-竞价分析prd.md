- **Date**: 2026-06-26

## 1. 定位

竞价分析是**可操作的竞价工作台**，不是只读看板。

| 维度 | 1.2 竞价意图看板（AI智能看板） | 2.2 竞价分析（开盘决策） |
|---|---|---|
| **性质** | 只读浏览 | **可操作工作台** |
| **数据** | 预计算的竞价意图评分 | 意图评分 + **实时运行选股/选债引擎** |
| **操作** | 点击跳转诊断 | **运行引擎 → 勾选标的 → 加入候选池 → 锁定板块** |
| **工作流** | 独立页面，无上下文 | **下游联动**：锁定板块→信号扫描自动筛选 |
| **默认用户** | 个人投资者（浏览） | 操盘手（操作） |

## 2. 核心操作

```
操盘手 9:25 竞价结束后进入此 Tab:

 1. 竞价意图全景自动加载               → 判断今天偏抢筹还是偏出货
 2. 查看一字定方向 + 板块共振            → 锁定 2-3 个强势板块
 3. 切换到 [竞价选股] 子Tab             → 运行 leader_auction V4.3
 4. 在结果中勾选 3-5 只                 → 点击 [加入候选池]
 5. 切换到 [竞价选债] 子Tab             → 运行 cb_auction V1.0
 6. 勾选转债 → 加入候选池
 7. 点击板块卡片 [锁定板块→信号扫描]     → 跳转到 2.3 信号扫描，矩阵自动筛选该板块
```

## 4. 关键操作定义

| 操作 | 触发 | 效果 |
|---|---|---|
| **运行引擎** | Tab 激活 + 有今日竞价数据 时自动运行 | 显示 leader_auction 和 cb_auction 结果 |
| **锁定板块** | 点击板块卡片 [🔒锁定→信号扫描] | 写入 Context → 信号扫描 Tab 自动筛选该板块 |
| **加入候选池** | 勾选股票 → [加入候选池] | CandidatePoolManager.addSource('auction', picks) |
| **一键加入全部** | [全选] → [加入候选池] | 当前列表全部加入候选池 |
| **重新运行** | [🔄 重新运行] 按钮 | 重新调引擎（如竞价数据更新） |
| **选择板块→查看强势股** | 点击板块共振详情中的板块条目 | 下方展开该板块的强势股列表 + 关联转债列表 |
| **一键锁定+选股** | 板块条目 [选股] 按钮 | 锁定该板块 + 自动筛选该板块竞价TOP10 |

## 4.1 板块共振详情面板

**位置**：右侧操作面板顶部，替代原纯文字工作流提示。

**展示内容**：

| 列 | 说明 | 数据来源 |
|---|---|---|
| 板块名 | 行业板块名称 | `stocks.industry` 聚合 |
| 信号数 | 该板块有竞价信号的股票数 | `stk_auction_o` 按 industry 统计 |
| 均涨幅 | 板块内股票竞价均涨跌幅 | 同上，AVG(chg_pct) |
| 热度条 | 可视化进度条（max=最大板块信号数） | 前端计算 |
| 领涨股 | 板块内竞价涨幅TOP2（代码+涨幅） | 按 chg_pct 降序取TOP2 |
| 操作 | [选股] 按钮 | 触发"选中板块→展开强势股" |

**交互**：
- 点击板块条目 → 右侧下方展开"强势股 + 关联转债"面板
- 点击 [选股] → 自动锁定板块 + 展示该板块竞价TOP10 + 关联转债

## 4.2 选中板块：强势股 + 关联转债

**位置**：竞价意图子Tab 的左侧面板下方（选中板块后动态展开）。

**强势股列表**（来自 `stk_auction_o` 按板块筛选）：
- 代码、名称、竞价涨幅%、竞量比、评分
- 每行有勾选框 → [全选加入候选池]

**关联转债列表**（来自 `cb_auction` 结果按概念匹配板块）：
- 代码、概念、溢价率%、竞价涨幅%、评分
- 每行有勾选框 → [全选加入候选池]

**目的**：让投资者在锁定一个强势板块后，一眼看到该板块的竞价强势股 + 关联可转债，不需要切换到"竞价选股"或"竞价选债"子Tab。

## 5. 与 1.2 的技术关系

1.2 的竞价意图看板**作为 2.2 的第一个子 Tab**保留：
- 复用 1.2 的全部 UI 组件（概览行/双榜单/走势图/雷达图/一字定方向/全量明细表）
- 增强：板块卡片增加 [🔒锁定→信号扫描] 操作按钮
- 增强：明细表增加勾选框 + [加入候选池] 操作
- 增强：风险公告检测（如中芯国际立案调查 → 自动标记排除）

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 开盘决策：操盘手默认入口，输出私有 Candidate 与 DecisionContext。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共竞价/行情 + 私有候选池。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 实盘前必须进入方案与风控。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
