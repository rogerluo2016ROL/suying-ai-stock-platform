## 1. 页面定位

信号总览是交易信号菜单的**默认主视图**（Tab key: `overview`）。操盘手在此页面完成：

1. 信号强度综合判断（六维雷达图一屏尽览）
2. 资金共振验证（北向/主力/融资是否与信号同向）
3. 趋势确认（均线排列 + 趋势强度）
4. 操作决策（仓位建议 → 加入候选池 / 跳转下单）

与 6.2 信号历史、6.3 风险扫描共同组成"总览→历史验证→风险排查"三级研判流程。

## 3. 核心数据结构（复用父设计）

```typescript
// 全部类型定义见 6.0 交易信号详细设计.md §2

// 本 Tab 使用的核心接口：
interface SignalResult {
  tsCode: string
  name: string
  compositeScore: number      // 加权综合分 → SignalVerdict
  rating: SignalRating         // STRONG_BUY | BUY | HOLD | SELL | STRONG_SELL
  actionText: string           // "建议重仓买入 (15-20%)"
  dimScores: DimScore[]        // → DimBreakdown (6条) + SixDimRadar (6轴)
  fundFlows: FundFlow[]        // → FundFlowPanel (3行)
  trend: TrendInfo             // → TrendStrength
  computedAt: string
  dataFreshness: string
}

interface DimScore {
  dim: 'kronos' | 'technical' | 'capital' | 'fundamental' | 'event' | 'market'
  label: string                // "Kronos预测" / "技术分析" / "资金面" / "基本面" / "事件驱动" / "市场情绪"
  icon: string                 // "🤖" / "📊" / "💰" / "🏢" / "⚡" / "🌐"
  score: number                // 0-100
  weight: number               // 0.10 ~ 0.20
  description: string
}

interface FundFlow {
  type: 'main_force' | 'north_bound' | 'margin'
  label: string
  amount: number
  direction: 'inflow' | 'outflow'
  changePct: number
  consecutiveDays: number
  summary: string
}

interface TrendInfo {
  score: number                // 0-100
  direction: 'up' | 'down' | 'sideways'
  directionLabel: string
  maStatus: 'bullish_alignment' | 'bearish_alignment' | 'entangled'
  maStatusLabel: string        // "均线多头排列"
  keyMAs: { ma5: number; ma10: number; ma20: number; ma60: number }
}
```

### 7.1 方向图标逻辑

```typescript
function getFlowArrow(direction: 'inflow' | 'outflow'): string {
  return direction === 'inflow' ? '▲' : '▼'
}

function getFlowColor(direction: 'inflow' | 'outflow'): string {
  // A股: 流入=看多=红色(var(--up)), 流出=看空=绿色(var(--down))
  return direction === 'inflow' ? 'var(--up)' : 'var(--down)'
}

function getFlowSummaryText(flows: FundFlow[]): string {
  const inflowCount = flows.filter(f => f.direction === 'inflow').length
  if (inflowCount === 3) return '💡 资金面偏多，主力+北向共振流入，短期看多信号明确'
  if (inflowCount >= 2) return '💡 资金面偏多，多项资金共振流入'
  if (inflowCount === 0) return '⚠️ 资金面偏空，多项资金流出，注意风险'
  return '💡 资金面分化，单项资金流入，关注持续性'
}
```

// 文件: components/signals/TrendStrength.tsx

function TrendStrength({ trend }: { trend: TrendInfo }) {
  const dirColor = trend.direction === 'up' ? 'var(--up)' 
    : trend.direction === 'down' ? 'var(--down)' 
    : 'var(--accent)'
  
  const maColor = trend.maStatus === 'bullish_alignment' ? 'var(--up)'
    : trend.maStatus === 'bearish_alignment' ? 'var(--down)'
    : 'var(--warn)'

  return (
    <div className="ti">
      <span className="ts" style={{ color: dirColor }}>{trend.score}</span>
      <div className="td">
        <span className="dir" style={{ color: dirColor }}>{trend.directionLabel}</span>
        <span className="st">{trend.maStatusLabel}</span>
        <span className="ma">
          MA5:<span className="mono up">{trend.keyMAs.ma5.toFixed(2)}</span>
          &nbsp; MA10:<span className="mono up">{trend.keyMAs.ma10.toFixed(2)}</span>
          &nbsp; MA20:<span className="mono up">{trend.keyMAs.ma20.toFixed(2)}</span>
          &nbsp; MA60:<span className="mono up">{trend.keyMAs.ma60.toFixed(2)}</span>
        </span>
      </div>

  )
}

## 9. 数据流

```
SignalDetailPage (父级)
  │
  ├── 选取 tsCode → GET /api/v1/signal/analyze/{ts_code}
  │   └── 返回 SignalResult (六维评分 + 资金流 + 趋势)
  │
  └── 根据 activeTab 渲染对应 Tab 组件
      │
      └── activeTab === 'overview' → <SignalOverviewTab
            signalResult={signalResult}
            userRole={userRole}
          />
```

### 9.1 加载态

```
┌── SignalOverviewTab (isLoading=true) ──┐
│ SignalVerdict:    骨架屏 (灰色条)        │
│ SixDimRadar:      雷达图区域 Spin        │
│ DimBreakdown:     6条灰色进度条 (pulse) │
│ FundFlowPanel:    3行骨架屏              │
│ TrendStrength:    骨架屏                  │
└──────────────────────────────────────────┘
```

### 9.2 错误态

```
各 Card 组件独立错误边界：
- 雷达图加载失败 → Card 内显示 Alert "六维数据加载失败" + 重试按钮
- 资金流加载失败 → Card 内显示空态 "暂无资金流数据"
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易信号：公共信号规则与用户私有订阅、处理状态分离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共信号 + 私有已读/订阅/处置。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 信号只作为订单依据之一。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
