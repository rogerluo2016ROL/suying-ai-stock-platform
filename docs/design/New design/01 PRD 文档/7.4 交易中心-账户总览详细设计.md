## 3. 核心数据结构

```typescript
interface AccountSummary {
  totalAsset: number
  availableCash: number
  marketValue: number
  frozen: number
  dailyPnL: number
  dailyPnLPct: number
  weeklyPnLPct: number
  monthlyPnLPct: number
  cumulativePnLPct: number
  pnlHistory: PnlDataPoint[]
}

interface PnlDataPoint {
  date: string
  dailyPnL: number
  cumulativePnL: number
}
```

---

## 4. 数据流

```
AccountOverview mount
  │
  ├── GET /trade/account
  │   └── 返回 AccountSummary (不含 pnlHistory)
  │
  ├── GET /trade/pnl-history?days=30
  │   └── 返回 pnlHistory[] (每日 + 累计)
  │
  ├── 渲染 KPI 卡片
  │
  ├── 渲染 PnlChart (ECharts)
  │   └── 二合一: 累计盈亏(面积图) + 每日盈亏(柱状图)
  │
  └── 轮询: setInterval(60s) → GET /trade/account
```

### 4.1 ECharts 盈亏曲线配置

```typescript
function buildPnlChartOption(pnlHistory: PnlDataPoint[]): EChartsOption {
  const dates = pnlHistory.map(d => d.date.slice(5))  // "06-01"
  const cumulative = pnlHistory.map(d => d.cumulativePnL)
  const daily = pnlHistory.map(d => d.dailyPnL)

  return {
    backgroundColor: 'transparent',
    tooltip: {
      trigger: 'axis',
      backgroundColor: '#1b2330',
      borderColor: '#2a3444',
      textStyle: { color: '#e8edf4', fontSize: 11 },
      formatter: (params: any) => {
        const d = params[0]
        return `${d.axisValue}<br/>累计盈亏: ¥${Number(d.value).toLocaleString()}`
      }
    },
    grid: { left: 12, right: 16, top: 12, bottom: 8 },
    xAxis: {
      type: 'category',
      data: dates,
      axisLine: { lineStyle: { color: '#1f2733' } },
      axisTick: { show: false },
      axisLabel: { color: '#5e6a7d', fontSize: 9, interval: 6 },
    },
    yAxis: {
      type: 'value',
      splitLine: { lineStyle: { color: '#1f2733' } },
      axisLabel: {
        color: '#5e6a7d',
        fontSize: 9,
        formatter: (v: number) => (v >= 0 ? '+' : '') + (v / 1000).toFixed(0) + 'K',
      },
    },
    series: [
      {
        name: '累计盈亏',
        type: 'line',
        data: cumulative,
        smooth: true,
        symbol: 'none',
        lineStyle: { color: '#3d8bff', width: 2 },
        areaStyle: {
          color: new echarts.graphic.LinearGradient(0, 0, 0, 1, [
            { offset: 0, color: 'rgba(61,139,255,0.2)' },
            { offset: 1, color: 'rgba(61,139,255,0.02)' },
          ]),
        },
      },
      {
        name: '每日盈亏',
        type: 'bar',
        data: daily,
        itemStyle: {
          color: (params: any) => params.value >= 0 ? '#2ec27e' : '#ff4d4f',
          borderRadius: [2, 2, 0, 0],
        },
        barWidth: 8,
      },
    ],
  }
}
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易中心：账户、订单、持仓、成交全部按 tenant/account/user 隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 强私有交易数据。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | paper/QMT/多券商统一 BrokerAdapter。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
