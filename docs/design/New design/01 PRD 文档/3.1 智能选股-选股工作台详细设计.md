## 3. 数据结构

### 3.1 TypeScript 接口

```typescript
// ── Screener Pick (选股结果) ──────────────────────────
interface ScreenerPick {
  rank: number                          // 排名
  tsCode: string                        // 代码 e.g. "000858.SZ"
  name: string                          // 名称
  score: number                         // 综合评分 0-100
  grade: StockGrade                     // S/A/B/C/D
  industry: string                      // 申万一级行业
  marketCap: number                     // 总市值（亿）
  modelKey: string                      // 来源模型
  isST: boolean                         // 是否 ST
  factors: Record<string, number>       // 模型专属因子值
}

type StockGrade = 'S' | 'A' | 'B' | 'C' | 'D'

// ── Model Config ──────────────────────────────────────
interface ModelConfig {
  modelKey: string                      // 'bi_trend_launch'
  modelName: string                     // '毕师傅趋势启动 V13'
  modelGroup: ModelGroup                // 分组
  styleTag: string                      // '趋势跟踪' / '龙头战法' / '短线波段' etc.
  cycle: 'daily' | 'weekly'             // 运行周期
  description: string                   // 简介
  enabled: boolean                      // 是否可用
}

type ModelGroup = 'trend' | 'multi-factor' | 'convertible-bond'

// ── Screener Run Request ──────────────────────────────
interface ScreenerRunRequest {
  modelKey: string
  tradeDate: string                     // '2026-06-26'
  topN: number                          // 10 | 20 | 30 | 50
  filters: {
    market?: 'all' | 'mainboard' | 'chinext' | 'star'
    excludeST: boolean
    industries?: string[]
    minMarketCap?: number
    maxMarketCap?: number
  }
}

// ── Screener Run Response ─────────────────────────────
interface ScreenerRunResponse {
  modelKey: string
  tradeDate: string
  picks: ScreenerPick[]
  totalFound: number
  runtimeMs: number
  cached: boolean
}

// ── Workbench State ───────────────────────────────────
interface WorkbenchState {
  // Model selection
  activeModelKey: string
  availableModels: ModelConfig[]

  // Params
  tradeDate: string                     // ISO date
  topN: number
  filters: ScreenerRunRequest['filters']

  // Results
  picks: ScreenerPick[]
  selectedPickIndex: number             // index into picks[]
  selectedBatchIndices: Set<number>     // batch selection

  // Detail card
  detailCardStock: ScreenerPick | null  // currently viewed in detail card

  // UI
  isRunning: boolean
  lastRunAt: string | null
  error: string | null
}
```

```typescript
function getGrade(score: number): StockGrade {
  if (score >= 90) return 'S'
  if (score >= 80) return 'A'
  if (score >= 60) return 'B'
  if (score >= 40) return 'C'
  return 'D'
}
```

### 3.3 进度条颜色逻辑

```typescript
function getBarColor(value: number, max: number, goodDirection: 'high' | 'low'): string {
  const ratio = value / max
  if (goodDirection === 'high') {
    if (ratio >= 0.8) return 'var(--up)'
    if (ratio >= 0.5) return 'var(--accent)'
    if (ratio >= 0.3) return 'var(--warn)'
    return 'var(--muted)'
  } else {
    if (ratio >= 0.8) return 'var(--up)'       // bad
    if (ratio >= 0.5) return 'var(--warn)'
    if (ratio >= 0.3) return 'var(--accent)'
    return 'var(--down)'                        // good
  }
}
```

## 4. 数据流

### 4.1 初始加载

```
ScreenerWorkbench mount
│
├── GET /api/v1/screener/models
│   └── 返回可用模型列表 + 分组信息
│       └── 渲染 ModelSelector
│
├── GET /api/v1/screener/latest-snapshot?date={latest}
│   └── 如果有最近的快照 → 自动加载到结果表格
│       └── 默认选中第一行 → 渲染详情卡
│
└── 从 URL params 读取 ?model=bi_trend_launch → 设置 activeModelKey
```

### 4.2 运行选股

```
[运行选股 ▶] click
│
├── 1. 收集参数: { activeModelKey, tradeDate, topN, filters }
│
├── 2. POST /api/v1/screener/run
│   │   Request: ScreenerRunRequest
│   │   │
│   │   Response: ScreenerRunResponse
│   │   └── screener-service 调用 Kronos 模型引擎
│   │       └── 结果写入 screening_snapshots 表 (PG)
│   │
│   └── dispatch:
│       ├── setPicks(response.picks)
│       ├── setSelectedPickIndex(0)         // 选中第一行
│       ├── setDetailCardStock(picks[0])    // 渲染详情卡
│       └── setLastRunAt(now)
│
├── 3. 详情卡渲染
│   └── modelRegistry.get(activeModelKey)
│       ├── 动态组件渲染 (component)
│       ├── 指标进度条 (indicatorGroups)
│       └── 评价文本 (evaluationTemplate)
│
└── 4. Loading state
    ├── isRunning = true  → 按钮变灰 + LoadingOverlay
    └── isRunning = false → 恢复交互
```

### 4.3 行点击 → 详情卡切换

```
ResultRow click
│
├── setSelectedPickIndex(rowIndex)
├── setDetailCardStock(picks[rowIndex])
│
└── 详情卡重新渲染 (同一 modelKey，不同 stock 数据)
    ├── indicatorGroups 重新计算 values
    ├── evaluationTemplate 重新生成评价文本
    └── riskChecks 重新评估风险
```

### 4.4 模型切换

```
ModelCard click (切换模型)
│
├── setActiveModelKey(newKey)
├── 清空 picks[] (结果不再匹配新模型)
├── 清空 detailCardStock
│
└── 详情卡标题切换到新模型名称
    └── 提示 "请运行选股以查看结果"
```

### 4.5 批量操作 — 加入候选池

```
[加入候选池 →] click
│
├── 1. 收集 selectedBatchIndices → picks[].tsCode
│
├── 2. 调用 CandidatePoolManager.addSource('screener', {
│       sourceModel: activeModelKey,
│       sourceDate: tradeDate,
│       stocks: selectedPicks.map(p => ({
│         tsCode: p.tsCode,
│         name: p.name,
│         score: p.score,
│         grade: p.grade,
│       })),
│     })
│
└── 3. Toast: "已添加 {n} 只到候选池"
    └── 更新 CandidatePreloadPanel (如果开盘决策已打开)
```

### 4.6 导出 CSV

```
[导出 CSV] click
│
├── 1. 构建表头: 通用列 + 模型专属指标列 (从 registry 获取)
│
├── 2. 构建数据行: picks[] (已排序)
│
├── 3. 生成 CSV blob (UTF-8 BOM for Excel 中文兼容)
│
└── 4. 浏览器下载
    └── 文件名: screener_{modelKey}_{tradeDate}.csv
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 智能选股：公共模型能力与用户私有筛选条件分离，结果可保存到个人候选池。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共模型评分 + 私有筛选参数。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不直接下单，只生成候选/方案。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
