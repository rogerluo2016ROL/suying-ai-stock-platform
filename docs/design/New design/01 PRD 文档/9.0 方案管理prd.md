# PRD — 方案管理

- **Date**: 2026-06-27 | **Owner**: product-lead | **Status**: Draft

## 1. 定位

方案管理是候选池→交易执行的**中转枢纽**。方案生命周期：创建(draft)→启动(running)→暂停(paused)→结算(closed)。

| 维度 | 操盘手 | 个人投资者 |
|---|---|---|
| **来源** | 候选池[生成方案] 一键创建 | 同上 |
| **核心操作** | 审核方案→启动→监控→对比→结算 | 查看方案→去交易中心下单 |
| **关注指标** | 总仓位/可用资金/合计盈亏/方案对比 | 买什么/买多少/什么价 |

## 2. 业务流程

```
候选池(2.4) ──[生成方案]──→ 方案管理(draft)
  │                              │
  │                    ┌─────────┼─────────┐
  │                    ▼         ▼         ▼
  │              [启动自动交易] [手动下单] [编辑/删除]
  │                    │         │
  │                    ▼         ▼
  │               running    交易中心(8.0)
  │                    │
  │              ┌─────┼─────┐
  │              ▼     ▼     ▼
  │           [暂停] [止损] [结算]
  │              │           │
  │              ▼           ▼
  │           paused      closed → 结算报告
  │
  └── 与各模块交互 ──────────────────────────────
      执行监控(2.5) ← 读取方案状态
      风控中心(10)  ← 止损触发→方案暂停
      量化交易(9.0) ← [启动]创建执行器
```

## 3. 二级功能

```
📐 方案管理

├── 📋 方案列表     6.1  默认主视图。总览KPI + 按状态分组的方案卡片
├── 📊 方案详情     6.2  单方案深度视图。标的/订单/风险/操作
├── 📈 方案对比     6.3  操盘手专用。2方案横向对比收益
└── 📜 结算报告     6.4  已归档方案盈亏分析
```

## 4. 操盘手 vs 个人投资者

| 子模块 | 操盘手 | 个人投资者 |
|---|---|---|
| 方案列表 | 全部方案+总览KPI(总仓位/可用资金/合计盈亏) | 仅"我的方案"+简化KPI |
| 方案详情 | 完整: 标的配置+订单+风险+操作按钮 | 简化: 标的名称+建议价+仓位%，[去交易中心下单] |
| 方案对比 | ✅ 全功能 | ❌ 不开放(隐藏Tab) |
| 结算报告 | 完整: 盈亏/胜率/回撤/各标的明细 | 简化: "赚了+1,200元" |

## 5. 与其他模块的交互

| 交互 | 方向 | 数据 |
|---|---|---|
| 候选池→方案管理 | 入口 | codes + 共识度/信号/预测 |
| 方案管理→交易中心 | 手动 | 标的+建议价+仓位 |
| 方案管理→量化交易 | 自动 | 创建执行器+risk_rules |
| 方案管理←执行监控 | 读取 | 订单状态+实时盈亏 |
| 方案管理←风控中心 | 触发 | 止损逼近→方案暂停告警 |

## 6. 状态机

```
draft ──[启动]──→ running ──[暂停]──→ paused ──[恢复]──→ running
  │                   │                                    │
  │                   │ [止损触发/日亏损3%]                 │ [结算]
  │                   ▼                                    ▼
  │               paused(自动)                          closed
  │                                                        │
  └──[手动下单]──→ 保持draft                               └──→ 结算报告(归档)
  └──[编辑/删除]──→ draft/删除
```

## 7. 方案编码规则

每个方案自动生成唯一编码：`{模型缩写}-{日期}-{序号}-{类型}`

| 字段 | 规则 | 示例 |
|---|---|---|
| 模型缩写 | 见下表 | LT, BS, QS, FS, FU |
| 日期 | YYYYMMDD | 20260627 |
| 序号 | 当日该模型第几个方案，01起 | 01 |
| 类型 | A=自动交易, M=手动方案 | A |

### 模型缩写表

| 模型 | 缩写 |
|---|---|
| 龙头战法 | LT |
| 毕师傅趋势 | BS |
| 秋神盘后 | QS |
| 匪爷短线 | FS |
| 长线价值 | CX |
| 综合多因子 | ZH |
| 大葱卡脖子 | DC |
| 可转债 | CB |
| 多模型融合 | FU |

### 展示规范

编码作为主标识，名称作为辅助描述：
```
🟢 LT-20260627-01A   龙头战法-开盘  标的3只  仓位37%  +2.1%
📄 FU-20260627-01M   竞价-信号融合  标的3只  建议35%  (待启动)
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 方案管理：Plan 是私有交易意图承载对象，可授权共享但默认仅本人可见。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 私有 Plan + 公共模型引用。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | Plan 启动前必须绑定账户/模式。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
