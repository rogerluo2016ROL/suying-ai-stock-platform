## 1. 页面定位

事件审计是风控中心**第五个 SubTab**（SubTab key: `audit`）。以审计摘要四宫格 + 风险事件时间线的形式，提供当日完整的风控活动记录。

## 2. 组件树

```

        ├── event-detail (secondary text)

```

## 3. 核心数据结构

```typescript
interface EventAuditData {
  auditSummary: AuditSummary
  auditTimeline: AuditEvent[]
}

interface AuditSummary {
  placed: number
  confirmed: number
  rejected: number
  circuitBreakerTriggers: number
}

interface AuditEvent {
  id: string
  time: string               // "14:32:05"
  level: 'danger' | 'warning' | 'info' | 'reset'
  type: AuditEventType
  icon: string               // emoji
  title: string
  detail: string
  link: string | null
  linkLabel: string | null
}

type AuditEventType =
  | 'stop_loss_close'
  | 'strategy_paused'
  | 'forced_sell'
  | 'audit_downgrade'
  | 'large_trade_confirm'
  | 'breaker_reset'
  | 'pre_check_pass'
  | 'market_regime_change'
```

## 5. 交互规范

### 5.1 审计摘要

- 4 宫格布局 (2×2 grid)
- 点击卡片跳转到 `8.4 策略日志` 或审计日志详情
- 大额确认数 > 0 时橙色背景高亮
- 风控拦截数 > 0 时红色背景高亮

### 5.2 事件时间线

- 按时间倒序排列
- danger 事件：红色左边框 + 红色标题
- warning 事件：橙色左边框
- info 事件：默认样式
- 可操作事件（stop_loss_close / strategy_paused / forced_sell）右侧显示操作链接
- 点击链接跳转对应页面

### 5.3 空态

```
┌──────────────────────────────────────────┐
│  ✅ 今日无风险事件                         │
│  风控系统运行正常，所有检查项通过           │
└──────────────────────────────────────────┘
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 风控中心：规则分全局/租户/账户，RiskVerdict 按账户和上下文归档。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共规则 + 私有判定结果。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 所有实盘动作强制经过。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
