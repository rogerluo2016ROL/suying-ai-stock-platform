## 1. 页面定位

策略风险是风控中心**第三个 SubTab**（SubTab key: `strategy`）。展示全部策略运行状态，对异常策略突出显示并提供恢复/调整操作。

## 2. 组件树

```
StrategyRiskPanel (pages/risk/StrategyRiskPanel.tsx)
│
├── StrategyRiskSummary
│   ├── 策略总数 count
│   ├── 运行中 count (green)
│   └── 已暂停 count (warn)
│
├── StrategyRiskTable
│   ├── TableHeader [策略] [状态] [日亏损] [持仓数] [风险事件]
│   └── StrategyRiskRow × N
│       ├── status-dot (active/paused/stopped)
│       ├── strat-name (bold)
│       ├── strat-dailyLoss (mono, colored)
│       ├── strat-positions (count)
│       ├── strat-riskEvents (count, red if >0)
│       └── (if paused) row-expand
│           ├── paused-reason detail
│           └── ActionButtons
│               ├── btn [▶️ 恢复策略]
│               └── btn [⚙️ 调整参数]
│
└── PausedStrategyDetail (展开行)
    ├── reason: string
    ├── pausedTime: string
    ├── triggerRule: string
    └── suggestedAction: string
```

## 3. 核心数据结构

```typescript
interface StrategyRiskData {
  strategies: StrategyRiskStatus[]
  summary: {
    total: number
    active: number
    paused: number
    stopped: number
  }
}

interface StrategyRiskStatus {
  id: string
  name: string
  code: string               // e.g. "SYS-QS-V3"
  status: 'active' | 'paused' | 'stopped'
  dailyLossPct: number
  positionCount: number
  riskEventCount: number
  pausedReason: string | null
  pausedTime: string | null
  triggerRule: string | null
  expanded: boolean          // UI state
}
```

## 5. 交互规范

### 5.1 行状态

- 活跃行：默认样式
- 暂停行：橙色背景高亮 (`--warn-bg`)，默认展开暂停原因
- 停止行：灰色文字

### 5.2 恢复操作

```
点击 [▶️ 恢复策略] → Modal:
  "确认恢复「竞价超预期 V4.3」？
   当前日亏损 -3.2%，已触发自动暂停。
   恢复后策略将重新开始执行。"
  [取消] [确认恢复]
```

### 5.3 调整参数

点击 [⚙️ 调整参数] → 跳转 `/quant-trading/config?strategy={id}` (8.2 策略配置)

### 5.4 空态

```
┌──────────────────────────────────────────┐
│  🤖 暂无活跃策略                           │
│  前往量化交易页创建或启用策略               │
│  [前往策略广场 →]                          │
└──────────────────────────────────────────┘
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 风控中心：规则分全局/租户/账户，RiskVerdict 按账户和上下文归档。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共规则 + 私有判定结果。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 所有实盘动作强制经过。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
