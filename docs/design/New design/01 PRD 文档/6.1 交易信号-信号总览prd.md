# PRD — 交易信号·信号总览

- **Date**: 2026-06-27 | **Owner**: product-lead | **Status**: Draft
- **Estimated effort tier**: Medium（前端 1 子页面 + 后端数据聚合 + ECharts 雷达图）

## 1. Background

信号总览是交易信号菜单的**默认主视图**。操盘手在开盘决策链路中选定标的后，在此页面对单只股票做"最后一公里"综合研判：

- 快速获取六维评分全景（雷达图一屏尽览）
- 验证资金是否与信号同向（北向/主力/融资）
- 获取可执行的操作建议（仓位建议 + 下一步动作）

当前问题：
1. 候选池、信号扫描只解决了"选哪只"的问题，但缺乏"信号到底多强、资金跟不跟"的综合视图
2. 操盘手需要在分散的页面切换（选股→信号→资金→诊断），信息碎片化
3. 个人投资者看到评分数字不理解含义，需要直观的图表+操作建议

## 2. Goal & Non-Goals

**目标**：
- 构建信号总览默认视图，KPI：操盘手 5 秒内形成"买/不买/观望"判断
- 六维雷达图 + 评分明细 + 资金流向 一屏呈现

**Non-Goals**：
- 不做多股对比（属于信号扫描 2.3 的范畴）
- 不做历史回溯（属于信号历史 6.2 的范畴）
- 不做风险排查（属于风险扫描 6.3 的范畴）
- 不引入新的数据源（复用 signal-service 六维评分引擎 + 资金流数据）

## 3. User Stories

| ID | As a | I want to | So that |
|---|---|---|---|
| US-1 | 操盘手 | 看到六维雷达图，每个维度有评分+权重 | 一眼判断信号在各维度的强弱分布 |
| US-2 | 操盘手 | 看到资金流向（北向/主力/融资） | 验证主力资金是否与信号同向 |
| US-3 | 操盘手 | 看到趋势强度评分+均线状态 | 判断技术面是否支持信号方向 |
| US-4 | 操盘手 | 获得明确的操作建议（买入/观望+仓位建议） | 直接指导下单决策 |
| US-5 | 个人投资者 | 看到综合评分+一句话操作建议 | 不需要专业知识就能理解 |
| US-6 | 个人投资者 | 看到简化的评分展示（折叠维度细节） | 信息不超载 |

## 4. Acceptance Criteria

| ID | Priority | AC | Verification method |
|---|---|---|---|
| AC-1 | P0 | 输入代码后六维雷达图正确渲染，6 个维度数据与 `/signal/analyze/{code}` 返回一致 | 对照 API 返回验证雷达图各点数值 |
| AC-2 | P0 | 六维评分明细进度条正确展示，每条含图标、名称、分数、权重 | 6 条进度条与数据一致，权重之和=100% |
| AC-3 | P0 | 信号判定（STRONG_BUY/BUY/HOLD/SELL）正确显示，颜色与映射规范一致 | STRONG_BUY=红色、BUY=橙色、HOLD=蓝色 |
| AC-4 | P0 | 资金流向三行（北向/主力/融资）正确展示方向+金额+连续天数 | 数据与 API 返回一致，方向箭头正确 |
| AC-5 | P1 | 操盘手视图展示完整（雷达图+资金+趋势），个人投资者展示简化（评分+一句话建议+雷达图折叠） | 角色切换后 UI 展示范围正确变化 |

### 5.2 操盘手 vs 个人投资者

| 模块 | 操盘手 | 个人投资者 |
|---|---|---|
| 信号判定 | 完整：评级+评分+操作建议+代码名称+计算时间 | 简化：评分+一句话建议 |
| 六维雷达图 | 完整雷达图+6维标注 | 折叠/简化雷达图 |
| 六维评分明细 | 完整6条进度条+权重 | 仅显示评分最高的2-3维 |
| 资金流向 | 完整三行+方向+金额+连续天数 | 一行概览（北向净流入/流出） |
| 趋势强度 | 完整：评分+方向+均线排列+MA5/10/20/60 | 简化：趋势方向+一句话 |
| 底部操作栏 | [候选池][下单][诊断][预警] | [自选][诊断] |

## 6. Technical Constraints

- 页面实现：作为 SignalDetailPage 的默认 Tab（`overview`），不创建独立页面
- 复用 `6.0 交易信号详细设计.md` 中定义的数据结构（SignalResult / DimScore / FundFlow / TrendInfo）
- 雷达图使用 ECharts 5.5 CDN，暗色主题
- 设计系统：遵循 `design-spec.md` 的 CSS token
- A 股涨跌色：红涨绿跌，不反转

## 7. Cost Estimate

- LLM token / 月：0（不涉及 LLM 调用）

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易信号：公共信号规则与用户私有订阅、处理状态分离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共信号 + 私有已读/订阅/处置。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 信号只作为订单依据之一。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
