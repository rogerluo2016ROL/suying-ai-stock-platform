## 2. 核心数据结构

```typescript
type TrainingStatus = 'draft' | 'queued' | 'running' | 'completed' | 'failed' | 'stopped'

interface TrainingTask {
  id: string
  name: string
  modelType: 'kronos' | 'lightgbm' | 'catboost'
  datasetName: string
  status: TrainingStatus
  hyperParams: Record<string, number | string | boolean>
  progress: {
    currentEpoch: number
    totalEpochs: number
    percent: number
    elapsed: string
  } | null
  metrics: {
    trainLoss: number
    valLoss: number
    trainAcc: number
    valAcc: number
    f1: number
    auc: number
  } | null
  createdAt: string
  duration: string | null
  errorLog: string | null
}

interface CreateTaskRequest {
  name: string
  modelType: string
  datasetId: string
  target: '1d_return' | '5d_return' | '20d_return'
  hyperParams: Record<string, any>
  timeWindow: [string, string]
  valSplit: number
  note: string
}
```

## 3. 数据流

```
TrainingTasks mount (admin guard)
├── GET /api/v1/training/tasks?page=1&size=50
├── GET /api/v1/training/datasets
├── GET /api/v1/training/model-types
└── GET /api/v1/training/presets

[新建任务] → POST /api/v1/training/tasks
[▶️ 开始] → POST /api/v1/training/tasks/{id}/start (状态 → queued)
[⏹️ 停止] → POST /api/v1/training/tasks/{id}/stop
[🔄 重跑] → POST /api/v1/training/tasks/{id}/rerun
[🗑 删除] → DELETE /api/v1/training/tasks/{id}
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 模型训练：仅模型管理员/系统管理员可操作，训练资源、实验和产物要隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 管理域数据。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不触达券商。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
