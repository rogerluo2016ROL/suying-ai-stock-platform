## 1. 页面定位

模型对比是智能选股的**交叉验证工具**。定位为"多模型投票器"——用户勾选模型 → 一键运行 → 看到哪些股票被多个模型同时选中：

- 共识度越高 = 置信度越高（★★★★ 优于 ★★）
- 右侧面板支持逐只跨模型评分对比
- 差异视图发现模型独有标的

## 5. 核心数据结构

### 5.1 页面状态

```typescript
interface ModelCompareState {
  selectedModels: string[]           // ["bi_trend_launch", "short", ...]
  running: boolean
  compareResult: CompareResult | null
  selectedStock: string | null        // 选中的 ts_code
  filterLevel: number | 'all'         // 4 | 3 | 2 | 1 | 'all'
  error: string | null
}

interface CompareResult {
  models: ModelResult[]
  consensus: {
    intersectionAll: string[]          // 所有模型交集
    intersection3: string[]            // 3-of-4 交集
    intersection2: string[]            // 2-of-4 交集
    onlyInOne: string[]                // 仅 1 个模型
    union: string[]
    steps: ConsensusStep[]
  }
  stockScores: Record<string, Record<string, ModelStockScore>>
}

interface ModelResult {
  modelKey: string
  modelName: string
  totalPicks: number
  picks: ScreenerPick[]
}

interface ConsensusStep {
  models: string[]
  intersectionCount: number
}

interface ModelStockScore {
  score: number
  rank: number
  indicators: Record<string, number>
}

interface ConsensusRow {
  tsCode: string
  name: string
  close: number
  changePct: number
  consensusLevel: number
  selectedByModels: string[]
  modelKeys: string[]                 // 模型 key 列表
}
```

### 5.2 共识度计算

```typescript
function buildConsensusRows(
  models: ModelResult[],
  consensus: CompareResult['consensus']
): ConsensusRow[] {
  const rows: ConsensusRow[] = []
  const stockMap = new Map<string, Set<string>>()

  // 构建 stock → 选中它的模型集合
  for (const m of models) {
    for (const pick of m.picks) {
      if (!stockMap.has(pick.tsCode)) {
        stockMap.set(pick.tsCode, new Set())
      }
      stockMap.get(pick.tsCode)!.add(m.modelKey)
    }
  }

  // 转换为 ConsensusRow
  const stockInfo = new Map<string, { name: string; close: number; changePct: number }>()
  for (const m of models) {
    for (const pick of m.picks) {
      stockInfo.set(pick.tsCode, {
        name: pick.name,
        close: pick.close,
        changePct: pick.changePct
      })
    }
  }

  for (const [code, modelSet] of stockMap) {
    const info = stockInfo.get(code)!
    rows.push({
      tsCode: code,
      name: info.name,
      close: info.close,
      changePct: info.changePct,
      consensusLevel: modelSet.size,
      selectedByModels: Array.from(modelSet),
      modelKeys: Array.from(modelSet)
    })
  }

  // 按共识度降序，同级按代码升序
  rows.sort((a, b) => b.consensusLevel - a.consensusLevel || a.tsCode.localeCompare(b.tsCode))
  return rows
}
```

## 6. 数据流与 API 调用

```
页面加载
  └── (空态, 显示"请选择模型并运行对比")

用户勾选模型 + 点击 [▶ 运行对比]
  │
  ├── setState({ running: true })
  │
  ├── POST /api/v1/screener/compare
  │     body: { model_keys: ["bi_trend_launch", "short", ...] }
  │
  ├── Response →
  │   ├── models[] → 各模型选股结果
  │   ├── consensus → buildConsensusRows() → 共识矩阵渲染
  │   ├── stockScores → 右侧评分面板渲染
  │   └── consensus.steps → 统计栏渲染
  │
  ├── setState({ running: false, compareResult: response })
  │
  └── 默认选中第一条全选标的 → 右侧展示评分对比

用户点击矩阵行
  └── setState({ selectedStock: tsCode })
      └── 右侧面板更新为对应股票的跨模型评分

用户点击筛选Tab
  └── setState({ filterLevel: n })
      └── 矩阵表格按 consensusLevel 过滤

用户点击 [加入候选池]
  └── POST /api/v1/candidate-pool/batch-add
      body: { codes: filteredConsensusCodes, source: "model-compare" }
```

## 8. 交互规范

### 8.1 模型选择

| 事件 | 行为 |
|---|---|
| Checkbox 点击 | 切换模型选中状态 |
| 选中 < 2 个 | "运行对比"按钮 disabled (gray) |
| 选中 ≥ 2 个 | "运行对比"按钮 active (accent) |
| 点击运行 | 按钮显示 loading spinner，所有模型并行运行 |

### 8.2 共识矩阵交互

| 事件 | 行为 |
|---|---|
| 行悬浮 (hover) | 行背景变 var(--elevated)，显示 pointer cursor |
| 行点击 | 选中该股票，右侧面板展示跨模型评分对比 |
| 列排序 | 默认按共识度降序 + 代码升序，可点击列头切换排序 |
| 筛选 Tab | 切换后仅显示对应共识度的行 |

### 8.3 状态处理

| 状态 | 处理方式 |
|---|---|
| 初始态（未运行） | 显示空态引导："请选择 2-4 个模型并点击运行对比" |
| 运行中 | 按钮显示 loading，矩阵区域显示骨架屏 |
| 结果空（无交集） | 显示 "所选模型无共同选股，请查看差异视图" |
| 错误态 | 显示 Alert + 重试按钮 |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 智能选股：公共模型能力与用户私有筛选条件分离，结果可保存到个人候选池。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共模型评分 + 私有筛选参数。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不直接下单，只生成候选/方案。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
