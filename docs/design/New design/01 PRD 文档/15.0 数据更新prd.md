# PRD — 数据更新

- **Date**: 2026-06-27 | **Status**: Draft

## 1. 定位

数据新鲜度监控 + 手动同步触发。三角色差异化：

| 角色 | 视图 | 操作 |
|---|---|---|
| 管理员 | 全部42表 + 同步触发 + 调度配置 | 全部 |
| 操盘手 | 核心表摘要（日K/分钟/竞价/龙虎榜）+ 新鲜度状态 | 只读 |
| 个人投资者 | 简化：数据状态 ✅正常 / ⚠️部分待更新 | 只读 |

> **角色映射（收口决策）**：管理员 → RBAC `admin`；操盘手 trader → `internal_analyst`；个人投资者 investor → `user`；`external_analyst` → 外部只读。权限与数据过滤由服务端按 JWT 角色执行，前端禁止传 `X-User-Role` 等身份头。
>
> **表数量口径（收口决策）**：「42 表（18 核心 + 24 辅助）」为设计示例数，实际表清单以 data-service `GET /api/v1/data/inventory` 返回为准，页面动态渲染；调度任务数量以调度配置实际清单为准。

## 2. 二级功能

```
⏱️ 数据更新

├── 📊 数据总览     15.1  总览条 + 核心表摘要（操盘手默认）

└── ⚙️ 同步调度     15.3  调度配置 + 下次运行时间（管理员）
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 数据更新：公共数据平台能力，普通用户只看简化新鲜度。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共数据质量。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不触达券商。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
