## 1. 页面定位

数据总览是数据更新模块的**首页 Tab**。三角色差异化展示数据健康概览，角色感知由顶层 `DataUpdate` 页面统一控制后透传。

### 角色切换逻辑

```
DataUpdate mount
├── 读取 currentRole (来自 Auth Context)
├── 渲染 Pill Tabs (根据 role 过滤可见项)
│   ├── admin: [数据总览] [全部数据表] [同步调度]
│   ├── trader: [数据总览] [全部数据表(只读核心表)]
│   └── investor: [数据总览(简化)]
└── 默认激活 Tab: "数据总览"
```

## 3. 核心数据结构

```typescript
interface DataOverviewState {
  role: 'admin' | 'trader' | 'investor'
  activeTab: 'overview' | 'tables' | 'schedule'

  health: {
    status: 'all_ok' | 'partial_stale' | 'has_errors'
    summary: string
    freshTables: number
    staleTables: number
    errorTables: number
    totalTables: number
    coreTablesReady: boolean
  }

  kpi: {
    totalTables: number
    coreTables: number
    auxTables: number
    totalRows: number
    freshCount: number
    freshPct: number
    nextSchedule: string
    lastGlobalSync: string | null
  }

  coreTables: CoreTableItem[]
}

interface CoreTableItem {
  id: string
  tableName: string
  displayName: string
  category: TableCategory
  isCore: boolean
  freshness: FreshnessLevel
  maxDate: string
  totalRows: number
  syncStatus: 'ok' | 'syncing' | 'failed' | 'never'
}
```

## 4. 数据流

```
DataOverviewTab mount
│
├── 1. 从父组件获取 role / activeTab
│
├── 2. GET /api/v1/data-update/health
│   └── 健康总览 (fresh/stale/error 计数)
│
├── 3. GET /api/v1/data-update/tables?isCore=true&limit=18
│   └── 核心表列表 (admin/trader 均需)
│
├── 4. investor: 仅调 health，不调 tables
│
└── 5. admin: 10s 轮询 health (实时更新)
    trader: 60s 轮询 health
    investor: 手动刷新
```

## 5. 三视图切换状态管理

```typescript
// 角色切换贯穿整个 DataUpdate 页面，Tab 间共享 role 状态
const [role, setRole] = useState<UserRole>(currentUserRole)

// 切换角色后刷新数据
useEffect(() => {
  if (role === 'investor') {
    fetchHealthOnly()
  } else {
    fetchHealthAndCoreTables()
  }
}, [role])
```

| 切换行为 | admin → trader | trader → investor | investor → admin |
|---|---|---|---|
| Tab 可见性 | 隐藏 [同步调度] | 隐藏 [全部表] [调度] | 显示全部 3 Tab |
| 数据请求 | 减少：不调调度 API | 再减少：仅 health | 增加：恢复全量 |
| 布局 | 紧凑核心表摘要 | 大号 OK Badge | 展开完整管理视图 |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 数据更新：公共数据平台能力，普通用户只看简化新鲜度。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共数据质量。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不触达券商。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
