## 1. 页面定位

数据更新是**数据新鲜度监控与同步管理**的统一入口。三视图按角色分层：

| 维度 | 管理员 (admin) | 操盘手 (trader) | 个人投资者 (investor) |
|---|---|---|---|
| **面板** | 全部 42 表 + 手动同步 + 调度配置 | 核心表摘要 + 新鲜度颜色 | 一句话 OK/Warning |
| **同步操作** | 单表/批量手动触发 | 无操作权 | 无操作权 |
| **调度配置** | 可修改 | 只读查看 | 隐藏 |
| **查看目的** | 管理数据管道健康 | 盘前确认数据就绪 | 知道数据是否正常 |

**新鲜度颜色规则**：
- **绿色 (Fresh)**: `max_date = 今天` — 数据已更新到最新交易日
- **橙色 (Stale)**: `max_date = T-1` — 数据滞后 1 天
- **红色 (Error)**: `max_date ≤ T-2` 或同步失败 — 需要关注

**页面入口**：
- 侧边栏菜单 "⏱️ 数据更新"（模型/系统管理主题）
- 操盘手盘前检查工作流自动跳转

```typescript

// ── 数据表 ──────────────────────────────
interface DataTable {
  id: string
  tableName: string               // "daily_bars" (数据库表名)
  displayName: string             // "日K线行情"
  category: TableCategory
  isCore: boolean                 // 是否核心表
  freshness: FreshnessLevel
  maxDate: string                 // "2026-06-26" (最新数据日期)
  daysBehind: number              // 滞后天数 (0 = 今日)
  totalRows: number               // 3,245,680
  dataStart: string               // "2015-01-05"
  updateFrequency: string         // "每日收盘后"
  frequencyMinutes: number        // 1440 (分钟, 用于调度)
  syncStatus: 'ok' | 'syncing' | 'failed' | 'paused' | 'never'
  lastSyncAt: string | null       // "2026-06-26 16:15:32"
  lastSyncDuration: number | null // 12.3 (秒)
  lastSyncRows: number | null     // 新增行数
  nextSyncAt: string | null       // "2026-06-26 18:00:00"
  errorMessage: string | null     // 失败原因
  errorRetries: number            // 重试次数
  dataSource: string              // "Tushare" / "东方财富"
}

// ── 调度配置 ──────────────────────────────
interface ScheduleConfig {
  autoSyncEnabled: boolean
  fullSyncFrequency: 'daily' | 'twice_daily' | 'hourly' | 'custom'
  fullSyncTime: string            // "18:00"
  fullSyncSecondTime: string | null // "06:00" (仅 twice_daily)
  incrementalFrequency: '30min' | 'hourly' | 'daily' | 'off'
  retryStrategy: '3x5min' | '5x2min' | 'none'
  retryCount: number              // 3
  retryIntervalMinutes: number    // 5
  tushareRateLimit: number        // 200 (次/分钟)
  tushareTokenStatus: 'ok' | 'expiring' | 'expired'
}

// ── 数据源状态 ────────────────────────────
interface DataSourceStatus {
  name: string                    // "Tushare"
  status: 'ok' | 'degraded' | 'down' | 'rate_limited'
  lastCallAt: string | null       // "2026-06-26 16:15:32"
  latency: number                 // 平均延迟 ms
  rateLimit: number | null        // 限流值 (null = 无限流)
  rateUsedPct: number             // 67 (百分比)
  errorMessage: string | null
}

// ── 同步历史 ────────────────────────────
interface SyncHistoryItem {
  id: string
  tableName: string
  displayName: string
  syncedAt: string               // "2026-06-26 16:15:32"
  result: 'success' | 'partial' | 'failed'
  rowsAdded: number
  duration: number               // 12.3s
  errorMessage: string | null
}
```

### 4.1 初始加载 (按角色)

### 4.2 手动同步 (admin only)

```
[🔄 手动同步] click (单表)
│
├── 1. syncingTableIds.add(tableId) → 按钮变 loading
│
├── 2. POST /api/v1/data-update/tables/{id}/sync
│   │   后端: data-service 触发对应表的数据拉取
│   │   │   ├── Tushare API 调用
│   │   │   ├── PG 直写
│   │   │   └── 更新 sync_log 表
│   │
│   │   Response: { success, rowsAdded, duration, newMaxDate }
│   │
│   └── Dispatch:
│       ├── 更新该表 maxDate / freshness / rows / lastSyncAt
│       ├── syncingTableIds.delete(tableId)
│       ├── 刷新 SummaryBar health
│       └── Toast: "daily_bars 同步完成 · +1,245 行 · 12.3s"
│
└── 3. 如果失败:
    ├── 该表 freshness = 'error'
    ├── errorMessage 显示
    └── Toast: "同步失败: Tushare 限流，已自动重试"
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 数据更新：公共数据平台能力，普通用户只看简化新鲜度。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共数据质量。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不触达券商。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
