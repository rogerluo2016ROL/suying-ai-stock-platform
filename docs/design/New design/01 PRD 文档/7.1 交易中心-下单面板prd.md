# PRD — 交易中心·下单面板

- **Date**: 2026-06-27 | **Status**: Draft

## 1. 定位

下单面板是交易中心的**核心操作区**。代码输入→行情确认→价格选择→数量设定→风控预检→确认下单。

## 2. 报价区

### Phase 1：实时行情条（当前版本）
- 显示：最新价/涨跌幅/涨跌额/今开/最高/最低/成交量
- **点击最新价 → 自动填入委托价栏**
- 数据来源：`stk_mins` 最新分钟K线

### Phase 2：盘口深度（五档优先，支持深度档位）
- 显示 5 档卖盘(卖1-5) + 5 档买盘(买1-5)，每档含价格+挂单量
- **点击任意买/卖价位 → 自动填入委托价栏**
- 深度档位：在数据源支持时提供 50 档 / 500 档模式，展示聚合价位、累计量、买卖压差和档位延迟；数据源不支持时降级为五档并明确标注。
- 数据来源：实时行情/券商行情 API；Tushare 仅作为可用性兜底，不承诺 500 档实时深度。

## 3. 下单流程

```
输入代码 → 行情条自动刷新 → 选择价格(点击行情/手动输入)
  → 输入数量 → 订单预览(金额/仓位%/手续费)
  → [🔍预检] → 确认下单
```

## 4. 方案带入

从方案管理跳转时 URL 携带参数：
- `?plan=xxx&code=xxx` → 自动填入代码/建议价/建议仓位
- 用户只需确认 → [预检] → [下单]

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易中心：账户、订单、持仓、成交全部按 tenant/account/user 隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 强私有交易数据。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | paper/QMT/多券商统一 BrokerAdapter。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
