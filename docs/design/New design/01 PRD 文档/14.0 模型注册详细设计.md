## 1. 页面定位

模型注册是 ML 工程师（admin 角色）专用页面，管理 MLflow 中已注册的模型版本，支持版本对比、A/B 上线切换（staging → production）、以及历史版本归档。与训练页面联动：训练任务完成后可通过 [注册模型] 按钮跳转到本页。

| 维度 | 模型训练 (menu 13) | 模型注册 (menu 14) |
|---|---|---|
| **使用者** | ML 工程师 | ML 工程师 |
| **核心流程** | 创建→训练→监控指标 | 注册→对比→上线→监控生产指标 |
| **数据来源** | training-service (8008) | MLflow Model Registry |
| **决策依据** | loss/acc/F1/AUC | 生产 acc/回测 Sharpe/IC |

**页面入口**：
- 侧边栏菜单 "📦 模型注册"（模型/系统管理主题）
- 模型训练页面 "已完成" 任务 → [注册模型] → 跳转本页 (携带 `?fromTraining=true&taskId=xxx`)
- 仅 admin 角色可见

### 3.2 核心数据模型

```typescript
// ── 模型版本 ──────────────────────────────
interface ModelVersion {
  id: string
  modelName: string               // "Kronos-日频-全市场"
  version: string                 // "7.2.0" (SemVer)
  modelType: ModelType            // 'kronos' | 'lightgbm' | 'catboost'
  stage: ModelStage
  metrics: {
    valAcc: number
    valLoss: number
    f1: number
    auc: number
    precision: number
    recall: number
    backtestSharpe?: number       // production 版本回测后补充
    backtestIC?: number
    backtestICIR?: number
    productionAcc30d?: number     // 生产环境30日准确率
    productionSharpe30d?: number  // 生产环境滚动30日Sharpe
  }
  hyperParams: Record<string, number | string | boolean>
  mlflowRunId: string
  mlflowRunName: string
  modelPath: string               // 模型文件路径
  dataWindow: {
    trainStart: string
    trainEnd: string
    valStart: string
    valEnd: string
  }
  tags: string[]
  description: string
  registeredBy: string
  registeredAt: string
  promotedAt: string | null       // 上线到 production 的时间
  promotedBy: string | null
  archivedAt: string | null
  archivedBy: string | null
  // 对比用
  previousVersion?: string        // "7.1.0"
  diffWithPrevious?: MetricDiff
}

// ── 指标差异 ──────────────────────────────
interface MetricDiff {
  metricName: string
  valueA: number
  valueB: number
  diff: number                    // 绝对值差异
  diffPct: number                 // 百分比差异
  trend: 'up' | 'down' | 'flat'  // B 相对于 A 的趋势
  isBetter: boolean               // 是否正向改善 (valLoss down=更好, valAcc up=更好)
}

// ── A/B 对比上下文 ──────────────────────────
interface VersionCompareContext {
  versionA: ModelVersion
  versionB: ModelVersion
  allMetrics: MetricDiff[]
  hyperParamChanges: {
    key: string
    valueA: number | string | boolean
    valueB: number | string | boolean
    changed: boolean
  }[]
  radarData: {
    dimensions: string[]
    seriesA: number[]
    seriesB: number[]
  }
}

// ── 注册请求 ──────────────────────────────
interface RegisterVersionRequest {
  modelName: string
  version: string
  modelType: ModelType
  mlflowRunId: string
  modelPath: string
  dataWindow: { trainStart: string; trainEnd: string; valStart: string; valEnd: string }
  tags: string[]
  description: string
}

// ── A/B 上线请求 ──────────────────────────
interface PromoteToProductionRequest {
  versionId: string
  autoArchivePrevious: boolean    // 是否自动归档当前 production 版本
}
```

## 4. 数据流

### 4.1 初始加载

```
ModelRegistry mount (admin guard)
│
├── GET /api/v1/model-registry/versions?page=1&size=50
│   └── 版本列表，按 modelName 分组，每组内 stage 排序: production → staging → archived
│
├── GET /api/v1/model-registry/model-names
│   └── 用于筛选下拉
│
├── GET /api/v1/model-registry/mlflow-runs?status=FINISHED
│   └── 可注册的 MLflow runs (用于注册 modal)
│
└── GET /api/v1/model-registry/production-metrics
    └── 当前 production 版本的30日趋势数据
```

### 4.2 注册新版本

```
[注册新版本] click → RegisterVersionModal open
│
├── 1. 填写模型名称 (选已有或新建)
│
├── 2. 选择 MLflow Run → 自动带回:
│   ├── metrics (valAcc/valLoss/f1/auc)
│   ├── hyperParams
│   ├── modelPath (from artifacts)
│   └── 数据窗口 (from run params)
│
├── 3. 版本号自动建议: 取最大版本号 + 0.0.1
│
├── 4. 添加标签 + 备注
│
├── 5. [注册] → POST /api/v1/model-registry/versions
│   │   Request: RegisterVersionRequest
│   │   Response: ModelVersion (stage: 'staging')
│   │
│   │   后端操作:
│   │   ├── 1) MLflow: register_model(runId, modelName)
│   │   ├── 2) MLflow: transition_model_version_stage(stage='staging')
│   │   ├── 3) DB: 写入 model_versions 表
│   │   └── 4) 如果同模型名无 production 版本 → 可选直接上线
│   │
│   └── Dispatch:
│       ├── versions.unshift(newVersion)
│       ├── close modal
│       └── Toast: "模型 v7.2.0 已注册为 Staging"
│
└── 6. 如果 fromTraining=true:
    └── 注册完成后 → 提示"是否立即上线?" → 可选直接 promote
```

### 4.3 A/B 上线切换 (核心交互)

```
[🔄 上线为 Production] click → Popconfirm

│   确认框内容:
│   ┌──────────────────────────────────┐
│   │ 🏭 当前 Production: v7.1.0         │
│   │     Acc 66.1% · Sharpe 2.18       │
│   │            ↓                      │
│   │ 🧪 将上线为 Production: v7.2.0     │
│   │     Acc 68.2% · Sharpe 2.34       │
│   │                                   │
│   │ v7.1.0 将自动归档                  │
│   │                                   │
│   │ [取消]          [确认上线]         │
│   └──────────────────────────────────┘
│
├── 确认后 → POST /api/v1/model-registry/versions/{id}/promote
│   │   Request: { autoArchivePrevious: true }
│   │
│   │   后端操作 (事务):
│   │   ├── 1) 查找当前同模型名的 production 版本
│   │   ├── 2) 标记旧版本 stage = 'archived', archivedAt = now()
│   │   ├── 3) MLflow: transition 新版本 → production
│   │   ├── 4) prediction-service: 热加载新模型 checkpoint
│   │   ├── 5) 发送通知: "模型 Kronos-日频 v7.2.0 已上线为 Production"
│   │   └── 6) 记录 audit log
│   │
│   └── Dispatch:
│       ├── 更新旧 production 卡片 → archived (淡出动画)
│       ├── 新版本卡片 stage → production (标签变色)
│       ├── 刷新 production-metrics 图表
│       └── Toast: "v7.2.0 已上线为 Production · 预测服务已热加载新模型"
│
└── 如果 autoArchivePrevious=false:
    └── 同一个模型名允许多个 production 版本 (用于 A/B 灰度)

### 4.4 版本对比

```
版本列表: 选中 versionA (勾选对比模式) → 再选 versionB
│
├── setCompareMode(true)
├── compareVersionAId = versionA.id
├── compareVersionBId = versionB.id
│
└── 右侧对比面板渲染:
    ├── 雷达图: A vs B 六维指标
    ├── 差异表格: 逐项对比 + 颜色标注
    ├── 超参数差异: 变化项高亮
    └── 一键上线按钮 (如果 B 全面优于 A)
```

### 4.5 归档/恢复/删除

```
[📦 归档] staging → POST /api/v1/model-registry/versions/{id}/archive
│   ├── 后端: transition → archived
│   ├── 更新本地 stage = 'archived'
│   └── 如果有 A/B 对比选中该版本 → 取消对比选中

[↩️ 恢复] archived → POST /api/v1/model-registry/versions/{id}/restore
│   ├── 后端: transition → staging
│   ├── 更新本地 stage = 'staging'
│   └── Toast: "版本已恢复为 Staging"

[🗑 删除] staging/archived → DELETE /api/v1/model-registry/versions/{id}
│   ├── Popconfirm: "确认删除版本 v7.0.0? 模型文件将保留"
│   ├── production 版本不可删除
│   └── 从列表移除
```

## 5. 状态流转图

```
┌──────────────┐
│  MLflow Run   │ (训练完成)
│  (FINISHED)   │
└──────┬───────┘
       │ [注册新版本]
       ▼
┌──────────────┐        ┌─────────────────┐
│   staging     │───────→│   production    │
│  (验证中)      │ [上线] │   (生产版本)     │
└──┬───────┬───┘        └────────┬────────┘
   │       │                     │
   │       │ [归档]               │ [自动归档]
   │       │                     │ (A/B 切换)
   │       ▼                     │
   │  ┌──────────────┐           │
   │  │   archived    │◄─────────┘
   │  │  (已归档)      │
   │  └──────┬───────┘
   │         │ [恢复]
   │         ▼
   │    回到 staging
   │
   │ [删除]
   ▼
  (移除)

约束规则:
  · 每个模型名最多 1 个 production 版本 (除非灰度模式)
  · A/B 上线: staging → production + 旧 production → archived (原子操作)
  · production 版本不可直接删除 (需先归档)
  · production 版本不可直接归档 (需先有替代版本上线)
  · 同一模型名允许多个 staging 版本 (用于并行验证)
  · archived → staging 恢复后，原 staging 版本不受影响
```

**阶段标签视觉规范**：

| 阶段 | CSS Class | 颜色 | 左侧指示线 |
|---|---|---|---|
| production | `stage-tag production` | `#2ec27e` 绿 | `var(--down)`, 3px solid |
| staging | `stage-tag staging` | `#f5a623` 黄 | `var(--warn)`, 3px solid |
| archived | `stage-tag archived` | `#5e6a7d` 暗灰 | `var(--muted)`, 3px dashed |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 模型注册：模型版本、灰度、回滚和线上标记由管理员治理。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共模型注册表 + 管理审计。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不触达券商。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
