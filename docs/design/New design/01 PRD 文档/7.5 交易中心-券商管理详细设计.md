## 1. 页面定位

券商管理是交易中心**第五个 Tab**（SubTab key: `broker`）。操盘手在此管理券商连接、切换交易模式（模拟盘/实盘）、查看风控参数与连接历史记录。

| 维度 | 操盘手 | 个人投资者 |
|---|---|---|
| **核心问题** | 券商连上了吗？实盘能下单吗？风控参数是多少？ | 跟券商无关（仅模拟盘） |
| **操作** | 连接/断开/切换账户/查看风控参数 | 仅查看模式状态 |
| **权限** | 模拟盘/实盘切换仅 admin 可用；普通用户风控参数只读 |

## 3. 核心数据结构

### 3.1 BrokerStatus

```typescript
type BrokerConnectionState = 'connected' | 'disconnected' | 'connecting'

interface BrokerStatus {
  broker: string                       // "Xtquant QMT"
  state: BrokerConnectionState
  accountMasked: string                // "888****456"
  latencyMs: number                    // 12
  lastHeartbeat: string                // ISO datetime
  tradingMode: 'paper' | 'live'
}
```

### 3.2 RiskConfig

```typescript
interface RiskConfig {
  singleOrderLimit: number             // 单笔上限 ¥
  positionConcentration: number        // 仓位集中度 %
  largeOrderThreshold: number          // 大额阈值 ¥
  circuitBreakerDailyLoss: number      // 熔断日亏损 %
  circuitBreakerCooldown: number       // 熔断冷却 分钟
  limitCheckPct: number                // 涨跌停检查 %
}
```

### 3.3 ConnectionLog

```typescript
interface ConnectionLog {
  id: string
  timestamp: string                    // "2026-06-27T09:30:00"
  action: 'connect' | 'disconnect' | 'auto_disconnect'
  status: 'success' | 'pending' | 'failed'
  detail: string
}
```

## 4. 数据流

```
BrokerManagement mount
  │
  ├── GET /trade/broker/status
  │   └── 返回 BrokerStatus
  │
  ├── GET /trade/risk-config
  │   └── 返回 RiskConfig
  │
  ├── GET /trade/broker/logs?limit=5
  │   └── 返回 ConnectionLog[]
  │
  ├── 渲染 TradingModeToggle
  │   └── userRole 来自 auth context (JWT payload)
  │
  ├── 渲染 BrokerConnectionCard
  │   └── status-dot 根据 state 变色
  │
  ├── 渲染 RiskConfigCard (只读)
  │   └── 6 参数以 lock 图标展示
  │
  └── 渲染 ConnectionHistoryCard
      └── 最近 5 条日志

事件流:

[🔄 刷新状态] 点击:
  → 本地 state → 'connecting'（瞬时状态）
  → GET /trade/broker/refresh
  → 更新 BrokerStatus.state + latencyMs

[🔌 断开连接] 点击:
  → Modal.confirm("确认断开券商连接？断开后实盘将无法下单。")
  → POST /trade/broker/disconnect
  → 更新 BrokerStatus.state → 'disconnected'
  → 刷新 ConnectionLog 列表

[TradingModeToggle] 切换 (仅 admin):
  → PUT /trade/broker/mode { mode: 'paper' | 'live' }
  → 更新 BrokerStatus.tradingMode
```

### 4.1 轮询策略

```typescript
useEffect(() => {
  // 初始加载
  fetchBrokerStatus()
  fetchRiskConfig()
  fetchConnectionLogs()

  // 仅轮询连接状态，每 30s
  const timer = setInterval(() => {
    fetchBrokerStatus()
  }, 30_000)

  return () => clearInterval(timer)
}, [])
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易中心：账户、订单、持仓、成交全部按 tenant/account/user 隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 强私有交易数据。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | paper/QMT/多券商统一 BrokerAdapter。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
