# PRD — 交易信号·风险扫描

- **Date**: 2026-06-27 | **Owner**: product-lead | **Status**: Draft
- **Estimated effort tier**: Small（前端 1 Tab + 4 检查卡片 + 后端风险扫描端点）

## 1. Background

信号评分是一个**概率值**，它未包含以下风险维度：

- 审计报告是否为非标意见（财务造假/重大错报风险）
- 近期公告是否包含退市/ST/立案调查/大额减持等利空
- 股票是否处于 ST/*ST/退市整理期
- 业绩是否出现大幅下滑/预亏

"风险扫描"子模块作为**下单前的安全闸**，执行四项硬检查。任一项为高危 → 一票否决，即使信号评分再强也标记风险。

## 2. Goal & Non-Goals

**目标**：
- 审计/公告/ST/业绩 四项检查，每项独立卡片展示
- 一票否决机制：任一项高危 → 综合风险评级标红
- 操盘手完整查看，个人投资者简化展示

**Non-Goals**：
- 不做量化风险模型（VaR/回撤计算，属于风控中心 10.0）
- 不做产业链风险/宏观风险评估（属于产业链拆解 4.x）
- 不做实时公告监控（属于 alert-service 预警范围）

## 3. User Stories

| ID | As a | I want to | So that |
|---|---|---|---|
| US-1 | 操盘手 | 看到审计意见类型+会计师事务所+年报年份 | 避开非标审计意见股票 |
| US-2 | 操盘手 | 看到近 30 天公告风险关键词扫描结果（减持/立案/处罚/退市） | 避开有重大利空公告的股票 |
| US-3 | 操盘手 | 看到 ST/退市状态检查 | 不买入 ST 或退市整理期股票 |
| US-4 | 操盘手 | 看到最新业绩增速+预告类型 | 避开业绩暴雷股票 |
| US-5 | 操盘手 | 四项检查结果合成为综合风险评级 | 一眼知道能不能下单 |
| US-6 | 个人投资者 | 看到简化版风险结论 | 不超载 |

## 4. Acceptance Criteria

| ID | Priority | AC | Verification method |
|---|---|---|---|
| AC-1 | P0 | 四项检查卡片正确渲染，每项含状态图标（✅/⚠️/🔴）、标签、详情 | 对照 API 返回数据验证 |
| AC-2 | P0 | 综合风险评级正确映射：全部 ✅ → 低风险(绿)，存在 ⚠️ → 中风险(黄)，存在 🔴 → 高风险(红) | 模拟各状态组合验证评级逻辑 |
| AC-3 | P1 | 操盘手看到完整四项+综合评级，个人投资者看到简化版（仅综合结论+风险项摘要） | 角色切换后展示范围正确 |

### 5.2 一票否决规则

| 检查项 | 一票否决条件 | 状态 |
|---|---|---|
| 审计检查 | 非标审计意见（保留/否定/无法表示） | 🔴 高危 |
| 公告检查 | 退市/ST/立案调查公告 | 🔴 高危 |
| 公告检查 | 大额减持(≥5%)/担保/诉讼 | ⚠️ 关注 |
| ST/退市 | ST/*ST/退市整理期 | 🔴 高危 |
| 业绩检查 | 预亏/大幅下滑(>50%) | 🔴 高危 |
| 业绩检查 | 预减/略减 | ⚠️ 关注 |

### 5.3 操盘手 vs 个人投资者

| 模块 | 操盘手 | 个人投资者 |
|---|---|---|
| 风险扫描 | 完整四项检查卡片 + 综合评级 | 简化：仅综合评级 + 风险项摘要（≤2行） |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易信号：公共信号规则与用户私有订阅、处理状态分离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共信号 + 私有已读/订阅/处置。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 信号只作为订单依据之一。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
