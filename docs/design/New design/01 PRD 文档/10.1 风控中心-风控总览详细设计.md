## 1. 页面定位

风控总览是风控中心**第一个 SubTab**（SubTab key: `overview`）。作为风控入口首页，以自上而下的信息层次呈现熔断器 → 四层防御 → KPI → 告警。

## 3. 核心数据结构

```typescript
interface RiskOverviewData {
  circuitBreaker: CircuitBreakerStatus
  defenseLayers: DefenseLayerStatus[]
  kpis: OverviewKpi[]
  recentAlerts: AlertItem[]
}

interface CircuitBreakerStatus {
  state: 'NORMAL' | 'TRIGGERED' | 'HALF_OPEN'
  dailyLossPct: number
  thresholdPct: number
  budgetRemainingPct: number
  totalAssets: number
  availableFunds: number
}

interface DefenseLayerStatus {
  layer: 'pre_trade' | 'strategy_exec' | 'global_breaker' | 'market_env'
  label: string
  icon: string
  status: 'normal' | 'warning' | 'danger'
  passedCount: number
  totalCount: number
  detail: string
}

interface OverviewKpi {
  key: string
  label: string
  value: number
  unit: string
  status: 'normal' | 'warning' | 'danger'
}

interface AlertItem {
  time: string
  level: 'danger' | 'warning' | 'info'
  message: string
  link: string | null
}
```

---

## 4. 数据流

```
RiskOverviewPanel (props: riskData from parent)
│
├── BreakerBanner ← riskData.circuitBreaker
├── DefenseLayerBars ← riskData.defenseLayers (内联计算或后端返回)
├── KPIOverviewRow ← riskData.riskKpis (过滤 overview 相关)
└── RecentAlerts ← riskData.recentAlerts (取前 3 条)
```

---

## 5. 实施顺序

1. BreakerBanner 组件 → 3 态切换
2. DefenseLayerBars → 4 层进度条
3. KPIOverviewRow → 4 张卡片
4. RecentAlerts → 告警列表
5. 金额屏蔽逻辑 (user 角色)

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 风控中心：规则分全局/租户/账户，RiskVerdict 按账户和上下文归档。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共规则 + 私有判定结果。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 所有实盘动作强制经过。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
