## 2. 核心数据结构

### 2.1 信号结果

```typescript
type DimName = 'kronos' | 'technical' | 'capital' | 'fundamental' | 'event' | 'market'
type SignalRating = 'STRONG_BUY' | 'BUY' | 'HOLD' | 'SELL' | 'STRONG_SELL'

const RATING_MAP: Record<SignalRating, { label: string; color: string; range: [number, number] }> = {
  STRONG_BUY:  { label: '强烈买入', color: '#ff4d4f', range: [80, 100] },
  BUY:         { label: '买入',     color: '#f5a623', range: [60, 80) },
  HOLD:        { label: '持有',     color: '#3d8bff', range: [40, 60) },
  SELL:        { label: '卖出',     color: '#2ec27e', range: [20, 40) },
  STRONG_SELL: { label: '强烈卖出', color: '#5e6a7d', range: [0,  20) },
}

interface DimScore {
  dim: DimName
  label: string           // "Kronos预测" / "技术分析" / "资金面" / "基本面" / "事件驱动" / "市场情绪"
  icon: string            // "🤖" / "📊" / "💰" / "🏢" / "⚡" / "🌐"
  score: number           // 0-100
  weight: number          // 权重 (6 维权重之和 = 1.0)
  description: string
}

const DEFAULT_DIM_WEIGHTS: Record<DimName, number> = {
  kronos: 0.20, technical: 0.20, capital: 0.20,
  fundamental: 0.15, event: 0.10, market: 0.15,
}

interface SignalResult {
  tsCode: string
  name: string
  compositeScore: number          // 加权综合分
  rating: SignalRating
  actionText: string              // "建议重仓买入 (15-20%)" / "建议轻仓观望" etc.
  dimScores: DimScore[]
  fundFlows: FundFlow[]
  trend: TrendInfo
  computedAt: string
  dataFreshness: string
}
```

### 2.2 资金流向

```typescript
type FundFlowType = 'main_force' | 'north_bound' | 'margin'

interface FundFlow {
  type: FundFlowType
  label: string           // "主力净流入" / "北向净流入" / "融资净流入"
  amount: number          // 净流入金额 (亿)
  direction: 'inflow' | 'outflow'
  changePct: number
  consecutiveDays: number // 连续流入天数
  summary: string         // "资金面偏多，主力+北向共振流入"
}
```

### 2.3 趋势强度

```typescript
interface TrendInfo {
  score: number           // 趋势强度 0-100
  direction: 'up' | 'down' | 'sideways'
  directionLabel: string  // "上升趋势" / "下降趋势" / "横盘震荡"
  maStatus: 'bullish_alignment' | 'bearish_alignment' | 'entangled'
  maStatusLabel: string   // "均线多头排列" / "均线空头排列" / "均线缠绕"
  keyMAs: { ma5: number; ma10: number; ma20: number; ma60: number }
}
```

### 2.4 风险扫描

```typescript
type RiskCheckStatus = 'pass' | 'warning' | 'danger'

interface RiskCheckItem {
  key: 'audit' | 'announce' | 'st' | 'forecast'
  label: string           // "审计检查" / "公告检查" / "ST/退市检查" / "业绩检查"
  status: RiskCheckStatus
  statusIcon: string      // "✅" / "⚠️" / "🔴"
  detail: string          // 详细描述
  tags?: { text: string; severity: 'info' | 'warn' | 'danger' }[]
}

interface RiskScanResult {
  checks: RiskCheckItem[]
  overallRisk: 'low' | 'medium' | 'high'
  overallRiskLabel: string  // "低风险" / "中等风险" / "高风险"
  summary: string           // "四项检查全部通过" / "存在1项关注事项"
}
```

interface SignalHistoryPoint {

interface SignalDetailState {

  signalResult: SignalResult | null
  signalHistory: SignalHistory | null
  riskScanResult: RiskScanResult | null
  isLoading: boolean
  error: string | null
}

## 3. 数据流

### 3.1 初始加载

```
URL: /signal?code=300750.SZ&source=candidate
  ├── 1. GET /api/v1/signal/quick-entries → 渲染 QuickSelectBar (候选池+自选+最近)
  ├── 2. GET /api/v1/signal/analyze/{ts_code} → SignalResult (六维评分 + 资金流 + 趋势)
  ├── 3. GET /api/v1/signal/history?code=300750.SZ → SignalHistory (30日趋势 + 命中率)
  └── 4. GET /api/v1/signal/risk-scan?code=300750.SZ → RiskScanResult (4项检查)
```

### 3.2 信号计算 (后端 signal-service)

```
POST /api/v1/signal/analyze
  Request:  { ts_code: "300750.SZ" }
  Process:
    ├── Kronos 模型预测得分 (prediction-service :8002)
    ├── 技术指标计算 (screener-service :8001): MACD/RSI/均线/量价
    ├── 资金流向聚合 (signal-service 内部): 北向/主力/融资
    ├── 基本面数据 (screener-service :8001): PE/PB/ROE/营收增速
    ├── 事件驱动评分 (signal-service 内部): 公告/新闻/政策匹配
    ├── 市场情绪 (diagnosis-service :8009): 舆情/社交媒体
    └── 加权计算 → compositeScore → rating → actionText
  Response: SignalResult
```

### 3.3 风险扫描 (后端 signal-service)

```
GET /api/v1/signal/risk-scan?code=300750.SZ
  Process:
    ├── 审计意见: 最近一期年报审计意见类型
    ├── 公告扫描: 近30天公告关键词匹配 (退市/ST/立案/处罚/减持)
    ├── ST检查: 是否ST/*ST/退市整理期
    └── 业绩检查: 最新季报营收/净利润增速 + 业绩预告
  Response: RiskScanResult
```

### 3.4 跳转

```
[加入候选池] → POST /api/v1/candidate-pool/add { ts_code }
[跳转交易中心下单] → /trade?code={tsCode}&ref=signal
[查看诊断] → /diagnosis?code={tsCode}&ref=signal
[设价格预警] → POST /api/v1/alert/rules { ts_code, rule_type: 'price' }
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易信号：公共信号规则与用户私有订阅、处理状态分离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共信号 + 私有已读/订阅/处置。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 信号只作为订单依据之一。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
