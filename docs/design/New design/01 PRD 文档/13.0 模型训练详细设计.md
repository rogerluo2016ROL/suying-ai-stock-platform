## 1. 页面定位

模型训练是 ML 工程师（admin 角色）专用页面，管理 Kronos Transformer + LightGBM + CatBoost 模型的训练任务全生命周期。页面提供训练任务 CRUD、超参数配置、实时指标监控，以及内置 MLflow 实验追踪面板。

| 维度 | 模型训练 (menu 13) | 模型注册 (menu 14) |
|---|---|---|
| **使用者** | ML 工程师 (admin) | ML 工程师 (admin) |
| **核心流程** | 创建任务 → 运行训练 → 看指标 | 注册模型 → staging → production |
| **数据写入** | training-service (8008) | training-service (8008) |
| **MLflow** | 实验创建 + 参数/指标记录 | 模型版本注册 + 标签 |

**页面入口**：
- 侧边栏菜单 "🧠 模型训练"（模型/系统管理主题）
- 仅 admin 角色可见

### 3.2 核心数据模型

```typescript
// ── 模型类型 ──────────────────────────────
type ModelType = 'kronos' | 'lightgbm' | 'catboost'

interface ModelTypeConfig {
  value: ModelType
  label: string
  description: string
  hyperParams: HyperParamDef[]
}

interface HyperParamDef {
  key: string
  label: string
  type: 'number' | 'select' | 'slider' | 'switch'
  default: number | string | boolean
  options?: { label: string; value: string | number }[]
  min?: number
  max?: number
  step?: number
  unit?: string
}

// ── 数据集 ────────────────────────────────
interface DatasetOption {
  id: string
  name: string                    // "日频全市场"
  stockCount: number              // 12580
  dateRange: [string, string]     // ["2020-01-01", "2026-06-25"]
  description: string
}

// ── 训练任务 ──────────────────────────────
interface TrainingTask {
  id: string
  name: string
  modelType: ModelType
  datasetId: string
  datasetName: string
  target: '1d_return' | '5d_return' | '20d_return'
  status: TrainingStatus
  hyperParams: Record<string, number | string | boolean>
  progress: {
    currentEpoch: number
    totalEpochs: number
    percent: number
    elapsed: string              // "2h 15min"
    estimatedRemaining: string   // "1h 30min"
  } | null
  metrics: {
    trainLoss: number
    valLoss: number
    trainAcc: number
    valAcc: number
    f1: number
    auc: number
    precision: number
    recall: number
    bestEpoch: number
    metricHistory: EpochMetric[]
  } | null
  mlflow: {
    experimentId: string
    runId: string
    runName: string
  } | null
  createdAt: string
  startedAt: string | null
  completedAt: string | null
  duration: string | null
  errorLog: string | null
  createdBy: string
}

// ── Epoch 指标历史 ────────────────────────
interface EpochMetric {
  epoch: number
  trainLoss: number
  valLoss: number
  trainAcc: number
  valAcc: number
  f1: number
  auc: number
  lr: number
}

// ── 超参数预设 ────────────────────────────
interface HyperParamPreset {
  id: string
  name: string                    // "Kronos 默认" / "快速实验" / "高精度"
  modelType: ModelType
  params: Record<string, number | string | boolean>
}

// ── MLflow 实验 ──────────────────────────
interface MlflowExperiment {
  id: string
  name: string
  artifactLocation: string
  lifecycleStage: string
  runCount: number
}

interface MlflowRun {
  runId: string
  runName: string
  experimentId: string
  status: 'RUNNING' | 'FINISHED' | 'FAILED' | 'KILLED'
  startTime: string
  endTime: string | null
  metrics: Record<string, number>
  params: Record<string, string>
  tags: Record<string, string>
}
```

## 4. 数据流

### 4.1 初始加载

```
ModelTraining mount (admin guard: useAuth() → role !== 'admin' → 403)
│
├── GET /api/v1/training/tasks?page=1&size=50
│   └── 返回训练任务列表
│       └── 按状态排序: running → queued → completed → failed → stopped → draft
│
├── GET /api/v1/training/datasets
│   └── 返回可用数据集列表
│
├── GET /api/v1/training/model-types
│   └── 返回模型类型 + 超参数定义
│
├── GET /api/v1/training/presets
│   └── 返回超参数预设
│
└── GET /api/v1/training/mlflow/experiments
    └── 返回 MLflow 实验列表
        └── 默认选中最新实验
```

### 4.2 创建训练任务

```
[新建任务] click → CreateTaskModal open
│
├── 1. 填写任务名称 + 选择模型类型
│   └── 模型类型变化 → 动态渲染对应超参数字段
│
├── 2. 选择数据集 + 目标 + 时间窗口
│
├── 3. (可选) 展开高级超参数 → 调整或选择预设
│   └── 预设选中 → 自动填充超参数
│
├── 4. [创建任务] → POST /api/v1/training/tasks
│   │   Request: CreateTaskRequest
│   │   Response: TrainingTask (status: 'draft')
│   │
│   └── Dispatch:
│       ├── tasks.unshift(newTask)
│       ├── close modal
│       └── Toast: "任务已创建，可以开始训练"
│
└── 5. (可选) 直接点击 [开始训练] 启动任务
```

### 4.3 启动/监控训练

```
[▶️ 开始训练] click
│
├── 1. POST /api/v1/training/tasks/{id}/start
│   │   后端: APScheduler 调度执行
│   │   │   ├── 1) 创建 MLflow experiment (如未存在)
│   │   │   ├── 2) 创建 MLflow run
│   │   │   ├── 3) 调用 Kronos/LightGBM/CatBoost 训练
│   │   │   ├── 4) 每 epoch 记录 metrics 到 MLflow
│   │   │   └── 5) 完成后保存模型到 Kronos/outputs/models/
│   │
│   │   Response: { taskId, status: 'queued', mlflowRunId }
│   │
│   └── Dispatch:
│       ├── update local task.status = 'queued'
│       └── 启动 10s 轮询 (task.status === 'running')
│
├── 2. 10s 轮询 GET /api/v1/training/tasks/{id}
│   │   返回最新 task 数据 (含 progress + metrics)
│   │
│   └── 当 status === 'running':
│       ├── 更新 ProgressBar (epoch X/Y)
│       ├── 更新 MetricsBar (最新 loss/acc/f1/auc)
│       ├── 更新 MLflow charts (追加新 epoch 数据点)
│       └── 继续轮询
│
├── 3. 当 status === 'completed':
│   ├── 停止轮询
│   ├── 更新 task 状态 + 最终指标
│   ├── Toast: "训练完成 ✅ · Loss: 0.324 · Acc: 68.2%"
│   └── 显示 [注册模型] 按钮
│
└── 4. 当 status === 'failed':
    ├── 停止轮询
    ├── 更新 task 状态 + 错误日志
    └── Toast: "训练失败 ❌ · 查看日志"
```

### 4.4 查看 MLflow 指标

```
选中任务 → RightColumn DetailPanel
│
├── 1. 根据 task.mlflow.runId → GET /api/v1/training/mlflow/runs/{runId}/metrics
│   └── 返回 metricHistory (全部 epoch)
│
├── 2. 渲染 ECharts 图表:
│   ├── Loss 曲线: train_loss + val_loss 双线
│   ├── Accuracy 曲线: train_acc + val_acc 双线
│   └── Learning Rate 曲线 (仅 Kronos)
│
├── 3. GET /api/v1/training/mlflow/runs/{runId}/params
│   └── 渲染超参数网格
│
└── 4. GET /api/v1/training/mlflow/runs/{runId}/artifacts
    └── 渲染文件列表 (可下载)
```

### 4.5 停止/重跑/删除

```
[⏹️ 停止] running → POST /api/v1/training/tasks/{id}/stop
│   ├── 后端: 发送停止信号 → APScheduler 取消 job
│   ├── MLflow: 标记 run status = 'KILLED'
│   └── 更新本地 status = 'stopped'

[🔄 重跑] completed/failed/stopped → POST /api/v1/training/tasks/{id}/rerun
│   ├── 后端: 复制任务 (相同配置) → 创建新 MLflow run
│   └── 新任务出现在列表顶部

[🗑 删除] → DELETE /api/v1/training/tasks/{id}
│   ├── Popconfirm: "确认删除? 此操作不可恢复"
│   ├── running/queued 状态不可删除 (需先停止)
│   └── 从列表移除
```

                │              │             │
                └──────────────┼─────────────┘
                               │ [🔄 重跑]
                               ▼
                         回到 draft (复制配置 → 新任务)

不可逆操作:
  · running [停止] → stopped (不可恢复，只能重跑)
  · 任何状态 [删除] → 不可恢复

## 6. 角色权限

| 维度 | admin (ML工程师) | 其他角色 |
|---|---|---|
| **页面访问** | 完整访问 | 403 Forbidden |
| **菜单可见** | 可见 | 隐藏 (侧边栏不渲染) |
| **操作权限** | 全部 (创建/启动/停止/重跑/删除) | — |
| **API 访问** | 全部端点 | 403 |

```typescript
// 路由守卫
function useModelTraining() {
  const { role } = useAuth()
  const isAdmin = role === 'admin'

  if (!isAdmin) {
    // 前端重定向到 403 页面
    // 后端 middleware: require_admin → HTTPException(403)
    return { forbidden: true }
  }

  return { forbidden: false, /* ... */ }
}
```

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 模型训练：仅模型管理员/系统管理员可操作，训练资源、实验和产物要隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 管理域数据。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不触达券商。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
