## 1. 页面定位

策略配置是量化交易**第二个 SubTab**（SubTab key: `config`）。操盘手在此创建/编辑策略的全部参数，按 4 个区段组织：基础参数、风险规则、仓位规则、卖出条件。

## 3. 核心数据结构

```typescript
interface StrategyConfigForm {
  // Basic
  id?: string                       // 编辑模式时有值
  name: string
  desc: string
  model: string                     // "dragon_v4.3" | "macd_golden" | ...
  runtime: 'after_hours' | 'intraday' | 'both'
  initialCapital: number
  maxPositions: number
  stocks: string[]

  // Risk
  dailyLossLimit: number            // 3.0
  stopLoss: number                  // 3.0
  takeProfit: number                // 15.0
  trailingStop: number              // 5.0 (0 = disabled)

  // Position
  singleStockCap: number            // 20
  totalPositionCap: number          // 80

  // Sell
  sellStopLoss: boolean
  sellTakeProfit: boolean
  sellSignalReverse: boolean
  sellTimeStop: boolean
  sellTimeStopDays: number          // 5
}

interface ConfigState {
  selectedStrategyId: string | null
  form: StrategyConfigForm
  isDraft: boolean
  isSaving: boolean
  errors: Record<string, string>
}
```

### 3.1 草稿机制

```typescript
const DRAFT_KEY = 'quant_strategy_draft'

function saveDraft(form: StrategyConfigForm): void {
  const key = form.id ? `${DRAFT_KEY}_${form.id}` : `${DRAFT_KEY}_new`
  localStorage.setItem(key, JSON.stringify(form))
}

function loadDraft(strategyId?: string): StrategyConfigForm | null {
  const key = strategyId ? `${DRAFT_KEY}_${strategyId}` : `${DRAFT_KEY}_new`
  const raw = localStorage.getItem(key)
  return raw ? JSON.parse(raw) : null
}

function clearDraft(strategyId?: string): void {
  const key = strategyId ? `${DRAFT_KEY}_${strategyId}` : `${DRAFT_KEY}_new`
  localStorage.removeItem(key)
}
```

## 4. 数据流

### 4.1 主数据流

```
StrategyConfig mount
  │
  ├── [新建模式]
  │   ├── 加载草稿 (如果有) → populate form
  │   └── 表单为空 → 使用默认值
  │
  ├── [编辑模式] (通过 query string ?id=xxx)
  │   ├── GET /strategy/auto/{id}
  │   ├── populate form (仅 stopped/paused 状态可编辑)
  │   └── 加载草稿 (覆盖 API 数据)
  │
  ├── autoSave: form onChange → debounce 2s → localStorage
  │
  ├── [💾 保存草稿]
  │   ├── 验证必填字段
  │   ├── 新建: POST /strategy/auto → 返回 id
  │   ├── 编辑: PUT /strategy/auto/{id}
  │   └── 清除草稿 + toast "草稿已保存"
  │
  ├── [▶️ 回测]
  │   ├── 先保存草稿 (同上)
  │   ├── POST /backtest/quick { strategyId, config }
  │   └── window.open("11.0 backtest-preview.html?strategy=" + id)
  │
  └── [🚀 部署上线]
      ├── 先保存 + validate
      ├── POST /strategy/auto/{id}/start
      └── 跳转 window.location.href = "8.3 strategy-monitor-preview.html?id=" + id
```

### 4.2 标的来源导入数据流

```
StockSourceImportPanel
  │
  ├── [🔬 从选股模型导入]
  │   ├── GET /screener/models → 获取可用选股模型列表
  │   ├── 用户选择模型 (如 "匪爷短线多因子")
  │   ├── GET /screener/results?model=feiye_short&limit=20
  │   ├── 返回候选标的列表 (ts_code, name, score)
  │   ├── 追加到 form.stocks[] (去重合并)
  │   └── toast "已从{modelName}刷新{N}只候选标的"
  │
  ├── [📐 从方案导入]
  │   ├── GET /plan?status=closed → 获取已完结方案列表
  │   ├── 用户选择方案 (如 "FU-20260627-01M")
  │   ├── GET /plan/{id}/stocks → 获取方案中的标的列表
  │   ├── 追加到 form.stocks[] (去重合并)
  │   └── toast "已从方案{planId}导入{N}只标的"
  │
  ├── [⭐ 从自选导入]
  │   ├── GET /watchlist/stocks → 获取用户自选股列表
  │   ├── 追加到 form.stocks[] (去重合并)
  │   └── toast "已从自选导入{N}只标的"
  │
  └── [📋 手动添加]
      ├── 弹出搜索弹窗 (输入 ts_code / name)
      ├── GET /stocks/search?q={keyword} → 搜索结果
      ├── 用户勾选 → 追加到 form.stocks[]
      └── 关闭弹窗
```

## 5. 校验规则

```typescript
interface ValidationRule {
  field: keyof StrategyConfigForm
  rule: (v: any) => string | null  // null = pass
}

const rules: ValidationRule[] = [
  { field: 'name', rule: v => v ? null : '策略名称不能为空' },
  { field: 'stocks', rule: v => v.length > 0 ? null : '请至少选择 1 只标的' },
  { field: 'initialCapital', rule: v => v >= 10000 ? null : '初始资金不能低于 10,000' },
  { field: 'maxPositions', rule: v => v >= 1 && v <= 20 ? null : '最大持仓 1-20 只' },
  { field: 'maxDrawdown', rule: v => v < 0 ? null : '最大回撤必须为负值' },
]
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 量化交易：策略模板可公共，策略实例、参数和运行日志必须私有隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共模板 + 私有策略实例。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 自动执行绑定账户并经过 RiskGate。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
