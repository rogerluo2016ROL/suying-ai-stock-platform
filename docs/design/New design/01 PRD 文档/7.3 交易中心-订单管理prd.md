# PRD — 交易中心·订单管理

- **Date**: 2026-06-27 | **Owner**: product-lead | **Status**: Draft
- **Estimated effort tier**: Medium（订单列表 + 筛选 + 改单弹窗 + 撤单/批量撤单）

## 1. Background

订单管理是交易中心的**订单追踪面板**。操盘手在此查看今日全部订单的成交状态，对待成交订单执行改单/撤单操作。

当前痛点：
1. 缺少改单功能——价格变动后只能撤单重新下
2. 缺少批量撤单——逐笔撤单效率低
3. 订单状态筛选不够直观
4. 个人投资者无订单追踪视图

## 2. Goal & Non-Goals

**目标**：
- 构建今日订单列表：时间/代码/方向/价格/数量/金额/状态
- 状态筛选Pill：[全部]/[待成交]/[已成交]/[已撤单]
- 待成交行支持[✏️改单]（弹窗修改价格/数量）+ [✖️撤单]
- [全部撤单]批量操作

**Non-Goals**：
- 不做历史订单查询（只展示今日）
- 不做订单导出
- 不改已成交/已撤单订单

## 3. User Stories

| ID | As a | I want to | So that |
|---|---|---|---|
| US-1 | 操盘手 | 看到今日全部订单及其状态（待成交/已成交/已撤单） | 掌握当日交易进展 |
| US-2 | 操盘手 | 使用状态筛选项快速过滤 | 聚焦特定状态的订单 |
| US-3 | 操盘手 | 点击[✏️改单]在弹窗中修改未成交订单的价格/数量 | 快速调整而不必撤单重下 |
| US-4 | 操盘手 | 点击[✖️撤单]撤销未成交订单 | 取消不再需要的挂单 |
| US-5 | 操盘手 | 点击[全部撤单]一次性撤销所有待成交订单 | 紧急/收盘前快速清理 |
| US-6 | 个人投资者 | 看到"我的今日订单"只读列表 | 了解自己的订单状态 |

## 4. Acceptance Criteria

| ID | Priority | AC | Verification method |
|---|---|---|---|
| AC-1 | P0 | 订单列表正确显示所有字段（时间/代码/方向/价格/数量/金额/状态） | 对照 API 返回数据验证 |
| AC-2 | P0 | 状态筛选项功能正常：[全部5][待成交2][已成交3] 点击切换 | 逐个点击验证过滤结果 |
| AC-3 | P0 | 改单弹窗：点击[✏️改单]→弹窗显示当前价格/数量→修改→[确认修改]→PUT /trade/order/{id}→订单价格/数量更新 | 修改一只待成交订单验证 |
| AC-4 | P0 | 撤单：点击[✖️撤单]→确认→DELETE /trade/order/{id}→订单状态变为"已撤单" | 撤销一只待成交订单验证 |
| AC-5 | P0 | [全部撤单]：点击→确认→批量 DELETE /trade/orders→所有待成交订单变为已撤单 | 验证全部待成交订单被撤销 |
| AC-6 | P1 | 个人投资者视图：订单列表只读，无改单/撤单按钮 | 切换角色验证 |

## 6. Technical Constraints

- 数据来源：`GET /api/v1/trade/orders?date=today`，30s 轮询
- 改单只能修改待成交（pending/partial）状态的订单
- [全部撤单] 仅撤销待成交状态订单，已成交不受影响

## 7. Out of Scope

| 编号 | 工作项 | 原因 |
|---|---|---|
| FW-1 | 历史订单查询 | 仅展示今日 |
| FW-2 | 订单导出 CSV | Phase 2 |
| FW-3 | 条件改单（价格触发自动修改） | Phase 3 |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易中心：账户、订单、持仓、成交全部按 tenant/account/user 隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 强私有交易数据。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | paper/QMT/多券商统一 BrokerAdapter。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
