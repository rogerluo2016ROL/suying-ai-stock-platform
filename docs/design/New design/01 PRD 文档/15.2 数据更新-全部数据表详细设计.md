## 1. 页面定位

全部数据表是数据更新模块的**第二个 Tab**，**仅管理员可见**。展示全部 42 张数据表的状态、新鲜度、同步历史，支持逐表手动同步。

> **角色映射（收口决策）**：管理员 → RBAC `admin`；操盘手 → `internal_analyst`；个人投资者 → `user`；`external_analyst` → 外部只读。Tab 可见性与写操作权限由服务端按 JWT 角色执行，前端禁止传 `X-User-Role` 等身份头。
>
> **表数量口径（收口决策）**：「42 表（18 核心 + 24 辅助）」为设计示例数，实际表清单以 data-service `GET /api/v1/data/inventory` 返回为准，页面动态渲染。

## 4. 数据流

### 4.1 初始加载

```
AllTablesTab mount (仅 admin)
│
├── GET /api/v1/data-update/tables?page=1&size=50
│   └── 全部 42 表 (isCore 区分核心/辅助)
│
├── GET /api/v1/data-update/sync-all/active
│   └── 检查是否有进行中的全量同步任务
│
└── admin: 15s 轮询 GET /api/v1/data-update/tables?since={timestamp}
    └── 增量刷新有变化的表
```

### 4.2 手动同步单表

```
[🔄 手动同步] click
│
├── syncingTableIds.add(tableId) → 按钮 Loading
│
├── POST /api/v1/data-update/tables/{id}/sync
│   │   Response: { success, rowsAdded, duration, newMaxDate }
│   │
│   └── Dispatch:
│       ├── 更新该表 maxDate / freshness / rows / lastSyncAt
│       ├── syncingTableIds.delete(tableId)
│       └── Toast: "daily_bars 同步完成 · +1,245行 · 12.3s"
│
└── 失败:
    ├── freshness = 'error', errorMessage 显示
    └── Toast: "同步失败: Tushare 限流 · 已自动重试"
```

### 4.3 全量同步

```
[🔄 全部同步] click → Popconfirm "确认触发全量同步? 预计 3-5 分钟"
│
├── POST /api/v1/data-update/sync-all
│   Response: { taskId, phases: 7, estimatedMinutes: 4 }
│
├── syncAllModalOpen = true
│
├── 5s 轮询 GET /api/v1/data-update/sync-all/{taskId}/progress
│   ├── 更新 PhaseProgress
│   └── 逐表刷新已完成的表状态
│
└── 全部完成 → Modal 关闭 → Toast + 全部刷新
```

## 5. 过滤逻辑

```typescript
const filteredTables = useMemo(() => {
  let result = [...coreTables, ...auxTables]

  if (filter.category !== 'all') {
    result = result.filter(t => t.category === filter.category)
  }

  if (filter.freshness === 'failed') {
    result = result.filter(t => t.syncStatus === 'failed')
  } else if (filter.freshness !== 'all') {
    result = result.filter(t => t.freshness === filter.freshness)
  }

  if (filter.search.trim()) {
    const q = filter.search.trim().toLowerCase()
    result = result.filter(t =>
      t.tableName.toLowerCase().includes(q) ||
      t.displayName.toLowerCase().includes(q)
    )
  }

  return {
    core: result.filter(t => t.isCore),
    aux: result.filter(t => !t.isCore),
    total: result.length
  }
}, [coreTables, auxTables, filter])
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 数据更新：公共数据平台能力，普通用户只看简化新鲜度。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共数据质量。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不触达券商。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
