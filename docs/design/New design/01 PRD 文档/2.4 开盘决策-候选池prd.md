## 1. 定位

候选池是开盘决策的**决策收口**。多源 picks 汇集于此，经共识排序 + 风险排除后，输出最终可执行标的。

操盘手在此 Tab 完成：交叉验证 → 排除风险 → 确认 3-5 只 → 生成交易方案。

## 2. 输入源

```
候选池 = 多源融合

来源                    Tab/菜单            数据
──────────────────────────────────────────────────
竞价选股 picks         竞价分析 Tab         leader_auction V4.3 输出
竞价选债 picks         竞价分析 Tab         cb_auction V1.0 输出
信号确认 picks         信号扫描 Tab         用户手动勾选
智能选股 picks         智能选股(独立菜单)   bi_trend/short/long/all 等盘后结果
自选共振               —                   watchlist 表
```

## 3. 融合算法

```typescript
// CandidatePoolManager.compute()
interface CandidateStock {
  code: string
  name: string
  industry: string
  price: number
  changePct: number
  
  // 来源追踪
  sources: ('auction' | 'signal' | 'screener' | 'watchlist')[]
  consensusLevel: 1 | 2 | 3  // ★☆☆ / ★★☆ / ★★★
  
  // 多维度评分
  auctionScore: number | null
  signalScore: number | null
  screenerScore: number | null
  compositeScore: number      // 综合评分
  
  // 预测
  kronosPrediction: { direction: 'up' | 'down' | 'flat'; confidence: number } | null
  
  // 风险标记
  riskFlags: RiskFlag[]
  isExcluded: boolean
  
  // 自选标记
  isInWatchlist: boolean
}

type RiskFlag = 
  | { type: 'audit'; opinion: string; penalty: number }
  | { type: 'announcement'; keyword: string }
  | { type: 'st_delist'; status: string }
  | { type: 'stop_loss_close'; distancePct: number }
```

### 共识度计算

| 条件 | 共识度 |
|---|---|
| 出现在 ≥3 个来源中 | ★★★ (3) — 最高共识 |
| 出现在 2 个来源中  | ★★☆ (2) |
| 出现在 1 个来源中  | ★☆☆ (1) |

### 综合评分

```
compositeScore = avg(auctionScore×0.3, signalScore×0.4, screenerScore×0.3)
缺某维度时权重重新归一化。
```

### 风险排除

```
一票否决（自动标记排除，不可撤销）：
  ├─ 审计: 无法表示意见/否定意见 → SELL，强制排除
  └─ 公告: "退市/暂停上市/立案调查" → 强制排除

警告标记（默认排除，可手动恢复）：
  ├─ 审计: 保留意见 → 标记
  ├─ ST/退市风险 → 标记
  └─ 距止损 < 1% → 标记
```

## 5. 方案生成链路（候选池内完成，不跳转页面）

```
候选池中勾选 3-5 只 → 点击 [生成方案]
    ↓ 自动生成方案编码: {模型缩写}-{日期}-{序号}-{类型}
    例: FU-20260627-01A (融合模型, 当日第1个, 自动交易)
    ↓
候选池右侧面板切换为"方案预览"（不跳转）
    ↓
Step 1 — 系统自动计算（1-2秒）
  根据选中股票，自动生成:
  ┌──────────────────────────────────────────┐
  │ 标的    方向  计划价   仓位  止损    止盈  │
  │ 宁德    买入  218.50  15%  196.50  251.00│
  │ 中芯    买入   68.20  12%   61.38   78.40│
  │ 兆易    买入  152.00  10%  136.80  174.80│
  │                                          │
  │ 总仓位: 37% · 可用资金 ¥342,000          │
  │ 总风险: -4.5%（全部止损触发）            │
  │ 🛡️ 风控预检: ✅ 全部通过                 │
  └──────────────────────────────────────────┘

Step 2 — 用户审查调整（可交互）
  仓位: 每只拖动滑块调整%
  止损: 可选 [ATR动态] [支撑位(diagnosis)] [固定%]
  止盈: 可选 [固定15%] [阻力位(diagnosis)] [移动止盈]
  可 [添加] [移除] 标的

Step 3 — 选择提交方式:
  ┌──────────────────────────────────────────────────────────────┐
  │ [🚀 确认提交→自动交易]                                       │
  │   → POST /api/v1/strategy/generate-from-picks               │
  │   → 创建策略 + 启动执行器 → 自动逐笔下单                     │
  │   → 订单 → 交易中心 + 执行监控 Tab                          │
  │   → 方案 → 执行监控"今日方案"面板                            │
  │                                                              │
  │ [📝 保存为手动方案]                                          │
  │   → POST /api/v1/strategy/generate-from-picks               │
  │   → 保存方案（不启动，不生成订单）                           │
  │   → 方案出现在执行监控"今日方案"面板                         │
  │   → 用户到交易中心手动逐笔下单                               │
  │                                                              │
  │ [💾 仅保存]                                                  │
  │   → 保存为草稿，停留在候选池                                 │
  └──────────────────────────────────────────────────────────────┘

Step 4 — 后续跟踪
  自动交易: 跳转执行监控 Tab → 看订单/持仓/方案
  手动方案: 跳转交易中心 → 逐笔下单
```

### 5.1 方案参数计算规则

| 参数 | 优先级 | 获取方式 |
|---|---|---|
| 计划价 | 1 | 当前市价 `daily_kline.close` |
| 仓位% | 1 | 等权分配(100%/N)或评分加权 |
| 止损价 | 1→2→3 | diagnosis `key_levels.stop_loss` → ATR×1.5 → 固定-8% |
| 止盈价 | 1→2 | 固定+15% → diagnosis `key_levels.resistance` |
| 风控预检 | — | `trade-service risk_gateway` 同 6 项规则 |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 开盘决策：操盘手默认入口，输出私有 Candidate 与 DecisionContext。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共竞价/行情 + 私有候选池。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 实盘前必须进入方案与风控。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
