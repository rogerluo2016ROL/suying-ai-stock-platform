# PRD — 智能看板·竞价意图

- **Date**: 2026-06-25
- **Owner**: product-lead
- **Status**: Draft
- **Estimated effort tier**: Medium（前端 1 页面 + 后端 1~2 新端点 + ECharts 集成）

## 1. Background

当前速赢AI已在 Dashboard 页面中嵌入竞价意图的两个碎片展示：

- 右侧边栏"竞价意图"卡（`Dashboard.tsx:566-633`）：仅展示 Top 3 看涨 + Top 2 看跌，信息密度极低；
- 多策略融合看板"竞价选股"Tab（`Dashboard.tsx:688-720`）：仅一张 5 列表格 + 板块统计，缺乏深度的分析视角。

**用户痛点**：

1. **操盘手**无法看到竞价撮合价的分时走势（9:15→9:25），无法判断主力做多/做空意图的演变过程；
2. **个人投资者**只能看到评分和涨幅，缺乏四维评分的直观展示（雷达图），也无法横向对比板块竞价热度；
3. 每次竞价选股都依赖 `一键选股` 触发流水线，缺乏独立、即时、可交互的竞价看板；
4. 数据分散在两处，需要反复切换 Tab 才能形成完整的竞价判断。

## 2. Goal & Non-Goals

**目标**：

- 构建独立的"竞价意图看板"页面，在 9:25 竞价结束后 30 秒内呈现完整的市场竞价全貌
- KPI：看板首屏渲染 ≤ 2s（含 API 数据）、用户从打开页面到完成竞价判断的平均时长 ≤ 60s

**Non-Goals**：

- 不做 9:15-9:25 实时竞价推流（本次只做竞价结果快照分析）
- 不做盘中连续竞价分析（已有"盘中选股"Tab 覆盖）
- 不做移动端 / 窄屏适配（桌面优先，≥1366px）
- 不引入新的数据源或数据库表（复用现有 `stk_auction_o` + `daily_kline` + `stocks`）

## 3. User Stories

| ID | As a | I want to | So that |
|---|---|---|---|
| US-1 | 短线交易者 | 一眼看到今天竞价的市场情绪分布（抢筹/中性/出货各多少只） | 快速判断今天是属于"进攻日"还是"防御日" |
| US-2 | 短线交易者 | 看到竞价涨幅和时间演变关系（撮合价曲线） | 判断高开是真实买盘推动还是诱多陷阱 |

| US-7 | 交易员 | 点击竞价个股跳转诊断页 | 深入分析看中的标的 |
| US-8 | 操盘手 | 看到抢筹 TOP 榜单与出货 TOP 榜单并列 | 快速识别今天的龙头股和风险股 |

### 5.2 API 契约

#### 复用端点（无需改动）

| 端点 | 方法 | 用途 |
|---|---|---|
| `/api/v1/signal/auction-intent?limit=200` | GET | 竞价意图分析（四维评分 + 意图标签），驱动全量明细表 + TOP 榜单 |
| `/api/v1/dashboard/auction?date=YYYY-MM-DD` | GET | 龙头竞价 picks + sector 统计，驱动"一字定方向"板块热力 |

#### 新增端点

**`GET /api/v1/signal/auction-timeline?code={code}&trade_date={date}`**

- **用途**：获取单只股票竞价时段（9:15-9:25）撮合价分时序列
- **Request**：`code` (必填), `trade_date` (可选，默认最新交易日)
- **Response (200)**：
```json
{
  "status": "ok",
  "code": "000001",
  "trade_date": "2026-06-25",
  "prev_close": 12.00,
  "timeline": [
    {"time": "09:15", "price": 12.15, "volume": 500000, "unmatched_buy": 200000, "unmatched_sell": 100000},
    {"time": "09:20", "price": 12.30, "volume": 1200000, "unmatched_buy": 350000, "unmatched_sell": 80000},
    {"time": "09:25", "price": 12.50, "volume": 2000000, "unmatched_buy": 0, "unmatched_sell": 0}
  ]
}
```
- **Response (404)**：`{"status": "not_found", "message": "该股票暂无竞价分时数据"}`
- **数据来源**：优先 Tushare `stk_auction` 实时 API（含分时），降级从 `stk_mins` 5分钟线取 9:30 首根K线作为近似展示；两者都无则返回 404

### 5.3 数据模型

不新增数据库表。数据来源：

| 数据 | 来源 | 说明 |
|---|---|---|
| 竞价意图评分 | `stk_auction_o` + `daily_kline` + `stocks` | PG 中已有，signal-service 四维模型计算 |
| 龙头竞价 picks | `AuctionScalpEngine` (leader_auction.py) | 秋神战法 V4.3，已由 screener-service 暴露 |
| 板块竞价统计 | `AuctionScalpEngine` 输出中的 sector 聚合 | 已在 `/dashboard/auction` 返回 |
| 竞价分时线 | `stk_auction`（Tushare 实时 API）或 `stk_mins` | 需新增端点，见 5.2 |

## 6. Technical Constraints

- 前端框架：React 18 + TypeScript 5.6 + Ant Design 5.22 + ECharts 5.5
- 页面实现：作为 `Dashboard.tsx` 的 Tab 面板（Tab key: `auction-intent`），替换现有简化版"竞价选股"Tab。与市场情绪/信号总览/自选跟踪共享同一页面，通过 `<Tabs>` 切换（雷达图 + 折线柱混合图）
- 后端框架：FastAPI + uvicorn，新增端点放入 `signal-service/app/routes.py`
- 设计系统：严格遵循 `docs/design/new front/design-spec.md` 及 `design-tokens.css` 的 CSS 变量
- A 股涨跌色：`var(--up)` = 红涨, `var(--down)` = 绿跌，不得反转
- 字体系统：价格/评分用 `--font-mono` + `tabular-nums`，文案用 `--font-body`
- 微服务间 HTTP 调用使用 `urllib` async wrapper，不引入 `httpx`/`aiohttp`
- 桌面优先：推荐宽度 ≥1366px，不要求移动端适配
- 不引入新的 npm/Python 依赖
- API P95 ≤ 500ms（signal-service 现有拍卖查询已在 ~200ms），分时线端点 P95 ≤ 1s

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 智能看板：三角色首页：操盘手看交易机会，个人投资者看自选解释，管理员看平台健康。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共行情/信号 + 私有自选/提醒。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 券商状态只做摘要提示。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
