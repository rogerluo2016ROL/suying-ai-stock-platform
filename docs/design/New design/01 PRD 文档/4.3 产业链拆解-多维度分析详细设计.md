```typescript
// 护城河评分维度
interface MoatDimension {
  moat: number          // 护城河 0-100
  growth: number        // 增长力 0-100
  profit: number        // 利润率 0-100
  irreplaceability: number // 不可替代性 0-100
  substitution: number  // 国产替代 0-100
}

interface MoatScore extends MoatDimension {
  ts_code: string
  name: string
  composite: number     // 综合分 = 加权求和
  starRating: number    // 1-5 星 (护城河+不可替代均分)
}

// 卡脖子分级
type BottleneckLevel = 'level_1' | 'level_2' | 'none'

interface BottleneckItem {
  ts_code: string
  name: string
  level: BottleneckLevel
  chainNode: string        // 产业链节点
  localizationRate: number // 国产化率 %
  techGap: string          // 技术差距描述
}

// 商业化进程
type ResonanceTag = 'triple' | 'waiting' | 'none'  // ✅ / ⚠️ / ❌

interface ResonanceData {
  ts_code: string
  name: string
  cyclePhase: 'intro' | 'growth' | 'mature' | 'decline'
  cycleScore: number       // 0-1
  policyScore: number      // 0-1
  earningsScore: number    // 0-1
  resonanceScore: number   // 乘积
  resonanceTag: ResonanceTag
}

// 分析汇总
interface CompanyAnalysisResult {
  moatScore: MoatScore
  bottleneck: BottleneckItem
  resonance: ResonanceData
}
```

## 2. 评分算法

### 2.1 护城河综合评分

```typescript
function calcMoatScore(dim: MoatDimension): number {
  const weights = { moat: 0.30, growth: 0.20, profit: 0.15, irreplaceability: 0.25, substitution: 0.10 }
  return dim.moat * weights.moat
       + dim.growth * weights.growth
       + dim.profit * weights.profit
       + dim.irreplaceability * weights.irreplaceability
       + dim.substitution * weights.substitution
}
```

### 2.2 子维度评分细则

#### 护城河 (moat, weight=0.30)

```
护城河分 = 技术壁垒×0.30 + 市场份额×0.25 + 专利数量×0.20 + 客户粘性×0.15 + 品牌溢价×0.10
```

| 子指标 | 数据源 | 归一化方法 |
|---|---|---|
| 技术壁垒 | LLM评估 (1-10) → ×10 | DeepSeek 基于研报/行业描述打分 |
| 市场份额 | `stocks.market_cap` / 行业总市值 | 百分位排名 → 0-100 |
| 专利数量 | 外部数据 / LLM估算 | 对数归一化 |
| 客户粘性 | `fina_indicator` 应收账款周转率 + LLM | 定性定量结合 |
| 品牌溢价 | 毛利率高于行业均值的幅度 | 差值归一化 |

#### 增长力 (growth, weight=0.20)

```
增长力分 = 营收增速×0.40 + 净利润增速×0.30 + ROE趋势×0.30
```

- 营收增速：`fina_indicator.revenue` YoY
- 净利润增速：`fina_indicator.net_profit` YoY
- ROE趋势：近3年 ROE 斜率

#### 利润率 (profit, weight=0.15)

```
利润率分 = 毛利率×0.40 + 净利率×0.35 + 经营现金流/营收×0.25
```

- 所有指标来自 `fina_indicator`，与行业均值对比归一化

#### 不可替代性 (irreplaceability, weight=0.25)

```
不可替代性分 = 技术独特性×0.40 + 切换成本×0.30 + 供应链地位×0.30
```

- **全部由 LLM 评估** (DeepSeek)，输入：公司信息 + 行业位置 + 竞争格局
- LLM 返回 3 个子维度分数 (0-100) + 评估依据

#### 国产替代 (substitution, weight=0.10)

```
国产替代分 = 国产化进度×0.50 + 政策扶持强度×0.30 + 进口替代空间×0.20
```

- 国产化进度：卡脖子清单映射
- 政策扶持：政策文件 LLM 评估
- 进口替代空间：行业进口额 / 国内产值

## 3. 三重共振公式

### 3.1 产业周期评分

```typescript
function calcCycleScore(phase: string, revenueGrowth: number): number {
  const phaseBase = {
    'intro': 0.2,    // 导入期
    'growth': 0.8,   // 成长期
    'mature': 0.5,   // 成熟期
    'decline': 0.1,  // 衰退期
  }
  return phaseBase[phase] || 0.5
}
```

### 3.2 政策强度评分

```
政策强度 = normalize(policyFileCount × 0.3 + policyBudget × 0.4 + policyFrequency × 0.3)
```

- `policyFileCount`：近1年相关政策文件数量
- `policyBudget`：政策涉及资金规模 (亿元)
- `policyFrequency`：政策发布频率 (次/季度)
- 数据来源：`policy_law` 表 + LLM 评估
- 归一化：Min-Max 到 0-1

### 3.3 业绩兑现评分

```typescript
function calcEarningsScore(netProfitYoY: number, revenueYoY: number): number {
  // 净利润 YoY > 20% 且 营收 YoY > 15% → 已兑现
  if (netProfitYoY > 20 && revenueYoY > 15) return 1.0
  // 净利润 YoY > 0 或 营收 YoY > 0 → 部分兑现
  if (netProfitYoY > 0 || revenueYoY > 0) return 0.5
  // 亏损或负增长 → 未兑现
  return 0.1
}
```

### 3.4 共振分 & 标签

```typescript
function calcResonance(cycleScore: number, policyScore: number, earningsScore: number): {
  score: number
  tag: ResonanceTag
} {
  const score = cycleScore * policyScore * earningsScore  // 0 ~ 1
  let tag: ResonanceTag
  if (score >= 0.40) tag = 'triple'
  else if (score >= 0.15) tag = 'waiting'
  else tag = 'none'
  return { score: parseFloat(score.toFixed(2)), tag }
}
```

## 5. 候选池联动 (CandidatePoolManager)

### 5.1 数据契约

加入候选池时携带的扩展字段：

```typescript
interface CandidatePoolEntry {
  ts_code: string
  name: string
  source: 'supply_chain_phase3'        // 来源标识
  moatScore: number                     // 护城河综合分
  bottleneckLevel: BottleneckLevel      // 卡脖子级别
  resonanceTag: ResonanceTag            // 三重共振标签
  resonanceScore: number                // 共振分
  addedAt: string                       // ISO datetime
}
```

### 5.2 联动时序

```
CompanyAnalysisTab                         CandidatePoolManager (板块2.4)
     │                                              │
     │ 1. 用户勾选公司 + 点击[加入候选池]              │
     │ 2. POST /api/v1/candidate-pool/batch-add      │
     │    body: { entries: CandidatePoolEntry[] }     │
     │─────────────────────────────────────────────►│
     │                                              │ 3. 写入 candidate_pool 表
     │ 4. 返回 { added: N, duplicates: M }           │
     │◄─────────────────────────────────────────────│
     │ 5. Toast: "已加入 N 只到候选池"                │
     │                                              │
     │ 6. [关联开盘决策] 按钮                          │
     │    → router.push('/open-decision?from=sc&      │
     │       codes=688012,002371&resonance=triple')  │
     │                                              │ 7. 开盘决策页读取 query params
     │                                              │    自动高亮对应公司
```

### 5.3 URL 参数传递

```
/open-decision?from=supply-chain&codes=688012.SH,002371.SZ&resonance=triple,waiting&moat=91,89
```

- `from`: 来源标识 (supply-chain)
- `codes`: 逗号分隔的 ts_code
- `resonance`: 逗号分隔的共振标签
- `moat`: 逗号分隔的综合评分

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 产业链拆解：公共产业链图谱与用户私有研究笔记分离，证据型标的进入候选池。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共图谱/政策 + 私有研究标注。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不直接交易，只输出 Candidate 证据。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
