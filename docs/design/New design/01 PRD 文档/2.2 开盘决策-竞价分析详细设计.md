## 1. 页面定位

竞价分析是**可操作的竞价工作台**（Operational Workbench），不是只读看板。

| 维度 | 1.2 竞价意图看板（AI智能看板） | 2.2 竞价分析（开盘决策） |
|---|---|---|
| **性质** | 只读浏览看板 | **可操作工作台** |
| **数据** | 预计算的竞价意图评分（信号服务） | 意图评分 + **实时运行选股/选债引擎** |
| **操作** | 点击行 → 跳转诊断 | **运行引擎 → 勾选标的 → 加入候选池 → 锁定板块 → 联动信号扫描** |
| **工作流** | 独立页面，无下游联动 | **下游联动**：锁定板块 → 信号扫描自动筛选 → 候选池汇总 |
| **默认用户** | 个人投资者（浏览） | 操盘手（操作 + 决策） |
| **Tab 层级** | 顶层页面 | 开盘决策二级 Tab（嵌套 3 个子面板） |
| **侧栏** | [锁定→信号扫描] 操作按钮 | 锁定板块信息实时展示 + 候选池摘要 + 工作流引导 |

### 核心操作流程

```
操盘手 9:25 竞价结束后进入此 Tab:

 步骤1 → 竞价意图全景自动加载             → 判断今天偏抢筹还是偏出货
 步骤2 → 查看一字定方向 + 板块共振          → 锁定 2-3 个强势板块
 步骤3 → 切换到 [竞价选股] 子Tab           → 运行 leader_auction V4.3
 步骤4 → 在结果中勾选 3-5 只               → 点击 [加入候选池]
 步骤5 → 切换到 [竞价选债] 子Tab           → 运行 cb_auction V1.0
 步骤6 → 勾选转债 → 加入候选池
 步骤7 → 点击板块卡片 [🔒锁定板块→信号扫描] → 跳转到 2.3 信号扫描，矩阵自动筛选该板块
```

```typescript
interface AuctionAnalysisState {
  // SubTab 激活状态
  activeSubTab: 'intent' | 'stock-pick' | 'bond-pick'

  // ===== 竞价意图 (复用 1.2 数据结构) =====
  intentResults: AuctionIntentItem[]
  sectorData: SectorItem[]
  timelineData: TimelinePoint[] | null

  // 聚合
  overview: IntentOverview
  topBullish: AuctionIntentItem[]
  topBearish: AuctionIntentItem[]

  // ===== 竞价选股 (leader_auction V4.3) =====
  stockPicks: StockAuctionPick[]
  stockPickEngineStatus: EngineStatus | null
  stockPicksLoading: boolean
  stockPicksError: string | null

  // ===== 竞价选债 (cb_auction V1.0) =====
  bondPicks: BondAuctionPick[]
  bondPickEngineStatus: EngineStatus | null
  bondPicksLoading: boolean
  bondPicksError: string | null

  // ===== UI 状态 =====
  selectedStock: AuctionIntentItem | null
  loading: boolean
  error: string | null
  lastRefresh: string
  intentFilter: string | null

  // 勾选状态
  checkedIntentStocks: string[]           // code[]
  checkedStockPicks: string[]             // code[]
  checkedBondPicks: string[]              // cb_code[]

  // 公告风险
  riskAnnouncements: RiskAnnouncement[]

### 5.1 页面初始化数据流

```
AuctionAnalysisTab mount (timeSlot === 'auction' | 'intraday')

├── Step 3: 竞价选债引擎 (懒加载，仅当 SubTab 首次激活)
│   └── POST /api/v1/dashboard/run-auction-modes

```

│   │   └── 失败 → 显示错误 + [🔄 重新运行]
│   └── 再次切换 → 显示缓存结果 (useRef)
│
└── activeSubTab === 'bond-pick'
    ├── 首次激活 → 触发 Step 3 (POST /run-auction-modes mode=cb_auction)
    └── 再次切换 → 显示缓存结果 (useRef)
```

### 5.3 数据缓存策略

```typescript
// useAuctionDataCache Hook
function useAuctionDataCache() {
  const stockPicksCache = useRef<StockAuctionPick[] | null>(null)
  const bondPicksCache = useRef<BondAuctionPick[] | null>(null)
  const intentCache = useRef<AuctionIntentItem[] | null>(null)

  // 竞价意图数据：10 分钟内不重复请求
  // 选股/选债结果：5 分钟内不重复请求
  // 手动 [🔄 重新运行] 时清除缓存

  const invalidateCache = (key: 'stock' | 'bond' | 'intent') => {
    switch (key) {
      case 'stock': stockPicksCache.current = null; break
      case 'bond': bondPicksCache.current = null; break
      case 'intent': intentCache.current = null; break
    }
  }

  return { stockPicksCache, bondPicksCache, intentCache, invalidateCache }
}
```

### 5.4 刷新策略

```
Tab 激活状态的刷新行为
│
├── SubTab = "竞价意图"

│   ├── 盘中 (09:35-15:00): 5min 轮询
│   └── 盘后/非交易时段: 停止轮询
│
├── SubTab = "竞价选股"
│   ├── 不自动轮询（引擎结果一次性）
│   └── 手动 [🔄 重新运行] 触发重新请求
│
└── SubTab = "竞价选债"

    └── 手动 [🔄 重新运行] 触发重新请求
```

### 6.2 加入候选池的规则

| 规则 | 说明 |
|---|---|
| **可重复来源** | 同一 code 可以从多个来源加入（竞价意图 + 选股引擎 + 信号扫描），权重累加 |
| **已入池标记** | 已在候选池的标的行显示灰色 + "已入池" Tag，复选框 disabled |
| **批量加入** | [全选] → [加入候选池] 批量加入，显示 Toast "已添加 N 只标的到候选池" |
| **风险排除** | 被 RiskAnnouncementBanner 标记为排除的标的，"已入池"自动改为"已排除"，不可加入 |
| **结果反馈** | 加入成功后，行状态变更为 `in_candidate_pool: true`，check box 转为 disabled |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 开盘决策：操盘手默认入口，输出私有 Candidate 与 DecisionContext。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共竞价/行情 + 私有候选池。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 实盘前必须进入方案与风控。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
