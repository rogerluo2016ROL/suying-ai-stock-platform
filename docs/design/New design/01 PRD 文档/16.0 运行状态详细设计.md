## 1. 页面定位

运行状态已从智能看板 Tab 迁出，作为独立页面属于**模型/系统管理**主题。定位为系统健康仪表盘，展示 12 微服务状态、51 调度任务、基础设施和数据新鲜度。

### 与数据更新的分工

| 维度 | 运行状态 (16.0) | 数据更新 (15.0) |
|---|---|---|
| 粒度 | 服务 + 基础设施 + 调度摘要 | 数据表详情 + 手动同步 |
| 操作 | 只读监控 | 触发同步 + 改配置 |
| 刷新 | 30s 主动探测 | 按需 + 同步时轮询 |
| 受众 | 三角色 | 三角色 |

### 三角色差异化

| 维度 | 管理员 | 操盘手 | 投资者 |
|---|---|---|---|
| 服务网格 | 12服务全展示(延迟ms) | 6核心服务(在线状态) | 不展示 |
| KPI | 6卡片全量 | 4卡片(服务/数据/调度/Redis) | 2卡片(系统OK/数据OK) |
| 调度时间线 | 全部51任务 | 最近6条 | 不展示 |
| 待处理事项 | 全部 | 仅交易相关 | 不展示 |
| 刷新间隔 | 30s | 60s | 手动 |
| 主动探测 | 全部12端点 | 6交易链路端点 | 不探测 |

## 4. 数据流

### 4.1 初始加载 + 主动探测

```
RuntimeStatus mount
│
├── 1. GET /api/v1/system/status
│   └── 后端聚合: 基础设施 + 调度摘要 + 数据新鲜度 + 交易日历
│
├── 2. 前端主动探测 12 × health endpoints
│   │   (admin: 12 / trader: 6 / investor: 跳过)
│   │   Promise.all + AbortSignal.timeout(3000)
│   │
│   └── 更新 ServiceGrid
│
├── 3. 定时刷新 (admin 30s / trader 60s / investor 手动)
│   ├── 主动探测: 每轮都跑
│   └── 后端聚合: 每 5 轮刷新一次
│
└── 4. 整体状态综合判定
    overall = servicesAllOnline && dbOk && redisOk && noFailedJobs
      ? 'healthy'
      : hasDownServices ? 'down' : 'degraded'
```

### 4.2 健康状态综合判定

```typescript
function computeOverallStatus(
  services: ServiceStatus[],
  infra: InfrastructureStatus,
  scheduler: SchedulerSummary,
  data: DataFreshnessSummary
): 'healthy' | 'degraded' | 'down' {

  const servicesDown = services.filter(s => !s.online).length
  const hasFailedJobs = scheduler.todayFailed > 0
  const dataIssues = data.totalTables - data.freshTables > 5

  if (servicesDown >= 3 || !infra.postgresql.online) return 'down'
  if (servicesDown > 0 || hasFailedJobs || dataIssues) return 'degraded'
  return 'healthy'
}
```

```typescript
const [role, setRole] = useState<UserRole>(currentUserRole)
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 运行状态：管理员全量监控，操盘手看交易相关摘要，个人看简化健康状态。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 平台运行数据。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 展示券商网关健康但不暴露凭证。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
