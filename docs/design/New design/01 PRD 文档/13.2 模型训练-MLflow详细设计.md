## 2. 核心数据结构

```typescript
interface MlflowExperiment {
  id: string
  name: string
  artifactLocation: string
  lifecycleStage: string
  runCount: number
}

interface MlflowRun {
  runId: string
  runName: string
  experimentId: string
  status: 'RUNNING' | 'FINISHED' | 'FAILED' | 'KILLED'
  startTime: string
  endTime: string | null
  metrics: Record<string, number>
  params: Record<string, string>
  tags: Record<string, string>
}

interface EpochMetric {
  epoch: number
  trainLoss: number
  valLoss: number
  trainAcc: number
  valAcc: number
  lr: number
}

interface MlflowExperimentState {
  experiments: MlflowExperiment[]
  selectedExperimentId: string | null
  runs: MlflowRun[]
  selectedRunId: string | null
  selectedRun: MlflowRun | null
  metricHistory: EpochMetric[]
  loading: boolean
}
```

## 3. 数据流

```
MlflowExperiments mount (admin guard)
├── GET /api/v1/training/mlflow/experiments
│   └── 默认选中第一个实验
├── 选中实验 → GET /api/v1/training/mlflow/experiments/{id}/runs
│   └── 默认选中最新 run
├── 选中 run → GET /api/v1/training/mlflow/runs/{runId}/metrics
│   └── 渲染 ECharts 曲线
├── GET /api/v1/training/mlflow/runs/{runId}/params
│   └── 渲染参数网格
└── GET /api/v1/training/mlflow/runs/{runId}/artifacts
    └── 渲染文件列表
```

> **MLflow 基线界定（收口决策）**：项目默认 `MLFLOW_MODE=mock`，training-service 返回内置模拟实验数据，上述 `/api/v1/training/mlflow/*` 端点在 mock 模式下行为一致（开箱可用，无外部依赖）；`real` 模式代理真实 MLflow（localhost:5000）。TopBar 的 `mlflowLink`「🔗 打开 MLflow Dashboard」在 mock 模式下隐藏或置灰。
>
> **角色映射（收口决策）**：admin guard 对应系统管理员/模型管理员 → RBAC `admin`；操盘手 → `internal_analyst`；个人投资者 → `user`；`external_analyst` → 外部只读。权限由服务端按 JWT 角色执行，前端禁止传 `X-User-Role` 等身份头。

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 模型训练：仅模型管理员/系统管理员可操作，训练资源、实验和产物要隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 管理域数据。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不触达券商。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
