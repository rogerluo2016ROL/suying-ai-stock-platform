## 3. 核心数据结构

```typescript
interface BacktestRunState {
  strategies: Strategy[]               // 可选策略列表
  selectedStrategyId: string
  selectedBenchmark: '000300.SH' | '000905.SH' | 'none'
  startDate: string
  endDate: string
  topN: number                         // 5-50
  feeRate: number                      // 0.0003
  slippage: number                     // 0.0001

  status: 'idle' | 'running' | 'completed' | 'failed'
  progress: number                     // 0-100
  estimatedTimeLeft: number            // 秒

  result: BacktestResult | null
}

interface Strategy {
  id: string
  name: string
  description: string
  category: 'trend' | 'mean_reversion' | 'momentum' | 'ml'
}
```

## 4. 数据流

```
BacktestRunPanel
│
├── 初始化
│   ├── useBacktest().loadStrategies() → GET /backtest/strategies
│   └── 设置默认参数: 最近1年 / 100万 / 0.03% / 0.01%
│
├── 用户操作: 点击 [▶️ 开始回测]
│   ├── 组装 BacktestParams
│   ├── POST /backtest/run → { backtestId, status: 'running' }
│   ├── 启动轮询: setInterval(pollProgress, 2000)
│   │   └── GET /backtest/{backtestId}/progress → { progress, status }
│   ├── 进度更新 → progress + 预计剩余时间
│   └── 状态 = 'completed' → 停止轮询
│       └── GET /backtest/{backtestId}/result → BacktestResult
│           ├── dailyPoints → EquityCurveChart
│           ├── metrics → MetricsGrid
│           ├── monthlyReturns → MonthlyHeatmap
│           └── trades → TradeDetails
│
└── 错误处理
    ├── 轮询失败: 重试 3 次 → showToast("回测失败，请重试")
    └── status = 'failed' → showToast("回测运行失败：" + errorMsg)
```

## 5. 实施顺序

1. ParamPanel 组件 → 参数表单 + 默认值
2. BacktestRunPanel 容器 → 状态管理 + API 调用
3. useBacktest hook → 策略加载 + 回测运行 + 轮询
4. EquityCurveChart → ECharts 权益曲线 (含回撤区域)
5. MetricsGrid → 8 项指标卡片
6. MonthlyHeatmap → ECharts 月度热力图
7. TradeDetails → 交易明细表格 + footer
8. 进度条 + 错误处理 + Toast

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 回测分析：回测引擎公共，参数、结果、报告默认私有。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共因子/行情 + 私有回测结果。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 复盘写回 Plan，不直接交易。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
