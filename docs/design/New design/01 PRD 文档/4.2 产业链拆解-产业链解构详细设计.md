## 2. TypeScript 数据结构

```typescript
// frontend/src/pages/supply-chain/types.ts

/** 产业链节点（树图/价值/竞争共用） */
interface ChainNode {
  id: string                              // e.g. "semi-equip-etch"
  name: string                            // display name
  parentId: string | null                 // null = root
  depth: number                           // 0 = root
  chokepointLevel: ChokepointLevel        // 🔴 / 🟡 / 🟢
  localizationRate: number                // 0-100 国产化率%
  children: ChainNode[]                   // 子树
  mappedCompanies: CompanyBrief[]         // 末端公司映射
  segmentMeta: SegmentMeta                // 环节元数据
}

type ChokepointLevel = 'primary' | 'secondary' | 'none'
// primary   = 🔴 一级卡脖子
// secondary = 🟡 二级卡脖子
// none      = 🟢 非卡脖子

interface SegmentMeta {
  grossMargin: number          // 毛利率 % (用于价值链)
  netMargin: number            // 净利率 %
  revenueShare: number         // 营收占比 %
  marketShare: number          // 市场份额 % (用于竞争格局)
  techBarrier: 1 | 2 | 3 | 4 | 5  // 技术壁垒星级
  cr5: number                  // CR5 集中度%
  patentCount: number          // 行业专利数
}

interface CompanyBrief {
  tsCode: string               // e.g. "688012.SH"
  name: string
  score: number                // 0-100
  marketCap: number            // 总市值（亿）
  tags: string[]               // ['龙头','国产替代','5nm']
  chokepointLevel: ChokepointLevel
}

/** 价值链段（用于横向柱状图） */
interface ValueChainSegment {
  segmentName: string
  grossMargin: number          // %
  netMargin: number            // %
  industryAvgGrossMargin: number
  representativeCompany: string
  chokepointLevel: ChokepointLevel
}

/** 竞争格局气泡（用于气泡图） */
interface CompetitiveNode {
  nodeName: string
  marketShare: number          // Y轴
  techBarrier: number          // X轴
  totalMarketCap: number       // 气泡大小
  companyCount: number
  chokepointLevel: ChokepointLevel
  top3Companies: string[]
}

/** 子Tab 枚举 */
type DecomposeSubTab = 'upstream' | 'value' | 'competition'

/** 跨板块上下文（板块1 → 板块2 输入） */
interface DecomposePhaseInput {
  currentIndustry: string           // 来自板块1行业映射
  conceptName: string               // Tushare 概念名
  stockCount: number                // 概念成分股数
  policyDirections: string[]        // 板块1解读出的方向
}
```

// 节点着色函数
function getChokepointColor(level: ChokepointLevel): string {
  switch (level) {
    case 'primary':   return '#e84749'  // 🔴 红色
    case 'secondary': return '#f5a623'  // 🟡 橙色
    case 'none':      return '#2ec27e'  // 🟢 绿色
  }
}

function getChokepointBgColor(level: ChokepointLevel): string {
  switch (level) {
    case 'primary':   return 'rgba(232,71,73,0.18)'
    case 'secondary': return 'rgba(245,166,35,0.15)'
    case 'none':      return 'rgba(46,194,126,0.12)'
  }
}

## 4. 交互流程

### 4.1 跨板块进入

```
板块1 [行业映射] 点击某一行 "→ 产业解构"
  │
  ├─ 写入 SupplyChainContext:
  │   activePhase = 2
  │   currentIndustry = "半导体设备"
  │   conceptName = "ths_半导体设备"
  │
  └─ ChainDecomposeTab mount:
      ├─ 读取上下文中的 currentIndustry
      ├─ GET /api/v1/supply-chain/chain-decompose?industry=半导体设备
      ├─ 解析返回的 ChainNode 树
      ├─ 渲染上游默认 Tab 树图
      └─ ContextBar 显示 "当前行业: 半导体设备 · 来自: 政策梳理"
```

### 4.2 子Tab 切换

```
用户点击 [价值链拆解]
  │
  ├─ setActiveSubTab('value')
  ├─ ChartPanel 切换为 ValueBarChart
  ├─ 使用同一份 ChainNode 数据计算 ValueChainSegment[]
  ├─ 右侧面板保留上次选中的节点（如有）
  └─ BottomBar 计数不变
```

### 4.3 节点点击 → 下钻

```
用户点击树图节点 "刻蚀设备"
  │
  ├─ ECharts click event params.name = "刻蚀设备"
  ├─ findChainNode(chainData, "刻蚀设备") → ChainNode
  ├─ setSelectedNode(chainNode)
  ├─ 右侧 NodeDetailCard 重新渲染:
  │   ├─ 环节名称: "刻蚀设备"
  │   ├─ 卡脖子标记: 🔴 一级卡脖子
  │   ├─ 国产化率: <5%（进度条 红色）
  │   ├─ 毛利率: 行业均值 45%
  │   ├─ CR5: 92%
  │   ├─ 技术壁垒: ★★★★★
  │   └─ 公司列表: [中微公司, 北方华创, 万业企业]
  └─ 如果是叶子节点 → ECharts 高亮该节点 + 触发展开
```

### 4.4 "仅看卡脖子" Toggle

```
用户开启 [仅看卡脖子] Switch
  │
  ├─ setFilterChokepoint(true)
  ├─ 递归过滤树 / 数组:
  │   filterNodes(nodes, ['primary', 'secondary'])
  ├─ 树图: 只显示 🔴 + 🟡 节点, 🟢 节点及其子树隐藏
  ├─ 气泡图: 只显示 🔴 + 🟡 气泡
  ├─ 价值链: 🟢 柱体变灰/虚线
  └─ 底部计数更新: "已识别 N 家卡脖子相关公司"
```

### 4.5 送入板块3

```
用户点击 [全部送入多维度分析 →]
  │
  ├─ 收集所有叶子节点/选中节点的 mappedCompanies
  ├─ 去重（按 tsCode）
  ├─ 写入 SupplyChainContext:
  │   decomposedCompanies = allCompanies (去重)
  │   activePhase = 3
  └─ 页面切换到 CompanyAnalysisTab
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 产业链拆解：公共产业链图谱与用户私有研究笔记分离，证据型标的进入候选池。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共图谱/政策 + 私有研究标注。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不直接交易，只输出 Candidate 证据。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
