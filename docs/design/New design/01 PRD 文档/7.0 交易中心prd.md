# PRD — 交易中心

- **Date**: 2026-06-27 | **Owner**: product-lead | **Status**: Draft

## 1. 定位

交易中心是**手动交易操作台**。下单、撤单、改单、持仓监控、账户总览、券商连接管理。

| 维度 | 操盘手 | 个人投资者 |
|---|---|---|
| **核心问题** | 单子下去了吗？成交了吗？仓位安全吗？ | 怎么买？买多少？我的持仓怎么样了？ |
| **操作** | 全部订单+持仓管理+快速下单 | 简化下单(从方案带入)+我的持仓 |
| **输入来源** | 方案管理[手动下单]跳转 → 自动带入标的 |

## 2. 与现有能力的对比

| 能力 | 现有 | 目标 |
|---|---|---|
| 下单 | ✅ 限价/市价 | ✅ 保留 + 方案带入自动填充 |
| 风控预检 | ✅ 6项（下单时检查） | ✅ 增加[预检]按钮（下单前独立检查） |
| 撤单 | ✅ 仅模拟盘 | ✅ 实盘也支持 |
| 改单 | ❌ | ✅ 新增（修改未成交订单的价格/数量） |
| 持仓管理 | ❌ UI缺失 | ✅ 新增持仓列表（浮盈/仓位/止损/操作） |
| 订单列表 | ✅ 基础 | ✅ 增强（筛选/排序/批量操作） |
| 账户总览 | ✅ KPI卡片 | ✅ 保留 + 四档周期筛选（今日/本周/本季/自定义） |
| 一键清仓 | ❌ | ✅ 新增（紧急情况，批量端点原子执行） |
| 券商连接管理 | ❌ | ✅ 新增（连接状态/模拟实盘切换/风控参数查看） |
| 条件单 | ❌ | 📋 留 Phase 2 |
| 盘口深度 | ❌ | ✅ 五档 P0；深度盘口（50/500档，按数据源能力降级）P1 |

## 5. 关键交互流程

### 从方案管理跳转

```
方案管理 → [📝 手动下单]
  │ URL: /trade-center?tab=order&plan=FU-20260627-01M&code=300750
  ▼
交易中心:
  自动填入: 代码300750、建议价218.50、建议仓位15%
  仓位%自动换算成股数（基于可用资金）
  用户只需: 确认价格/数量 → [🔍预检] → [确认下单]
```

### 改单流程

```
订单管理 → 点击待成交行的 [✏️改单]
  │ 弹出改单弹窗
  ▼
  可修改: 价格 / 数量
  [确认修改] → PUT /trade/order/{id}
  → 订单状态不变（待成交），价格/数量更新
```

### 一键清仓

```
持仓监控 → [一键清仓]
  │ 确认: "将以市价卖出全部6只持仓，预计回收约¥943,600"
  ▼
  POST /api/v1/trade/liquidate 批量清仓端点
  → 服务端逐只提交市价卖单，每笔经过风控闸门（原子执行 + 单次审计）
  → 结果汇总: 5只成功, 1只失败(持仓不足)
```

## 6. 操盘手 vs 个人投资者

| 子模块 | 操盘手 | 个人投资者 |
|---|---|---|
| 下单面板 | 完整 + 快速Chip选择 | 简化（方案带入为主） |
| 持仓监控 | 全部持仓 + 止损/加仓/减仓 | 仅"我的持仓" + 只读 |
| 订单管理 | 全部订单 + 改单/撤单/批量 | 仅今日订单 + 只读 |
| 账户总览 | 完整金额 + 盈亏曲线 | 金额打码 `¥***` |
| 券商管理 | 连接/断开/模拟实盘切换 + 风控参数查看 | 仅查看模式状态 |
| 一键清仓 | ✅ | 确认后可用 |
| 改单 | ✅ | ❌ |

> 角色映射：操盘手 = RBAC `internal_analyst`，个人投资者 = `user`，系统管理员 = `admin`。金额打码与数据过滤一律由服务端按 JWT 角色执行，前端禁止传 `X-User-Role` 等身份头。

## 7. 新增 API

| 端点 | 用途 |
|---|---|
| `PUT /api/v1/trade/order/{id}` | 改单（修改未成交订单价格/数量） |
| `POST /api/v1/trade/order/pre-check` | 独立风控预检（下单前检查） |
| `POST /api/v1/trade/liquidate` | 一键清仓（批量端点，原子执行 + 单次审计，待实现时验证） |
| `GET /api/v1/trade/pnl-history` | 盈亏历史曲线。四档周期：`?period=today\|week\|quarter` 或自定义 `?start=YYYY-MM-DD&end=YYYY-MM-DD`（默认近30日） |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易中心：账户、订单、持仓、成交全部按 tenant/account/user 隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 强私有交易数据。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | paper/QMT/多券商统一 BrokerAdapter。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
