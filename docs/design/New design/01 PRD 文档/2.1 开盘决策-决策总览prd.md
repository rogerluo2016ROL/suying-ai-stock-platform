## 1. 定位

决策总览是开盘决策的**首页 Tab**，操盘手 9:00 打开平台后的第一屏。回答五个问题：

| 顺序 | 问题 | 对应面板 | 数据来源 |
|---|---|---|---|
| Q1 | 昨晚发生了什么？ | 隔夜新闻速览 | stock_news / announcements / cctv_news |
| Q2 | 昨天市场怎么样？ | 昨日复盘 | daily_kline(t-1) / stk_limit(t-1) / 龙虎榜 |
| Q3 | 候选池准备好了吗？ | 候选池预加载 | 昨日 screening_snapshots / watchlist |
| Q4 | 今天能不能做？ | 情绪+风控 KPI | market_regime_v2 / circuit_breaker |
| Q5 | 做什么方向？ | 竞价预告 | 板块热度 / 竞价时间倒计时 |

## 3. 面板说明

### 3.1 隔夜新闻速览

| 信息 | 来源 | 操盘手价值 | 刷新 |
|---|---|---|---|
| 重大公告 | `announcements` 表 (昨日+今晨) | 识别立案调查/退市/ST 等一票否决事件 | 60s |
| 外盘表现 | Tushare 全球指数 / 手动配置 | A50期货/US市场 → A股开盘方向参考 | 5min |
| 舆情热词 | `stock_news` 表 NLP 关键词聚合 | 感知市场情绪焦点 | 60s |
| 新闻联播 | `cctv_news` 最近一期文字稿摘要 | 政策信号 | 日级 |

> 操盘手核心场景：看到"中芯国际立案调查"→ 立即从候选池预加载中剔除 → 避免竞价后踩雷。

### 3.2 昨日复盘

| 信息 | 来源 | 操盘手价值 |
|---|---|---|
| 市场涨跌比 | `daily_kline(t-1)` 聚合 | 判断昨日是普涨/普跌/分化 |
| 涨停/跌停统计 | `stk_limit(t-1)` | 市场攻击力 + 恐慌程度 |
| 昨日强势板块 TOP3 | `daily_kline(t-1)` 按 industry 聚合均涨幅 | 板块惯性可能延续到今天 |
| 昨日弱势板块 TOP3 | 同上 | 回避弱势板块 |
| 自选表现 | `watchlist` + `daily_kline(t-1)` | 我的股票昨天怎么样了 |

### 3.3 候选池预加载

从 `screening_snapshots` 表加载昨日盘后选股结果（bi_trend、leader_scalp、short、long 等），按策略分组展示。这是操盘手 9:00 看到的**初始候选池**——竞价后会被竞价分析和信号扫描的结果补充和修正。

候选池数据来自 `CandidatePoolManager`（与候选池 Tab 共享同一实例）：
- `CandidatePoolManager.addSource('screener', yesterdayPicks)` → 盘后选股结果
- `CandidatePoolManager.addSource('watchlist', watchlistCodes)` → 自选共振标记
- 竞价后 → 竞价分析 Tab 追加 `addSource('auction', auctionPicks)`
- 信号扫描后 → 信号扫描 Tab 追加 `addSource('signal', confirmedSignals)`

### 3.4 情绪+风控 KPI

复用市场情绪看板(1.1)的情绪指数 + 风控中心(独立)的熔断器状态。决策总览只展示摘要，详情点击跳转。

### 3.5 竞价倒计时

盘前时段显示"距竞价数据采集还剩 X 分钟"，倒计时到 09:25。用户可设置"竞价开始后自动切换到竞价分析 Tab"。

## 4. 时段感知

决策总览的展示内容随当前时段动态变化：

| 时段 | 显示 | 隐藏 |
|---|---|---|
| 盘前(09:00-09:25) | 竞价倒计时 + 隔夜新闻 + 昨日复盘 + 候选池预加载 + 情绪KPI | — |
| 竞价(09:25-09:30) | 情绪KPI + 竞价概况摘要 | 竞价倒计时 + 隔夜新闻折叠 |
| 盘中(09:30-15:00) | 情绪KPI + 信号密度 + 自选触发 + 执行摘要 | 竞价相关 |
| 盘后(15:00+) | 情绪KPI + 今日复盘(替代昨日复盘) + 下一调度倒计时 | 竞价相关 |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 开盘决策：操盘手默认入口，输出私有 Candidate 与 DecisionContext。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共竞价/行情 + 私有候选池。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 实盘前必须进入方案与风控。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
