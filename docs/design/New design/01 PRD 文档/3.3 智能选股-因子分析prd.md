## 1. Background

### 1.1 什么是因子分析

因子分析回答三个问题：

```
Q1: 哪个因子有效？
    → IC (信息系数) = 因子值 与 未来收益 的相关系数
    +0.05 = 有效正相关  ·  0.00 = 没用  ·  -0.03 = 反向有效

Q2: 有效但稳定吗？
    → ICIR (信息比率) = IC均值 / IC标准差
    > 1.0 = 稳定可靠  ·  < 0.5 = 时灵时不灵

Q3: 哪些因子在说同一件事？
    → 相关性矩阵
    动量 和 量能 r=0.85 → 冗余，留一个就行
```

### 1.2 数据流

```
选股运行 1000 只股票的历史数据
  │
  ├─ 提取每只股票的因子值 (OBV, WR, 量比, 动量, 质量...)
  ├─ 提取每只股票的未来收益 (T+1, T+5, T+20)
  │
  ▼
对每个因子:
  计算 因子值 与 未来收益 的相关系数 → IC
  滚动多期计算 → IC 均值 / IC 标准差 → ICIR
  统计正相关天数占比 → 命中率

对因子之间:
  计算两两相关性矩阵 → 哪些因子冗余

对因子效果:
  按因子值分 10 组 → 第1组收益 - 第10组收益 → 分层收益 (多空spread)
```

### 1.3 现有项目能力

速赢AI 已有完整的因子分析引擎，能力包括：

| 能力 | 位置 | 说明 |
|---|---|---|
| 单因子 IC 计算 | `calibration.py` `run_calibration()` | 对 1000 只股票计算因子 IC |
| 滚动窗口 IC/ICIR | `calibration.py:191-212` | 跨时间窗口 IC 均值/标准差/ICIR |
| 因子权重校准 | `calibration.py:204-212` | `w = abs(icir) * 0.08` |
| 命中率统计 | `supply_chain_ic.py:126` | 正相关天数占比 |
| 多窗口汇总 | `calibration.py:198` | 输出排名表 |
| 回测含 IC | `backtest/engine.py:181` | 回测结果含 `mean_ic/std_ic/icir` |

**缺失的前端能力**：
- IC 柱状图可视化（现有只在命令行输出）
- 相关性矩阵可视化（ECharts heatmap）
- 十分位分层收益分析
- 行业因子暴露

### 1.4 当前痛点

| 问题 | 表现 |
|---|---|
| 因子有效性未知 | 用户不知道最近哪个因子有效——IC 是正还是负？是否显著？ |
| 无因子相关性分析 | 多个因子可能高度相关（OBV 和量比 r=0.78），造成冗余 |
| 无行业因子暴露 | 不同行业对同一因子的敏感度不同（高 PE 在科技是常态，在银行是异常） |
| 调参无依据 | 用户想调整模型权重但不知道哪个因子该加/减 |

## 2. Goal & Non-Goals

**目标**：

- 研究哪个因子最近有效，指导模型调参和因子权重调整
- 提供单因子 IC/ICIR、因子相关性矩阵（ECharts heatmap）、因子收益率分层、行业因子暴露
- KPI：用户能在 30 秒内识别出最近 30 天最有效的 3 个因子和最无效的 3 个因子

**Non-Goals**：

- 不做因子挖掘/新因子构造（那是 Kronos 因子引擎的范畴）
- 不做因子回测信号生成（那是 backtest-service 的范畴）
- 不做全市场实时因子计算（本页面读取预计算的因子分析缓存）

## 3. 使用场景

### 场景 A：毕师傅 V13 的因子该调权重了

```
进入因子分析 → 选择模型 bi_trend_launch → 近 60 天
  │
  ├─ IC 柱状图:
  │   OBV趋势  IC=+0.062  ICIR=1.52  ← 有效且稳定 ✅
  │   WR超卖   IC=+0.038  ICIR=0.72  ← 有效但不稳定
  │   量比     IC=+0.051  ICIR=1.18  ← 有效 ✅
  │   波动率   IC=-0.028  ICIR=-0.85 ← 反向有效(低波=好)
  │   强动态   IC=+0.015  ICIR=0.31  ← 近期失效 ❌
  │
  ├─ 相关性矩阵:
  │   OBV趋势 ↔ 量比 = 0.78  ← 高度相关，冗余
  │
  └─ 决策:
      去掉"强动态"因子  (ICIR < 0.5)
      OBV 和 量比 只保留 OBV  (相关系数 > 0.7)
      → 回到模型管理，更新 bi_trend V14 的因子权重
```

### 场景 B：判断当前市场适合什么风格

```
进入因子分析 → 选择模型 short + long → 近 30 天
  │
  ├─ short 因子:
  │   动量 IC=+0.07  ← 动量有效 → 趋势市特征
  │   质量 IC=+0.01  ← 质量无效
  │
  ├─ long 因子:
  │   估值 IC=+0.01  ← 估值无效 → 不是价值市
  │   ROE  IC=+0.02  ← 基本面弱有效
  │
  └─ 决策:
      当前市场偏趋势驱动，减配价值因子权重
      建议短期增加 leader_scalp + bi_trend，减少 long 的仓位分配
```

### 场景 C：验证新因子是否值得加入模型

```
进入因子分析 → 自定义因子 → 输入 "涨停封单率" → 近 120 天
  │
  ├─ IC=+0.073, ICIR=1.65  ← 有效且稳定 ✅
  ├─ 与 OBV趋势 相关性 r=0.12  ← 低相关，信息不重叠 ✅
  ├─ 分层单调: D1=-1.2% → D10=+5.8% ← 区分度好 ✅
  │
  └─ 决策: 封单率值得加入 leader_scalp 因子体系
```

### 6.3 数据模型

```typescript
interface FactorIC {
  factorKey: string
  factorName: string
  category: string
  icMean: number
  icStd: number
  icir: number
  tStat: number
}

interface CorrelationMatrix {
  factors: string[]
  matrix: number[][]
}

interface FactorDecile {
  decile: number
  label: string
  cumReturn: number
  avgReturn: number
}

interface IndustryExposure {
  industry: string
  exposure: number           // 该行业在该因子上的均值（标准化后）
  rank: '偏高' | '中性' | '偏低'
}

interface FactorAnalysisState {
  days: number                    // 7 | 30 | 60 | 120
  selectedFactor: string          // 当前查看分层分析的因子
  icData: FactorIC[]
  correlationData: CorrelationMatrix | null
  decileData: FactorDecile[] | null
  loading: boolean
  error: string | null
}
```

## 7. Technical Constraints

- 前端: React 18 + TS 5.6 + Ant Design 5.22 + ECharts 6.1
- 路由: `/screener/factors`
- 后端: FastAPI + uvicorn，新增端点放入 `services/screener-service/app/routers/factors.py`
- IC/相关性预计算：在 `training-service` 的 APScheduler 中定时计算，写入 PG 缓存表 `factor_ic_cache`（表结构见详细设计 §6.2）；单因子 IC/ICIR 与 training-service 现有 `GET /api/v1/training/factors/ic`（`services/training-service/app/routes.py:1103`，返回 `ic_mean/ic_std/icir_mean/direction/rolling`）口径保持一致，实现时可复用其计算逻辑，避免两套 IC 算法
- API P95 ≤ 500ms（读缓存）
- 不引入新 npm/Python 依赖
