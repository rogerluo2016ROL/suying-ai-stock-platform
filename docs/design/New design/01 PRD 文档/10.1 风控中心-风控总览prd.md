- **Date**: 2026-06-27 | **Owner**: product-lead | **Status**: Draft
- **父级 PRD**: `10.0 风控中心prd.md`

## 1. 定位

风控总览是风控中心的**首页/默认 Tab**。回答核心问题：**"系统边界还在吗？"** 从四层防御视角，自上而下呈现熔断器 → 防御层 → KPI → 告警的信息层次。

| 维度 | 操盘手 | 个人投资者 |
|---|---|---|
| **核心问题** | 四层防御全部正常？哪个层有风险？ | 我的账户安全吗？ |
| **可见内容** | 熔断器 + 四层防御 + KPI + 最近告警 | 熔断器 + 简化 KPI |
| **操作** | 从告警跳转处理 | 仅查看 |

## 3. 四层防御定义

| 层级 | 名称 | 职责 | 检查项 |
|---|---|---|---|
| L1 | 交易前置 | 下单前风控校验 | 资金/仓位/涨跌停/集中度/频率/ST 共6项 |
| L2 | 策略执行 | 策略级风险控制 | 日亏损上限/单票上限/行业上限/策略状态 |
| L3 | 全局熔断 | 账户级兜底保护 | 日亏损阈值(5%)/周亏损阈值(10%)/连续亏损天数 |
| L4 | 市场环境 | 宏观环境判断 | 市场风向/波动率/流动性/黑天鹅信号 |

## 4. 交互

- 熔断器横幅：NORMAL 绿色、TRIGGERED 红色、HALF_OPEN 橙色
- 四层防御条：绿色满格=全部通过、黄色部分=有警告、红色=有阻断
- KPI 卡片：红色左边框=有风险、橙色=预警、绿色=正常
- 告警列表：点击跳转对应处理页面

## 5. AC

| ID | AC |
|---|---|
| AC-1 | 熔断器状态实时展示（正常/触发/半开），颜色正确 |
| AC-2 | 四层防御条状态正确反映每层检查项通过率 |
| AC-3 | KPI 数字实时反映风控统计数据 |
| AC-4 | 告警按时间倒序排列，区分危险/警告/信息三级 |
| AC-5 | 个人投资者看到简化版本（屏蔽金额+减少信息密度） |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 风控中心：规则分全局/租户/账户，RiskVerdict 按账户和上下文归档。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共规则 + 私有判定结果。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 所有实盘动作强制经过。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
