## 1. 总体架构

```text
Web / Mobile Web
  -> API Gateway
  -> Auth/RBAC/Tenant Context
  -> 业务微服务
     ├─ screener-service      公共模型 + 私有候选
     ├─ prediction-service    公共预测 + 私有任务
     ├─ strategy-service      私有 Plan / Strategy
     ├─ signal-service        公共信号 + 私有订阅
     ├─ trade-service         私有账户/订单/持仓 + BrokerAdapter
     ├─ backtest-service      公共引擎 + 私有回测
     ├─ training-service      管理员/模型管理员
     └─ data-service          公共数据同步
  -> PostgreSQL / Redis / Object Storage / Model Registry
  -> Broker Gateway
     ├─ PaperBroker
     ├─ XtquantQmtAdapter
     └─ FutureBrokerAdapter
```

关键变化：

- `tenant context` 成为所有服务的第一层依赖。
- 公共数据和私有数据分表或字段隔离。
- 交易服务从“单本地引擎”升级为“账户级 BrokerAdapter 路由”。
- 模型服务输出必须带版本、数据口径、可见范围和缓存策略。

## 2. 租户与账户模型

```typescript
interface Tenant {
  tenantId: string
  name: string
  planTier: 'free' | 'pro' | 'team' | 'enterprise'
  status: 'active' | 'suspended'
  limits: {
    users: number
    brokerAccounts: number
    strategies: number
    dailyModelCalls: number
  }
}

interface UserAccount {
  userId: string
  tenantId: string
  // 业务角色仅作语义描述，鉴权以 RBAC 4 角色为准，映射规则见
  // `0.1 总体方案收口设计.md` §5.1 角色映射表：
  // trader/risk_admin -> internal_analyst, investor -> user,
  // model_admin/sys_admin -> admin, external_analyst -> 外部只读
  role: 'trader' | 'investor' | 'risk_admin' | 'model_admin' | 'sys_admin'
  rbacRole: 'admin' | 'internal_analyst' | 'external_analyst' | 'user'
  permissions: string[]
  defaultTradeAccountId?: string
}

interface TradeAccount {
  accountId: string
  tenantId: string
  ownerUserId: string
  brokerAdapter: 'paper' | 'xtquant_qmt' | 'broker_rest'
  mode: 'paper' | 'live'
  accountMasked: string
  status: 'connected' | 'degraded' | 'disconnected'
}
```

建议新增字段：

| 字段 | 所在对象 | 用途 |
|---|---|---|
| `tenantId` | 私有业务对象 | 租户隔离 |
| `ownerUserId` | Candidate/Plan/Strategy/Backtest | 个人归属 |
| `accountId` | Order/Position/RiskVerdict | 交易账户隔离 |
| `visibility` | Plan/Report/StrategyTemplate | 私有/租户共享/公共 |
| `dataScope` | 模型输出/回测结果 | public/user/tenant |

## 3. 数据存储分层

| 层 | 表/对象 | 隔离策略 |
|---|---|---|
| 公共基础层 | `stocks`, `daily_kline`, `industry`, `policy`, `model_versions` | 无 `tenantId`，只读共享 |
| 公共计算层 | 公共预测快照、因子评分、信号模板 | `dataScope='public'` |
| 私有决策层 | watchlist、Candidate、Plan、Strategy、Backtest | 必带 `tenantId/ownerUserId` |
| 私有交易层 | broker accounts、orders、positions、fills、risk verdicts | 必带 `tenantId/accountId` |
| 审计层 | login、permission、broker、order、risk、model publish | append-only，跨租户查询需权限 |

P0 可先用字段过滤；P1 引入 PostgreSQL RLS；P2 根据规模再拆库。

## 4. 服务改造点

| 服务 | 当前事实 | 改造方向 |
|---|---|---|
| backend/auth | 已有 JWT/RBAC，角色仍偏内部 | 增加 Tenant、Membership、Permission、套餐限制 |
| api-gateway | 已统一路由 | 注入 `X-Tenant-Id`、`X-User-Id`、`X-Service-Auth` |
| screener-service | 公共筛选能力较强 | 输出 Candidate 时写私有归属 |
| prediction-service | Kronos 预测端点 | 输出版本、口径、公共缓存和用户任务 |
| strategy-service | Plan/Strategy 仍以内存为主 | Plan/Strategy 持久化，带租户和账户 |
| trade-service | BrokerInterface/Xtquant 已有雏形 | 改为账户级 adapter registry + gateway health |
| backtest-service | 支持通用回测 | 支持按 Plan/contextId 回测并写回私有结果 |
| training-service | 管理类能力 | 仅模型管理员/系统管理员可访问 |
| data-service | 公共同步 | 增加数据质量 API 和页面级 freshness |

## 5. BrokerAdapter 架构

```typescript
interface BrokerAdapter {
  adapterId: string
  capabilities: Array<'stock_cn' | 'paper' | 'live' | 'cancel' | 'position' | 'asset' | 'callback'>
  connect(account: BrokerAccountConfig): BrokerConnection
  preflight(order: OrderDraft): BrokerPreflight
  placeOrder(order: OrderDraft): OrderResult
  cancelOrder(orderId: string): CancelResult
  queryAccount(accountId: string): AccountSnapshot
  queryPositions(accountId: string): Position[]
  queryOrders(accountId: string): Order[]
}
```

QMT 云端部署建议：

```text
Cloud trade-service
  -> secure tunnel / private network
  -> Windows Broker Gateway
     -> QMT / miniQMT
     -> xtquant SDK
```

安全规则：

- 用户券商凭证加密存储，前端永不返回明文。
- QMT 路径、session、资金账号只存在 broker gateway。
- 云端 trade-service 只拿账户健康、持仓、订单回报。
- 网关断连时，实盘按钮禁用，模拟盘不受影响。

## 6. 权限矩阵

> **注（2026-08-06 收口）**：本矩阵的 5 角色为业务语义角色，权限判定统一按 `0.1 总体方案收口设计.md` §5.1「角色映射表」映射到项目实际 RBAC 4 角色（`admin / internal_analyst / external_analyst / user`）执行：trader / risk_admin → `internal_analyst`，investor → `user`，model_admin / sys_admin → `admin`，external_analyst → 外部只读。金额打码与数据过滤一律服务端按 JWT 角色执行，前端禁止传 `X-User-Role` 等身份头（见 0.1 §5.2）。

| 能力 | trader | investor | risk_admin | model_admin | sys_admin |
|---|---|---|---|---|---|
| 公共行情/预测 | 读 | 读 | 读 | 读 | 读 |
| 私有候选/方案 | 本人/授权 | 本人 | 只读审计 | 不可 | 全租户 |
| 模拟下单 | 可 | 可 | 不可 | 不可 | 可 |
| 实盘下单 | 可，需账户授权 | 可选，强复核 | 不可 | 不可 | 可 |
| 策略启停 | 可 | 不可 | 可暂停 | 不可 | 可 |
| 风控规则 | 申请 | 不可 | 租户级配置 | 不可 | 全局配置 |
| 模型训练/注册 | 不可 | 不可 | 不可 | 可 | 可 |
| 数据同步/运行状态 | 摘要 | 简化 | 摘要 | 摘要 | 全量 |

## 7. 云端部署基线

P0 云端形态：

- 前端：静态资源部署，API 走 HTTPS。
- 后端：Docker Compose 或单机容器编排。
- 数据库：PostgreSQL 15+，Redis 7。
- 文件：模型、报告、导出文件进入对象存储或挂载卷。
- 交易网关：QMT 需要 Windows 节点，和云端通过专线/VPN/隧道连接。
- 观测：服务健康、调度、模型任务、券商连接、下单延迟、拒单率。

P1 扩展：

- K8s 部署、独立 worker、RLS、Prometheus/Grafana、集中日志。
- 租户套餐、额度、限频、审计导出。

## 8. 下一步工程拆解

1. 后端迁移：Tenant/UserMembership/BrokerAccount/PrivateObjectOwnership。
2. API 契约：所有列表接口增加 dataScope 和权限过滤。
3. 前端：角色化导航、页面密度、数据域标识。
4. 交易：BrokerAdapter registry、QMT gateway、模拟盘保持默认。
5. 模型：公共缓存 + 私有任务 + 模型版本显示。
6. 验收：跨租户不可见、实盘不可绕过风控、审计不可修改。
