## 3. 核心数据结构

```typescript
interface MonitorState {
  selectedStrategyId: string | null
  strategy: Strategy | null
  navHistory: NavPoint[]
  drawdownHistory: DrawdownPoint[]
  positions: StrategyPosition[]
  todayTrades: TodayTrade[]
  kpi: MonitorKPI
  pollingTimer: number | null
  showSettlement: boolean
}

interface MonitorKPI {
  nav: number                       // 当前净值
  initialCapital: number            // 初始资金
  dailyPnl: number                  // 今日盈亏金额
  dailyPnlPct: number               // 今日盈亏%
  cumReturn: number                 // 累计收益率
  cumReturnPct: number              // 累计收益率%
  maxDrawdown: number               // 最大回撤%
  maxDrawdownDate: string           // 最大回撤日期
}

interface DrawdownPoint {
  date: string
  drawdown: number                  // 负值, -0.01 = -1%
}

interface TodayTrade {
  time: string                      // "10:15"
  direction: 'buy' | 'sell'
  tsCode: string
  name: string
  qty: number
  price: number
  status: 'filled' | 'pending' | 'rejected'
}

interface NavPoint {
  date: string                      // "2026-06-01"
  nav: number                       // 1.000
  dailyReturn: number
  cumReturn: number
  benchmarkReturn?: number
}
```

### 3.1 回撤计算

```typescript
function computeDrawdown(navHistory: NavPoint[]): DrawdownPoint[] {
  let maxNav = navHistory[0]?.nav ?? 1
  return navHistory.map(p => {
    maxNav = Math.max(maxNav, p.nav)
    return {
      date: p.date,
      drawdown: (p.nav - maxNav) / maxNav
    }
  })
}
```

### 3.2 轮询机制

```typescript
function useMonitorPolling(strategyId: string | null) {
  const [data, setData] = useState<MonitorData>(null)

  useEffect(() => {
    if (!strategyId) return

    const fetchData = async () => {
      const [nav, positions, trades] = await Promise.all([
        fetch(`/strategy/auto/${strategyId}/nav`).then(r => r.json()),
        fetch(`/strategy/auto/${strategyId}/positions`).then(r => r.json()),
        fetch(`/strategy/auto/${strategyId}/trades/today`).then(r => r.json()),
      ])
      setData({ nav, positions, trades, drawdown: computeDrawdown(nav) })
    }

    fetchData()
    const timer = setInterval(fetchData, 30000)
    return () => clearInterval(timer)
  }, [strategyId])

  return data
}
```

## 4. 数据流

```
StrategyMonitor mount
  │
  ├── 获取策略列表 → GET /strategy?status=running,paused
  │   └── 默认选中第一个活跃策略
  │
  ├── 加载监控数据 (并行)
  │   ├── GET /strategy/auto/{id}/nav → navHistory[] + drawdown[]
  │   ├── GET /strategy/auto/{id}/positions → StrategyPosition[]
  │   └── GET /strategy/auto/{id}/trades?today=1 → TodayTrade[]
  │
  ├── 计算派生数据
  │   ├── drawdownHistory = computeDrawdown(navHistory)
  │   └── kpi = aggregate(positions, navHistory)
  │
  ├── 30s 轮询 (setInterval)
  │   └── 重新请求全部 3 个接口 → 增量更新
  │
  ├── [⏸️ 暂停] → POST /strategy/auto/{id}/pause → 更新状态
  ├── [▶️ 恢复] → POST /strategy/auto/{id}/resume → 更新状态
  ├── [⚙️ 调整参数] → 跳转 8.2 strategy-config-preview.html?id={id}
  └── [🏁 结算] → 确认 → POST /strategy/auto/{id}/settle
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 量化交易：策略模板可公共，策略实例、参数和运行日志必须私有隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共模板 + 私有策略实例。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 自动执行绑定账户并经过 RiskGate。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
