## 2. 核心数据结构

### 2.1 TypeScript 类型

```typescript
interface PlanCompareMetric {
  label: string                   // "总盈亏"
  valueA: number
  valueB: number
  unit: string                   // "元" | "%" | "天" | "只" | ""
  format: 'money' | 'percent' | 'count' | 'ratio'
  higherIsBetter: boolean        // true: 值越大越好; false: 回撤越小越好
}

interface PlanCompareData {
  planA: PlanBrief
  planB: PlanBrief
  metrics: PlanCompareMetric[]
  dailyReturnsA: DailyReturn[]
  dailyReturnsB: DailyReturn[]
  overlappingStocks: OverlapStock[]
  winner: 'A' | 'B' | 'tie'
}

interface PlanBrief {
  id: string
  name: string
  status: PlanStatus
  totalPnl: number
  totalPnlAmount: number
  winRate: number
  winCount: number
  totalCount: number
  maxDrawdown: number
  holdingDays: number
  stockCount: number
  sharpeRatio: number
}

interface DailyReturn {
  date: string                   // "06-20"
  cumulativeReturn: number       // 0.032 = +3.2%
}

interface OverlapStock {
  tsCode: string                 // "300750.SZ"
  name: string                   // "宁德时代"
  allocA: number                 // 15%
  allocB: number                 // 12%
}
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 方案管理：Plan 是私有交易意图承载对象，可授权共享但默认仅本人可见。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 私有 Plan + 公共模型引用。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | Plan 启动前必须绑定账户/模式。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
