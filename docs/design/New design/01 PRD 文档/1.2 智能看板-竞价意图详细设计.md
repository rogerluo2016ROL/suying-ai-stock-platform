## 4. 数据结构定义

### 4.1 页面状态 (useState)

```typescript
interface AuctionDashboardState {
  // 数据
  intentResults: AuctionIntentItem[]          // 来自 /signal/auction-intent
  sectorData: SectorItem[]                     // 来自 /dashboard/auction
  timelineData: TimelinePoint[] | null         // 来自 /signal/auction-timeline (按需)
  
  // 聚合
  overview: IntentOverview                     // 6 个意图计数
  topBullish: AuctionIntentItem[]              // 抢筹 TOP 10
  topBearish: AuctionIntentItem[]              // 出货 TOP 10
  
  // UI 状态
  selectedStock: AuctionIntentItem | null      // 当前选中个股
  loading: boolean
  error: string | null
  lastRefresh: string
  intentFilter: string | null                  // 明细表意图筛选
}

interface IntentOverview {
  total: number
  strongBullish: number    // score >= 75
  mildBullish: number      // 60 <= score < 75
  neutral: number          // 40 <= score < 60
  mildBearish: number      // 25 <= score < 40
  strongBearish: number    // score < 25
}

interface SectorItem {
  name: string                              // 板块名
  count: number                             // 竞价标的数
  avgChgPct?: number                        // 均价涨幅（需后端补充）
  heatPercent: number                       // count/maxCount * 100
}
```

### 4.2 复用已有类型

```typescript
// 来自 Dashboard.tsx 已有定义，提取为共享类型文件
interface AuctionIntentItem {
  code: string
  name: string
  auction_price: number
  prev_close: number
  chg_pct: number
  vs_vwap: number
  vol_ratio: number
  open_gap: number
  vol: number
  amount: number
  intent: string        // "强烈抢筹" | "偏多抢筹" | "中性" | "偏空出货" | "强烈出货"
  icon: string          // "🔥" | "📈" | "➖" | "📉" | "⚠️"
  level: string         // "bullish" | "neutral" | "bearish"
  score: number
  reasons: string[]
  breakdown: {
    price_direction: number      // 0-40
    buy_sell_pressure: number    // 0-25
    auction_strength: number     // 0-20
    opening_continuity: number   // 0-15
  }
}

interface TimelinePoint {
  time: string           // "09:15" ~ "09:25"
  price: number          // 撮合价
  volume: number         // 匹配量
  unmatchedBuy: number   // 买一未匹配量
  unmatchedSell: number  // 卖一未匹配量
}
```

## 6. 数据流与 API 调用

```
页面加载 (useEffect [])
│
├── Promise.all([
│     GET /api/v1/signal/auction-intent?limit=200    ← signal-service
│     GET /api/v1/dashboard/auction?date=YYYY-MM-DD  ← screener-service
│   ])
│   │
│   ├── intentResults → 聚合 IntentOverview + 拆分 topBullish/topBearish
│   │   ├── filter(level==='bullish').sort(score desc).slice(0,10) → topBullish
│   │   └── filter(level==='bearish').sort(score asc).slice(0,10)  → topBearish
│   │
│   └── sectorData → SectorHeat 渲染
│
├── 自动刷新定时器 (竞价时段 9:25-9:35 每 30s 轮询)
│   └── setInterval → Promise.all([...])
│
└── 选中个股 → 按需加载分时线
    └── GET /api/v1/signal/auction-timeline?code={code}&trade_date={date}
        │
        ├── 成功 → 渲染 TimelineChart
        └── 失败/空 → 降级显示 Empty 提示 + stk_mins 首根K线近似
```

### 性能优化

- `auction-intent?limit=200` 已在 `/dashboard-summary` 中缓存计算结果，端点独立调用时建议 signal-service 内部加 60s 缓存
- 分时线端点 `auction-timeline` 按需加载（仅在用户选中个股后请求），避免首屏阻塞
- 板块热度 sectors 数据量小（≤8条），与 `auction-intent` 并行请求
- 表格虚拟滚动：全量 200 行用 Ant Design Table 内置分页即可，不需要 `react-window`

## 7. 交互规范

### 7.1 选中-联动机制

| 触发 | 联动目标 | 行为 |
|---|---|---|
| 点击抢筹 TOP 行 | 个股信息卡 + 雷达图 + 走势图 | 更新 `selectedStock`，雷达图重绘，走势图按需加载 |
| 点击出货 TOP 行 | 同上 | 同上 |
| 点击全量明细表行 | 同上 | 同上（表行高亮 + `aria-pressed="true"`） |
| 点击板块卡片 | 全量明细表 | 按板块名筛选明细表 |

### 7.2 状态处理

| 状态 | 处理 |
|---|---|
| **加载中** | 刷新按钮 `aria-busy="true"` + Spin 覆盖图表区域，概览行保留骨架屏 |
| **空态 (无数据)** | 全页 Empty 组件 "今日暂无竞价数据，请确认是否为交易日"，保留顶部上下文条 |
| **错误态** | 对应区域显示 Alert "数据加载失败" + 重试 Button，不影响其他已加载区域 |
| **分时线无数据** | 走势图区域降级为 Empty + 文字 "暂无分时数据，展示竞价结果快照"，显示竞价价/昨收/涨幅 |
| **非交易时段** | 正常展示最近交易日数据，顶部条提示 "数据显示 2026-06-25 竞价结果" |

### 7.3 键盘与可访问性

- 表格行：Tab 导航，Enter 选中，`role="row"` + `aria-selected`
- 刷新按钮：`aria-label="刷新竞价数据"` + `aria-busy`
- 板块卡片：`role="button"` + `tabindex="0"` + `onKeyDown Enter` 触发筛选
- 雷达图/走势图：提供表格形式的文字替代数据（`sr-only` 区域）
- 意图筛选下拉：`aria-label="按意图筛选"`

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 智能看板：三角色首页：操盘手看交易机会，个人投资者看自选解释，管理员看平台健康。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共行情/信号 + 私有自选/提醒。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 券商状态只做摘要提示。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
