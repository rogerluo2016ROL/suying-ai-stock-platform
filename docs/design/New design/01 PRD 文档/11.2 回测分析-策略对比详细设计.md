## 3. 核心数据结构

```typescript
interface CompareState {
  strategies: Strategy[]               // 可选策略列表
  checkedIds: string[]                 // 已选中策略 ID (2-4)
  benchmark: string                    // 基准指数
  startDate: string
  endDate: string

  status: 'idle' | 'running' | 'completed' | 'failed'
  result: CompareResult | null
}

interface CompareResult {
  strategies: StrategyCompareItem[]
  benchmark: BenchmarkCompareItem
}

interface StrategyCompareItem {
  strategyId: string
  strategyName: string
  color: string                        // ECharts 颜色
  dailyPoints: DailyPoint[]
  metrics: {
    annualReturnPct: number
    maxDrawdownPct: number
    sharpeRatio: number
    winRate: number
    calmarRatio: number
    totalTrades: number
  }
}

interface BenchmarkCompareItem {
  name: string
  annualReturnPct: number
  maxDrawdownPct: number
  dailyPoints: { date: string; cumReturn: number }[]
}
```

## 4. 数据流

```
StrategyComparePanel
│
├── 初始化
│   ├── useCompare().loadStrategies() → GET /backtest/strategies
│   └── 默认选中前 2 个策略
│
├── 用户操作: 勾选/取消策略
│   ├── checkedIds.length < 2 → 禁用 [运行对比]
│   ├── checkedIds.length > 4 → 禁止继续勾选
│   └── 更新颜色分配 (按选中顺序)
│
├── 用户操作: 点击 [▶️ 运行对比]
│   ├── 组装请求: { strategyIds, benchmark, startDate, endDate }
│   ├── POST /backtest/compare → { compareId, status: 'running' }
│   ├── 轮询 progress → 完成
│   └── GET /backtest/compare/{compareId} → CompareResult
│       ├── strategies[] → CompareChart + CompareTable
│       └── benchmark → 基准线 + 基准行
│
└── 指标高亮计算
    ├── 每列找最优值 (年化/Calmar/夏普/胜率/交易次数→max, 回撤→min)
    └── 标注 🥇 + best-cell CSS class
```

## 5. 高亮计算逻辑

```typescript
function computeBestValues(items: StrategyCompareItem[]): Record<string, string> {
  const best: Record<string, string> = {};

  const metricsToCompare = [
    { key: 'annualReturnPct', direction: 'max' },
    { key: 'maxDrawdownPct', direction: 'min' },
    { key: 'sharpeRatio', direction: 'max' },
    { key: 'winRate', direction: 'max' },
    { key: 'calmarRatio', direction: 'max' },
    { key: 'totalTrades', direction: 'max' },
  ];

  for (const { key, direction } of metricsToCompare) {
    const values = items.map(i => i.metrics[key]);
    const bestVal = direction === 'max' ? Math.max(...values) : Math.min(...values);
    const bestItem = items.find(i => i.metrics[key] === bestVal);
    if (bestItem) best[key] = bestItem.strategyId;
  }

  return best;
}
```

## 6. 实施顺序

1. StrategyChecks 组件 → 复选框 + 颜色预览 + 最少2个校验

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 回测分析：回测引擎公共，参数、结果、报告默认私有。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共因子/行情 + 私有回测结果。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 复盘写回 Plan，不直接交易。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
