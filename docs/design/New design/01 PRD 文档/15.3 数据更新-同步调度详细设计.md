## 1. 页面定位

同步调度是数据更新模块的**第三个 Tab**，**仅管理员可见**。管理自动同步的 Cron 表达式配置，展示调度任务状态、数据源健康、下次运行倒计时和同步历史。

> **角色映射（收口决策）**：管理员 → RBAC `admin`；操盘手 → `internal_analyst`；个人投资者 → `user`；`external_analyst` → 外部只读。Tab 可见性与写操作权限由服务端按 JWT 角色执行，前端禁止传 `X-User-Role` 等身份头。
>
> **调度任务数量口径（收口决策）**：文中调度任务为示例，实际任务清单以调度配置（`GET /api/v1/data-update/schedules`）返回为准，页面动态渲染。

## 3. 核心数据结构

```typescript
interface SyncScheduleState {
  // 配置
  config: ScheduleConfig
  configDirty: boolean

  // 数据源
  dataSources: DataSourceStatus[]

  // 调度列表
  schedules: ScheduleItem[]
  editingSchedule: ScheduleItem | null
  isAdding: boolean

  // 倒计时
  countdowns: CountdownItem[]

  // 历史
  history: SyncHistoryItem[]

  // UI
  loading: boolean
}

interface ScheduleItem {
  id: string
  cron: string                      // "0 18 * * 1-5"
  name: string                      // "全量日K同步"
  category: TableCategory | 'system'
  enabled: boolean
  nextRunAt: string | null          // "2026-06-26T18:00:00"
  lastRunAt: string | null
  lastResult: 'success' | 'failed' | 'skipped' | null
  tableCount: number                // 覆盖表数
  createdAt: string
  updatedAt: string
}

interface CountdownItem {
  scheduleId: string
  name: string
  nextRunAt: string
  remainingSeconds: number
  remainingText: string             // "1h 25m"
  urgency: 'normal' | 'soon' | 'imminent'  // >1h / ≤1h / ≤5min
}

interface ScheduleConfig {
  autoSyncEnabled: boolean
  fullSyncFrequency: 'daily' | 'twice_daily' | 'hourly' | 'custom'
  fullSyncTime: string              // "18:00"
  incrementalFrequency: '30min' | 'hourly' | 'daily' | 'off'
  retryStrategy: '3x5min' | '5x2min' | 'none'
}
```

## 4. 数据流

### 4.1 初始加载

```
SyncScheduleTab mount (仅 admin)
│
├── GET /api/v1/data-update/schedule
│   └── 全局配置 + 数据源状态
│
├── GET /api/v1/data-update/schedules
│   └── 全部调度任务列表
│
├── GET /api/v1/data-update/sync-history?limit=10
│   └── 最近 10 条同步历史
│
└── 5s 倒计时定时器 (仅前端计算, 不调 API)
    └── countdowns.forEach(c => c.remainingSeconds -= 5)
```

### 4.2 新建/编辑调度

```
[➕ 新建调度] / [✏️ 编辑] click
│
├── 展开 AddEditSchedulePanel 或弹窗
│
├── 填写: Cron / 名称 / 分类 / 启用
│
├── [保存]
│   ├── 新建: POST /api/v1/data-update/schedules
│   ├── 编辑: PUT /api/v1/data-update/schedules/{id}
│   │
│   └── Response → 刷新调度列表 + 重新计算倒计时
│
└── [取消] → 关闭面板
```

### 4.3 启停调度

```
Toggle Switch 切换
│
├── PUT /api/v1/data-update/schedules/{id}
│   Request: { enabled: true/false }
│
└── Done:
    ├── 启用 → 计算 nextRunAt + 恢复倒计时
    └── 禁用 → nextRunAt = null + 倒计时移除
```

### 4.4 删除调度

```
[🗑️] click → Popconfirm "确认删除调度 '全量日K同步'?"
│
├── DELETE /api/v1/data-update/schedules/{id}
│
└── Toast "调度已删除" + 刷新列表
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 数据更新：公共数据平台能力，普通用户只看简化新鲜度。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共数据质量。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不触达券商。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
