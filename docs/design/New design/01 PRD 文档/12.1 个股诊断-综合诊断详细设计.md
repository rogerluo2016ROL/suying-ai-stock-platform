## 1. 页面定位

综合诊断是 SubTab `overview` 对应的面板。使用 **14:10 双栏布局**（左宽右窄），以 ECharts 雷达图为视觉中心，右侧展示五维维度分解。

## 4. 关键价位横向条状图 (备选)

除 4 格卡片布局外，提供横向价位条状图作为备选展示：

```typescript
const LevelBar = ({ levels }: { levels: KeyLevels }) => (
  <div className="level-bar">
    <div className="level-track">
      {/* 止损线, 支撑位, 当前价, 阻力位, 目标价 从左到右 */}
      {['stopLoss', 'support', 'currentPrice', 'resistance', 'target'].map(key => {
        const price = levels[key]
        const pct = ((price - levels.currentPrice) / levels.currentPrice) * 100
        return (
          <div className="level-marker" key={key}
            style={{ left: `${50 + pct * 2}%` }}>
            <span className="level-price">{price}</span>
            <span className="level-label">{label}</span>
          </div>
        )
      })}
    </div>
  </div>
)
```

## 5. ECharts 雷达图配置

```typescript
function buildRadarOption(diagnosis: DiagnosisResult): EChartsOption {
  const { dimensions, stockName } = diagnosis

  return {
    radar: {
      center: ['50%', '52%'],
      radius: '65%',
      indicator: [
        { name: '技术面\n{weight}%', max: 100 },
        { name: '资金面\n{weight}%', max: 100 },
        { name: '基本面\n{weight}%', max: 100 },
        { name: 'AI预测\n{weight}%', max: 100 },
        { name: '情绪面\n{weight}%', max: 100 },
      ].map((d, i) => ({
        ...d,
        name: d.name.replace('{weight}', dimensions[i].weight * 100)
      })),
      axisName: { fontSize: 11, color: 'var(--fg-2)', fontWeight: 600 },
      splitArea: {
        areaStyle: {
          color: Array(5).fill(['rgba(61,139,255,.02)', 'rgba(61,139,255,.04)']).flat()
        }
      },
      axisLine: { lineStyle: { color: 'var(--border)' } },
      splitLine: { lineStyle: { color: 'var(--border)' } }
    },

    series: [{
      type: 'radar',
      data: [{
        name: stockName,
        value: dimensions.map(d => d.score),
        areaStyle: { color: 'rgba(61,139,255,0.15)' },
        lineStyle: { color: '#3d8bff', width: 2 },
        itemStyle: { color: '#3d8bff' },
        label: {
          show: true,
          formatter: (p: any) => p.value,
          fontSize: 10,
          fontFamily: 'var(--font-mono)',
          color: 'var(--fg)'
        }
      }]
    }],

    tooltip: {
      trigger: 'item',
      formatter: (p: any) => {
        const dim = dimensions[p.dataIndex]
        return `${dim.name}: ${p.value}分`
      }
    },

    backgroundColor: 'transparent'
  }
}
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 个股诊断：公共诊断模型与个人备注、报告、关注状态分离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共诊断 + 私有笔记/报告。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 诊断不构成直接下单指令。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
