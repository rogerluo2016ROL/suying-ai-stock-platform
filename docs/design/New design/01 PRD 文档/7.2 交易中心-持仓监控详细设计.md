## 1. 页面定位

持仓监控是交易中心**第二个 Tab**（SubTab key: `position`）。操盘手在此总览全部持仓的盈亏、仓位占比与距止损距离，并执行止损、减仓、一键清仓等操作。

## 3. 核心数据结构

```typescript
interface PositionRecord {
  tsCode: string
  name: string
  holdQty: number             // 持仓股数
  currentPrice: number        // 现价
  costPrice: number           // 成本价
  marketValue: number         // 市值 = holdQty × currentPrice
  pnl: number                 // 浮动盈亏金额
  pnlPct: number              // 浮动盈亏%
  allocationPct: number       // 仓位占比
  stopLoss: number | null     // 止损价
  stopDistancePct: number | null // 距止损%
  riskTag: 'safe' | 'warning' | 'danger'
}

type SortField = 'pnlPct' | 'allocationPct' | 'marketValue'
type SortDir = 'asc' | 'desc'

interface PositionKpiData {
  totalMarketValue: number
  totalPnL: number
  totalAllocationPct: number
  positionCount: number
}
```

### 3.1 风险标签计算

```typescript
function computeRiskTag(distancePct: number | null): PositionRecord['riskTag'] {
  if (distancePct === null) return 'safe'
  if (distancePct <= 1) return 'danger'
  if (distancePct <= 3) return 'warning'
  return 'safe'
}

function computeStopDistance(currentPrice: number, stopLoss: number | null): number | null {
  if (stopLoss === null) return null
  return ((currentPrice - stopLoss) / currentPrice) * 100
}
```

### 3.2 排序逻辑

```typescript
function sortPositions(
  positions: PositionRecord[],
  field: SortField,
  dir: SortDir
): PositionRecord[] {
  return [...positions].sort((a, b) => {
    const va = a[field]
    const vb = b[field]
    return dir === 'desc' ? vb - va : va - vb
  })
}
```

## 4. 数据流

```
PositionMonitor mount
  │
  ├── GET /trade/position
  │   └── 返回 positions[], totalMarketValue, totalPnL
  │
  ├── 计算 KPI (前端聚合)
  │   ├── totalMarketValue = Σ marketValue
  │   ├── totalPnL = Σ pnl
  │   ├── totalAllocationPct = Σ allocationPct
  │   └── positionCount = positions.length
  │
  ├── 计算风险标签
  │   └── 每行 stopDistancePct → riskTag
  │
  ├── 排序 (默认 pnlPct desc)
  │   └── 监听 sortField / sortDir 变化
  │
  └── 轮询: setInterval(30s) → GET /trade/position
```

### 4.1 一键清仓流程

```
1. 点击 [🔴 一键清仓]
2. 确认弹窗:
   "将以市价卖出全部 N 只持仓，预计回收约 ¥xxx,xxx · 确认继续？"
3. POST /api/v1/trade/liquidate (后端批量市价卖出全部持仓，原子事务+单次审计)
4. 前端跟踪每笔结果
5. Toast 汇总: "5只成功, 1只失败(持仓不足)"
6. 刷新持仓列表
```

### 4.2 批量止损流程

```
1. 点击 [🟠 批量止损]
2. 筛选 riskTag ∈ {danger, warning} 的持仓
3. 确认弹窗: "将对 M 只风险持仓挂止损单 · 止损价=现价×95% · 确认继续？"
4. POST /api/v1/trade/batch-stop-loss (后端批量限价卖出, price=stopLossPrice, qty=当前持仓)
5. Toast 汇总
6. 刷新持仓列表
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易中心：账户、订单、持仓、成交全部按 tenant/account/user 隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 强私有交易数据。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | paper/QMT/多券商统一 BrokerAdapter。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
