# PRD — 量化交易

- **Date**: 2026-06-27 | **Owner**: product-lead | **Status**: Draft

## 1. 定位

量化交易是**策略全生命周期管理台**。策略广场→创建→回测→部署→监控→优化。

| 维度 | 操盘手 | 个人投资者 |
|---|---|---|
| **核心问题** | 哪种策略适合当前市场？回测表现如何？跑起来后盈亏怎么样？ | 有没有适合我的策略？一键跟单可以吗？ |
| **操作** | 完整链路：创建→回测→部署→监控→调参 | 简化为"一键跟单"或浏览策略广场 |
| **技术门槛** | 可配置全部参数（risk_rules/position_rules/sell_conditions） | 不需要懂参数 |

## 2. 业务流程

```
策略广场 ──浏览──→ 选择策略 ──→ 策略详情(回测数据/因子/风险)
  │                    │
  │              ┌─────┼─────┐
  │              ▼     ▼     ▼
  │         [一键跟单] [自定义] [回测]
  │              │     │     │
  │              │     ▼     ▼
  │              │  配置参数  回测结果
  │              │     │     │
  │              │     └──┬──┘
  │              │        ▼
  │              └──→ [部署上线]
  │                    │
  │                    ▼
  │              策略监控(净值/持仓/日志/风险)
  │                    │
  │              ┌─────┼─────┐
  │              ▼     ▼     ▼
  │         [暂停] [调参] [结算]
  │
  └── 与各模块交互 ──────────────────────────
      方案管理(9) → 方案启动 → 量化交易执行
      交易中心(7) ← 策略下单 → 券商接口
      风控中心(10) ← 策略触发止损/熔断
      回测分析(11) → 策略回测验证
```

## 6. 操盘手 vs 个人投资者

| 子模块 | 操盘手 | 个人投资者 |
|---|---|---|
| 策略广场 | 全部策略+回测数据+自定义 | 前3个推荐策略+[一键跟单] |
| 策略配置 | 全部参数可编辑 | 不可见（一键跟单用预设） |
| 策略监控 | 完整净值+持仓+日志 | 简化：今日盈亏+持仓列表 |
| 策略日志 | 完整可筛选导出 | 折叠 |

## 6.1 策略来源与可见性

### 三个来源

| 来源 | 说明 | 可见性 |

| **方案转策略** | 方案管理 closed 方案 → 保存为模板 | 同上 |


## 6.2 回测数据

策略广场每张卡片展示的回测指标（年化/回撤/夏普/胜率）来自 `backtest_snapshots` 缓存表，不在广场加载时实时计算。

- 系统模板：训练服务每日定时回测 → 写入缓存
- 用户策略：部署前至少跑过一次回测 → 写入缓存
- 缓存过期：策略参数变更后标记为 stale，下次回测刷新

## 6.3 一键跟单

```
[🚀一键跟单] = 以系统策略为模板，自动创建一份用户私有副本 → 跳转 8.3 部署上线

1. POST /strategy/fork { template_id, auto_start: true }
2. 预设参数：继承模板的 risk_rules/position_rules
3. 用户只需输入：投入金额
4. 自动创建 → 自动部署 → 跳转策略监控
```

## 6.4 策略编码规则

每个策略自动生成唯一编码：`{来源}-{模型缩写}-V{版本号}`

| 字段 | 规则 | 示例 |
|---|---|---|
| 来源 | SYS=系统模板, USR=用户创建, FORK=一键跟单 | SYS, USR, FORK |
| 模型缩写 | 同方案编码规则 (LT/BS/FS/...) | LT, FS, GRID |
| 版本号 | V1起, 修改参数自动+1 | V1, V2 |

### Fork 链路追溯

```
SYS-LT-V1              ← 系统原始模板
  └── FORK-SYS-LT-V1   ← 用户A一键跟单 (编码保留父策略引用)
        └── USR-FS-V2  ← 用户A调参后另存为自定义 ← 与方案编码规则一致

版本升级: 修改参数(risk_rules等) → V1→V2
          修改选股模型 → 视为新策略, 重新编码
          一键跟单 → 生成新编码, parent字段记录来源
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 量化交易：策略模板可公共，策略实例、参数和运行日志必须私有隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共模板 + 私有策略实例。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 自动执行绑定账户并经过 RiskGate。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
