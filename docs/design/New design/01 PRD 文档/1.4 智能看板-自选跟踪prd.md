# PRD — 智能看板·自选跟踪

- **Date**: 2026-06-25
- **Owner**: product-lead
- **Status**: Draft
- **Estimated effort tier**: Medium（前端 Tab 面板 + 后端 3~4 个 CRUD 端点 + 1 个聚合端点）

## 1. Background

自选股是投资者最基础、最高频的使用场景。"我的自选"回答三个问题：**我关注的股票今天怎么样了？有没有新信号？需不需要操作？**

当前速赢AI的自选功能几乎不可用：

| 现有功能 | 位置 | 实际情况 |
|---|---|---|
| `watchlist` 表（PG + SQLite） | `init_postgres.sql:524-529` | 表存在，列: id/code/added_at/note |
| Dashboard "自选监控"卡片 | `Dashboard.tsx:527-564` | **不读 watchlist 表**，查的是 `stocks ORDER BY market_cap LIMIT 10` |
| ScreenerV2 "加入自选"按钮 | `ScreenerV2.tsx:124-129,403-406` | **桩代码**：只弹 toast，不调任何 API |
| CRUD API | — | **不存在**：无法增/删/查自选股 |

**用户痛点**：

1. 无法添加/删除自选股——`watchlist` 表是空壳
2. 选股结果无法一键加入自选跟踪——ScreenerV2 的按钮是假的
3. 无法看到自选股的聚合行情——没有"我的自选涨了还是跌了"的总览
4. 无法看到自选股的信号联动——哪些自选股触发了买卖信号？
5. 操盘手需要板块集中度分析，个人投资者需要简单的盈亏总览

## 2. Goal & Non-Goals

**目标**：

- 打通自选股全链路：ScreenerV2 加入自选 → 自选表 CRUD → 自选跟踪看板
- KPI：用户从选股到加入自选 < 2 次点击，打开自选跟踪 Tab 后 3 秒内判断自选池整体涨跌

**Non-Goals**：

- 不做自选股分组/多列表管理（V1 单列表）
- 不做价格预警（到价提醒，需 alert-service 集成）
- 不做自选股历史变动记录（谁在何时加入/移除）
- 不做自选股与持仓联动（自选 ≠ 持仓，虽然可以重叠）

## 3. User Stories

| ID | As a | I want to | So that |
|---|---|---|---|
| US-1 | 所有用户 | 在选股结果中一键加入自选 | 不需要手动输入代码添加 |
| US-2 | 所有用户 | 在自选跟踪 Tab 看到所有自选股的实时行情（现价/涨跌幅/5日迷你走势/市值） | 一眼掌握自选池整体状态 |
| US-3 | 所有用户 | 看到自选股的信号联动（哪些触发了强买/买入/减仓/卖出/拐点） | 快速知道哪些自选股值得进一步分析 |
| US-4 | 操盘手 | 看到自选池的行业分布和集中度提示 | 避免过度集中于单一板块 |
| US-5 | 操盘手 | 看到自选池的等权平均盈亏 + 每只贡献度 | 判断选股方向是否与市场一致 |
| US-6 | 个人投资者 | 看到简单的盈亏数字（整体涨了还是跌了）+ 最强/最弱 | 不需要动手算就知道今天表现 |
| US-7 | 所有用户 | 在自选列表中点击股票跳转诊断页 | 从跟踪到深度分析的无缝过渡 |
| US-8 | 所有用户 | 在自选列表中移除不再关注的股票 | 保持自选池聚焦 |

### 5.2 API 契约

#### 新增端点（自选 CRUD）

**`GET /api/v1/watchlist`**

- **用途**：获取当前用户的自选股列表
- **Response**：`{"codes": ["000001", "600519", ...], "count": 12}`
- **说明**：V1 无用户系统时，所有用户共享同一自选表。后续加 JWT 用户隔离

**`POST /api/v1/watchlist`**

- **用途**：批量添加自选股
- **Request**：`{"codes": ["000001", "600519"]}`
- **Response**：`{"added": 2, "skipped": 0, "errors": []}`
- **校验**：code 必须在 `stocks` 表中存在，不存在则 skip 并返回 errors
- **去重**：已存在的 code 不重复插入

**`DELETE /api/v1/watchlist?code=000001`**

- **用途**：移除单只自选股
- **Response**：`{"removed": true, "code": "000001"}`

**`GET /api/v1/watchlist/dashboard`**

- **用途**：自选跟踪看板聚合端点，一次返回行情+信号+板块聚合
- **Response (200)**：

### 5.3 数据模型

不新增表。复用现有 `watchlist` 表（PG `init_postgres.sql:524-529`）：

```sql
CREATE TABLE IF NOT EXISTS watchlist (
    id SERIAL PRIMARY KEY,
    code TEXT NOT NULL REFERENCES stocks(code),
    added_at TIMESTAMP DEFAULT NOW(),
    note TEXT
);
```

数据来源：

| 数据 | 来源 | 说明 |
|---|---|---|
| 自选股名单 | `watchlist` 表 | CRUD 端点直读 |
| 行情（现价/涨跌幅/量/额） | `daily_kline` 最新交易日 | JOIN `watchlist.code` |
| 市值/行业 | `stocks` 表 | JOIN `watchlist.code` |
| 信号级别/评分 | `signal-service /analyze/{code}` | 批量调用，建议后端聚合时内部缓存 |
| 止损线 | `diagnosis-service key_levels.stop_loss` 或策略 ATR | 取更严格的一个 |
| 5日走势 | `daily_kline` 最近 5 个交易日收盘价 | 轻量折线图数据 |

## 6. Technical Constraints

- 前端框架：React 18 + TypeScript 5.6 + Ant Design 5.22
- 页面实现：作为 `Dashboard.tsx` 的 Tab 面板（Tab key: `watchlist`），不创建独立路由
- 后端框架：FastAPI，新增端点放入 `backend/app/routers/watchlist.py`
- 设计系统：严格遵循 `docs/design/new front/design-spec.md` 及 `design-tokens.css`
- A 股涨跌色：`var(--up)` = 红涨, `var(--down)` = 绿跌
- 5日迷你走势：SVG `<polyline>` 轻量实现，不用 ECharts（避免 12 个 ECharts 实例性能问题）
- API P95 ≤ 500ms（`watchlist/dashboard` 聚合端点，含批量信号查询）
- V1 无用户隔离（`watchlist` 表无 `user_id` 列），后续版本加 JWT 用户绑定。当前所有登录用户共享同一自选表
