## 1. 页面定位

信号总览是信号系统的**首页/入口**。定位为"雷达屏"——用户打开页面后：
- 3 秒内形成对今日信号态势的判断（偏多/偏空/震荡）
- 10 秒内定位到最值得关注的板块
- 点击任意信号色块跳转个股诊断进行深度分析

与"信号深度分析看板"（后续独立 PRD）形成 **总览→深潜** 的两级信息架构。

### 5.2 信号级别颜色映射

```typescript
const SIGNAL_COLORS: Record<SignalLevel, string> = {
  STRONG_BUY:    '#ff4d4f',   // 强买=红, A股买入预期涨=红色
  BUY:           '#fa8c16',   // 买入=橙
  HOLD:          '#1677ff',   // 持有=蓝
  REDUCE:        '#faad14',   // 减仓=黄
  SELL:          '#8c8c8c',   // 卖出=灰
  TIMING_ALERT:  '#722ed1',   // 拐点=紫
}

// 矩阵色块的深浅映射 (score → opacity/lightness, 评分越高颜色越深)
function signalCellColor(level: SignalLevel, score: number): string {
  const base = SIGNAL_COLORS[level]
  // score 0-100 → lightness 90% to 45% (低分淡, 高分深)
  const lightness = 90 - (score / 100) * 45
  // 用 CSS hsl 或 rgba opacity 实现深浅
  // 简化: opacity = 0.3 + score/100 * 0.7
  const opacity = 0.3 + (score / 100) * 0.7
  return `${base}${Math.round(opacity * 255).toString(16).padStart(2, '0')}`
  // 或纯用 opacity: `rgba(r, g, b, ${opacity})`
}
```

### 5.3 矩阵数据转换

```typescript
// 将 signals[] 按 industry 分组, 每组按偏多程度排序
function buildMatrixRows(signals: SignalCellData[], filter: FilterMode): MatrixRow[] {
  const filtered = applyFilter(signals, filter)
  
  // 按行业分组
  const grouped = new Map<string, SignalCellData[]>()
  for (const s of filtered) {
    const ind = s.industry || '其他'
    if (!grouped.has(ind)) grouped.set(ind, [])
    grouped.get(ind)!.push(s)
  }
  
  // 每组内买入信号在前, 卖出在后
  for (const [_, cells] of grouped) {
    cells.sort((a, b) => {
      const order: SignalLevel[] = ['STRONG_BUY','BUY','TIMING_ALERT','HOLD','REDUCE','SELL']
      return order.indexOf(a.level) - order.indexOf(b.level)
    })
  }
  
  // 按偏多程度排序行 (强买+买入占比最高的排第一)
  const rows: MatrixRow[] = Array.from(grouped.entries()).map(([sector, cells]) => {
    const buyCount = cells.filter(c => c.level === 'STRONG_BUY' || c.level === 'BUY').length
    const sellCount = cells.filter(c => c.level === 'REDUCE' || c.level === 'SELL').length
    return {
      sector,
      cells,
      buyCount,
      sellCount,
      totalCount: cells.length,
      bullishRatio: cells.length > 0 ? buyCount / cells.length : 0,
    }
  })
  
  rows.sort((a, b) => b.bullishRatio - a.bullishRatio)
  return rows
}

interface MatrixRow {
  sector: string
  cells: SignalCellData[]
  buyCount: number
  sellCount: number
  totalCount: number
  bullishRatio: number
}
```

    axisLabel: { fontSize: 10, color: 'var(--fg-2)' },
    splitLine: { lineStyle: { color: 'var(--border)' } }
  },
  
  series: [{
    type: 'scatter',
    data: sectors.map(s => ({
      value: [s.buyCount + s.sellCount, s.avgScore, s.marketCap || 1e10],
      name: s.sector,
      itemStyle: {
        // buySellRatio 越大越偏绿, 越小越偏红
        color: (() => {
          const ratio = s.buySellRatio || 1
          if (ratio >= 3) return '#2ec27e'
          if (ratio >= 2) return '#52c41a'
          if (ratio >= 1) return 'var(--accent)'
          if (ratio >= 0.5) return '#fa8c16'
          return '#ff4d4f'
        })()
      }
    })),
    
    symbolSize: (val: number[]) => {
      const cap = val[2] as number
      return Math.max(20, Math.min(80, Math.sqrt(cap) / 1e8 * 25))
    },
    
    label: {
      show: true,
      formatter: '{b}',
      position: 'right',
      fontSize: 11,
      color: 'var(--fg-2)',
      fontFamily: 'var(--font-body)'
    },
    
    emphasis: {
      scale: 1.5,
      label: { fontSize: 13, fontWeight: 600 }
    }
  }],
  
  tooltip: {
    formatter: (params: any) => {
      const d = params.data
      const sectorName = d.name
      return `${sectorName}<br/>信号数: ${d.value[0]}只<br/>均分: ${d.value[1].toFixed(1)}<br/>市值: ${(d.value[2]/1e8).toFixed(0)}亿`
    }
  },
  
  backgroundColor: 'transparent'
}

## 7. 数据流与 API 调用

```
页面加载 (useEffect [])
│
├── Promise.all([
│     GET /api/v1/signal/market-scan?session=post        ← signal-service (新增)
│     GET /api/v1/signal/daily-stats?days=30             ← signal-service (新增)
│     GET /api/v1/signal/history?limit=20                ← signal-service (复用)
│   ])
│   │
│   ├── marketScan →
│   │   ├── signals[] → buildMatrixRows() → SignalMatrix 渲染
│   │   ├── signalDistribution → SignalOverviewCard 渲染
│   │   ├── sectorResonance → SignalOverviewCard 板块共振统计
│   │   └── topSignals[] → TopSignalsCard 渲染
│   │
│   ├── dailyStats → SignalTrendChart 渲染
│   │
│   └── history → LiveSignalStream 渲染
│
├── 自动刷新 (30s 轮询)
│   └── setInterval → GET /market-scan + GET /history
│       (趋势图不刷新, 日级别数据)
│
└── 悬浮 Tooltip (前端纯展示, 数据来自 marketScan.signals[])
    └── onMouseEnter → 从缓存数据中查找 code 对应的 components 展示
```

### 性能优化策略

| 策略 | 说明 |
|---|---|
| **后端预计算** | `market-scan` 读 `signal_snapshots` 缓存表，不实时计算六维评分 |
| **前端数据缓存** | `signals[]` 数据已在内存中，悬浮 Tooltip 直接查内存，不额外请求 |
| **矩阵虚拟化？不需要** | 600 个 9×9px div ≈ 极低渲染开销，原生 DOM 即可 |
| **趋势图采样** | 30 个点，不需要降采样 |
| **气泡图节流** | 板块数 ~30 个，气泡散点图渲染量可忽略 |

## 8. 交互规范

### 8.1 矩阵色块交互

| 事件 | 行为 |
|---|---|
| 鼠标悬浮 (hover) | 色块 scale(1.5) + 显示 Tooltip（代码/名称/涨跌幅/评分/六维分解）|
| 鼠标离开 | 色块恢复 + Tooltip 消失 |
| 点击 | `window.open('/diagnosis?code=' + code, '_blank')`，新标签页打开 |
| 键盘 Tab | 色块可聚焦，`role="button"`, `tabindex="0"`, `aria-label` 含代码+信号等级 |
| 键盘 Enter | 同点击行为 |

### 8.2 筛选器行为

| 筛选 | 矩阵变化 | 其他区域 |
|---|---|---|
| 全部信号 | 展示所有有信号股票 | 不变 |
| 仅买入 | 只显示 STRONG_BUY + BUY + TIMING_ALERT 的色块 | 不变 |
| 仅卖出 | 只显示 REDUCE + SELL 的色块 | 不变 |
| 仅拐点 | 只显示 TIMING_ALERT 的色块 | 不变 |
| 仅自选 | 只显示自选池中的信号股票 | 最强信号 TOP 8 同步筛选 |

### 8.3 状态处理

| 状态 | 处理方式 |
|---|---|
| **加载中** | 矩阵区域显示骨架屏（灰色方块占位），刷新按钮 `aria-busy="true"`，右侧面板显示 Spin |
| **空态 (无信号)** | 矩阵区域 + 概况卡片显示 Empty "今日暂无交易信号" + "请确认是否为交易日"，趋势图保留历史数据 |
| **部分错误** | 对应卡片显示 Alert "加载失败" + 重试按钮，其他区域不受影响 |
| **全页错误** | 矩阵 + 所有卡片显示 Alert + 重试按钮 |

### 8.4 键盘与可访问性

- 矩阵色块：`role="button"`, `tabindex="0"`, `aria-label="{code} {name} {level} {score}分"`
- 色块颜色辅以文字（Tooltip 中已含文字标签），满足"颜色不是唯一信息来源"规则
- 趋势图/气泡图：提供 `sr-only` 文字替代数据表格
- 筛选 Radio：`role="radiogroup"`, 每个选项 `aria-checked`
- 实时信号流：`role="log"`, `aria-live="polite"`（有新信号时播报）

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 智能看板：三角色首页：操盘手看交易机会，个人投资者看自选解释，管理员看平台健康。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共行情/信号 + 私有自选/提醒。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 券商状态只做摘要提示。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
