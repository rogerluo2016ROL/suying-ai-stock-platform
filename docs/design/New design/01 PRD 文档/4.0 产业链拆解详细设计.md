# 详细设计 — 产业链拆解·总体设计

> **关联 PRD**: `4.0 产业链拆解prd.md` | **Date**: 2026-06-27

## 1. 前端架构

```
App.tsx
└── <Route path="/supply-chain" element={<SupplyChainWorkbench />} />

SupplyChainWorkbench.tsx
├── TopBar (标题 + 操盘手/投资者 视角切换)
├── ProgressBar (● 政策梳理 → ○ 产业链解构 → ○ 多维度分析)
├── ContextBar (当前上下文: 已选方向/行业/候选公司数)
├── TabContent (根据 activePhase 渲染对应板块)
│   ├── Phase1: <PolicyAnalysisTab />
│   ├── Phase2: <ChainDecomposeTab />
│   └── Phase3: <CompanyAnalysisTab />
└── FooterBar (研究路径引导)
```

### 跨板块上下文 (React Context)

```typescript
interface SupplyChainContext {
  activePhase: 1 | 2 | 3
  viewMode: 'trader' | 'investor'    // 操盘手/投资者视角
  
  // 板块1 → 板块2
  policyDirections: PolicyDirection[]  // LLM解读出的方向
  mappedIndustries: MappedIndustry[]   // 映射后的行业+概念+成分股
  
  // 板块2 → 板块3
  decomposedCompanies: DecomposedCompany[]  // 下钻到的公司+卡脖子级别
  
  // 板块3 → 候选池
  selectedCompanies: string[]              // 用户勾选的公司代码
  
  // LLM模板
  savedTemplates: PolicyTemplate[]         // 已保存的政策解读模板
}
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 产业链拆解：公共产业链图谱与用户私有研究笔记分离，证据型标的进入候选池。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共图谱/政策 + 私有研究标注。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不直接交易，只输出 Candidate 证据。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
