# PRD — 交易信号·信号历史

- **Date**: 2026-06-27 | **Owner**: product-lead | **Status**: Draft
- **Estimated effort tier**: Small（前端 1 Tab + ECharts 折线图 + 后端历史查询端点）

## 1. Background

信号总览给出的是"此刻"的信号判断，但操盘手需要验证信号的**稳定性**和**历史准确率**：

- 今天评分 85 → 过去 30 天评分趋势是上升还是下降？
- STRONG_BUY 信号在过去一个月命中率如何？方向正确率多少？
- 当前评分是否处于历史极值（过热/恐慌）？

"信号历史"子模块解决此问题：展示 30 日评分变化趋势 + 同级别历史命中率。

## 2. Goal & Non-Goals

**目标**：
- 30 日信号评分趋势折线图，含等级阈值标注线
- 同级别（STRONG_BUY/BUY）历史命中率统计
- 支持时间区间拖拽缩放（DataZoom）

**Non-Goals**：
- 不做多股历史对比（属于信号扫描 + 多股对比的维度）
- 不做历史回测损益计算（属于 backtest-service）
- 不做分钟级评分回溯（评分引擎基于日线）

## 3. User Stories

| ID | As a | I want to | So that |
|---|---|---|---|
| US-1 | 操盘手 | 看到 30 日信号评分折线图，叠加 STRONG_BUY(80) / BUY(60) / SELL(40) 阈值线 | 快速判断当前评分在历史中的相对位置 |
| US-2 | 操盘手 | 拖拽 DataZoom 缩放到特定时间区间 | 聚焦近 7 天/近 14 天的信号变化趋势 |
| US-3 | 操盘手 | 看到 STRONG_BUY 和 BUY 两个级别的历史命中率 | 评估该信号对该股票的预测可靠性 |
| US-4 | 个人投资者 | 看到简化版趋势图（7 日） | 信息不超载 |

## 4. Acceptance Criteria

## 6. Technical Constraints

- 页面实现：作为 SignalDetailPage 的 Tab 面板（Tab key: `history`）
- ECharts 5.5 CDN
- 阈值线配色：STRONG_BUY(80)=红色虚线, BUY(60)=橙色虚线, SELL(40)=灰色虚线
- 数据来源：`GET /api/v1/signal/history?code={tsCode}&days=30`

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易信号：公共信号规则与用户私有订阅、处理状态分离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共信号 + 私有已读/订阅/处置。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 信号只作为订单依据之一。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
