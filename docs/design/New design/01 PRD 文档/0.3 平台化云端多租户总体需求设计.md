## 1. 改版目标

速赢AI 从单人/内部工具升级为可云端开放的多账户量化投资平台。所有需求、页面、接口和模型输出必须同时满足三类用户：

| 用户 | 核心目标 | 产品体验 |
|---|---|---|
| 操盘手 | 快速形成可执行交易方案，安全接入模拟/实盘账户 | 专业工作台、强上下文、强风控、低操作摩擦 |
| 个人投资者 | 看懂机会和风险，安全使用模拟盘或受限实盘 | 简化视图、解释优先、默认保护、少参数 |
| 系统管理员 | 管理租户、账号、券商通道、数据、模型和审计 | 全局控制台、权限治理、运行监控、合规审计 |

产品主张从“AI 工具集合”升级为：

```text
公共行情与模型能力 + 私有账户/方案/交易数据隔离 + 多券商执行通道 + 云端可运营后台
```

## 2. 数据域与隔离

未来云端部署后，每个账号都同时拥有公共数据和私有数据。页面和接口必须明确数据归属。

| 数据域 | 例子 | 归属 | 可见性 | 写入权限 |
|---|---|---|---|---|
| 公共市场数据 | 股票基础信息、行情、行业、财报、公告、政策、产业链图谱 | platform | 全账号可读 | 管理员/数据服务 |
| 公共模型输出 | Kronos 基础预测、公共因子评分、策略模板、模型版本 | platform | 按套餐/角色可读 | 模型管理员/系统 |
| 账户私有数据 | 自选股、候选池、方案、策略参数、回测配置 | tenant/user | 仅本人/同租户授权可见 | 用户本人/授权操盘手 |
| 交易私有数据 | 券商账户、委托、成交、持仓、资金、审单记录 | tenant/account | 强隔离，默认仅账户授权人可见 | 授权操盘手/用户 |
| 管理审计数据 | 登录、权限变更、券商连接、风控放行、模型发布 | platform/tenant | 管理员和审计角色可见 | 系统追加写 |

原则：

1. 公共数据可共享，私有决策和交易数据必须带 `tenantId/accountId/userId`。
2. API 查询默认只能返回当前身份可见的数据；管理员跨租户查询必须显式带审计原因。
3. 任何资金相关动作必须写入不可变审计日志。
4. 原型页必须显示“公共/私有/混合”数据域，避免用户误解数据归属。

## 3. 角色体验重构

### 3.1 操盘手视角

操盘手默认进入“交易决策工作台”。优先展示 P0 主链路：

```text
候选池 -> 方案管理 -> 下单面板 -> 风控闸门 -> 回测复盘
```

页面要求：

- 所有跳转保留 `DecisionContext`。
- 每个资金动作展示券商账户、交易模式、风控结论。
- 复杂参数默认展开；空态要给出可执行下一步。
- 实盘动作必须经过预检、确认、审计。

### 3.2 个人投资者视角

个人投资者默认进入“我的投资助理”。优先展示：

```text
自选跟踪 -> 个股诊断 -> AI 方案解释 -> 模拟交易 -> 风险提醒
```

页面要求：

- 隐藏模型训练、模型注册、全量数据表、系统运行细节。
- 投资建议必须配解释、风险、置信度和“不构成投资建议”提示。
- 默认模拟盘；实盘需开户/券商绑定/风险测评/二次确认。
- 不展示其他用户方案、订单、持仓、券商账户。

### 3.3 系统管理员视角

管理员默认进入“平台运营控制台”。优先展示：

```text
租户/用户 -> 权限/套餐 -> 数据服务 -> 模型服务 -> 券商通道 -> 审计与风控
```

页面要求：

- 支持查看平台公共数据质量和各租户服务状态。
- 支持配置角色权限、券商适配器、风控规则和模型发布。
- 所有跨租户操作必须记录原因、操作人、影响范围。

## 4. 云端开放需求

| 能力 | P0 | P1 | P2 |
|---|---|---|---|
| 多租户账号体系 | `tenantId/accountId/userId` 字段与权限模型 | 租户套餐/额度 | 企业 SSO/OIDC |
| 数据隔离 | 私有表按租户和账户过滤 | PostgreSQL RLS | 分库/冷热分层 |
| 券商接入 | QMT/Xtquant 网关 + 模拟盘统一接口 | 多券商适配器 | 用户自助绑定券商 |
| 风控与审计 | 所有下单前 RiskGate + append-only audit | 审计查询和导出 | 合规模板/留痕报表 |
| 运维部署 | Docker Compose 云端基线 | K8s/独立 Worker | 多地域/容灾 |
| 计费与额度 | 管理员手工配置 | 套餐、并发、调用额度 | 在线支付/发票 |

## 5. 多券商交易需求

券商接入统一走 `BrokerAdapter`，前端只感知交易模式和账户状态，不直接感知 SDK。

| 适配器 | 短期定位 | 部署约束 | 备注 |
|---|---|---|---|
| `paper` | 默认模拟盘 | 云端 Linux 可运行 | 所有用户默认可用 |
| `xtquant_qmt` | A股实盘 P0 | Windows/QMT 网关机器 | 通过安全网关桥接云端 |
| `broker_rest` | 其他券商 REST | 按券商 API | 统一签名、限频、回执 |
| `broker_gateway` | 企业专线/柜台 | 私有部署 | 后续扩展 |

硬性规则：

1. 实盘券商凭证不进入前端。
2. 云端不直接暴露 QMT 本机路径，必须通过交易网关。
3. 每个券商账户绑定 `tenantId/accountId`，禁止跨账户下单。
4. 模拟盘和实盘接口一致，但 UI 必须清晰标识交易模式。

## 6. 全模块改版原则

| 模块 | 改版重点 |
|---|---|
| 智能看板 | 从全局市场看板升级为“角色化首页”，操盘手看交易机会，个人看自选解释，管理员看平台健康 |
| 开盘决策 | 候选池成为 P0 主入口，输出私有 Candidate |
| 智能选股 | 公共模型 + 私有筛选条件，结果可保存到个人候选池 |
| 产业链拆解 | 公共图谱 + 私有研究标注，输出证据型 Candidate |
| K线预测 | 公共预测能力，私有关注列表和预测对比 |
| 交易信号 | 公共信号模板 + 私有订阅/阅读/处理状态 |
| 交易中心 | 多账户、多模式、多券商，所有交易私有隔离 |
| 量化交易 | 策略模板公共，策略实例私有，执行必须绑定账户 |
| 方案管理 | Plan 私有，支持授权共享和审计 |
| 风控中心 | 规则公共/租户级，判定结果私有，审计只追加 |
| 回测分析 | 公共回测引擎，私有参数和结果，口径必须透明 |
| 个股诊断 | 公共诊断模型 + 私有备注/关注/报告 |
| 模型训练 | 管理员/模型管理员能力，普通用户不可见 |
| 模型注册 | 模型版本和灰度发布，仅管理员可操作 |
| 数据更新 | 公共数据平台能力，个人只看简化状态 |
| 运行状态 | 管理员全量，操盘手摘要，个人仅健康状态 |

## 7. 下一步工程对接边界

本轮只更新需求、架构、详细方案、PRD 和原型预览，不直接改生产前后端逻辑。下一步工程对接应按以下顺序：

1. 数据模型：补 `tenantId/accountId/userId/visibility/scope`。
2. API：所有私有资源走当前用户上下文过滤。
3. 前端：按角色裁剪导航和页面密度。
4. 交易：抽象 `BrokerAdapter`，QMT 走网关，模拟/实盘统一订单对象。
5. 模型：输出带 `modelVersion/runId/dataScope`，公共输出和私有实验隔离。
