# PRD — 开盘决策·信号扫描

- **Date**: 2026-06-26
- **Owner**: product-lead
- **Status**: Draft

## 1. 定位

信号扫描是**信号验证工作台**，不是信号浏览看板。操盘手带着竞价分析锁定的板块进入，逐一验证每只股票的信号质量，做出确认/降级/排除的决策。

| 维度 | 1.3 信号总览（AI智能看板） | 2.3 信号扫描（开盘决策） |
|---|---|---|
| **目的** | 浏览全市场信号分布 | **在锁定范围内逐只验证信号** |
| **主视图** | 色块矩阵（视觉扫描） | **验证列表（逐行对比决策）** |
| **操作** | 点击跳转诊断 | **确认→候选池 / 降级 / 排除** |
| **范围** | 全市场 | **锁定板块**（从竞价分析传入） |

## 4. 每行操作按钮逻辑

| 条件 | 可用按钮 | 默认推荐 |
|---|---|---|
| 信号强买/买入 + 预测↑ + 无风险 | [确认] [降级] [排除] | **[确认]** 高亮 |
| 信号强买/买入 + 预测↓/→ + 无风险 | [确认] [降级] [排除] | **[降级]** 高亮 |
| 信号持有/减仓 + 预测↑（逆势信号） | [确认] [降级] [排除] | **[降级]** 高亮 |
| 任意信号 + 有风险标记 | [确认] [降级] **[排除]** | **[排除]** 高亮（一票否决） |

## 5. 无板块锁定时的 fallback

如果用户没有从竞价分析跳转（直接点开信号扫描 Tab），则：
- 不显示"🔒锁定板块"横幅
- 验证列表显示全市场信号（退化为类似 1.3 的浏览模式）
- 右侧面板显示"👆 请先从竞价分析锁定板块，再进行信号验证"
- 用户仍可手动筛选板块、逐只验证

## 6. Acceptance Criteria

| ID | Priority | AC |
|---|---|---|
| AC-1 | P0 | 从竞价分析跳转后，验证列表只显示锁定板块的股票 |
| AC-2 | P0 | 每行展示：代码/名称/信号等级/评分/预测方向/一致性/风险/操作按钮 |
| AC-3 | P0 | 点击 [确认] → 股票进入右侧"已确认"列表 |
| AC-4 | P0 | 点击 [降级] → 股票进入右侧"降级"列表 |
| AC-5 | P0 | 点击 [排除] → 股票从验证列表移除（可撤销） |
| AC-6 | P0 | 右侧展示选中股票的六维评分 + Kronos预测 + 风险检查 |
| AC-7 | P1 | 默认推荐按钮根据信号+预测+风险自动高亮 |
| AC-8 | P1 | 无板块锁定时显示引导提示 |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 开盘决策：操盘手默认入口，输出私有 Candidate 与 DecisionContext。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共竞价/行情 + 私有候选池。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 实盘前必须进入方案与风控。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
