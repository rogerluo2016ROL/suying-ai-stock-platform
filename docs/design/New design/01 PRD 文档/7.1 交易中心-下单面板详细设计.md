## 4. 数据流

### 4.1 下单 6 步流程

```
步骤1: onCodeChange(tsCode)
  → GET /trade/quote?ts_code=xxx
  → GET /trade/orderbook?ts_code=xxx&depth=5
  → 更新 stockInfo, stockName
  → 渲染 StockInfoBar + OrderBookDepth

步骤2: 用户选择方向 + 输入价格/数量
  → direction = 'buy' | 'sell'
  → price, qty 更新；点击盘口价格时 price = selectedLevel.price
  → 触发 recalcAmount()

步骤3: recalcAmount()
  → estimatedAmount = price × qty × 100
  → estimatedFee = estimatedAmount × 0.0003
  → allocationPct = estimatedAmount / account.totalAsset
  → 触发 runRiskChecks()

步骤4: runRiskChecks()
  → 6 项检查实时计算
  → 更新 riskChecks[], riskOverall
  → 渲染风险检查条目

步骤5: [🔍预检] / 自动触发
  → 如有 warn → overall = 'warn'
  → 如有 fail → overall = 'fail', btnConfirm.disabled = true
  → 全部 pass → overall = 'pass'

步骤6: [确认下单]
  → 如 amount > 50000 → 二次确认弹窗
  → POST /trade/order { tsCode, side, orderType, price, qty }
  → toast "✅ 订单已提交 · 编号 #ORD-06143"
  → 刷新订单列表 + 持仓
```

### 4.2 风控预检逻辑

```typescript
function runRiskChecks(
  stockInfo: StockQuote,
  direction: string,
  price: number,
  qty: number,
  account: AccountSummary,
  positions: PositionRecord[]
): RiskCheckItem[] {
  const amount = price * qty * 100
  const checks: RiskCheckItem[] = []

  // 1. 资金充足
  if (direction === 'buy') {
    const ok = account.availableCash >= amount
    checks.push({
      id: 'fund', label: '资金充足',
      status: ok ? 'pass' : 'fail',
      message: ok
        ? `可用 ¥${account.availableCash.toLocaleString()} > 需 ¥${amount.toLocaleString()}`
        : `可用 ¥${account.availableCash.toLocaleString()} < 需 ¥${amount.toLocaleString()}`
    })
  }

  // 2. 持仓充足 (卖出时)
  if (direction === 'sell') {
    const pos = positions.find(p => p.tsCode === stockInfo.tsCode)
    checks.push({
      id: 'position', label: '持仓充足',
      status: pos && pos.holdQty >= qty * 100 ? 'pass' : 'fail',
      message: pos
        ? `持有 ${pos.holdQty} 股${pos.holdQty >= qty * 100 ? '可卖' : '(不足)'}`
        : '无持仓'
    })
  }

  // 3. 涨跌停正常
  checks.push({
    id: 'limit', label: '涨跌停正常',
    status: (price < stockInfo.highLimit && price > stockInfo.lowLimit) ? 'pass' : 'fail',
    message: `当前价 ¥${price} (涨停 ¥${stockInfo.highLimit} / 跌停 ¥${stockInfo.lowLimit})`
  })

  // 4. 仓位上限
  const newAlloc = amount / account.totalAsset * 100
  const existingAlloc = positions
    .filter(p => p.tsCode === stockInfo.tsCode)
    .reduce((sum, p) => sum + p.allocationPct, 0)
  const totalAlloc = existingAlloc + newAlloc
  checks.push({
    id: 'stock_cap', label: '仓位上限',
    status: totalAlloc <= 20 ? 'pass' : 'fail',
    message: `本次仓位 ${newAlloc.toFixed(1)}%${totalAlloc > 20 ? ' (超单股上限20%)' : ' < 单股上限20%'}`
  })

  // 5. 单笔上限
  checks.push({
    id: 'single_cap', label: '单笔上限',
    status: amount <= 200000 ? 'pass' : 'fail',
    message: `金额 ¥${amount.toLocaleString()} ${amount <= 200000 ? '<' : '>'} 单笔上限 ¥200,000`
  })

  // 6. 大额交易
  checks.push({
    id: 'large_trade', label: '大额交易',
    status: amount > 50000 ? 'warn' : 'pass',
    message: amount > 50000 ? `> ¥50,000 · 需人工确认` : `≤ ¥50,000`
  })

  return checks
}
```

function setAllocation(pct: number) {
  const price = parseFloat(orderForm.price) || 0
  const availableAmount = account.availableCash * pct / 100
  const qty = Math.floor(availableAmount / (price * 100))
  setQty(Math.max(1, qty))
}

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易中心：账户、订单、持仓、成交全部按 tenant/account/user 隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 强私有交易数据。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | paper/QMT/多券商统一 BrokerAdapter。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
