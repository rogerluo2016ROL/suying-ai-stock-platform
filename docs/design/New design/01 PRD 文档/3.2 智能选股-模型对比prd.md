# PRD — 智能选股·模型对比

- **Date**: 2026-06-26
- **Owner**: product-lead
- **Status**: Draft
- **Estimated effort tier**: Medium（前端 1 页面 ~800 行 + 后端 1 新端点 ~200 行 + ECharts 集成）

## 1. Background

速赢AI 拥有 12 个选股模型，覆盖不同策略（趋势、短线、盘后龙头、长线价值等）。当前问题：

| 问题 | 表现 |
|---|---|
| 模型结果孤立 | 跑完 bi_trend 再跑 short，无法看到两只都选中的重叠股票 |
| 无共识验证 | 单个模型可能出现误判，多模型同时选中的标的更具确定性 |
| 无法对比评价 | 同一只股票在不同模型中的评分逻辑不同，无法横向对比 |
| 缺乏可视化 | 交并集关系只能用眼睛去对——容易遗漏共识标的 |

**用户痛点**：

1. **操盘手**需要"交叉验证"——4 个模型都选中的股票比 1 个模型选中的更可信；
2. **分析师**需要"发现分歧"——为什么同行业 A 被 bi_trend 选中而 short 没选？因子差异在哪？
3. **决策者**需要按共识度排序——★★★★ 共识 > ★★★ > ★★ > ★。

## 2. Goal & Non-Goals

**目标**：

- 同时运行 2-4 个模型，交叉对比选股结果，发现共识标的
- 提供交集/并集/差异可视化（表格式共识矩阵，非实际 Venn 图）
- 共识度排序 + 逐只跨模型评分对比
- KPI：用户选中模型后 5 秒内看到共识结果 + 共识度排序

**Non-Goals**：

- 不做模型本身的参数对比或性能评估（那是模型管理/回测的范畴）
- 不做历史模型对比快照的回看（V1 仅做本次运行对比）
- 不替代选股工作台的单模型运行（模型对比 = 批量运行 + 交叉分析）

## 3. User Stories

| ID | As a | I want to | So that |
|---|---|---|---|
| US-1 | 操盘手 | 勾选 2-4 个模型并一键运行对比 | 同时获得多模型的选股结果，无需逐个运行 |
| US-2 | 操盘手 | 看到共识矩阵（按共识度 ★★★★→★ 分组展示股票） | 一眼识别哪些股票被多个模型同时选中 |
| US-3 | 操盘手 | 看到模型交并集的统计数字（A ∩ B = N 只） | 量化理解模型之间的覆盖重叠程度 |
| US-4 | 分析师 | 点击某只股票后看到该股在所有模型中的评分对比 | 理解不同模型对同一标的的评价差异 |
| US-5 | 分析师 | 看到差异视图（只在模型 A 中而不在模型 B 中的股票） | 发现每个模型的独特选股逻辑 |
| US-6 | 决策者 | 看到统计栏：各模型选股数量 + 逐步交集过滤后的最终共识 | 理解从 20 只 → 8 只 → 3 只的收敛过程 |
| US-7 | 所有用户 | 支持结果导出为 CSV/Excel | 将共识标的清单导入自选池或候选池 |
| US-8 | 所有用户 | 一键将共识标的加入候选池 | 快速将交叉验证结果落地为可交易的候选标的 |

### 5.2 API 契约

#### 新增端点

**`POST /api/v1/screener/compare`**

- **用途**：同时运行多个模型并返回交叉对比结果
- **Request**：
```json
{
  "model_keys": ["bi_trend_launch", "short", "leader_scalp", "long"],
  "filters": {
    "date": "2026-06-26",
    "market": "all"
  }
}
```
- **Response (200)**：
```json
{
  "status": "ok",
  "models": [
    {
      "model_key": "bi_trend_launch",
      "model_name": "毕师傅V13",
      "total_picks": 20,
      "picks": [
        {
          "ts_code": "300750.SZ",
          "name": "宁德时代",
          "close": 235.50,
          "change_pct": 4.2,
          "score": 85,
          "factors": { "obv_trend": 78, "wr_oversold": 65, "vol_ratio": 2.4 }

    }

  "consensus": {
    "intersection_all": ["300750.SZ", "688981.SH", "002594.SZ"],
    "intersection_3": ["600519.SH", "000858.SZ"],
    "intersection_2": ["601012.SH", "603259.SH", "300274.SZ"],
```

### 5.3 数据模型

核心数据结构：

```typescript
interface ConsensusRow {
  tsCode: string
  name: string
  close: number
  changePct: number
  consensusLevel: number        // 4 = ★★★★ (all selected), 1 = ★
  selectedBy: string[]           // ["bi_trend_launch", "short", ...]
}

interface ModelScores {
  modelKey: string
  modelName: string
  score: number
  rank: number
  indicators: Record<string, number>
}

interface StockCrossScores {
  tsCode: string
  name: string
  scores: ModelScores[]
}
```

## 6. Technical Constraints

- 前端: React 18 + TS 5.6 + Ant Design 5.22 + ECharts 6.1
- 路由: `/screener/compare`
- 后端并行运行模型：使用 `asyncio.gather()` 并发调用各模型选股逻辑
- API P95 ≤ 3s（4 个模型并行）
- 不引入新 npm/Python 依赖
- 共识矩阵不用实际 Venn 图/弧线图，用表格 + 共识度列表示

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 智能选股：公共模型能力与用户私有筛选条件分离，结果可保存到个人候选池。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共模型评分 + 私有筛选参数。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不直接下单，只生成候选/方案。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
