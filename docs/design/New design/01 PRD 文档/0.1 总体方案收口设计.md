> **Date**: 2026-06-27 | **Owner**: product-lead | **Status**: Draft

## 1. 收口目标

平台定位从“多个 AI 投研交易工具”收束为“AI 投研交易操作系统”。后续所有模块必须服务同一条主链路：

```
产业/政策/选股/预测
  → 候选池
  → 交易信号/个股诊断
  → 方案
  → 风控闸门
  → 手动下单/量化执行
  → 持仓风控
  → 回测复盘
  → 模型/数据治理
```

一级菜单保留现有 16 个模块，不再继续横向加菜单。后续优化优先补齐跨模块对象、状态机、权限、数据质量和原型质量门禁。

2026-06-27 平台化升级补充：平台未来会开放给操盘手、个人投资者和系统管理员，并部署到云端支持多账户、多租户和多券商交易。后续需求、架构、详细方案和原型以以下三份文档为新增基线：

| `0.3 平台化云端多租户总体需求设计.md` | 定义三类用户、公共/私有数据隔离、云端开放和多券商目标 |

## 2. 核心对象边界

| 对象 | 定位 | 产生模块 | 消费模块 |
|---|---|---|---|
| `DecisionContext` | 跨页面上下文。记录来源、标的、交易日、模型、风险与数据状态 | 所有入口 | 所有跳转目标 |
| `Candidate` | 候选标的。只表达“值得关注”，不承诺交易 | 开盘决策、智能选股、产业链、K线预测 | 交易信号、诊断、方案管理 |
| `Signal` | 单标的交易信号。表达方向、强度、置信度和解释 | 交易信号、K线预测、模型服务 | 候选池、方案、交易中心 |
| `Plan` | 组合方案。表达一组标的、仓位、计划价、止损止盈和执行状态 | 候选池、方案管理 | 交易中心、量化交易、风控中心 |
| `Strategy` | 可自动执行的策略实例。表达规则、参数、标的来源和运行状态 | 量化交易 | 风控中心、策略日志、回测分析 |
| `Order` | 券商侧委托指令。表达买卖方向、价格、数量、状态和成交回报 | 交易中心、量化交易 | 订单管理、持仓、事件审计 |
| `RiskVerdict` | 风险判定结果。表达通过、警告、拒绝、人工复核 | 风控服务 | 候选池、方案、交易、量化、风控中心 |
| `DataFreshness` | 数据新鲜度与质量。表达更新时间、缺口、降级原因 | 数据更新、运行状态 | 所有决策页 |

## 3. 统一上下文

所有跨模块跳转都必须携带或可恢复 `DecisionContext`：

```typescript
interface DecisionContext {
  contextId: string
  tradeDate: string
  code?: string
  codes?: string[]
  sourceModule:
    | 'dashboard' | 'opening_decision' | 'screener' | 'supply_chain'
    | 'prediction' | 'signal' | 'plan' | 'strategy' | 'risk'
  sourceId?: string
  candidateId?: string
  signalId?: string
  planId?: string
  strategyId?: string
  orderId?: string
  modelVersion?: string
  riskVerdict?: 'pass' | 'warn' | 'reject' | 'manual_review'
  dataFreshness?: {
    status: 'fresh' | 'delayed' | 'stale' | 'degraded'
    updatedAt: string
    reason?: string
  }
}
```

原则：URL 只传关键 ID，完整上下文由后端或前端缓存恢复，避免把候选池大对象塞进 query string。

## 4. 风控闸门

风控中心不是单页功能，而是全链路服务。所有会改变资金、仓位或自动执行状态的动作必须经过 `RiskGate`。

| 闸门 | 触发动作 | 结果 |
|---|---|---|
| 候选池风控 | 生成方案前批量检查 | 排除高危标的，警告标的默认不勾选 |
| 方案风控 | `draft → running` | 校验总仓位、单票仓位、止损、回撤预算 |
| 审单风控 | 手动下单/自动下单前 | 通过、需确认、拒绝、人工复核 |
| 策略风控 | 策略部署、恢复、调参 | 校验日亏损、频率、行业暴露、熔断状态 |
| 持仓风控 | 持仓逼近止损、公告、审计风险 | 告警、暂停策略、止损建议、一键平仓复核 |
| 全局熔断 | 账户级亏损或系统级异常 | 暂停交易、停止自动执行、写入事件审计 |

## 5. 角色权限

> **注（2026-08-06 收口）**：下表为早期 6 角色业务能力描述，已被 §5.1「角色映射表」取代——权限判定一律以项目实际 RBAC 4 角色（`admin / internal_analyst / external_analyst / user`）为准，本表仅保留作业务语义参考。

| 能力 | 操盘手 | 个人投资者 | 风控员 | 量化研究员 | 模型管理员 | 系统管理员 |
|---|---|---|---|---|---|---|
| 查看行情/信号/诊断 | 全量 | 简化 | 全量 | 全量 | 只读 | 全量 |
| 查看金额 | 全量 | 脱敏/仅本人 | 全量 | 脱敏 | 脱敏 | 全量 |
| 生成方案 | 可 | 可，简化参数 | 只读 | 可，用于研究 | 不可 | 可 |
| 手动下单 | 可 | 可，需复核 | 不可 | 不可 | 不可 | 可 |
| 启停策略 | 可 | 不可 | 可暂停/恢复 | 可部署模拟策略 | 不可 | 可 |
| 修改风控规则 | 申请 | 不可 | 可 | 不可 | 不可 | 可 |
| 训练/注册模型 | 不可 | 不可 | 不可 | 发起实验 | 可 | 可 |
| 数据同步/运行状态 | 只读摘要 | 简化状态 | 只读 | 只读 | 只读 | 全量操作 |

平台化后，角色权限不只控制菜单显示，还必须参与 API 数据过滤。所有私有对象默认按 `tenantId / ownerUserId / accountId` 过滤；系统管理员跨租户访问必须写入审计原因。

### 5.1 角色映射表（RBAC 收口）

项目代码实际 RBAC 为 4 角色：`admin / internal_analyst / external_analyst / user`（见 `backend/app/` 与 ADR-001）。设计文档中的业务角色统一按下表映射：

| 设计文档角色 | 映射 RBAC 角色 | 说明 |
|---|---|---|
| sys_admin 系统管理员 | `admin` | 平台运营、跨租户管理，跨租户访问必须写审计原因 |
| model_admin 模型管理员 | `admin` | 模型训练/注册/发布管理，权限并入 admin |
| trader 操盘手 | `internal_analyst` | 方案生成、手动下单、策略启停 |
| risk_admin 风控员 | `internal_analyst` | 风控规则配置、暂停/恢复策略，与操盘手同角色、按页面/操作粒度区分 |
| 量化研究员 | `internal_analyst` | 研究用途的方案/回测/实验，权限同 internal_analyst |
| investor 个人投资者 | `user` | 简化视图，金额脱敏、仅本人数据 |
| external_analyst 外部分析师 | `external_analyst` | 外部只读 |

**声明**：全站设计文档（0.x ~ 16.x 全部 PRD 与详细设计）中出现的 `trader / investor / risk_admin / model_admin / sys_admin` 均按本表映射到 RBAC 4 角色，后续不再逐一改写各文档的角色描述；接口鉴权以 JWT 中的 RBAC 角色为准，业务角色名仅用于产品语义表达。

### 5.2 平台化字段全局注入规则

收口决策（2026-08-06），适用于全部模块 PRD 与详细设计：

1. **后端注入**：`tenantId / ownerUserId / accountId` 一律由后端从 JWT + 会话上下文（`PlatformContext` / `Membership` / `BrokerAccount`）解析注入，**API 请求 schema 不显式传这些字段**。
2. **DB 必带**：DB 层写操作必须携带 `tenant_id / owner_user_id / account_id`；私有对象读查询默认按这三个字段过滤。
3. **前端禁令**：前端禁止传 `X-User-Role` 等身份头（网关侧同时剥离 `X-Owner-User-Id` 等可伪造头，见 `api-gateway` `sanitize_client_headers`）；金额打码 / 数据过滤一律服务端按 JWT 角色执行，前端只做展示适配。
4. **文档引用**：各模块文档中的平台化字段段落（`tenantId / ownerUserId / dataScope` 等模板化描述）统一以本节为准，不再逐页重复粘贴；如与本节冲突，以本节为准。

## 6. 数据可信度门禁

每个决策页必须显示数据状态，至少包括：

- 行情时间：最新行情、盘口、分钟线、日线分别标注更新时间。
- 数据质量：缺口、NULL 率、覆盖范围、是否使用降级数据。
- 模型版本：模型名、版本、训练日期、线上环境。
- 回测口径：是否扣成本、是否样本外、是否消除前视和幸存者偏差。
- 禁用规则：关键数据过期或风控服务不可用时，禁止自动下单和策略恢复。

当前重点关注的数据债务：`stk_factor_pro` 技术因子、`moneyflow_hsgt` 资金流、`sw_daily` 行业日线、`ths_member` 概念覆盖、`change_pct/pct_chg` 字段统一。

## 7. 原型质量门禁

进入详细原型设计前，核心预览页必须满足：

| 门禁 | 标准 |
|---|---|
| 静态文件 | `check-upgraded-previews.mjs` 通过 |
| 控制台 | 核心页无 `pageerror` 和 ECharts 初始化错误 |
| 图表 | 有 ECharts 的页面 canvas 非空，缺数据时展示明确空态 |
| 布局 | 1440×900 下无横向滚动；关键按钮和表格不溢出 |
| 交互 | 价格、盘口、风险预检、方案动作、Tab 切换有可见状态 |
| 降级 | 数据源缺失时页面保留上下文，并显示降级原因 |
