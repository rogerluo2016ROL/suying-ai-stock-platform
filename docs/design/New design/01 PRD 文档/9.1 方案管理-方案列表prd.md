## 1. 定位

方案列表是方案管理模块的**默认主视图**。操盘手在此总览全部方案的运行状态、资金占用与盈亏情况，并快速执行启动/暂停/结算等生命周期操作。个人投资者则仅看到"我的方案"简化视图。

| 角色 | 场景 | 核心诉求 |
|---|---|---|
| 操盘手 | 开盘后检查今日方案执行状态 | 总仓位是否超标？哪些方案正在运行？日盈亏如何？ |
| 操盘手 | 盘中监控 + 快速操作 | 点击卡片查看详情 → 暂停/恢复/结算 |
| 个人投资者 | 开盘后查看推荐方案 | 买什么？仓位多少？→ 去交易中心下单 |

## 3. 功能规格

### 3.1 KPI 指标行

| KPI | 说明 | 数据来源 | 刷新策略 |
|---|---|---|---|
| 总仓位 | 所有 running 方案的仓位加权汇总，进度条展示 | GET /api/v1/strategy/summary → totalPosition（后端聚合，前端不做跨方案汇总） | 15s 轮询 |
| 可用资金 | 账户可用资金余额（由 strategy-service 聚合 trade-service 账户数据） | GET /api/v1/strategy/summary → availableCash | 15s 轮询 |
| 合计盈亏 | 所有 running 方案日盈亏金额合计，红涨绿跌 | GET /api/v1/strategy/summary → totalPnl | 15s 轮询 |
| 方案数 | "运行中 N / 草稿 M" 双数字分开展示 | GET /api/v1/strategy/summary → planCounts | 列表刷新时更新 |

### 3.2 筛选标签

| 筛选 | 说明 | 默认 |
|---|---|---|
| 全部 | 展示所有状态方案（按状态分组排序） | **默认选中** |
| 运行中 | 仅 running 状态，绿色计数 badge | — |
| 草稿 | 仅 draft 状态，灰色计数 badge | — |
| 已归档 | 仅 closed 状态，暗色计数 badge | — |

> 筛选标签为 Pill 样式，选中高亮蓝色。计数随方案增删实时更新。

### 3.3 方案卡片

**卡片布局**（从上到下）：

| 区域 | 内容 | 状态差异 |
|---|---|---|
| 头部 | StatusDot + 方案名 + StatusBadge（状态文字） | running 绿点脉冲 / draft 灰点 / closed 暗灰点 |
| 指标行 | 标的数 / 仓位% / 日盈亏 / 创建时间 | draft/closed 无日盈亏 |
| 标签列表 | 标的 Chip（名称 + 仓位%） | 展示前 5 个，超出的用 "+N" 折叠 |
| 订单进度 | Progress bar + "X/Y 已成交" | 仅 running 显示；draft 显示"尚未下单" |
| 操作按钮 | 状态驱动的操作按钮组 | 见下表 |

**操作按钮映射**：

| 状态 | 可用操作 |
|---|---|
| running | [⏸️ 暂停] [🏁 结算] |
| paused | [▶️ 恢复] [🏁 结算] |
| draft | [🚀 启动] (primary) [✏️ 编辑] [🗑 删除] (danger) |
| closed | [查看详情] (text link) |

### 3.4 交互规则

| 交互 | 行为 |
|---|---|
| 点击方案卡片 | ① 卡片选中高亮（蓝色左边框） ② SubTabBar 自动切换到"方案详情" Tab |
| 筛选切换 | 过滤卡片列表，保留分组标题（running / draft / closed） |
| 启动方案 | Popconfirm "确认启动自动交易？" → POST /start → 卡片更新为 running |
| 结算方案 | Popconfirm "确认结算？将平仓所有持仓并归档" → POST /settle → 卡片移入已归档 |
| 删除方案 | Popconfirm "确认删除？不可恢复" → DELETE → 卡片淡出移除 |

## 4. 角色差异

| 维度 | 操盘手 | 个人投资者 |
|---|---|---|
| 可见方案 | 全部方案 | 仅"我的方案"（owner_id 筛选） |
| KPI 行 | 完整 4 卡（总仓位/可用资金/合计盈亏/方案数） | 仅 2 卡（可用资金/合计盈亏） |
| 筛选标签 | [全部] [运行中] [草稿] [已归档] | [全部] [运行中] [草稿]（隐藏已归档） |
| 操作按钮 | 完整（启动/暂停/恢复/结算/编辑/删除） | 简化（启动 → 跳转交易中心 / 删除） |
| 金额显示 | 完整金额 | 打码 ¥***（服务端按 JWT 角色打码，前端不传身份头） |

## 5. Acceptance Criteria

| ID | Priority | AC |
|---|---|---|
| AC-1 | P0 | KPI 行展示 4 张指标卡（总仓位/可用资金/合计盈亏/方案数），数据随 15s 轮询实时更新 |
| AC-2 | P0 | 筛选标签支持 4 种状态过滤，切换即时生效，方案卡片按状态分组（running → draft → closed）显示 |
| AC-3 | P0 | 每张方案卡片展示状态圆点（含脉冲动画）、方案名、标的 Chip、订单进度条和状态驱动的操作按钮 |
| AC-4 | P0 | 点击方案卡片 → 卡片选中高亮 + SubTabBar 自动切换到"方案详情" Tab，展示该方案完整信息 |
| AC-5 | P1 | 操作按钮触发后卡片即时更新（启动/暂停/恢复/结算/删除），无需手动刷新页面 |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 方案管理：Plan 是私有交易意图承载对象，可授权共享但默认仅本人可见。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 私有 Plan + 公共模型引用。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | Plan 启动前必须绑定账户/模式。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
