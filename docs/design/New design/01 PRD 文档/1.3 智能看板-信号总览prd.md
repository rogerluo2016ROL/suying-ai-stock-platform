# PRD — 智能看板·信号总览

- **Date**: 2026-06-25
- **Owner**: product-lead
- **Status**: Draft
- **Estimated effort tier**: Medium（前端 1 页面 ~900 行 + 后端 1 新端点 ~150 行 + ECharts 集成）

## 1. Background

当前速赢AI的信号功能分散在多处：

- Dashboard 右侧边栏的市场情绪 + 异动预警提供了碎片化的信号信息；
- `/signals` 页面（`Signals.tsx`）只支持单只股票输入代码后分析，缺乏全市场扫描视角；
- `signal-service` 提供了六维评分引擎（Kronos + 技术 + 资金 + 基本面 + 事件风险 + 市场适应），但只在 `/analyze/{code}` 单只调用，无法让用户快速感知全市场信号分布。

**用户痛点**：

1. **操盘手**开盘前/收盘后需要一眼判断今天是"进攻日"还是"防御日"——需要看到全市场买卖信号的分布比例和趋势变化；
2. **操盘手**需要识别板块级别的信号共振——半导体 12 只同时触发买入 vs 房地产 8 只触发卖出，这是比单只信号更可靠的决策依据；
3. **个人投资者**需要快速知道"今天有没有值得关注的机会"，而不是盲搜代码；
4. 缺乏信号的时间维度——今天的信号密度和历史相比是异常还是正常？多空比在拐点？
5. 现有页面无法承载"一屏尽览全市场信号"的信息密度需求。

## 2. Goal & Non-Goals

**目标**：

- 构建"信号总览"页面，作为信号系统的首页入口，一屏内呈现全市场信号全景
- KPI：用户打开页面后 3 秒内形成对今日信号态势的判断（偏多/偏空/震荡），10 秒内定位到最值得关注的板块

**Non-Goals**：

- 不做个股深度信号分析（已有 `/signals` 页面覆盖，总览点击个股后跳转）
- 不做实时盘中信号推流（本次做盘后快照 + 历史趋势）
- 不替代 Dashboard 的市场情绪模块（市场情绪是价格维度，信号是综合维度，互补不互替）
- 不做信号策略回测（回测属于 backtest-service 范畴）
- 不引入新的数据源（复用 signal-service 评分引擎 + PG 数据）

### 5.3 数据模型

#### 新增 PG 表（缓存层）

```sql
CREATE TABLE IF NOT EXISTS signal_snapshots (
    id SERIAL PRIMARY KEY,
    code TEXT NOT NULL,
    trade_date DATE NOT NULL,
    session TEXT NOT NULL DEFAULT 'post',
    level TEXT NOT NULL,              -- STRONG_BUY / BUY / HOLD / REDUCE / SELL / TIMING_ALERT
    score DOUBLE PRECISION NOT NULL,
    kronos_score DOUBLE PRECISION,
    technical_score DOUBLE PRECISION,
    fund_flow_score DOUBLE PRECISION,
    fundamental_score DOUBLE PRECISION,
    event_risk_score DOUBLE PRECISION,
    market_adapt_score DOUBLE PRECISION,
    price DOUBLE PRECISION,
    change_pct DOUBLE PRECISION,
    industry TEXT,
    generated_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(code, trade_date, session)
);

CREATE INDEX idx_signal_snapshots_date_level ON signal_snapshots(trade_date, level);
CREATE INDEX idx_signal_snapshots_industry ON signal_snapshots(trade_date, industry);
```

> 此表为信号扫描结果的持久化缓存，避免每次请求实时调用六维评分引擎（全市场 4000+ 只股票 × 6 个 scorer = 大量计算）。定时任务（APScheduler）在盘后/盘中等关键时点触发批量计算并写入此表。

## 6. Technical Constraints

- 页面实现：作为 `Dashboard.tsx` 的 Tab 面板（Tab key: `signal-overview`），不创建独立路由。与市场情绪/竞价意图/自选跟踪共享同一页面，通过 `<Tabs>` 切换
- 后端框架：FastAPI + uvicorn，新增端点放入 `signal-service/app/routes.py`
- 设计系统：严格遵循 `docs/design/new front/design-spec.md` 及 `design-tokens.css`
- A 股涨跌色：`var(--up)` = 红涨, `var(--down)` = 绿跌，不得反转。信号色块中 🟢强买 用 `var(--accent)` 或特定色（非涨跌色），避免与涨跌混淆
- 信号级别颜色映射：
  - `STRONG_BUY` → `#ff4d4f`（强买=红色，A股买入预期涨=红）
  - `BUY` → `#fa8c16`（橙色，次强买入）
  - `HOLD` → `#1677ff`（蓝色，持有/中性）
  - `REDUCE` → `#faad14`（黄色，减仓）
  - `SELL` → `#8c8c8c`（灰色，卖出）
  - `TIMING_ALERT` → `#722ed1`（紫色，拐点）
- 字体：价格/评分用 `--font-mono` + `tabular-nums`，文案用 `--font-body`
- 桌面优先：推荐宽度 ≥1440px，1280px 以下压缩为单列
- 不引入新 npm/Python 依赖
- API P95 ≤ 500ms（market-scan 读缓存），daily-stats P95 ≤ 300ms
