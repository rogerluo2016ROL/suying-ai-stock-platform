# 详细设计 — 产业链拆解·政策梳理

> **关联 PRD**: `4.1 产业链拆解-政策梳理prd.md` | **Date**: 2026-06-27

## 1. 页面定位

政策梳理是 `SupplyChainWorkbench` 的 **Phase 1 板块**，作为产业链拆解·研究工坊的入口。它完成"政策输入 → LLM 解读 → 行业映射"完整链路，并为 Phase 2（产业链解构）提供映射结果。

| 维度 | 政策梳理 (Phase 1) | 产业链解构 (Phase 2) |
|---|---|---|
| **输入** | 政策原文 / URL / PDF / 政策库 / 热门题材 | Phase 1 的行业映射结果 |
| **产出** | 核心方向 + 政策强度 + 行业映射表 | 三种解构图 + 公司清单 |
| **编辑** | 全部 LLM 字段可修正 | 只读展示 |
| **模板** | 支持保存/加载解读模板 | 无模板功能 |

## 3. 核心数据结构

### 3.1 PolicyInput

```typescript
type InputMethod = 'paste' | 'url' | 'pdf' | 'library' | 'hot_topic'

interface PolicyInput {
  method: InputMethod
  content: string                    // 粘贴的文本 或 抓取的网页内容
  rawUrl?: string                    // 原始URL (仅 url 方式)
  pdfFiles?: UploadFile[]            // PDF文件列表 (仅 pdf 方式)
  policyLibraryId?: string           // 政策库记录ID (仅 library 方式)
  hotTopicKey?: string               // 热门题材key (仅 hot_topic 方式)
  charCount: number                  // 字符数
  submitted: boolean                 // 是否已提交解读
}
```

### 3.2 PolicyDirection

```typescript
interface PolicyDirection {
  id: string                         // UUID
  index: number                      // 方向序号 1/2/3/...
  title: string                      // 方向标题 "半导体设备国产替代"
  description: string                // 方向描述
  isEdited: boolean                  // 是否被用户修改过
  originalTitle?: string             // LLM原始输出 (用于还原)
  originalDescription?: string       // LLM原始输出 (用于还原)
}

interface PolicyStrength {
  stars: number                      // 1-5 星
  label: string                      // "强力政策" / "中等力度" / ...
  isEdited: boolean
  originalStars?: number
}

interface PolicyDetail {
  funding: string                    // 资金支持描述
  fundingEdited: boolean
  originalFunding?: string

  timeWindow: string                 // 时间窗口描述
  timeWindowEdited: boolean
  originalTimeWindow?: string

  rawAnalysis: string                // LLM完整原始分析 (折叠)
}
```

### 3.3 MappedIndustry

```typescript
type MatchMethod = 'exact' | 'fuzzy' | 'llm_fallback'
type ConfidenceLevel = 'high' | 'medium' | 'low'

interface MappedIndustry {
  id: string
  directionId: string                // 关联 PolicyDirection.id
  directionTitle: string             // 冗余, 方便展示
  industryName: string               // 映射行业名
  conceptCode: string                // Tushare概念代码 ths_xxxx
  conceptName: string                // Tushare概念中文名
  stockCount: number                 // 上市公司数量
  matchMethod: MatchMethod
  confidence: number                 // 0-1 (仅 llm_fallback 有意义)
  confidenceLevel: ConfidenceLevel
  isManualOverride: boolean          // 是否用户手动修正了映射
}
```

### 3.4 PolicyTemplate

```typescript
interface PolicyTemplate {
  id: string
  name: string                       // 模板名称 "大基金三期-2026Q1"
  sourcePreview: string              // 政策来源前200字
  sourceHash: string                 // 源文本hash (用于相似度检测)
  directions: PolicyDirection[]      // 核心方向
  strength: PolicyStrength           // 政策强度
  funding: string                    // 资金支持
  timeWindow: string                 // 时间窗口
  mappings: MappedIndustry[]         // 行业映射结果
  tags: string[]                     // 标签 ["半导体", "政策"]
  createdAt: string                  // ISO datetime
  updatedAt: string
}
```

### 3.5 页面状态

```typescript
interface PolicyAnalysisState {
  // 视角
  viewMode: 'trader' | 'investor'

  // Step 1: 输入

  // Step 2: LLM解读
  directions: PolicyDirection[]

  timeWindow: string
  rawAnalysis: string
  isAnalyzing: boolean              // 解读进行中
  analysisError: string | null

  // Step 3: 行业映射
  mappedIndustries: MappedIndustry[]
  unmappedDirections: PolicyDirection[]
  isMapping: boolean                 // 映射进行中
  mappingError: string | null

  // 模板
  templates: PolicyTemplate[]
  templatesExpanded: boolean
  similarityAlert: SimilarityAlert | null

  // UI
  activeStep: 1 | 2 | 3             // 当前步骤
  lastSubmission: string | null      // 最后提交时间
}
```

## 5. 数据流

### 5.1 LLM解读调用流程

```
PolicyAnalysisTab: 用户点击 [🔍 LLM解读]
│
├── 1. 构建请求体
│   └── POST /api/v1/screener/supply-chain/policy/analyze
│       body: {
│         content: string,          // 政策文本
│         source_type: InputMethod,
│         source_url?: string,
│         view_mode: 'trader' | 'investor'
│       }
│
├── 2. screener-service 处理
│   ├── 文本预处理 (截取前5000字, 清理格式)
│   ├── 构建 System Prompt + User Prompt
│   ├── 调用 DeepSeek LLM
│   └── 解析 LLM 输出为结构化 JSON:
│       {
│         directions: [{ title, description }],
│         strength: { stars: 4, label: "强力政策" },
│         funding: "国家大基金三期 3000亿...",
│         time_window: "2026-2028 三年行动计划",
│         raw_analysis: "..."
│       }
│
├── 3. 相似度检测 (并行)
│   └── POST /api/v1/supply-chain/policy/template/check-similar
│       body: { content_hash: sha256(content) }
│       response: { similarity: 0.87, matched_template: {...} }
│       └── 若 similarity > 0.8 → 前端弹出 SimilarityAlert
│
├── 4. 前端更新状态
│   ├── set directions, strength, funding, timeWindow
│   ├── set activeStep = 2
│   └── dispatch('SET_POLICY_DIRECTIONS', directions)
│
└── 5. 自动触发行业映射
    └── PolicyAnalysisTab 监测到 directions 更新
        → 自动调用 GET /api/v1/supply-chain/policy/industry-map
```

### 5.2 行业映射流程

```
PolicyAnalysisTab: directions 变更
│
├── 1. 精确匹配
│   └── 每个 direction.title → 查询《产业-重点方向-Tushare映射》
│       匹配方式: 精确名称匹配 → 编辑距离≤2匹配
│
├── 2. 未匹配方向收集
│   └── unmappedDirections = directions 中无法匹配的项
│
├── 3. LLM兜底 (仅未匹配方向)
│   └── POST /api/v1/supply-chain/policy/industry-map
│       body: {
│         directions: unmappedDirections,
│         candidate_industries: [...]  // 所有可用行业列表
│       }
│       response: [{
│         direction_title: "...",
│         matched_industry: "...",
│         concept_code: "ths_xxx",
│         confidence: 0.75
│       }]
│
├── 4. 合并结果
│   ├── 精确匹配: confidence=1.0, matchMethod='exact'
│   ├── 模糊匹配: confidence=0.8, matchMethod='fuzzy'
│   └── LLM兜底: confidence=variable, matchMethod='llm_fallback'
│
└── 5. 更新供应链上下文
    └── dispatch('SET_MAPPED_INDUSTRIES', mappedIndustries)
        → SupplyChainContext.mappedIndustries 可供 Phase 2 消费
```

### 5.3 模板保存/加载流程

```
保存模板:
├── 1. 收集当前所有字段 (directions + strength + funding + timeWindow + mappings)
├── 2. 弹出 Modal: 输入模板名称 + 标签
├── 3. POST /api/v1/screener/supply-chain/policy/template/save
│     body: { name, tags, directions, strength, funding, timeWindow, mappings }
├── 4. 刷新本地模板列表

加载模板:
├── 1. 在 TemplateList 中点击 [加载]
│     或 SimilarityAlert 中点击 [加载模板]
├── 2. GET /api/v1/supply-chain/policy/template/{id}
├── 3. 填充: directions, strength, funding, timeWindow, mappings
├── 4. 标记来源: "来源模板: xxx"
├── 5. 更新 steps: activeStep = 3 (所有步骤已完成)
```

### 5.4 视角切换流程

```
ViewToggle: 操盘手 ↔ 个人投资者
│
├── 1. 更新 viewMode
│
├── 2. 联动变更:
│   ├── InputMethodTabs 顺序:
│   │   操盘手: [粘贴文章] [URL] [PDF] [政策库]
│   │   投资者: [热门题材] [粘贴文章] [URL] [政策库]
│   │
│   ├── 编辑权限:
│   │   操盘手: 所有字段 editable
│   │   投资者: 仅 strength.stars editable, 其他 readonly
│   │
│   ├── 操作按钮:
│   │   操盘手: [保存模板] [进入产业链解构]
│   │   投资者: [加入自选] [查看股票列表]
│   │
│   └── LLM解读深度:
│       操盘手: 完整 prompt, 提取≥3条方向
│       投资者: 简化 prompt, 提取1-2条方向
│
└── 3. 若已有解读结果, 切换后触发重新解读? → 否, 保留当前结果
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 产业链拆解：公共产业链图谱与用户私有研究笔记分离，证据型标的进入候选池。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共图谱/政策 + 私有研究标注。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 不直接交易，只输出 Candidate 证据。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
