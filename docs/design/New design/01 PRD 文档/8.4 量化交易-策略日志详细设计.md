## 3. 核心数据结构

```typescript
type LogType = 'order' | 'stop_loss' | 'take_profit' | 'pause' | 'error' | 'info'
type LogFilter = LogType | 'all'

interface StrategyLog {
  id: string
  time: string                      // "10:15" or "2026-06-27 10:15:00"
  fullDatetime: string              // ISO datetime for sorting
  type: LogType
  level: LogLevel                   // derived
  icon: string                      // "📝" "🛑" "✅" "⏸️" "ℹ️" "❌"
  levelColor: string                // CSS color var
  event: string                     // "买入 300750 宁德 500股"
  detail: string                    // "风控:✅全部通过"
  strategyId: string
}

interface LogLevelMeta {
  type: LogType
  icon: string
  label: string

const LOG_LEVEL_META: Record<LogType, LogLevelMeta> = {
```

### 3.1 筛选逻辑

```typescript
function filterLogs(logs: StrategyLog[], filter: LogFilter): StrategyLog[] {
  if (filter === 'all') return logs
  return logs.filter(l => l.type === filter)
}
```

### 3.2 导出逻辑

```typescript
interface ExportLogsParams {
  strategyId: string
  type: LogFilter
}

async function exportLogs({ strategyId, type }: ExportLogsParams): Promise<void> {
  // Option A: 前端生成 CSV
  const response = await fetch(`/strategy/auto/${strategyId}/logs?type=${type}&limit=9999`)
  const { items } = await response.json()
  const csv = [
    '时间,级别,事件,详情',
    ...items.map(l => `"${l.time}","${LOG_LEVEL_META[l.type].label}","${l.event}","${l.detail}"`)
  ].join('\n')
  const blob = new Blob(['\uFEFF' + csv], { type: 'text/csv;charset=utf-8' })
  const url = URL.createObjectURL(blob)
  const a = document.createElement('a')
  a.href = url
  a.download = `策略日志_${strategyId}_${new Date().toISOString().slice(0,10)}.csv`
  a.click()
  URL.revokeObjectURL(url)
}
```

## 4. 数据流

```
StrategyLog mount
  │
  ├── 获取策略列表 → GET /strategy?status=running,paused,stopped
  │   └── 默认选中第一个策略（优先 running，其次 paused，最后 stopped）
  │
  ├── 加载日志 → GET /strategy/auto/{id}/logs?type=all&page=1&limit=50
  │   ├── 返回 { items: StrategyLog[], total: number, todayCount: number }
  │   └── 渲染 LogTable
  │
  ├── 监听 filter 变化 → 重新请求 (type={filter})
  ├── 监听 page 变化 → 重新请求 (page={page})
  │
  ├── 30s 轮询 → 仅请求 type=all,limit=50 (顶部最新50条)
  │   └── 增量合并: 保留已有 + 追加新日志
  │
  └── [📥 导出日志]
      ├── Option A: GET /strategy/auto/{id}/logs/export (后端生成 CSV 流)
      │   └── 浏览器自动下载
      └── Option B: 前端请求全量 → CSV 字符串 → Blob 下载
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 量化交易：策略模板可公共，策略实例、参数和运行日志必须私有隔离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共模板 + 私有策略实例。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 自动执行绑定账户并经过 RiskGate。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
