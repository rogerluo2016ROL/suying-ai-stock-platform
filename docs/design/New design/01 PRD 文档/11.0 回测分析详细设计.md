## 1. 页面定位

回测分析是**策略/模型的历史表现验证工具**。在实盘部署前，验证策略在历史上能不能赚钱。

采用 **SubTabBar 多页签架构**，3 个子 Tab 各司其职：

```
⏪ 回测分析
│
├── [SubTabBar: 📊回测运行 | 📋策略对比 | 📜交易明细]
│
├── 📊 回测运行     11.1  选策略→设参数→跑回测→权益曲线+指标+交易明细
├── 📋 策略对比     11.2  多策略叠加权益曲线+核心指标对比表
└── 📜 交易明细     11.3  逐笔交易记录(买入/卖出/P&L/持有天数)
```

| 维度 | 操盘手 | 个人投资者 |
|---|---|---|
| **核心问题** | 策略在历史上表现如何？哪个参数最优？和别的策略比谁好？ | 这个模型靠谱吗？能赚钱吗？ |
| **可见 Tab** | 3 个全可见 | 回测运行（简化） + 交易明细 |
| **操作** | 完整参数配置 + 多策略对比 + 导出 | 简化为选择策略+日期 |

> **角色映射（项目 RBAC 4 角色）**：操盘手 → `internal_analyst`；个人投资者 → `user`；系统管理员 → `admin`；外部分析师 → `external_analyst`（只读）。金额打码/数据过滤一律由服务端按 JWT 角色执行，前端禁止传 `X-User-Role` 等身份头。

## 4. 核心数据结构

```typescript
// ===== 回测参数 =====
interface BacktestParams {
  strategyId: string
  startDate: string                  // "2025-01-01"
  endDate: string                    // "2026-06-25"
  initialCapital: number             // 1000000
  feeRate: number                    // 0.0003
  slippage: number                   // 0.0001
  stampDuty: number                  // 0.0005 (仅卖出)
  topN: number                       // 20
  benchmark?: string                 // "000300.SH" 基准指数
}

// ===== 回测结果 =====
interface BacktestResult {
  id: string
  params: BacktestParams
  status: 'running' | 'completed' | 'failed'
  progress: number                   // 0-100

  dailyPoints: DailyPoint[]
  metrics: BacktestMetrics
  trades: TradeRecord[]
  monthlyReturns: MonthlyReturn[]

  createdAt: string
  completedAt?: string
}

interface DailyPoint {
  date: string                       // "2025-01-02"
  nav: number                        // 1,023,500
  cumReturn: number                  // +0.0235 = +2.35%
  dailyReturn: number                // +0.012 = +1.2%
  benchmarkCumReturn: number         // +0.008 = +0.8%
  drawdown: number                   // 0 = 无回撤
  drawdownPct: number                // 0%
}

interface BacktestMetrics {
  totalReturn: number                // +0.428
  totalReturnPct: number             // +42.8%
  annualReturn: number               // +0.263
  annualReturnPct: number           // +26.3%
  maxDrawdown: number                // -0.153
  maxDrawdownPct: number             // -15.3%
  sharpeRatio: number                // 1.85
  calmarRatio: number                // 1.72
  winRate: number                    // 0.623
  profitLossRatio: number            // 2.35
  annualVolatility: number           // 0.182
  dailyTurnover: number              // 0.15 (日均换手)
  totalTrades: number                // 87
  winningTrades: number              // 54
  losingTrades: number               // 33
  maxConsecutiveWins: number         // 7
  maxConsecutiveLosses: number       // 4
  avgHoldingDays: number             // 12.3
}

// ===== 交易记录（round-trip 成对记录，/trades 端点的统一返回结构） =====
// 一次完整交易 = 买入 + 卖出 成对呈现，供交易明细页直接展示。
// 原始逐笔成交（side/qty/amount）作为子资源 TradeLeg 保留，
// 经 GET /backtest/{backtestId}/trades/{tradeId}/legs 按需获取。
interface TradeRecord {
  id: number
  tsCode: string
  name: string
  buyDate: string                    // "2025-01-03"
  sellDate: string                   // "2025-01-10"
  buyPrice: number                   // 195.00
  sellPrice: number                  // 218.50
  qty: number                        // 成交股数
  amount: number                     // 买入金额
  returnPct: number                  // +12.1 (收益率 %)
  holdingDays: number                // 5
  reason: 'take_profit' | 'stop_loss' | 'expire'
}

// ===== 原始逐笔成交（legs 子资源） =====
interface TradeLeg {
  id: number
  tradeId: number                    // 所属 TradeRecord.id
  tsCode: string
  side: 'buy' | 'sell'
  date: string
  price: number
  qty: number
  amount: number
  fee: number                        // 手续费+印花税
}

interface MonthlyReturn {
  year: number
  month: number
  returnPct: number                  // +5.2%
}

// ===== 策略对比 =====
// CompareResult 统一口径（11.2 详细设计引用本定义，不再自行重定义）：
// - 策略 metrics 使用全量 BacktestMetrics（对比表仅取 6 项子集展示）；
// - 基准 metrics 含 sharpeRatio。
interface CompareResult {
  strategies: StrategyResult[]
  benchmark: BenchmarkResult
}

interface StrategyResult {
  strategyId: string
  strategyName: string
  dailyPoints: DailyPoint[]
  metrics: BacktestMetrics
  color: string                      // ECharts 颜色
}

interface BenchmarkResult {
  name: string                       // "沪深300"
  dailyPoints: { date: string; cumReturn: number }[]
  metrics: Pick<BacktestMetrics, 'annualReturnPct' | 'maxDrawdownPct' | 'sharpeRatio'>
}
```

## 5. 数据流

```
┌──────────────────────────────────────────────────────────────┐
│                       回测数据流                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  用户配置参数 → POST /backtest/run                           │
│       │                                                      │
│       ▼                                                      │
│  backtest-service (8007)                                     │
│       │                                                      │
│       ├── 加载历史K线数据 (PG/screener-service)                │
│       ├── 按策略信号生成交易                                   │
│       ├── 逐日计算收益/回撤/费用                               │
│       └── 存储结果到 PG                                       │
│       │                                                      │
│       ▼                                                      │
│  GET /backtest/{id}/progress (轮询 2s/次)                     │
│       │                                                      │
│       ▼                                                      │
│  GET /backtest/{id}/result (完成后拉取)                       │
│       │                                                      │
│       ├── dailyPoints → 收益曲线 + 回撤曲线                    │
│       ├── metrics → 统计指标面板                               │
│       ├── monthlyReturns → 月度热力图                         │
│       └── trades → 交易明细表 (round-trip 成对记录)            │
│                                                              │
│  交易明细页:                                                  │
│  GET /backtest/{backtestId}/trades → round-trip 交易列表      │
│  GET /backtest/{backtestId}/trades/{tradeId}/legs             │
│       → 某笔交易的原始逐笔成交 (buy/sell legs, 展开查看)       │
│                                                              │
│  注: 上述 {id} 一律为 backtestId（回测记录 ID），              │
│      非 strategyId。按策略查交易时，先经                       │
│      GET /backtest/history?strategyId={id} 取最近回测记录。    │
│                                                              │
│  策略对比数据流:                                               │
│  POST /backtest/compare → 并行跑多个策略 → CompareResult      │
│                                                              │
│  数据量预估:                                                  │
│  ├── 1年约250个交易日 → dailyPoints 250条                     │
│  ├── 交易约50-100笔 → trades 100条                            │
│  └── 图表渲染无性能瓶颈                                        │
└──────────────────────────────────────────────────────────────┘
```

## 7. API 端点清单

> 路径参数 `{id}` 一律为 **backtestId**（回测记录 ID），非 strategyId。
> `tenantId / ownerUserId` 由后端从 JWT + 会话解析注入，请求 schema 不显式传；DB 层写操作必带。
> 实现状态：现有 backtest-service (`/api/v1/backtest` 前缀) 已实现 `/run`、`/compare`、`/factors`、`/ic-decay` 等；下表中标注 *(新增)* 的端点为本次设计新增，**待实现时验证**。

| 方法 | 端点 | 用途 | 响应 |
|---|---|---|---|
| `GET` | `/api/v1/backtest/strategies` | 可回测策略列表 *(新增)* | `Strategy[]` |
| `POST` | `/api/v1/backtest/run` | 启动回测 | `{ backtestId, status: 'running' }` |
| `GET` | `/api/v1/backtest/{id}/progress` | 查询回测进度 *(新增)* | `{ progress, status }` |
| `GET` | `/api/v1/backtest/{id}/result` | 获取回测结果 *(新增)* | `BacktestResult` |
| `GET` | `/api/v1/backtest/{id}/trades` | 分页交易明细（round-trip） *(新增)* | `{ items: TradeRecord[], total }` |
| `GET` | `/api/v1/backtest/{id}/trades/{tradeId}/legs` | 单笔交易的原始逐笔成交 *(新增)* | `{ items: TradeLeg[] }` |
| `POST` | `/api/v1/backtest/compare` | 多策略对比运行 | `{ compareId, status }` |
| `GET` | `/api/v1/backtest/compare/{id}` | 获取对比结果 *(新增)* | `CompareResult` |
| `GET` | `/api/v1/backtest/history` | 历史回测记录（支持 `?strategyId=` 过滤） *(新增)* | `BacktestResult[]` |
| `DELETE` | `/api/v1/backtest/{id}` | 删除回测记录 *(新增)* | `{ success }` |

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 回测分析：回测引擎公共，参数、结果、报告默认私有。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共因子/行情 + 私有回测结果。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 复盘写回 Plan，不直接交易。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
