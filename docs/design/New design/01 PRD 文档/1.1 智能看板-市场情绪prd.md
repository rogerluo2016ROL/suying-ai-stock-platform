# PRD — 智能看板·市场情绪

- **Date**: 2026-06-25
- **Owner**: product-lead
- **Status**: Draft
- **Estimated effort tier**: Large（前端 1 页面 ~1000 行 + 后端 3~4 新端点 + 情绪快照存储 + 2 个 ECharts）

## 1. Background

市场情绪（Market Sentiment）是量化交易决策的"背景板"——在牛市追涨、在熊市防御、在震荡市做波段，都需要先判断市场处在哪种情绪状态。

当前速赢AI已有部分情绪相关能力：

| 现有能力 | 位置 | 不足 |
|---|---|---|
| `market_regime_v2` 八维风向模型 | `market_regime.py`，已嵌入 `dashboard-summary` | 仅作为 Dashboard JSON 中的一个字段，无独立展示、无历史追踪 |
| 基础市场情绪评分（涨跌幅聚合） | `signal-service/dashboard-summary:17-87` | 公式简单（`(avg_chg+3)/6×100`），维度单一 |
| 涨跌停统计 | `stk_limit` 表 + Dashboard 卡片 | 无趋势追踪、无盘中实时变化 |
| 异常成交量预警 | Dashboard 预警区域 | 仅 Top 5，无系统性监控 |
| 资金流向评分 | `score_money_flow` scorer | 仅用于个股信号分析，无全市场资金全景 |
| 北向资金/融资融券 | `market_regime_v2` 子维度 | 仅用于综合评分，无独立展示 |

**用户痛点**：

1. **操盘手**需要盘前/盘中/盘后持续监控市场情绪变化，判断今天是"进攻"还是"防守"，现有 Dashboard 只给一个数字，没有演变过程
2. **操盘手**需要板块级别的情绪分化——全市场中性不代表所有板块中性，TMT 狂热+周期悲观=结构性机会
3. **个人投资者**需要一个"一眼看懂"的仪表盘——像水温计一样直观地显示市场冷热
4. 缺乏情绪急变预警——情绪从 70 骤降到 40 比停留在 40 更有操作意义
5. 用户提供的设计材料中，舆情/衍生品等模块短期内数据源不足，需要合理规划优先级

## 2. Goal & Non-Goals

**目标**：

- 构建独立的"市场情绪看板"，以综合情绪指数为核心，向下展开为八维解构 + 板块分化 + 情绪趋势
- KPI：用户打开页面后 3 秒内判断当前市场情绪等级（极熊/偏熊/中性/偏牛/极牛），10 秒内定位情绪异常信号

**Non-Goals**：

- 不做 NLP 舆情分析（需要额外的新闻/社交媒体数据源 + LLM 集成，留待 Phase 3~4）
- 不做期权 PCR/VIX 等衍生品情绪指标（需要衍生品行情数据源，留待 Phase 3）
- 不做个性化情绪报告/建议生成（需要用户画像 + LLM，留待后续智能 PRD）
- 不做盘中实时秒级推送（本次做分钟级轮询刷新）
- 不新增数据采集渠道（复用现有 `daily_kline`/`stk_limit`/`money_flow` 数据）

## 3. User Stories

| ID | As a | I want to | So that |
|---|---|---|---|
| US-1 | 操盘手 | 看到一个 0-100 的综合情绪指数仪表盘（含八维分解） | 3 秒内判断当前市场是"进攻市"（>60）还是"防御市"（<40）|
| US-2 | 操盘手 | 看到 30/60/120 日的情绪趋势图，标注关键高点和低点 | 判断情绪是在上升通道、下降通道还是区间震荡 |
| US-3 | 操盘手 | 看到各行业板块的情绪分化热力图（偏牛板块 vs 偏熊板块） | 识别结构性机会——在整体中性市场中找到局部狂热/恐慌的板块 |
| US-4 | 操盘手 | 看到涨跌停数量 + 炸板率的实时统计 | 判断市场攻击力和封板意愿，识别"假强势" |
| US-5 | 个人投资者 | 看到情绪等级对应的"操作基调"文字建议 | 不需要懂专业术语也知道今天该激进还是保守 |
| US-6 | 个人投资者 | 看到情绪急变时触发预警（颜色+文案+声音提示） | 快速感知市场情绪的反转信号 |
| US-7 | 研究用户 | 看到情绪与沪深300/中证500指数的叠加对比图 | 验证情绪指数是否领先指数，或同步，或滞后 |
| US-8 | 研究用户 | 看到情绪关键事件标注（政策发布日、黑天鹅事件等） | 理解情绪剧烈变化背后的原因 |

### 5.3 数据模型

#### 新增 PG 表

```sql
-- 每日情绪快照（缓存 + 历史追溯）
CREATE TABLE IF NOT EXISTS sentiment_snapshots (
    id SERIAL PRIMARY KEY,
    trade_date DATE NOT NULL UNIQUE,
    score DOUBLE PRECISION NOT NULL,
    level TEXT NOT NULL,               -- BULL / NEUTRAL_BULL / NEUTRAL / NEUTRAL_BEAR / BEAR / BLACK_SWAN
    confidence DOUBLE PRECISION,
    trend_score DOUBLE PRECISION,
    breadth_score DOUBLE PRECISION,
    liquidity_score DOUBLE PRECISION,
    leverage_score DOUBLE PRECISION,
    foreign_score DOUBLE PRECISION,
    valuation_score DOUBLE PRECISION,
    risk_score DOUBLE PRECISION,
    sentiment_score DOUBLE PRECISION,
    up_count INTEGER,
    down_count INTEGER,
    blow_count INTEGER,
    avg_chg DOUBLE PRECISION,
    factor_hints TEXT,
    alerts JSONB DEFAULT '[]',
    generated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_sentiment_snapshots_date ON sentiment_snapshots(trade_date DESC);

-- 关键事件表
CREATE TABLE IF NOT EXISTS key_events (
    id SERIAL PRIMARY KEY,
    event_date DATE NOT NULL,
    event TEXT NOT NULL,
    event_type TEXT NOT NULL,          -- 政策 / 外部 / 黑天鹅 / 公司
    impact_level TEXT DEFAULT 'medium',-- high / medium / low
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

> `sentiment_snapshots` 由 APScheduler 在每个交易日盘后（15:30）自动执行 `market_regime_v2` 计算并写入。历史回溯端点直接读此表。

## 6. Technical Constraints

- 前端框架：React 18 + TypeScript 5.6 + Ant Design 5.22 + ECharts 6.1
- 页面实现：作为 `Dashboard.tsx` 的 Tab 面板，不创建独立路由。左侧菜单仅一项"AI 智能看板"，页内通过 `<Tabs>` 切换：概览 \| 市场情绪 \| 竞价意图 \| 信号总览 \| 自选跟踪
- 后端框架：FastAPI + uvicorn，新增端点放入 `signal-service/app/routes.py`
- 设计系统：严格遵循 `docs/design/new front/design-spec.md` 及 `design-tokens.css`
- 情绪等级颜色映射（以 A 股惯例为准）：

| 等级 | 分值 | 背景色调 | 说明 |
|---|---|---|---|
| 极牛 (BULL) | 80-100 | 红暖系（`var(--up)` 渐变） | A股牛=红，风险提示 |
| 偏牛 (NEUTRAL_BULL) | 60-80 | 橙暖系（`var(--warn)` 渐变） | 偏暖但不过热 |
| 中性 (NEUTRAL) | 40-60 | 蓝灰系（`var(--accent)` 浅色） | 中性 |
| 偏熊 (NEUTRAL_BEAR) | 20-40 | 绿冷系（`var(--down)` 浅色） | A股熊=绿 |
| 极熊 (BEAR) | 0-20 | 绿冷系（`var(--down)` 渐变） | 极熊=深绿 |
| 黑天鹅 (BLACK_SWAN) | — | 紫色（`#722ed1`） | 异常事件 |

- 仪表盘（Gauge）：ECharts gauge 类型，半径 80-100px，极牛端红色、极熊端绿色
- 情绪趋势图：折线图 + 背景色带（Y 轴分段着色）
- 板块热力图：CSS Grid 实现，无需 ECharts heatmap（板块数约 28 个，CSS 性能更好）
- 桌面优先：推荐宽度 ≥1440px
- 不引入新 npm/Python 依赖
- API P95 ≤ 500ms（sentiment-index 读缓存），sentiment-history P95 ≤ 500ms（从 snapshots 表聚合）
