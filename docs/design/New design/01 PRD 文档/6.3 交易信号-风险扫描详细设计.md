## 1. 页面定位

风险扫描是交易信号菜单的**第三 Tab**（Tab key: `risk`），定位为**下单前的安全闸**。

四项硬检查按固定顺序垂直排列：
1. 🔍 审计检查
2. 📋 公告检查
3. ⚠️ ST/退市检查
4. 📊 业绩检查

任一高危 → 综合风险评级标红，建议暂停下单。所有通过 → 绿色低风险。

## 3. 核心数据结构

```typescript
// 见 6.0 交易信号详细设计.md §2.4

type RiskCheckStatus = 'pass' | 'warning' | 'danger'

interface RiskCheckItem {
  key: 'audit' | 'announce' | 'st' | 'forecast'
  label: string              // "审计检查" / "公告检查" / "ST/退市检查" / "业绩检查"
  icon: string               // "🔍" / "📋" / "⚠️" / "📊"
  status: RiskCheckStatus
  statusIcon: string         // "✅" / "⚠️" / "🔴"
  statusLabel: string        // "已通过" / "关注" / "高危"
  detail: string             // 详细描述
  tags?: RiskTag[]           
}

interface RiskTag {
  text: string               // "减持 0.5%" / "正常上市" / "营收预增"
  severity: 'info' | 'warn' | 'danger'
}

interface RiskScanResult {
  checks: RiskCheckItem[]
  overallRisk: 'low' | 'medium' | 'high'
  overallRiskLabel: string   // "低风险" / "中等风险" / "高风险"
  summary: string            // "四项检查全部通过" / "存在1项关注事项"
  dangerCount: number        // 高危项数量
  warningCount: number       // 关注项数量
}
```

## 4. 风险检查卡片（RiskCheckCard）

```typescript
// 文件: components/signals/RiskCheckCard.tsx

interface RiskCheckCardProps {
  item: RiskCheckItem
}

const STATUS_BG_MAP: Record<RiskCheckStatus, string> = {
  pass: 'rgba(46,194,126,0.06)',
  warning: 'rgba(245,166,35,0.06)',
  danger: 'rgba(255,77,79,0.06)',
}

const STATUS_BORDER_MAP: Record<RiskCheckStatus, string> = {
  pass: 'rgba(46,194,126,0.2)',
  warning: 'rgba(245,166,35,0.25)',
  danger: 'rgba(255,77,79,0.25)',
}

function RiskCheckCard({ item }: RiskCheckCardProps) {
  return (
    <div 
      className="ri"
      style={{ 
        background: STATUS_BG_MAP[item.status],
        borderColor: STATUS_BORDER_MAP[item.status],
      }}
    >
      <div className="ris">
        <span className="ric">{item.statusIcon}</span>
        <span>{item.icon} {item.label}</span>
        <span style={{ marginLeft: 'auto' }}>
          <RiskStatusBadge status={item.status} label={item.statusLabel} />
        </span>
      </div>
      <div className="rid">{item.detail}</div>
      {item.tags && item.tags.length > 0 && (
        <div className="rit">
          {item.tags.map((tag, i) => (
            <span key={i} className={tag.severity === 'info' ? 'it' : tag.severity === 'warn' ? 'iw' : 'id'}>
              {tag.text}
            </span>
          ))}
        </div>
      )}
    </div>
  )
}

function RiskStatusBadge({ status, label }: { status: RiskCheckStatus; label: string }) {
  const color = status === 'pass' ? 'var(--down)' : status === 'warning' ? 'var(--warn)' : 'var(--up)'
  const bg = status === 'pass' ? 'rgba(46,194,126,0.1)' : status === 'warning' ? 'rgba(245,166,35,0.1)' : 'rgba(255,77,79,0.1)'
  
  return (
    <span style={{
      fontSize: 10, padding: '2px 8px', borderRadius: 4,
      color, background: bg, fontWeight: 600,
    }}>
      {label}
    </span>
  )
}
```

## 6. 一票否决逻辑

```typescript
// 后端: signal-service/app/services/risk_scanner.py

function computeOverallRisk(checks: RiskCheckItem[]): {
  overallRisk: 'low' | 'medium' | 'high'
  summary: string
} {
  const dangerCount = checks.filter(c => c.status === 'danger').length
  const warningCount = checks.filter(c => c.status === 'warning').length
  
  if (dangerCount > 0) {
    return {
      overallRisk: 'high',
      summary: `存在 ${dangerCount} 项高危事项，建议暂停下单`,
    }
  }
  
  if (warningCount > 0) {
    return {
      overallRisk: 'medium',
      summary: `存在 ${warningCount} 项关注事项，建议谨慎操作`,
    }
  }
  
  return {
    overallRisk: 'low',
    summary: '四项检查全部通过',
  }
}
```

## 7. 视图差异：操盘手 vs 个人投资者

```typescript
interface RiskScanTabProps {
  riskScanResult: RiskScanResult
  userRole: 'trader' | 'investor'
}

const isTrader = userRole === 'trader'

{isTrader ? (
  // 完整四项卡片 + 综合评级
  <>
    {riskScanResult.checks.map(check => <RiskCheckCard item={check} />)}
    <OverallRiskBanner result={riskScanResult} />
  </>
) : (
  // 简化：仅综合评级 + 风险摘要
  <>
    <OverallRiskBanner result={riskScanResult} />
    <SimplifiedRiskSummary checks={riskScanResult.checks} />
  </>
)}

// SimplifiedRiskSummary: 仅展示非 pass 状态的检查项摘要（≤2 行）
function SimplifiedRiskSummary({ checks }: { checks: RiskCheckItem[] }) {
  const nonPassChecks = checks.filter(c => c.status !== 'pass')
  if (nonPassChecks.length === 0) return null
  
  return (
    <div style={{ marginTop: 8, fontSize: 11, color: 'var(--fg-2)' }}>
      {nonPassChecks.map(c => (
        <div key={c.key} style={{ padding: '4px 0' }}>
          {c.statusIcon} {c.label}: {c.detail.slice(0, 60)}...
        </div>
      ))}
    </div>
  )
}
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 交易信号：公共信号规则与用户私有订阅、处理状态分离。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共信号 + 私有已读/订阅/处置。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 信号只作为订单依据之一。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
