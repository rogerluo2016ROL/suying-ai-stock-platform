## 1. 页面定位

执行监控是开盘决策的**盘中持续监控** Tab。操盘手在 9:30 开盘后切换至此，持续跟踪：**订单执行状态 → 持仓盈亏变化 → 策略运行健康**。

与风控中心的关系：执行监控展示「执行层」信息（订单/持仓/策略状态），风控中心展示「规则层」信息（熔断/止损规则/审计/公告）。两者互补。

| 使用场景 | 时段 | 用户关注 |
|---|---|---|
| 9:30 开盘后 | 盘中 | 订单是否成交 → 持仓盈亏变化 → 是否触发止损 |
| 11:30 午间 | 盘中 | 上午策略表现 → 半日盈亏统计 |
| 15:00 收盘后 | 盘后 | 全日订单回顾 → 持仓市值快照 → 策略日终复盘 |

## 2. 角色显示规则

| 区域 | 操盘手 (admin) | 个人投资者 (user) |
|---|---|---|
| 账户总览 | 完整金额 + 总资产 | 金额打码 `¥***` + 百分比显示 |
| 订单列表 | 全部订单 + 撤单/改单操作 | 仅「我的订单」 + 只读 |
| 持仓盈亏 | 全部持仓 + 止损/加仓/减仓 | 仅「我的持仓」 + 止损建议（只读）|
| 策略状态 | 全部策略 + 启动/暂停操作 | 只读 + 「策略今日盈亏」摘要 |
| 金额列 | `¥218.50` | `¥***` |
| 盈亏金额 | `+12,580` | `+***` (百分比可见) |

```typescript
type RoleViewMode = 'trader' | 'investor'

function maskAmount(amount: number, role: RoleViewMode): string {
  if (role === 'investor') return '¥***'
  return `¥${amount.toLocaleString()}`
}

function maskPnL(pnl: number, pnlPct: number, role: RoleViewMode): {
  amount: string
  pct: string
} {
  return {
    amount: role === 'investor' ? '+***' : `¥${pnl.toLocaleString()}`,
    pct: `${pnlPct >= 0 ? '+' : ''}${pnlPct.toFixed(2)}%`
  }
}
```

## 5. 数据流

```
ExecutionMonitorTab mount
│
├── 读取 OpeningDecisionContext
│   ├── timeSlot → 决定刷新频率 (盘中 30s / 盘后 60s / 非交易 不刷新)

├── 并行加载:
│   ├── GET /api/v1/trade/account                              ← trade-service
│   │   └── response: AccountOverview
│   │

│   │
│   ├── GET /api/v1/trade/positions                            ← trade-service
│   │   └── response: { positions: PositionRecord[] }
│   │
│   ├── GET /api/v1/strategy/status                            ← strategy-service

│   └── GET /api/v1/trade/circuit-breaker/status               ← trade-service

│
├── 计算:
│   ├── 账户聚合 → AccountBar

└── 操盘手操作:

    │   └── body: { code, direction: 'sell', type: 'market', volume }
    └── 加仓/减仓 → POST /trade/order
        └── body: { code, direction, price, volume }
```

### 6.1 自动刷新机制

```
盘中 (intraday):
├── 30s 自动轮询 (setInterval 30_000)
├── 刷新指示器显示 "下次刷新: XXs" 倒计时
├── 手动刷新按钮随时可用
└── 数据更新时行闪烁动画 (黄色闪一下, 持续 300ms)

盘后 (post-market):
├── 60s 自动轮询 (策略/持仓可能还有变化)
└── 刷新指示器文字变小/淡化

非交易时段 (non-trading):
└── 不自动刷新，显示上次数据 + "数据显示 {date}"
```

```typescript
// hooks/useAutoRefresh.ts
function useAutoRefresh(
  callback: () => Promise<void>,
  intervalMs: number | null,    // null = 停止
  enabled: boolean
) {
  const [countdown, setCountdown] = useState(intervalMs ? intervalMs / 1000 : 0)

  useEffect(() => {
    if (!enabled || intervalMs === null) return

    const timer = setInterval(() => {
      callback()
      setCountdown(intervalMs / 1000)
    }, intervalMs)

    const countdownTimer = setInterval(() => {
      setCountdown(prev => Math.max(0, prev - 1))
    }, 1000)

    return () => {
      clearInterval(timer)
      clearInterval(countdownTimer)
    }
  }, [intervalMs, enabled])
}
```

## 平台化优化补充

> 继承自 `0.3 平台化云端多租户总体需求设计.md`、`0.4 平台化云端多券商架构设计.md`、`0.5 平台化详细方案设计.md`。

| 维度 | 设计要求 |
|---|---|
| 模块定位 | 开盘决策：操盘手默认入口，输出私有 Candidate 与 DecisionContext。 |
| 角色差异 | 操盘手保留专业工作台；个人投资者默认简化解释视图；系统管理员获得配置、审计和运行治理视图。 |
| 数据隔离 | 公共竞价/行情 + 私有候选池。所有私有对象必须写入 `tenantId / ownerUserId / accountId? / visibility / dataScope`。 |
| 云端部署 | API 必须从认证上下文恢复租户与用户身份，禁止前端传入越权租户；列表接口默认只返回当前身份可见数据。 |
| 券商/交易 | 实盘前必须进入方案与风控。凡涉及资金、订单、策略启停的动作必须经过 `RiskGate` 并写入 append-only 审计。 |
| 原型要求 | 页面顶部展示角色视图、数据域、账户隔离、券商模式和云端就绪状态；不得把公共行情数据与私有交易数据混在同一区块而不标识。 |
