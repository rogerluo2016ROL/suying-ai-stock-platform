# 速赢AI 公共对象字段契约

日期：2026-06-28  
适用范围：新 UI、BFF、后端服务、模型服务、交易服务、数据库迁移  
主链路：候选池 -> 方案管理 -> 下单面板 -> 风控闸门 -> 回测复盘

## 1. 契约目标

`DecisionContext`、`Candidate`、`Plan`、`Order`、`RiskVerdict` 是速赢AI P0 交易决策闭环的公共对象。所有前端页面、BFF 聚合接口、微服务和数据库表必须围绕这五个对象传递上下文、归属边界和审计链路。

## 2. 公共归属字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| tenant_id | string | 私有对象必填 | 租户边界。公共市场/模型数据可为 `platform`。 |
| owner_user_id | string | 用户私有对象必填 | 对象所属用户。管理员跨租户查看不能改写归属。 |
| account_id | string/null | 交易对象必填 | 交易账户边界。订单、持仓、风控、账户数据必填。 |
| visibility | private/tenant_shared/public | 必填 | 默认 `private`。模板可 `tenant_shared`，公共行情/模型可 `public`。 |
| data_scope | public/tenant/user/account | 必填 | 决定最小隔离范围。交易对象默认 `account`。 |
| role_view | trader/investor/admin | 响应建议返回 | 前端按角色裁剪页面复杂度。 |
| trade_mode | paper/live/null | 交易相关必填 | 默认 `paper`。实盘必须经风控和审计。 |
| broker_adapter | paper/xtquant_qmt/broker_rest/null | 交易相关必填 | 前端只展示适配器状态，不接触密钥。 |

## 3. 公共链路字段

| 字段 | 类型 | 说明 |
|---|---|---|
| decision_context_id | string/null | 记录模型、用户或系统动作的决策上下文 |
| candidate_id | string/null | 候选标的来源 |
| plan_id | string/null | 投资方案 |
| order_id | string/null | 订单 |
| risk_verdict_id | string/null | 风控判定 |
| backtest_id | string/null | 回测或复盘结果 |
| model_version | string/null | 使用的模型版本 |
| data_as_of | string/null | 数据时点 |
| created_at | datetime | 创建时间 |
| updated_at | datetime/null | 更新时间 |
| created_by | string/null | 创建人 |
| audit_trace_id | string/null | 审计链路 ID |

## 4. DecisionContext

记录一次决策的输入、意图、模型、证据和用户动作。任何候选加入、方案生成、下单、风控放行都应能追溯到一个 `DecisionContext`。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| decision_context_id | string | 是 | 主键，建议 `DC-YYYYMMDD-xxxx` |
| source_type | screener/signal/prediction/supply_chain/manual/strategy/system | 是 | 来源类型 |
| source_id | string/null | 否 | 来源对象 ID，如 signal_id、screen_run_id |
| intent | string | 是 | 用户或系统意图，如 `open_decision_candidate` |
| title | string | 是 | 前端展示标题 |
| summary | string | 是 | 简明解释 |
| payload | object | 是 | 原始输入、筛选条件、上下文 |
| evidence | array | 是 | 证据列表，包含字段、数值、来源 |
| model_refs | array | 否 | 模型/规则版本 |
| confidence | number/null | 否 | 0-100 |
| status | draft/confirmed/expired/cancelled | 是 | 默认 `draft` |

## 5. Candidate

候选标的是进入方案前的统一对象，来源可以是智能选股、信号扫描、产业链公司、K线预测或人工加入。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| candidate_id | string | 是 | 主键 |
| code | string | 是 | 股票代码 |
| name | string | 是 | 股票名称 |
| market | string | 否 | 交易市场 |
| industry | string | 否 | 行业 |
| theme_tags | array | 否 | 主题/产业链标签 |
| source_mode | string | 是 | 来源模式，如 `auction_resonance` |
| source_score | number | 是 | 来源评分 |
| signal_strength | number/null | 否 | 信号强度 |
| prediction_return_pct | number/null | 否 | 预测涨跌幅 |
| risk_level | low/medium/high/blocked | 是 | 默认 `medium` |
| entry_reason | string | 是 | 入池理由 |
| factor_breakdown | object | 否 | 因子拆解 |
| evidence_refs | array | 否 | 证据引用 |
| candidate_status | watch/selected/rejected/planned/ordered/expired | 是 | 默认 `watch` |

| candidates | array | 是 | 候选快照 |
| target_positions | array | 是 | 目标仓位 |
| capital | number | 是 | 计划资金 |
| max_positions | number | 是 | 最大持仓数 |
| single_max_pct | number | 是 | 单票上限 |
| rebalance_rule | object | 否 | 调仓规则 |

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| order_id | string | 是 | 平台订单 ID |
| broker_order_id | string/null | 否 | 券商订单 ID |
| code | string | 是 | 股票代码 |
| name | string | 否 | 股票名称 |
| direction | buy/sell | 是 | 买卖方向 |
| order_type | limit/market | 是 | 委托类型 |
| price | number | 是 | 委托价格 |
| volume | number | 是 | 委托数量 |
| amount | number | 是 | 预估金额 |
| status | pending/submitted/filled/partial/cancelled/rejected/failed | 是 | 订单状态 |
| trade_mode | paper/live | 是 | 交易模式 |
| broker_adapter | paper/xtquant_qmt/broker_rest | 是 | 券商适配器 |
| pre_check_result | object | 是 | 交易前检查结果 |
| risk_verdict_id | string | 实盘必填 | 风控判定 |

| filled_at | datetime/null | 否 | 成交时间 |

## 8. RiskVerdict

风控判定覆盖候选、方案、订单和账户动作。它既是页面展示对象，也是实盘动作的硬闸门。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| risk_verdict_id | string | 是 | 主键 |
| target_type | candidate/plan/order/account/strategy | 是 | 判定对象类型 |
| target_id | string | 是 | 判定对象 ID |
| result | pass/warn/reject/manual_review | 是 | 结论 |
| severity | info/warn/high/blocker | 是 | 严重程度 |
| score | number | 是 | 0-100，越高风险越大 |
| checks | array | 是 | 规则检查明细 |
| blockers | array | 否 | 阻断原因 |
| warnings | array | 否 | 警告项 |
| required_actions | array | 否 | 继续前必须动作 |
| reviewer_id | string/null | 否 | 人工复核人 |
| reviewed_at | datetime/null | 否 | 人工复核时间 |
| expires_at | datetime/null | 否 | 判定有效期 |

## 9. 页面消费原则

1. 公共行情、公共模型、公共策略模板可以跨用户共享。
2. 自选、候选、方案、订单、持仓、风控、复盘必须按 tenant/user/account 隔离。
3. 前端不能信任路由或 localStorage 里的租户/账户作为权限依据；后端必须从认证上下文和服务端账户绑定解析。
4. 每个页面响应都应带 `context`、`freshness`、`lineage`、`actions`。
5. 下单默认走模拟盘；实盘必须具备 BrokerAccount、RiskVerdict、审计记录和二次确认。
