## 2. 后端设计优化评估（任务 2 —— 设计文档层面）

### 2.1 P0 —— 安全与权限原则冲突

1. **2.5 执行监控详细设计用前端注入 `X-User-Role` 头做数据过滤/金额打码** —— 直接违反 0.3/0.4「权限以后端 JWT/RBAC 为准」原则。必须改为：后端按 JWT 角色过滤，金额打码在服务端完成。
2. **角色模型三套并存**：0.1 列 6 角色、0.4 收敛 5 角色（trader/investor/risk_admin/model_admin/sys_admin）、代码实为 RBAC 4 角色（admin/internal_analyst/external_analyst/user）。需在 0.1/0.4 补**角色映射表**，全部详细设计的角色描述按映射表改写。
3. 9.3 水印「操盘手专用」应走后端权限而非装饰。

### 2.3 P1 —— 设计缺口

1. **风控中心写操作 API 全缺**：PRD AC-4 要求暂停/恢复策略、止损/减仓/一键平仓，详细设计只有 `GET /trade/risk-dashboard` 一个聚合端点。需补 POST 端点设计 + `services/trade-service/app/routers/risk.py` 文件清单扩写。
2. **风险评分算法三处口径不一**（10.0 PRD 审计/公告各+40 vs 10.2 PRD 公告+40/审计+20 vs 10.0 详设按 tag.level +40/+20）——统一为详设版并回写两份 PRD。
3. **服务归属未定项收口**：`POST /risk/check-batch`（risk-service 存在性未定，建议并入 trade-service，与熔断/RiskGate 同域）；产业链 LLM 调用归属（建议 screener 调 LLM 网关而非 strategy-service）；5.x `PredictionResult` 聚合了 signal 数据，聚合职责建议放 prediction-service BFF 层但需写明降级策略。
4. **16.0 前端直连探测不可行**：compose 下 8001–8010 仅绑 127.0.0.1 且已接 kronos-auth，浏览器直连 health 会撞 CORS/鉴权。改为 api-gateway 聚合探测（扩展现有 `/runtime/readiness`）。
5. **MLflow 基线冲突**：13.x/14.0 假定真实 MLflow（localhost:5000 + Model Registry），项目默认 `MLFLOW_MODE=mock` 且 compose 无 mlflow 服务。需在设计中界定 mock/real 两种模式的 API 行为。
6. **0.5 网关路由矩阵补登**：缺 `/api/v1/watchlist`、`/api/v1/risk` 前缀；各详细设计新增端点多数未登记。
7. **候选池持久化决策**：2.0 Q-2「V1 不持久化」与 0.5 Phase B3-2 Candidate 快照契约、平台化方向冲突——需明确 V1 落库（建议持久化，成本不高）。
8. **数据契约补全**：`signal_history` 表 schema（6.x 命中率依赖）、`sentiment_snapshots`+`key_events` 表、审计表 schema、factor IC 缓存表——均只有引用无定义。
9. **42 表 / 51 调度任务**为硬编码示例数，需与实际 data-service 配置对齐并给出清单来源。
10. **1.4 自选跟踪内部矛盾**：PRD 声明「V1 无用户隔离共享一张表」与平台化「私有对象必带 tenantId/ownerUserId」冲突——按平台化为准（加字段，默认单租户）。

### 2.4 P1 —— 文档勘误（编号/版本漂移）

- 4.x 全部文档把父文档误引为「5.0 产业链拆解」；9.0 PRD 子模块编号误写 6.1-6.4；13.0/14.0/15.0 详设头部引用「5.7/5.8/5.9 prd.md」——批量修正
