# ADR-015.4: stock_profiles.py PG 路径迁移到 `_pg_write` UPSERT

- 状态：**Accepted**（2026-06-22 tech-lead 自实施 + SIT 7/7 pass，含真实写库验证 UPSERT 业务列刷新 + updated_at 100% 还原不刷）
- 日期：2026-06-22
- 决策者：tech-lead 起草自实施
- 影响范围：`services/data-service/app/sync/stock_profiles.py` 单文件 PG 写入路径
- 父 ADR：ADR-015 §决策 4 + ADR-015.2 优先级重排（P2 → P1）

## 上下文

ADR-015.2 审计 tushare.py 时发现：盘点报告低估了 path #4 真正未收口的 PG 模块。`stock_profiles.py` PG 路径用 `inline-execute_values` + 手拼 `ON CONFLICT(code) DO UPDATE SET`（`stock_profiles.py:81-99`），16 列 high risk，未走 `_pg_write` 主干。

ADR-015.0 已为 `_pg_write` 加 `conflict_action="update"` 参数，本 ADR 是 015.0 API 的第二个真实业务用例（首个：ADR-015.1 stocks.py）。

### 现状

```python
# stock_profiles.py:81-99 (inline-execute_values)
update_cols = [c for c in pg_cols if c != "code"]  # 14 业务列
set_clause = ", ".join(f"{c}=EXCLUDED.{c}" for c in update_cols)
sql = f"INSERT INTO stock_profiles(...) VALUES(...) ON CONFLICT(code) DO UPDATE SET {set_clause}"
execute_values(cur, sql, all_rows, page_size=500)
```

业务语义：UPSERT（公司基本信息可能变化：chairman/manager/employees/introduction 等），14 业务列全更新，**不刷新 updated_at**（pre-existing 行为，首次 INSERT 走 DEFAULT NOW()，后续 UPSERT 不刷）。

### 不做此决策的后果

1. stock_profiles.py 保留 inline-execute_values，不走 `_insert_rows` 自动列过滤（schema drift 防御缺失）
2. 手拼 SQL 字符串，列名错位风险（虽当前 16 列对齐，但防御性收口）
3. ADR-015 path #4 真正未收口模块残留

## 决策

### 决策 0：文件改动白名单

| # | 文件 | 允许改动 |
|---|---|---|
| 1 | `services/data-service/app/sync/stock_profiles.py` | PG 路径 inline-execute_values → `_pg_write(update)`；SQLite 路径保留 `INSERT OR REPLACE`（方案 A 决策） |
| 2 | `docs/adr/015.4-stock-profiles-pg-write-migration.md` | 本 ADR |
| 3 | `progress/tech-lead.md` | SIT 段 |

**禁止**：pg_writer.py / etl.py / scheduler.py / SQLite 路径 / 任何其他 sync 模块。

### 决策 1：`_pg_write` 调用契约

```python
from app.sync.pg_writer import _pg_write

pg_written = _pg_write(
    "stock_profiles",
    columns=pg_cols,  # 15 列: code + 14 业务列
    conflict_cols=["code"],
    rows=all_rows,
    conflict_action="update",
    update_cols=[c for c in pg_cols if c != "code"],  # 14 业务列
)
```

语义对照（与原 inline SQL 100% 等价）：

| 原 inline SQL 子句 | _pg_write 参数 |
|---|---|
| `ON CONFLICT(code)` | `conflict_cols=["code"]` |
| `DO UPDATE SET {14 列=EXCLUDED.x}` | `update_cols=[14 业务列]` |
| 无 `updated_at=NOW()` | 不传 `now_cols`（100% 还原现状） |
| `execute_values(page_size=500)` | `_insert_rows` 内部 `execute_values(page_size=1000)` |

**关键决策：不刷 updated_at**。原 inline 代码不刷，本 ADR 100% 还原（最小变更原则，参考 ADR-013 S-1 教训：不擅自扩 scope）。stock_profiles 表虽有 `updated_at DEFAULT NOW()`，但现状是首次 INSERT 走 DEFAULT，后续 UPSERT 不刷。若业务需刷 updated_at，另开 follow-up issue（不在本 ADR 范围）。

### 决策 2：返回值语义

原 inline：`pg_written = cur.rowcount`（execute_values 后总影响行数，含 INSERT + UPDATE）。
新 `_pg_write`：返回 `_insert_rows` 的 `written`（`cur.rowcount if > 0 else 0`）。
两者语义一致（execute_values 的 rowcount 在 UPSERT 时报总影响行数）。

## 备选方案

- **A. 保留 inline-execute_values** —— pros: 0 改动；cons: path #4 治理失败，schema drift 无防御；**否决**
- **B. 顺手刷 updated_at** —— pros: 监控更准；cons: 改变 pre-existing 行为，违反最小变更原则（ADR-013 S-1 教训）；**否决**（若需，另开 follow-up）
- **C. 改 DO NOTHING** —— pros: 简单；cons: 业务回归（公司信息永不更新）；**否决**
- **D（推荐）**：PG 路径走 `_pg_write(update)`，100% 还原现状（不刷 updated_at），SQLite 保留 —— 采纳
