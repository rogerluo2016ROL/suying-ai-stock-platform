# ADR-015.5: namechange.py PG 路径迁移到 `_pg_write` UPSERT

- 状态：**Accepted**（2026-06-22 tech-lead 自实施 + SIT 7/7 pass，含真实写库验证 UPSERT end_date 回填 + source 列 + st_type 变更）
- 日期：2026-06-22
- 决策者：tech-lead 起草自实施
- 影响范围：`services/data-service/app/sync/namechange.py` 单文件 PG 写入路径（部分）
- 父 ADR：ADR-015 §决策 4 P3 + ADR-015.0（前置）

## 上下文

ADR-015 盘点报告 §1 将 `namechange.py` 列为 P3（PG-only inline，需 UPSERT）。现状两处 PG inline：

1. **`_upsert_st_history` (L106-126)**：`executemany` + `ON CONFLICT(code, start_date) DO UPDATE SET end_date, st_type, source`。业务 UPSERT（ST 区间续接，end_date 随摘帽事件回填）。SQL 在 VALUES 里硬编码 `source='tushare_namechange'` 字面量，intervals 元组是 4 元素 `(code, start_date, end_date, st_type)`。
2. **`_fallback_snapshot` (L129-153)**：`cur.execute` 单条 `INSERT INTO st_history(...) SELECT ... FROM stocks WHERE is_st=1 ON CONFLICT(code, start_date) DO UPDATE SET end_date, source`。**INSERT...SELECT** 形态（从 stocks 表导数据），不走 executemany。

### st_history 表 schema

```sql
CREATE TABLE st_history (
    code TEXT NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE,
    st_type TEXT,
    source TEXT DEFAULT 'tushare_namechange',
    PRIMARY KEY (code, start_date)
);
```

**无 updated_at 列**（与 stocks / stock_profiles 不同），PK = (code, start_date)。

### 不做此决策的后果

1. `_upsert_st_history` 保留 inline executemany，不走 `_insert_rows` 自动列过滤（schema drift 防御缺失）
2. ADR-015 path #4 真正未收口的 PG 模块残留（namechange 是 015.2 重排后剩余两个之一）

## 决策

### 决策 0：文件改动白名单

| # | 文件 | 允许改动 |
|---|---|---|
| 1 | `services/data-service/app/sync/namechange.py` | (a) `_upsert_st_history` inline executemany → `_pg_write(update)`；(b) `_fallback_snapshot` **保留 inline**（INSERT...SELECT 形态，`_pg_write` 无法表达）；(c) `sync_st_history` 调用方适配（intervals 4 元组 → 5 元组含 source） |
| 2 | `docs/adr/015.5-namechange-pg-write-migration.md` | 本 ADR |
| 3 | `progress/tech-lead.md` | SIT 段 |

**禁止**：pg_writer.py / etl.py / scheduler.py / `_fallback_snapshot` 逻辑 / 任何其他 sync 模块。

### 决策 1：`_upsert_st_history` 改造

**问题**：现状 SQL 在 VALUES 硬编码 `source='tushare_namechange'`，intervals 是 4 元组。`_pg_write` 是 values-based，不支持 SQL 字面量列（只走 EXCLUDED 或 NOW）。

**方案**：调用方把 source 作为业务列拼进 rows。`_parse_st_intervals` 返回 4 元组不变（保持解析层纯净），在 `_upsert_st_history` 内部 map 成 5 元组：

```python
def _upsert_st_history(intervals: list[tuple]) -> int:
    if not intervals:
        return 0
    # intervals: (code, start_date, end_date, st_type) → 拼 source 列
    rows = [(c, sd, ed, st, "tushare_namechange") for (c, sd, ed, st) in intervals]
    from app.sync.pg_writer import _pg_write
    return _pg_write(
        "st_history",
        columns=["code", "start_date", "end_date", "st_type", "source"],
        conflict_cols=["code", "start_date"],
        rows=rows,
        conflict_action="update",
        update_cols=["end_date", "st_type", "source"],
    )
```

语义对照（与原 inline SQL 100% 等价）：

| 原 inline SQL 子句 | _pg_write 参数 |
|---|---|
| `ON CONFLICT(code, start_date)` | `conflict_cols=["code", "start_date"]` |
| `DO UPDATE SET end_date, st_type, source` | `update_cols=["end_date", "st_type", "source"]` |
| `source='tushare_namechange'` 字面量在 VALUES | rows 拼 source 列（调用方 map） |
| 无 `updated_at=NOW()` | 不传 `now_cols`（表无 updated_at 列） |
| `executemany` | `_insert_rows` 内部 `execute_values(page_size=1000)` |

**关键**：`code` 和 `start_date` 是 PK，不在 `update_cols`（约束 2：update_cols ∩ conflict_cols = ∅）。表无 updated_at，不传 now_cols。

### 决策 2：`_fallback_snapshot` 保留 inline

`_fallback_snapshot` 是 `INSERT INTO st_history(...) SELECT ... FROM stocks WHERE is_st=1 ON CONFLICT...` —— **INSERT...SELECT** 形态（从 stocks 表导数据，不是 values-based）。

`_pg_write` / `_insert_rows` 是 values-based（`execute_values` 接 rows list），**无法表达 SELECT 子查询**。强行改造会破坏 fallback 逻辑（要么改成两步：先 SELECT 拿 rows 再 `_pg_write`，引入竞态；要么保留 inline）。

按最小变更原则 + ADR-015 方案 A 决策（YAGNI），**保留 `_fallback_snapshot` inline**。本 ADR 只收口 `_upsert_st_history`。

## 备选方案

- **A. 两处都切 `_pg_write`** —— pros: 大一统；cons: `_fallback_snapshot` 是 INSERT...SELECT，`_pg_write` 无法表达，强行改两步引入竞态 + 破坏 fallback；**否决**
- **B. 只收口 `_upsert_st_history`，fallback 保留 inline** —— pros: 最小变更 + 收口高频路径；cons: fallback 仍 inline（但 fallback 是降级路径，低频）；**采纳**
- **C. 改 DO NOTHING** —— pros: 简单；cons: 业务回归（end_date 永不回填，ST 区间错误）；**否决**

## 影响

### 正面

- `_upsert_st_history`（主路径）走 `_insert_rows` 自动列过滤，schema drift 防御
- 消除 inline executemany 手拼 SQL
- ADR-015 path #4 真正未收口 PG 模块 -1（剩 etl_rt_k）

### 负面

- `_fallback_snapshot` 仍 inline（降级路径，低频，可接受）
