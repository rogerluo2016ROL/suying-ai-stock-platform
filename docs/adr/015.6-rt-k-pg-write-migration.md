# ADR-015.6: etl_rt_k PG 路径迁移到 `_insert_rows` UPSERT — path #4 收官

- 状态：**Accepted**（2026-06-22 tech-lead 自实施 + SIT 7/7 pass，含真实写库验证 UPSERT close/high/vol 刷新；path #4 收官）
- 日期：2026-06-22
- 决策者：tech-lead 起草自实施
- 影响范围：`packages/kronos-data/kronos_data/etl.py` `sync_rt_k` 单函数 PG 写入路径
- 父 ADR：ADR-015 §决策 4 P3 + ADR-015.0（前置）

## 上下文

ADR-015 盘点报告 §1 将 `etl_rt_k` 列为 P3（dual-target，inline-execute_values）。本 ADR 审计 + 收口，是 path #4 真正未收口 PG 模块的**最后一个**。

### 审计发现

`packages/kronos-data/kronos_data/etl.py` 有两个 rt_k 相关函数：

1. **`sync_rt_sw_k` (L1463-1500)**：**已经走 `_insert_rows`**（L1497 `_insert_rows(db, "rt_sw_k", cols, rows)`，DO NOTHING 默认）。盘点报告标的 "inline-execute_values" 已过时 —— ADR-009/010 期间已收口。**audit no-op**。
2. **`sync_rt_k` (L1503-1577)**：`db.execute` 逐行 `INSERT INTO rt_k ... ON CONFLICT(code,trade_date) DO UPDATE SET open/high/low/close/vol/amount`（L1557-1568），inline-cursor 逐行 UPSERT，5000 行 = 5000 次 round-trip。**真正未收口**。

### sync_rt_k 现状

```python
# etl.py:1534-1569
sql = "SELECT code, trade_date, open, high, low, close, vol, amount FROM stk_mins ... GROUP BY ..."
rows = db.execute(sql, (latest_dt,)).fetchall()  # 聚合结果
for r in rows:
    db.execute(
        "INSERT INTO rt_k (code, trade_date, open, high, low, close, vol, amount) "
        "VALUES (...) ON CONFLICT (code, trade_date) DO UPDATE SET open=..., high=..., ...",
        (r[0], r[1], r[2], r[3], r[4], r[5], r[6], r[7])
    )
    inserted += 1
```

数据来自 `stk_mins` 聚合（SELECT...GROUP BY），rows 是 query 结果。业务语义 UPSERT（盘中每 5min 刷新当日 rt_k，OHLCV 随分钟线累积更新）。

### rt_k 表 schema（DB 实际）

```sql
-- DB 实际 (init_postgres.sql 的 ts_code 是 stale DDL, ADR-009/010 已对齐到 code)
rt_k: code TEXT, trade_date DATE, open/high/low/close DOUBLE,
      pre_close/change/pct_chg DOUBLE, vol/amount DOUBLE
      UNIQUE(code, trade_date)
```

现状只写 8 列（OHLCV + code + trade_date），pre_close/change/pct_chg 不写（聚合 SQL 也没算，pre-existing 行为）。本 ADR 100% 还原。

### 不做此决策的后果

1. `sync_rt_k` 保留 inline-cursor 逐行 UPSERT，5000 次 round-trip 性能差
2. 不走 `_insert_rows` 自动列过滤（虽 rt_k 当前无 drift，但防御性收口）
3. path #4 真正未收口 PG 模块残留（本 ADR 是最后一个）

## 决策

### 决策 0：文件改动白名单

| # | 文件 | 允许改动 |
|---|---|---|
| 1 | `packages/kronos-data/kronos_data/etl.py` | 仅 `sync_rt_k` 函数：inline-cursor 逐行 UPSERT → `_insert_rows(update)` 批量；`sync_rt_sw_k` 零碰（已收口）；其他 32+ sync 函数零碰 |
| 2 | `docs/adr/015.6-rt-k-pg-write-migration.md` | 本 ADR |
| 3 | `progress/tech-lead.md` | SIT 段 |

**禁止**：pg_writer.py / scheduler.py / sync_rt_sw_k / 任何其他 sync 函数 / rt_k 表 schema。

### 决策 1：`sync_rt_k` 改造

把聚合结果 rows 收集成 list，调 `_insert_rows(update)`：

```python
cols = ["code", "trade_date", "open", "high", "low", "close", "vol", "amount"]
rows = db.execute(sql, (latest_dt,)).fetchall()
if rows:
    written = _insert_rows(
        db, "rt_k", cols, [tuple(r) for r in rows],
        conflict_action="update",
        conflict_cols=["code", "trade_date"],
        update_cols=["open", "high", "low", "close", "vol", "amount"],
    )
    db.commit()
```

语义对照（与原 inline SQL 100% 等价）：

| 原 inline SQL 子句 | _insert_rows 参数 |
|---|---|
| `ON CONFLICT(code, trade_date)` | `conflict_cols=["code", "trade_date"]` |
| `DO UPDATE SET open, high, low, close, vol, amount` | `update_cols=[6 列]` |
| 逐行 `db.execute` | `_insert_rows` 内部 `execute_values(page_size=1000)` 批量 |
| 无 `updated_at` | 不传 `now_cols`（表无 updated_at） |

**关键**：`code` 和 `trade_date` 是 UNIQUE 约束（非 PK，PK 是 id），在 `conflict_cols` 不在 `update_cols`（约束 2）。

### 决策 2：sync_rt_sw_k audit no-op

`sync_rt_sw_k` (L1497) 已走 `_insert_rows(db, "rt_sw_k", cols, rows)`，DO NOTHING 默认。盘点报告 "inline-execute_values" 标注过时，本 ADR 确认 no-op，零改动。

| Checkpoint | 触发 | 动作 |

| RB-1 | `_insert_rows` 返回 0 但 rows 非空 | 检查 conflict_cols 是否 UNIQUE；schema drift |

| RB-3 | 聚合 SQL 竞态 | 不改聚合 SQL，只改写入段 |

## 备选方案

- **A. 保留 inline-cursor** —— pros: 0 改动；cons: 5000 次 round-trip 性能差，path #4 收官失败；**否决**
- **B. 改 DO NOTHING** —— pros: 简单；cons: 业务回归（盘中 rt_k 不随分钟线更新）；**否决**
- **C（推荐）**：聚合 rows 收集成 list，`_insert_rows(update)` 批量 —— 采纳

## 影响

### 正面

- sync_rt_k 性能提升（5000 行逐行 → 1 次批量）
- 走 `_insert_rows` 自动列过滤 + retries，schema drift 防御
- **path #4 真正未收口 PG 模块收官**（stocks/stock_profiles/namechange/rt_k 全收口）

### 负面

- 无（行为 100% 等价）
