# RBAC 与会员管理实施计划

## 目标

把平台从“前端写死菜单/角色展示”升级为“后端授权、前端按权限展示”的模式，并新增管理员授权页和会员管理页。

## 范围

- 管理员可查看用户、调整角色、启停账号、配置会员状态和会员周期。
- 角色内置默认菜单权限，管理员可修改每个角色的菜单权限。
- 前端菜单和路由按后端返回权限展示。
- 顶部红框状态栏改成紧凑状态入口：只常驻关键状态，细节放入下拉面板。
- 会员管理页展示用户是否会员、套餐、周期、剩余天数、到期风险。

## 非目标

- 不接支付系统。
- 不做真实券商账户授权。
- 不改交易模型策略逻辑。
- 不清理与本需求无关的历史改动。

## 实施步骤

1. 后端测试先行
   - 覆盖角色权限默认值。
   - 覆盖管理员修改角色权限。
   - 覆盖用户授权时同步角色和会员周期。
   - 覆盖非管理员无法访问管理接口。

2. 后端数据和接口
   - 新增角色权限持久化表。
   - 扩展会员记录字段：状态、套餐、起止时间、备注、更新时间。
   - 新增会员事件表，记录开通、续期、停用、变更。
   - 新增接口：
     - `GET /api/v1/admin/permissions/roles`
     - `PUT /api/v1/admin/permissions/roles/{role_name}`
     - `PUT /api/v1/admin/users/{user_id}/authorization`
     - `GET /api/v1/admin/memberships`
   - 登录用户响应返回 `permissions` 和 `membership`。

3. 前端权限接入
   - 登录态类型增加 `permissions`、`membership`。
   - 菜单配置增加 `permission` 字段。
   - 菜单和管理路由按后端权限展示。
   - 保留旧角色判断作为兼容兜底。

4. 前端页面
   - 新增“权限授权”页：用户授权、角色权限矩阵、会员周期配置。
   - 新增“会员管理”页：会员列表、周期、状态、到期风险。
   - 顶部状态栏改成“角色 / 模式 / 账户”紧凑显示，更多信息进入下拉。

5. 验证
   - 后端聚焦 pytest。
   - 前端 typecheck。
   - 必要时跑管理页轻量浏览器冒烟。

## 验收标准

- 管理员能打开权限授权页和会员管理页。
- 管理员能修改用户角色、会员状态、会员周期。
- 管理员能修改角色默认菜单权限。
- 普通用户看不到管理员菜单和接口不可访问。
- 顶部状态栏不再占用大量横向空间，每页展示一致但更简洁。
- 现有交易、行情、模型页面不因新权限改造中断。
