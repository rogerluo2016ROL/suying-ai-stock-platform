# 竞价选债 T+0 模型设计

日期：2026-06-30

## 模型目标

“竞价选债 T+0 模型”从股票竞价异动出发，找到今日竞价一字板且封单金额超过 5 亿的股票，再用同花顺概念推导相关转债清单。

模型不直接预测收益，也不替用户隐瞒风险。它输出的是题材扩散线索：哪只股票触发，触发了哪些同花顺概念，这些概念下有哪些转债可以作为 T+0 观察对象。

## 核心口径

股票触发条件：

1. 今日进入涨停列表，优先取 `limit_list_d.limit_type = 'U'`。
2. 竞价阶段已经封板。第一版用 `first_time <= '09:30:00'` 判断。
3. 封单金额 `fd_amount > 500_000_000`，单位按数据库原始元口径处理。
4. 前一交易日不是涨停。前一日若在 `limit_list_d` 中以 `limit_type = 'U'` 出现，则排除。
5. `fd_amount` 缺失时不进入触发股票池。模型不估算封单金额。

概念口径：

1. 主口径使用同花顺概念，数据来自 `ths_member` 和 `ths_index`。
2. 概念推导从触发股票出发，通过 `ths_member.con_code` 匹配股票代码，兼容 `000001.SZ` 和 `000001` 两种形态。
3. 过滤明显噪音概念，包括地区、昨日涨停、百日新高、同花顺特色指数、大小盘、估值、股息、减持、重仓等标签。
4. 一个股票可以触发多个概念。模型先保留全部候选概念，再按概念当日强度选出最强的两个概念。
5. 概念当日强度使用概念成分股的竞价涨幅均值，来源为 `stk_auction_o`，公式为 `(open / close - 1) * 100`。这里的 `close` 是竞价表里的昨收口径，不使用当天收盘涨幅。
6. 概念成分股数量不参与强弱排序。

转债清单口径：

1. 只要某个概念下的股票有可转债，就进入概念转债清单。
2. 转债不做硬过滤。强赎、溢价率、成交额、剩余规模、临近退市等只作为风险提示。
3. 同一转债命中多个触发概念时，只保留一行，但展示全部命中概念和触发来源。

## 排序规则

模型按题材相关性排序，不按交易便利性排序。

概念先筛到最强两个，再进入转债清单。转债排序从高到低：

1. 正股本身就是触发股票的转债。
2. 转债正股命中的触发概念数量更多。
3. 命中的概念中，触发股票数量更多。
4. 命中的概念中，触发股票封单金额合计更高。

溢价率、成交额、强赎状态、剩余规模不参与主排序。它们只影响风险提示文案。

## 输出字段

触发股票字段：

- `trigger_stock_code`：触发股票代码。
- `trigger_stock_name`：触发股票名称。
- `fd_amount`：封单金额，原始单位为元。
- `fd_amount_yi`：封单金额，换算为亿元。
- `first_time`：首次封板时间。
- `prev_was_limit_up`：前一交易日是否涨停。入选记录应为 `false`。

概念字段：

- `concept_code`：同花顺概念代码。
- `concept_name`：同花顺概念名称。
- `trigger_stock_count`：该概念下命中的触发股票数量。
- `concept_fd_amount_yi`：该概念下触发股票封单金额合计。
- `concept_strength`：概念成分股平均竞价涨幅，用于选择最强两个概念；缺失时为 `null`。
- `concept_strength_source`：概念强度来源，当前为 `auction_avg`。
- `auction_sample_count`：参与概念竞价涨幅计算的成分股数量。

转债字段：

- `cb_code`：转债代码。
- `cb_name`：转债名称。
- `stk_code`：正股代码。
- `stk_name`：正股名称。
- `matched_concepts`：命中的触发概念列表。
- `trigger_sources`：对应触发股票列表。
- `theme_score`：题材相关性分数。
- `relation_reason`：入选原因，例如“正股为触发股”或“命中机器人、减速器两个触发概念”。

风险提示字段：

- `call_status`：强赎状态。
- `premium_rate`：转股溢价率。
- `cb_amount`：转债成交额。
- `remain_size_yi`：剩余规模，亿元。
- `delist_date`：退市日期。
- `risk_notes`：可读风险提示。

## 数据来源

主要表：

- `limit_list_d`：涨停列表、首次封板时间、封单金额、昨日涨停判断。
- `ths_member`：同花顺概念成分股。
- `ths_index`：同花顺概念名称。
- `cb_basic`：转债基础信息、正股映射、剩余规模、退市日期。
- `cb_daily`：转债行情、成交额、溢价率。
- `cb_call`：强赎状态。

辅助表：

- `stocks`：股票名称和 ST 过滤。
- `stk_auction_o`：竞价开盘价和竞价涨幅，仅用于展示或补充，不用于估算封单金额。

## 结果形态

命令行和服务接口应返回同一套结构，便于后续接入前端。

顶层结构：

```json
{
  "model": "cb_auction_t0",
  "trade_date": "2026-06-30",
  "trigger_stocks": [],
  "concepts": [],
  "bonds": [],
  "rejections": []
}
```

`rejections` 记录未入选原因，包括“封单金额缺失”“封单金额不足 7 亿”“昨日已涨停”“缺少同花顺概念”“概念下无转债”。这部分对复盘很重要，不能省略。

## 验证方式

第一阶段只做规则模型，不训练机器学习模型。

验证步骤：

1. 用最近 20 个交易日回放，统计每天触发股票数量、概念数量、转债数量。
2. 抽样核对触发股票，确认封单金额和昨日涨停排除没有误判。
3. 抽样核对概念推导，确认没有把地区、昨日涨停、指数风格标签当题材。
4. 记录转债 T+0 表现，但不把短期回测收益作为第一版上线门槛。

通过标准：

1. 每条转债都能追溯到触发股票和触发概念。
2. 封单金额超过 7 亿的判断来自真实 `fd_amount`，不是估算。
3. 风险只提示，不删除转债。
4. 排序能解释，优先级来自题材相关性。

## 不做的事

第一版不做以下内容：

1. 不用模型预测涨跌。
2. 不用成交额、溢价率、强赎状态剔除转债。
3. 不估算缺失的封单金额。
4. 不把行业板块作为主口径。
5. 不把旧 `cb_auction` 改成新逻辑。

## 后续实现建议

新增独立引擎，例如 `CbAuctionT0Engine`，避免影响现有 `CbAuctionEngine`。工具入口可以新增 `tools/cb_auction_t0_picks.py`，服务层后续再接入智能选股接口。

实现时先完成命令行版本和 20 日回放，再决定是否接入前端。这样可以先验证数据口径，避免界面先行导致模型逻辑被固化。

## 实现后的运行命令

当前日清单：

```bash
KRONOS_PG_URL="postgresql://kronos:kronos@localhost:6432/kronos" \
python tools/cb_auction_t0_picks.py 2026-06-30 --top-n 50
```

历史日期回放：

```bash
for d in 2026-06-10 2026-06-11 2026-06-12; do
  KRONOS_PG_URL="postgresql://kronos:kronos@localhost:6432/kronos" \
  python tools/cb_auction_t0_picks.py "$d" --top-n 50 --json-only
done
```

20 个交易日验证时，先确认 PostgreSQL 已启动，且 `limit_list_d`、`ths_member`、`ths_index`、`cb_basic`、`cb_daily`、`cb_call` 均有目标日期附近数据。
