# 全模型飞书自动推送设计

日期：2026-07-14

状态：待用户复核
目标群：`AI 投研分析`（沿用 `configs/model_pipeline.json` 的 `default_chat_id`）

## 目标

所有通过 `tools/run_research_pipeline.py` 运行的已注册选股、选债模型，在生成结果文件后自动把运行摘要推送到默认飞书群。调用者不再需要手动添加 `--send-feishu`。

本次改动不改变模型逻辑、数据刷新规则、入选结果或报告内容。它只改变运行结束后的通知行为。

## 使用方式

正常运行模型时，流水线默认发送飞书消息：

```bash
python tools/run_research_pipeline.py --model <模型名>
```

调试、回放或测试时，可以单次关闭推送：

```bash
python tools/run_research_pipeline.py --model <模型名> --no-send-feishu
```

保留 `--send-feishu`，避免现有脚本和历史命令失效。新旧命令都进入同一套发送逻辑。

## 配置和边界

`configs/model_pipeline.json` 增加顶层配置 `send_feishu_by_default: true`。命令行参数优先级高于配置：

1. `--send-feishu`：本次发送。
2. `--no-send-feishu`：本次不发送。
3. 未传参数：读取 `send_feishu_by_default`。

默认群继续从 `default_chat_id` 读取。命令行的 `--chat-id` 可以临时指定其他群。

“全部模型”指 `configs/model_pipeline.json` 中注册、并由统一流水线执行的模型。直接调用底层 Python 引擎不会自动发送，因为底层引擎只负责计算结果，不负责交付。项目内需要自动交付的任务应调用统一流水线。

## 运行流程

流水线按以下顺序处理一次运行：

1. 刷新数据并运行模型。
2. 写入 Markdown、JSON、manifest 等本地结果。
3. 可选同步飞书文档。
4. 发送飞书摘要。
5. 从发送结果中提取 `message_id`，查询目标群的近期消息，核对该消息确实存在。优先使用机器人身份查询；机器人缺少群消息读取权限时，使用本机已登录的用户身份做只读核验。
6. 把推送状态、目标群和 `message_id` 写回本次 `result.json` 与 `pipeline.json`。记录中不保存应用密钥或访问令牌。

消息包含模型名称、交易日期、运行模式、入选数量和报告位置。已有候选降级说明、备用数据源说明继续保留。

## 失败处理

模型或报告生成失败时，流水线不发送选股结果，防止群里出现不完整结果。

飞书发送或送达核验失败时，本地模型结果仍然保留。命令返回失败状态，并在本次运行记录中写明 `push_status: failed` 和不含密钥的错误摘要。调用者不能把这种运行当成“已交付”。

飞书发送成功但反查不到消息时，状态记为 `unconfirmed`，命令同样返回失败。这样可以区分“接口接受请求”和“群里确认可见”。

## 密钥处理

代码继续优先使用现有 `lark-cli` 机器人身份；如果运行环境配置了 `LARK_APP_ID` 和 `LARK_APP_SECRET`，则使用飞书开放平台接口。设计不把密钥复制到仓库配置、日志、结果文件或测试夹具中。

仓库根目录现有 `.env` 中的旧 `FEISHU_*` 配置不作为统一流水线的密钥来源。本次启用不修改或提交该文件。

## 测试和验收

自动化测试至少覆盖以下情况：

- 未传推送参数时，配置为 `true` 会发送。
- `--no-send-feishu` 会跳过发送。
- `--send-feishu` 兼容旧命令。
- 缺少目标群、发送失败、无法提取消息 ID、送达核验失败时，运行状态明确失败。
- 运行记录保存推送状态和消息 ID，不保存密钥。

真实验收使用一条标明“飞书自动推送功能测试”的消息，不附带虚构选股结果。验收步骤为：发送消息、反查 `AI 投研分析` 群、核对消息 ID、保存非敏感证据。
