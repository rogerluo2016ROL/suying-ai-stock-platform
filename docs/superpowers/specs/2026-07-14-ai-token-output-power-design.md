# 富余电力驱动的 AI 推理 Token 输出产业链设计

**日期：** 2026-07-14
**状态：** 设计已确认，待文档审阅
**建议 chain_id：** `ai_token_output_power`
**适用模板：** `complex_tech`
**首要用途：** 产业链研究、证据链管理、四股票池筛选；不直接产生买卖指令

## 1. 设计结论

本产业链从“可计费的模型输出 Token”倒推上游资源，主线为：

```text
区域/时段可用低成本电力
  → 数据中心和推理算力部署
  → 推理吞吐量与 Token 产能
  → API、SaaS、Agent 和行业应用收入
  → 毛利和现金流兑现
```

“中国电力过剩”不作为一个全国统一事实使用。模型必须区分弃风弃光、低谷电、园区/自备电力和名义富余容量，并核验电力是否可长期、稳定、合规地接入高功率计算负载。

Token 是计量单位和商业化载体，不是单独的硬件产业。低价电力只有在能够转化为有效推理算力、可计费 Token 和收入时，才构成产业链价值。

## 2. 研究边界

### 2.1 纳入范围

- 大模型云端推理、端侧推理和多模态推理；
- 低谷电、弃风弃光、绿电交易、储能和数据中心供电；
- AI 芯片、HBM、先进封装、服务器、网络、液冷和推理软件；
- API、Agent、SaaS、行业模型和算力租赁的 Token 变现；
- 公司—节点映射、证据事件、阶段、四股票池和市场交易层。

### 2.2 不纳入范围

- 不把“宣布布局 AI”当作 Token 产能证据；
- 不把电力装机、园区签约或购电意向当作可用算力证据；
- 不把股价上涨、换手或市场热度当作产业链真实性证据；
- 不把区块链 Token、数字资产发行和 AI 输出 Token 混为一条链；
- 不自动生成买卖建议，不接入实盘交易。

## 3. 总体架构

本链采用三层结构：

```text
纵向主链：L1-L8
  需求 → 任务 → 核心产品 → 底层支撑 → 集成 → 配套 → 基础设施 → 商业变现

横向研究：7 个产业维度
  功能价值、技术路线、物理 BOM、价值池、竞争壁垒、供需周期、证据验证

选股叠加：市场交易层
  估值、涨跌、换手、资金、预期、拥挤度和策略信号
```

市场交易层不参与证明产业链成立，只负责判断已被验证的业务是否具备交易机会。

## 4. L1-L8 纵向拆解

| 层级 | 名称 | Token 输出链内容 | 主要证据 |
|---|---|---|---|
| L1 | 需求层 | 企业 Agent、智能客服、代码生成、搜索、内容生成、多模态应用 | API 调用量、DAU、Token 消耗量、付费客户数 |
| L2 | 任务层 | 实时推理、批量推理、长上下文、视频生成、端侧推理 | QPS、并发数、上下文长度、输入/输出 Token 比 |
| L3 | 核心产品层 | 大模型、推理 API、模型服务平台、Agent 平台 | 模型调用量、Token 价格、SLA、客户留存 |
| L4 | 底层支撑层 | GPU/ASIC、HBM、先进封装、推理软件、光互联 | Tokens/s、Tokens/W、显存、芯片供货和适配 |
| L5 | 集成层 | AI 服务器、推理集群、模型压缩、量化、调度、推理引擎 | 集群上线、利用率、延迟、KV Cache 命中率 |
| L6 | 配套层 | 液冷、电源、变压器、PCB、连接器、光模块、存储 | 机柜功率、PUE、冷却能力、交付订单 |
| L7 | 基础设施层 | 低谷电、弃风弃光、绿电交易、储能、IDC、智算中心 | 可用 MW、电价、供电小时、并网容量、机房利用率 |
| L8 | 商业变现层 | 按 Token 计费、API、SaaS、Agent 服务、算力租赁 | Token 收入、单 Token 价格、毛利率、续费率、现金流 |

## 5. 七个产业研究维度

### 5.1 功能与任务价值 `function_value`

判断 Token 是否解决真实任务，以及客户是否持续付费。

关键问题：

- 输出 Token 是否对应可量化的生产效率或业务结果；
- 是高价值推理，还是低价值重复生成；
- 客户是否持续增加调用量并续费。

### 5.2 技术路线与成熟度 `technology_route`

比较 GPU、ASIC、量化、稀疏化、蒸馏、KV Cache 和不同模型架构的单位电力效率。

关键指标：

- Tokens/s；
- Tokens/W；
- 推理延迟；
- 模型精度损失；
- 芯片和软件适配周期。

### 5.3 物理 BOM 与供给结构 `physical_bom`

从电力输入到 Token 输出拆解物理设备：电力、变压器、服务器、AI 芯片、HBM、先进封装、光模块、液冷、存储和网络。

关键问题：

- 哪个环节限制 Token 产能；
- 设备是否已经交付并上线；
- 供应是否集中、是否存在替代路线。

### 5.4 价值量与利润池 `value_pool`

分析每 100 万输出 Token 的收入和成本由谁获得。

必须跟踪：

- 每百万输出 Token 售价；
- 电费、算力折旧、机房和网络成本占比；
- 推理毛利率；
- Token 价格下降速度；
- 各层实际利润留存。

### 5.5 竞争格局与壁垒 `competition_moat`

判断低成本电力和推理能力是否具有排他性。

可能壁垒：

- 长期低价电力合同；
- 变电站和并网能力；
- 高效推理软件；
- 模型适配和客户迁移成本；
- API 客户和数据闭环。

### 5.6 供需与产业周期 `supply_demand_cycle`

同时观察电力、芯片、机房、推理需求和 Token 价格，避免只看某一段扩张。

关键指标：

- 电价和可用电力小时；
- GPU/ASIC 交付周期；
- 智算中心利用率；
- API 价格和 Token 调用量；
- 服务器库存和 IDC 出租率。

### 5.7 证据与商业验证 `evidence_validation`

所有结论必须落到公司、节点、证据、来源和日期。

证据等级：

| 等级 | 含义 | 最高股票池 |
|---|---|---|
| E0 | 概念或公开表态 | D 概念观察池 |
| E1 | 有电力、园区或算力规划 | D 概念观察池 |
| E2 | 数据中心或算力设备已建成 | C 技术卡位池 |
| E3 | 有真实推理运行、QPS 或 Token 数据 | B 客户验证池 |
| E4 | 有 API 收入、客户订单或客户验证 | B 客户验证池 |
| E5 | Token 收入和利润连续兑现 | A 业绩兑现池 |

## 6. 电力侧专门拆解

电力来源必须细分为四类：

1. 弃风弃光电力；
2. 夜间或负荷低谷电力；
3. 园区、自备电力或长期购电协议；
4. 只有理论容量、尚未获得接入条件的名义富余容量。

每个电力映射至少保存：

- `power_source_type`；
- `available_mw`；
- `available_hours`；
- `tariff_or_cost`；
- `grid_connection_status`；
- `storage_support`；
- `curtailment_or_valley_evidence`；
- `as_of_date`；
- `review_status`。

没有并网、供电时段和电价证据时，只能标记为 `unknown`，不能默认低成本。

## 7. Token 产能和成本模型

### 7.1 产能公式

```text
billable_tokens
  = available_mw
  × operating_hours
  × utilization
  × tokens_per_mw_hour
  × cluster_availability
```

`tokens_per_mw_hour` 必须按模型、上下文长度、精度、批处理方式和硬件类型分别估算，禁止使用一个跨模型通用常数。

### 7.2 单位成本公式

```text
cost_per_million_tokens
  = (electricity_cost
     + compute_depreciation
     + facility_and_cooling_cost
     + network_cost
     + operation_cost
     + financing_cost)
    / billable_tokens
```

### 7.3 商业闭环门槛

只有以下条件同时成立，才允许从“算力产能”升级为“Token 商业化”：

```text
可用电力
→ 可接入
→ 算力上线
→ 推理运行
→ Token 可计费
→ 收入确认
→ 毛利改善
```

## 8. 四股票池规则

### A：Token 业绩兑现池

- E4/E5；
- 有 Token/API 收入和客户证据；
- 推理毛利或现金流已验证；
- 无并网、能源合规和重大客户集中风险。

### B：Token 客户验证池

- E3/E4；
- 推理集群已经运行；
- 有客户测试、API 调用或明确扩容计划；
- 仍缺少连续收入或利润确认。

### C：Token 技术卡位池

- E2 及以上；
- 有明确产品、型号、参数或已上线设备；
- 没有充分 Token 收入证据。

### D：电力/算力概念观察池

- E0/E1；
- 只有电力、园区、算力规划或产业理论映射；
- 不写入正式推荐快照，不进入策略持仓回测。

## 9. 市场交易层

市场交易层单独计算，不反向证明产业链成立。包含：

- 估值和盈利预测；
- 涨幅、换手和资金流；
- 机构覆盖和市场拥挤度；
- MACD、OBV、趋势和板块共振；
- 交易模型的买入、观察和拒绝信号。

最终机会分只能在产业证据准入之后计算：

```text
产业节点吸引力
× 业务真实性
× 商业兑现度
→ 市场预期调整
→ 交易机会分
```

股价上涨、换手增加或概念热度不能提高 `evidence_validation` 分数。

## 10. 证据链和状态迁移

```text
D 概念观察
  --电力/园区可验证--> C 技术卡位
  --算力上线和推理运行--> B 客户验证
  --订单/API收入/客户扩容--> A 业绩兑现
  --证据过期或业务否认--> 降级
  --映射被证伪--> 排除
```

所有迁移必须保存原池、新池、触发证据、日期、审核状态、下一验证节点和预计日期。

## 11. 多映射和重复证据规则

- 每个 `mapping_id` 独立评分；
- 股票级结果选择证据等级最高、业务受益度最高的主映射；
- 同一公告、同一产品、父子节点重复证据不重复计分；
- 没有独立分部收入或独立订单，不增加多映射奖励；
- 输出全部次要映射和未采纳原因；
- 被拒绝或禁用的映射不得进入正式候选排名。

## 12. 数据质量和失败处理

### 12.1 缺失数据

- 缺失不等于零分；
- 保存 `NULL`、`unknown` 和 `coverage_ratio`；
- 覆盖率不足时限制最高股票池；
- 不允许用市场信号填补产业证据。

### 12.2 电力存在但无法转化

如果有电力证据，但没有并网、机房、服务器或推理运行证据，维持 E1/D 池。

### 12.3 Token 使用量增长但不盈利

如果 Token 数增长但价格下降、利用率不足或推理成本过高，降低价值池和商业化评分，不自动升级股票池。

### 12.4 公司声称布局但无独立证据

保留为 `company_claim` 或 `candidate`，不得自动标记为已验证业务。

## 13. 验收标准

设计进入实施前，必须能够验证：

1. L1-L8 节点齐全；
2. 每个节点可保存七个产业研究维度；
3. 市场交易层与产业证据层分离；
4. 电力来源可区分弃电、低谷电、合同电和名义容量；
5. Token 产能和单位成本可按模型与硬件类型计算；
6. 每个公司映射可下钻到证据、来源、日期和审核状态；
7. E0-E5 能映射到 A/B/C/D 股票池；
8. 被拒绝、过期或未审核证据不会进入正式推荐池；
9. 同一证据不会在多条映射中重复计分；
10. 缺失数据输出 `unknown`，不生成伪造分数。

## 14. 实施边界

本设计只定义产业链、证据链、评分口径和股票池准入规则，不在本阶段修改数据库或选股引擎。实施前需要：

1. 用户审阅本设计文档；
2. 按确认内容编写实施计划；
3. 先以 `staging` 版本物化 Token 输出链；
4. 完成 dry-run、证据覆盖检查和 V1/V2 对照后，再考虑正式注册。
