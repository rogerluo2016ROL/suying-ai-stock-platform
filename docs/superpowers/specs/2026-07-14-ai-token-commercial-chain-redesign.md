# AI Token 商业输出产业链重构设计

**日期：** 2026-07-14

**状态：** 已确认，待实施计划

**目标链：** `ai_token_output`

**替代对象：** 现有 `ai_token_output_power` 电力主轴模型

## 1. 设计结论

产业链研究对象调整为：中国企业通过模型 API、Agent、MaaS、推理服务和算力服务，向国内外客户输出可计费 Token 并形成收入。

产业链主轴为：

```text
Token 需求场景
→ 模型与 AI 产品
→ 推理优化软件
→ 核心算力硬件
→ 集群与网络支撑
→ Token 服务与交付平台
→ 计量、计费与运营
→ 商业变现与国内外输出
```

电力、IDC、液冷等仍然重要，但不再承担产业链主轴角色。电力进入“推理效率与单位 Token 成本”维度；IDC、液冷、电源、网络等进入集群支撑和 BOM 维度。

“海外输出”是商业变现加分项，不是纳入产业链的必要条件。国内 API、Agent、MaaS 或算力服务形成真实收入，同样属于 Token 输出。

## 2. 范围与边界

### 2.1 纳入范围

- 消耗推理 Token 的企业和个人应用；
- 基础模型、行业模型、Agent 平台与 MaaS；
- 推理引擎、编译器、量化、蒸馏、调度和 KV Cache 优化；
- GPU、ASIC、CPU、HBM、先进封装和 AI 服务器；
- AI 集群、光模块、交换机、PCB、液冷、电源和存储；
- 推理云、API 网关、MaaS、算力租赁和边缘推理；
- Token 计量、套餐、定价、结算、客户运营和安全合规；
- 国内 API、Agent、SaaS、行业方案及海外输出形成的收入。

### 2.2 不纳入或不等同

- 不把区块链 Token、虚拟资产和 AI 输出 Token 混为一类；
- 不把“建设数据中心”直接等同为具有 Token 生产和销售能力；
- 不把芯片、服务器或光模块收入直接标记为 Token 收入；
- 不把低价电力或园区规划单独作为正式池升级依据；
- 不用股价上涨、资金流入或媒体热度反向证明产业关系；
- 不把海外概念等同于已实现海外收入。

## 3. 八层纵向产业链

| 层级 | 名称 | 核心环节 | 公司级核心证据 |
|---|---|---|---|
| L1 | Token 需求场景 | Agent、代码生成、客服、搜索、营销、多模态、行业 AI | 活跃客户、调用频率、Token 消耗量、付费率、留存率 |
| L2 | 模型与 AI 产品 | 基础模型、行业模型、Agent 平台、MaaS | 模型上线、客户数量、调用量、定价、SLA、续费 |
| L3 | 推理优化软件 | 推理引擎、量化、蒸馏、编译器、调度、KV Cache | 性能测试、适配清单、Tokens/s、延迟、单位成本下降 |
| L4 | 核心算力硬件 | GPU/ASIC、CPU、HBM、先进封装、AI 服务器 | 芯片适配、供货、订单、性能、客户认证、收入占比 |
| L5 | 集群与网络支撑 | AI 集群、光模块、交换机、PCB、液冷、电源、存储 | 集群交付、订单、BOM 价值、机柜功率、PUE、客户占比 |
| L6 | Token 服务与交付平台 | 推理云、API 网关、MaaS、算力租赁、边缘推理 | 平台上线、调用量、并发、可用率、客户、服务收入 |
| L7 | 计量、计费与运营 | Token 计量、套餐、定价、结算、运营、安全合规 | 计费规则、ARPU、获客成本、续费、毛利、合规能力 |
| L8 | 商业变现与输出 | 国内 API、Agent/SaaS、行业方案、海外服务输出 | Token/API 收入、客户增长、毛利率、现金流、海外收入 |

L1 和 L2 允许公司映射，但必须有具体产品和客户证据；不能仅用“属于 AI 概念”生成映射。

## 4. 七个横向研究维度

### 4.1 需求真实性 `demand_authenticity`

判断需求是否高频、持续且有人付费。核心指标包括活跃客户、调用频率、Token 消耗量、付费率、留存率和具体业务结果。

### 4.2 模型与产品竞争力 `model_product_strength`

判断模型或产品是否在准确率、延迟、可控性、行业知识、生态和客户体验上形成竞争力。自研模型不是必要条件，稳定整合和交付能力也可以形成价值。

### 4.3 推理效率与单位 Token 成本 `inference_unit_economics`

判断单位输出 Token 的综合经济性，包括硬件折旧、电力、机房、冷却、网络、运维和融资成本。电力仅是该维度的一个成本项，不单独决定产业等级。

### 4.4 核心 BOM 与供应链卡位 `bom_supply_position`

判断公司在芯片、服务器、光互联、PCB、液冷、电源和存储中的价值量、份额、替代难度、客户认证和供应约束。

### 4.5 平台交付和客户黏性 `delivery_customer_stickiness`

判断平台是否能稳定交付推理服务，以及客户是否因 API、数据、工作流、Agent 编排和迁移成本形成黏性。

### 4.6 商业化与国内外输出 `commercial_output`

判断 Token 是否形成收入、毛利和现金流。国内输出与海外输出分别记录；海外收入、海外客户和跨境交付能力作为加分项，不作为基础门槛。

### 4.7 证据强度与兑现阶段 `evidence_realization`

判断公司处于概念、产品、客户验证、持续交付还是业绩兑现阶段，并记录证据来源、日期、原文、审核状态和反证。

## 5. 证据等级与四个股票池

| 等级 | 最低事实要求 | 股票池 |
|---|---|---|
| E0 | 只有概念、关键词或跨链推断 | D 候选观察池 |
| E1 | 有公司级产品、研发或适配证据 | D 候选观察池 |
| E2 | 产品、技术、供货、订单或项目得到验证 | C 核心卡位池 |
| E3 | 有真实客户调用、上线运行或持续交付证据 | B 客户验证池 |
| E4 | Token/API/Agent/算力服务收入得到验证 | A 商业兑现池 |
| E5 | 收入、利润、客户和现金流连续兑现 | A 核心兑现池 |

硬门槛：

- 没有公司级证据，最高只能进入 D 池；
- 没有客户调用、上线或持续交付证据，不得进入 A/B 池；
- 上游硬件公司可以凭真实供货和订单进入 C 池，但不得标记为具有 Token 收入；
- 只有电力、IDC 或园区规划的公司维持 D 池；
- rejected/disabled 映射不得进入任何正式池；
- 市场交易信号不能改变证据等级和股票池等级。

## 6. 选股评分模型

评分单元为“公司 × 业务标签 × 产业层级”，不是公司整体。

```text
Token 产业总分
= 业务真实性       20%
+ Token 价值捕获    20%
+ 技术与推理效率    15%
+ 客户及商业化      15%
+ 竞争壁垒          10%
+ 成长兑现          10%
+ 证据质量          10%
```

### 6.1 各项定义

- 业务真实性：产品、业务和产业层级是否匹配；
- Token 价值捕获：公司能否从调用、订阅、API、算力或供应链订单中获得收入；
- 技术与推理效率：性能、延迟、适配和单位 Token 成本；
- 客户及商业化：客户数量、调用、交付、续费和收入；
- 竞争壁垒：技术、认证、生态、数据、规模和转换成本；
- 成长兑现：收入增速、订单变化、毛利和现金流；
- 证据质量：原始性、审核状态、时效、交叉验证和反证情况。

证据等级是硬门槛，综合分是同一股票池内的排序工具。高分不能越过证据门槛升级股票池。

## 7. 市场交易层

市场层继续与产业研究层隔离，包括估值、趋势、成交、资金、拥挤度和具体交易模型信号。

```text
产业链和证据 → 决定是否纳入及进入哪个池
产业评分      → 决定同池基本排序
市场交易层    → 决定观察或交易时点
```

毕师傅硬核科技、毕师傅趋势战法、秋神午后选股等模型只能应用于已经通过产业证据门槛的候选，不能用技术走势补足产业证据。

## 8. 数据模型调整

### 8.1 链标识

新主链使用 `ai_token_output`。现有 `ai_token_output_power` 保留为历史 staging 版本，不直接覆盖，避免历史数据和新口径混用。

### 8.2 主要字段

每条公司映射至少保存：

- `chain_id`、`layer_id`、`business_tag`；
- `token_role`：需求方、模型方、优化方、硬件方、集群方、平台方、运营方或变现方；
- `domestic_output_status`、`overseas_output_status`；
- `token_metric_type`、`token_volume`、`token_price`；
- `customer_status`、`delivery_status`、`revenue_status`；
- `evidence_grade`、`review_status`、`evidence_ids`；
- 七维评分、覆盖率、缺失字段和下一验证节点。

未知指标保存为 `unknown` 或 `NULL`，不使用行业均值或默认值伪造公司数据。

## 9. 映射重建规则

现有 1,018 条 `ai_token_output_power` 映射不得整体继承到新主链。迁移时执行：

1. 股票代码标准化，合并 `300308` 与 `300308.SZ` 等重复表示；
2. 重新判断公司业务标签属于 L1-L8 中哪个具体环节；
3. “云服务”“软件”“数据中心”等宽泛标签默认进入待复核，不自动进入 L6/L8；
4. 原链 verified 只表示原产业链关系得到验证，不继承为新链 verified；
5. 保留原始映射 ID、来源链和推断规则，形成可追溯关系；
6. 自动映射统一从 E0/D 开始，只有经人工审核的公司级证据才能升级。

## 10. 查询与展示

接口和前端应分别展示：

- 八层产业链地图和各层公司数量；
- 七维评分、覆盖率和缺失证据；
- A/B/C/D 四池及升级原因；
- 每家公司原始证据、审核状态和反证；
- 国内输出与海外输出分别统计；
- 产业评分和市场交易评分分栏展示。

“映射数”“去重公司数”“正式池公司数”必须分开，避免把一家公司多个业务标签误认为多家公司。

## 11. 验收标准

1. 新链 L1-L8 和七维配置完整，电力不再作为主层级或股票池升级前提；
2. 新链与旧 `ai_token_output_power` 数据隔离；
3. 代码标准化后不存在同公司同层重复映射；
4. L1/L2 可以接收有产品和客户证据的公司映射；
5. 数据中心、云服务、软件等宽泛标签不会自动进入正式池；
6. E0-E5 与 A/B/C/D 硬门槛可复现；
7. 上游硬件收入与 Token 商业收入明确区分；
8. 国内和海外商业输出可分别查询；
9. 未知指标保持 unknown/NULL；
10. 旧链历史数据不删除，production 注册需单独授权。

## 12. 实施边界

本设计确认后，实施计划应覆盖配置、迁移、映射重建、评分引擎、物化、API、审计、测试和 staging UAT。未经再次授权，不进行 production 注册，不删除旧链数据，不自动将 D 池公司升级为正式池，也不生成投资建议。
