### 1. 数据种子 -- 确保诊断所需各维度数据可用

```sql
-- 技术面数据
SELECT COUNT(DISTINCT code) as stock_count,
       COUNT(*) as record_count
FROM daily_kline
WHERE trade_date >= date('now', '-60 days');
-- 预期: stock_count >= 2000, record_count >= 500000

-- 资金流数据
SELECT COUNT(DISTINCT code) as stock_count
FROM capital_flow
WHERE trade_date >= date('now', '-30 days');
-- 预期: stock_count >= 500（北向资金标的）

-- 基本面数据
SELECT COUNT(DISTINCT code) as stock_count
FROM fundamental_data;
-- 预期: stock_count >= 2000

-- 研报数据（情绪面）
SELECT COUNT(DISTINCT code) as report_count
FROM research_reports
WHERE publish_date >= date('now', '-90 days');
-- 预期: 至少有数据可查
```

## 附录 B: 诊断评分计算公式

```
综合评分 = 技术面 × 0.40 + 资金面 × 0.25 + 基本面 × 0.20 + AI预测 × 0.10 + 情绪面 × 0.05
```

**维度缺失时的重新加权规则**：

| 缺失维度 | 计算公式 |
|----------|----------|
| AI 预测不可用 | 技术面 × 0.444 + 资金面 × 0.278 + 基本面 × 0.222 + 情绪面 × 0.056 |
| 情绪面 + AI 预测不可用 | 技术面 × 0.471 + 资金面 × 0.294 + 基本面 × 0.235 |
| 仅技术面 + 基本面可用 | 技术面 × 0.667 + 基本面 × 0.333 |

## 附录 E: 已知限制与测试注意事项

1. **Kronos 模型加载时间**: 首次加载 Kronos 权重需 10-30 秒（MPS/CUDA 编译），冷启动时诊断总耗时可能 > 40 秒。测试时需预留首次预热时间。
2. **外部数据依赖**: 技术面、资金面、基本面、研报数据均依赖 akshare/Tushare 外部 API。离线测试需使用本地 SQLite 缓存。需验证数据过期（> 1 天未更新）场景。
3. **北向资金覆盖**: 仅沪股通/深股通标的股有北向资金数据，非北向标的（约 30% A 股）的资金面评分不含北向指标。测试需覆盖两类股票。
4. **NLP 情感分析**: 情绪面的 NLP 情感分析依赖 LLM 调用（如有），延迟和成本可能较高。需评估是否对每只股票实时调用还是预计算缓存。
5. **PDF 图表渲染**: 导出 PDF 中的 K 线图和雷达图需服务端渲染（如 Plotly `kaleido` 或 `orca`），需确认渲染环境依赖（如 `orca` 需单独安装）。
6. **多股对比并发**: 多股对比诊断会并行调用多个数据源服务，需注意并发控制和超时设置（任一数据源超时不应阻塞整体）。
7. **评分一致性**: Kronos 预测为确定性推理（相同输入 → 相同输出），但技术面和情绪面的部分指标依赖实时数据，相同股票不同时间的诊断评分可能因数据更新而变化。测试需记录数据截止时间。
8. **移动端适配**: 五维雷达图和 K 线预测图在移动端小屏幕上需自适应缩小或提供横屏模式，对比视图可能需要纵向堆叠。
