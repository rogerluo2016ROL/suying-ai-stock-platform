## P0 落地核对（逐条对 `docs/reviews/audit-frontend-2026-06-22.md` §P0）

### P0-01 — paper/live 下单统一走 axios 鉴权 ✅

- **裸 fetch 已根除**：`grep -n "fetch(" frontend/src/hooks/useLiveTrade.ts` 仅命中 L217 注释文本（`// Previously the paper branch used a raw fetch() that bypassed client.ts`），**无任何可执行 `fetch(` 调用**。
- **统一入口**：`placeOrder` L221-230 统一 `await liveTradeApi.placeOrder(params.code, params.direction, params.volume, params.price)`，不再按 `mode` 分叉下单路径。paper/live 由后端 account/broker 配置区分（注释 L216-220 说明）。
- **鉴权契约**：`liveTradeApi.placeOrder`（`frontend/src/api/liveTrade.ts:12-13`）→ `api.post('/trade/order', ...)`，`api` 是 `frontend/src/api/client.ts:3-8` 的 axios 实例（`withCredentials: true`）。请求拦截器 L69-75 注入 `Authorization: Bearer <token>`，响应拦截器 L81-112 实现 401→refresh→retry。**Authorization 头 + httpOnly cookie + 401 refresh 三项鉴权契约对 paper/live 一致生效**，audit 指出的"模拟盘绕过鉴权"已闭合。
- **测试覆盖**：`useLiveTrade.test.tsx` P0-01 两用例断言 paper 模式 POST 到 `/api/v1/trade/order` 且 body 为 `{code,direction,price,volume}`、失败时透传后端 `detail` —— 覆盖到位。

### P0-02 — navigate 移 useEffect ✅

- `LoginPage.tsx:17-21` `useEffect(() => { if (isAuthenticated) navigate('/', { replace: true }) }, [isAuthenticated, navigate])` —— navigate **不在 render 体内**。
- L23-26 render 期 `if (isAuthenticated) return null` 占位 —— 避免 render 期副作用 + 避免 StrictMode "Cannot update during render" 警告。
- 登录成功路径 L33-34 `navigate(redirect, { replace: true })` 仍在 `onFinish` async handler 内（事件回调，非 render 期），正确。
- **测试覆盖**：`LoginPage.test.tsx` 通过 `vi.mock` 替换 `useNavigate` 为 spy + `useAuth` 返回 `isAuthenticated:true`，断言 `render()` 不抛 + `navigate` 最终被 `('/', {replace:true})` 调用 —— 直接验证修复意图。

### P0-03 — catch-all 走 ProtectedRoute 保留 redirect ✅（代码侧）

- `App.tsx:171` 未登录态 `<Route path="*" element={<ProtectedRoute><Dashboard /></ProtectedRoute>} />`（HEAD 原为 `<LoginPage/>`，git diff 确认）。
- `ProtectedRoute.tsx:25-27` 未登录 → `<Navigate to={'/login?redirect=' + encodeURIComponent(location.pathname + location.search)} replace />` —— **redirect 含 pathname+search**，登录后 `LoginPage.tsx:33` `navigate(redirect,{replace:true})` 回原页。
- **代码正确性结论**：P0-03 代码修复正确，未登录访问受保护 URL 会带 redirect 跳 /login。
- ⚠️ **但 SIT 测试 `auth-redirect.test.tsx` 当前无法验证此路径**（见 W-1 + SIT Audit）—— 因 FE-P1（P1-05）在 `App.tsx:109` 引入 `const { mode: themeMode, setMode: setThemeMode } = useTheme()`，而该测试渲染完整 `<App>` 时未包 `<ThemeProvider>`，导致 `useTheme must be used within ThemeProvider` 抛错。**这是 P1 渗入 P0 scope 文件导致的测试不可执行，不是 P0-03 代码缺陷。**

### P0-04 — 熔断器轮询错误分级 ✅

- `useLiveTrade.ts:133-146` `.catch((err: unknown) => {...})`：
  - L138-141 `if (axios.isAxiosError(err) && err.response?.status === 404) { setCircuitBreaker(null); return }` —— 404 / 无熔断器配置 → 合法 null。
  - L142-145 其他错误（网络 / 401 / 403 / 5xx）→ **不 setCircuitBreaker(null)**，保留上一次有效状态，`console.warn` 记录（不弹 message，避免 30s 轮询骚扰）。
- 注释 L134-137 清晰说明分级语义（"transient blip must not mask a triggered breaker"）—— 专业。
- **测试覆盖**：`useLiveTrade.test.tsx` P0-04 两用例：404 → `circuitBreaker` null；500（fake timers 推进 30s 轮询）→ 保留首次 TRIGGERED 态不清空 —— 覆盖到位，且用 `vi.useFakeTimers` + `vi.advanceTimersByTimeAsync(31000)` 模拟轮询间隔，方法正确。
