## Findings

### Warning

#### W-1 — `P1-5` 的 `except jwt.PyJWTError` 未覆盖非 PyJWT 异常（防御深度略浅）
- **位置**: `backend/app/services/auth_service.py:215-217`（`rotate_refresh_token` 的 `try: payload = decode_token(old_token) except jwt.PyJWTError: return None`）
- **问题**: `decode_token` 是 `jwt.decode` 薄封装。`jwt.decode` 对**非字符串 token**（如 `None`、`int`、`dict`）会抛 `TypeError`/`AttributeError`（非 `PyJWTError`），不被 `except jwt.PyJWTError` 捕获 → 异常冒泡到调用方。当前调用链 token 来自受控的 Authorization header（FastAPI 已保证是 str），实际不会触发；但 P1-5 的意图是"防御性深度防御任何 future code path"，`except jwt.PyJWTError` 比 `except Exception` 窄一档，未来若 token 来源变松（如直接传 DB 字段），防御会有缝。
- **严重性**: warning —— 当前无触发路径（token 来自 HTTP header，必为 str），非正确性 bug；但与 P1-5 docstring 声称的"defends against any future code path"目标略有 gap。
- **修复建议**: 把 `except jwt.PyJWTError` 扩为 `except (jwt.PyJWTError, TypeError, ValueError): return None`，或直接 `except Exception: return None`（rotate 失败统一返 None，与下方 `_hash_token` 不匹配的逻辑一致）。dev 可选改或不改。

### Suggestion

#### S-1 — `P1-1` `_sync_get_json` 成功路径无 encoding fallback
- **位置**: `services/diagnosis-service/app/diagnosis_engine.py:632`（`json.loads(resp.read().decode("utf-8"))`）
- **问题**: 成功响应若 body 非 UTF-8（极少见，Kronos 是内部服务），`decode("utf-8")` 抛 `UnicodeDecodeError` 不被 `_http_get_json` 的调用方处理。错误路径（HTTPError/URLError）都有 fallback，成功路径反而更脆。
- **严重性**: suggestion —— 与 strategy-service `_http_get` 范式一致（同样无 fallback），Kronos 内部服务恒返回 UTF-8 JSON，实际不会触发。保持一致性优先，记录为已知项。

#### S-2 — `P1-8` `_RATE_GC_INTERVAL=512` 是魔法数
- **位置**: `services/api-gateway/app/main.py:29`（`_RATE_GC_INTERVAL = 512`）
- **问题**: 512 是经验值，无配置化或注释说明为何选 512（trade-off：扫太频繁拖慢热路径，太稀疏内存堆积久）。当前值对单实例合理，但不可调。
- **严重性**: suggestion —— 非问题，512 是合理经验值（约每秒级扫一次于中等 QPS）。建议加一行注释说明"512 ≈ 中等 QPS 下每秒扫一次，trade-off 内存 vs 热路径开销"，或改成 `os.environ.get("RATE_GC_INTERVAL", "512")` 可调。可选。
